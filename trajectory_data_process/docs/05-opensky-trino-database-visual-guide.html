0 / 连接方式

先定义一个最小可重复的 Trino CLI 入口

OpenSky 官方 Trino 文档要求使用 minio catalog、osky schema 和外部认证。 用户名必须是 OpenSky 小写用户名。下面的命令不会查询数据，只用于确认 CLI 能登录。

性能规则：除了 SHOW TABLES 和 DESCRIBE，查询状态向量表必须带 hour 分区过滤；查询 flights_data4 必须带 day 分区过滤。

示例变量

1776592800 = 2026-04-19 10:00:00 UTC，一小时分区。

1776556800 = 2026-04-19 00:00:00 UTC，一天分区。

KRDU 机场中心：lat 35.878659，lon -78.7873，elevation 435 ft。

验证 CLI 登录和默认 schema
export OPENSKY_USER="your_lowercase_opensky_username"

trino --user="${OPENSKY_USER:?set OPENSKY_USER}" --password \
  --server=https://trino.opensky-network.org \
  --external-authentication \
  --catalog minio \
  --schema osky \
  --execute "SELECT current_catalog, current_schema"
1 / 数据库有什么

OpenSky Trino 是很多表，但本项目只需要两类核心信息

官方当前暴露 14 张表。多数 Mode S/ADS-B 原始消息表适合低层协议研究；AeroViz 的训练数据拉取主要使用： state_vectors_data4 提供逐秒级位置、速度、航向、垂直速度、地面状态和双高度； flights_data4 提供一条航班级的起降机场估计，用于 landing/depart/pass 标签证据。

必须

state_vectors_data4

状态向量。训练点、轨迹几何、高度语义都从这里来。

必须

flights_data4

航班元数据。判断机场到达/离场候选，用 day 分区。

可选

其他 *_data4

Mode S / ADS-B 细分消息。当前训练管线不直接依赖。

备查

readsb_adsc_sv

ADS-C 卫星状态向量。适合远洋/极区研究，不是首批机场训练目标。

2 / 项目需要什么

训练目标不是“下载航迹”，而是构造机场附近的可审计 4D episode

Trino 状态向量行 time, icao24, lat, lon, velocity, heading, vertrate, onground, baroaltitude, geoaltitude
机场证据 航班元数据 estdepartureairport / estarrivalairport 区分 landing 和 depart 候选
几何 机场半径 episode 默认 5 NM entry 到 exit；保留 raw index 引用
质量 双高度点 训练点必须保留 baro + geo；缺 geo 进入 quarantine
输出 JSONL 训练层 history_rows / raw_tracks / airport_events / quarantine / manifests
项目问题 需要的 Trino 数据 当前代码入口
机场附近有哪些飞机？ state_vectors_data4 + bbox + hour fetch-profile terminal_all
哪些是落地/离场候选？ flights_data4.estarrivalairport / estdepartureairport fetch-profile airport_ops
垂直剖面要用哪种高度？ baroaltitude 和 geoaltitude 都要，且分开存 history_group_to_dual_altitude_points()
哪些样本可训练？ 双高度非空、时间 gap 合理、5 NM episode 完整 attach_training_points_or_quarantine()
验证 4 个生产候选机场当天的 arrival/depart 候选量

  --server=https://trino.opensky-network.org \
  --external-authentication \
  --catalog minio \
  --schema osky \
  --execute "WITH airports(airport) AS (VALUES 'KRDU', 'KSJC', 'KSMF', 'KSTL')
SELECT
  a.airport,
  count_if(f.estarrivalairport = a.airport) AS landing_candidates,
  count_if(f.estdepartureairport = a.airport) AS departure_candidates,
  count(DISTINCT f.icao24) AS distinct_aircraft
FROM airports a
LEFT JOIN flights_data4 f
  ON f.day = 1776556800

GROUP BY a.airport
ORDER BY a.airport"

4 / 高度语义

本项目必须同时保留 geo altitude 和 barometric altitude

垂直剖面、跑道对齐、进近下滑剖面和模型训练会被高度来源强烈影响。OpenSky 的 baroaltitude 是气压高度，适合和航空运行中的 altimeter/FL 语义关联； geoaltitude 是几何/GNSS 高度，更适合和 WGS84/Cesium 视觉空间对齐。 这两者不能互相覆盖，也不能在缺失时用另一个字段静默填充。

barometric altitude / baroaltitude

来源
ADS-B/Mode S 状态向量气压高度，单位 metres。
项目用途
保留 aircraft-reported pressure altitude，用于 QNH 修正、低高度/落地证据和训练输入。
注意
不等于机场标高，不等于 AGL，不等于 Cesium 里可直接贴地的几何高度。

geometric altitude / geoaltitude

来源
GNSS/geometric altitude，单位 metres，可能为空。
项目用途
用于 3D 空间和 WGS84 轨迹的垂直对齐，并作为训练样本的第二高度通道。
注意
缺失时写入 quarantine；不要用 baroaltitude 或机场标高填补。
当前代码约定： history_group_to_track() 把 baroaltitude 放入兼容 OpenSky track 的 path[*][3]；history_group_to_dual_altitude_points() 再把同一 history row 的 baroaltitude 和 geoaltitude 分别输出成 baro_altitude_m 与 geo_altitude_m，并标记 geo_altitude_match.method = "same_history_row"。
抽样查看 geo 与 baro 的差值，不要假设二者相等
trino --user="${OPENSKY_USER:?set OPENSKY_USER}" --password \

  --external-authentication \
  --catalog minio \
  --schema osky \
  --execute "SELECT
  time,
  icao24,
  callsign,
  onground,
  baroaltitude,
  geoaltitude,
  geoaltitude - baroaltitude AS geo_minus_baro_m
FROM state_vectors_data4
WHERE hour = 1776592800
  AND time BETWEEN 1776592800 AND 1776593700
  AND lat BETWEEN 35.578659 AND 36.178659
  AND lon BETWEEN -79.2373 AND -78.3373

5 / 项目落地层

代码中的数据拉取路线

推荐生产路径

  1. fetch_cylw_opensky.py --dataset-mode training --training-source history-db 调用 traffic.data.opensky.history。
  2. opensky_history_db.py 请求状态向量列和航班机场元数据列。
  3. write_history_rows() 先保存 Trino 返回行，不排序、不重命名、不去重。
  4. history_training.py 在派生副本中规范列名、分段、构造 raw track 和双高度点。
  5. trajectory_events.py 提取 5 NM airport episode 并生成 label evidence。
  6. training_dataset.py 附加双高度训练点；缺 geo_altitude_m 则 quarantine。

为什么不把 CZML 输入当训练数据？

trajectory_normalization.py 面向可视化，会截取进近窗口并可做显示用高度偏移。 训练数据必须从 history_rows/v2 和派生的 airport_events/v2 开始， 保证 raw evidence 与 derived training sample 分层。

6 / 验证清单

每次拉取前后的快速验证

拉取前

确认表存在、核心 schema 未变、目标机场当天有 arrival/depart 候选。

拉取中

保持小时间块、限制并发、避免没有 hour/day 的查询。

拉取后

核对双高度覆盖率、label 分布、quarantine reason 和 raw-to-derived 引用。

检查项 成功信号 失败时优先看哪里
状态向量密度 rows_total 和 aircraft_total 非零 bbox、时间窗口、OpenSky known data gaps
双高度覆盖 points_with_both_altitudes 足够高 geoaltitude null、coverage、receiver stale 过滤
标签证据 landing/depart/pass 都有明确 evidence flights_data4 join、5 NM crossing completeness
垂直剖面 baro/geo 差值被记录，而不是被覆盖 raw path index 3、training_points 高度字段
在数据库侧预估 airport_ops 与 terminal-area 的重叠关系
trino --user="${OPENSKY_USER:?set OPENSKY_USER}" --password \
  --server=https://trino.opensky-network.org \
  --external-authentication \
  --catalog minio \
  --schema osky \
  --execute "WITH area AS (
  SELECT DISTINCT icao24
  FROM state_vectors_data4
  WHERE hour = 1776592800
    AND time BETWEEN 1776592800 AND 1776593700
    AND lat BETWEEN 35.578659 AND 36.178659
    AND lon BETWEEN -79.2373 AND -78.3373
    AND time - lastcontact <= 15
),
ops AS (
  SELECT DISTINCT
    icao24,
    estdepartureairport,
    estarrivalairport
  FROM flights_data4
  WHERE day = 1776556800
    AND (estdepartureairport = 'KRDU' OR estarrivalairport = 'KRDU')
)
SELECT
  count(*) AS area_aircraft,
  count_if(ops.icao24 IS NOT NULL) AS area_aircraft_with_krdu_ops_metadata,
  count_if(ops.estarrivalairport = 'KRDU') AS landing_metadata_aircraft,
  count_if(ops.estdepartureairport = 'KRDU') AS departure_metadata_aircraft,
  count_if(ops.icao24 IS NULL) AS possible_pass_or_unknown_aircraft
FROM area
LEFT JOIN ops ON ops.icao24 = area.icao24"
