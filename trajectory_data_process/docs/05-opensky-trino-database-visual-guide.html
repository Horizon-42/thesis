0 / 连接方式

先定义一个最小可重复的 Trino CLI 入口

OpenSky 官方 Trino 文档要求使用 minio catalog、osky schema 和外部认证。 用户名必须是 OpenSky 小写用户名。日常探索时不要反复运行 --execute 一次性命令； 更方便的方式是先进入交互式 Trino shell，然后连续粘贴多条 SQL。

性能规则：除了 SHOW TABLES 和 DESCRIBE，查询状态向量表必须带 hour 分区过滤；查询 flights_data4 必须带 day 分区过滤。

时间输入方式

查询里优先写 2026-04-19T10:00:00Z 这样的 ISO UTC 时间。

hour_start 和 day_start 用 from_iso8601_timestamp() 转成 OpenSky 分区键。

KRDU 机场中心：lat 35.878659，lon -78.7873，elevation 435 ft。

推荐：交互式会话

执行一次 trino ... 进入 trino:osky> 提示符。首次提交查询时完成浏览器外部认证； 同一 CLI 会话内继续执行 SQL 不需要重复登录，直到认证 token 失效或会话退出。

脚本化备选

本文后续 Trino 查询默认都是交互式 SQL。需要脚本化时，再把同一段 SQL 放进 trino --execute "..." 或 trino --file query.sql。

一次登录：进入交互式 Trino shell
export OPENSKY_USER="your_lowercase_opensky_username"

trino --user="${OPENSKY_USER:?set OPENSKY_USER}" --password \
  --server=https://trino.opensky-network.org \
  --external-authentication \
  --catalog minio \
  --schema osky
进入 trino:osky> 后连续执行这些 SQL
SELECT current_catalog, current_schema;

1 / 数据库有什么

OpenSky Trino 是很多表，但本项目只需要两类核心信息

官方当前暴露 14 张表。多数 Mode S/ADS-B 原始消息表适合低层协议研究；AeroViz 的训练数据拉取主要使用： state_vectors_data4 提供逐秒级位置、速度、航向、垂直速度、地面状态和双高度； flights_data4 提供一条航班级的起降机场估计，用于 landing/depart/pass 标签证据。

必须

state_vectors_data4

状态向量。训练点、轨迹几何、高度语义都从这里来。

必须

flights_data4

航班元数据。判断机场到达/离场候选，用 day 分区。

可选

其他 *_data4

Mode S / ADS-B 细分消息。当前训练管线不直接依赖。

备查

readsb_adsc_sv

ADS-C 卫星状态向量。适合远洋/极区研究，不是首批机场训练目标。

2 / 字段字典

逐列理解 state_vectors_data4 和 flights_data4

这两张表的字段不是普通业务字段，而是航空监视数据和 OpenSky 推断结果的混合。 训练管线应把 state_vectors_data4 当作逐点观测事实，把 flights_data4 当作航班级机场标签证据。开始看列之前，先把飞机身份、航班身份和注册身份分清楚； 同样，也不要把 baroaltitude 和 geoaltitude 混成一个高度。

先分清三种“身份”：飞机、航班、注册号

身份类型 回答的问题 例子 在本项目里怎么用 不能怎么用
icao24 是哪一个应答机/飞机在广播这条状态？ a1b2c3 这类 24-bit 十六进制地址 用作 OpenSky 表内的飞机身份键。连接 state_vectors_data4 和 flights_data4 时，用 icao24 加 firstseen/lastseen 时间窗。 不能当航班号。因为同一架飞机一天可以飞多段航班，单看 icao24 不知道它这一刻是在飞哪一班。
callsign / 航班号 这架飞机此刻以什么运行呼号在飞？ AAL123、UAL456 这类航空公司代码加数字 用于人工核对、展示和辅助判断。它更接近 ATC 呼号，很多时候看起来像商业航班号。 不能当稳定主键。它可能为空、格式不整齐、每天重复使用，也可能和旅客票面航班号不完全一致。
registration / 注册号 这架飞机的法定机身注册/尾号是什么？ N123AB、B-1234 这类 tail number 做机队、机型、单机历史分析时有用。通常需要外部 aircraft metadata 把 icao24 映射到 registration。 这两张核心 Trino 表默认不直接提供注册号；不要在没有外部映射时假设 icao24 就是注册号。
一句话： icao24 更像“这架飞机/应答机是谁”，callsign 更像“这一趟任务用什么呼号飞”， registration 更像“这架飞机机身上登记的尾号”。训练数据 join 优先用 icao24 + 时间窗； 人工理解航班再看 callsign 和机场推断字段。
在 trino:osky> 中先验证字段是否和本文一致
DESCRIBE state_vectors_data4;
DESCRIBE flights_data4;

state_vectors_data4：逐点状态向量字段

一行通常表示某架飞机在某个 UTC 秒附近的一个状态向量。它适合构造轨迹点、速度/航向/垂直速度特征、 机场附近 episode，以及双高度训练样本。

字段 类型/单位 直观含义 项目解释和航空注意点
time Unix 秒，UTC 该状态向量有效的时间 这是训练点的主时间轴。SQL 里建议用 from_iso8601_timestamp('2026-04-19T10:00:00Z') 转换，不要手写难读的 epoch 秒。
icao24 24-bit 十六进制地址 飞机应答机地址 这是 OpenSky 里最常用的飞机身份键：它标识发出 ADS-B/Mode S 信号的应答机/飞机。 它不是航班号；航班号/呼号表达“这一次运行任务叫什么”。它也不是注册号；注册号是机身法定尾号，通常要查外部 aircraft metadata。 项目用法：用 icao24 把同一时间窗内的状态向量串成轨迹，并和 flights_data4 连接；但训练 label 不能只靠它决定 landing/depart。
lat 度，WGS84 纬度 机场 bbox、5 NM 半径 entry/exit、轨迹可视化都依赖它。为空或过旧时不能进入训练点。
lon 度，WGS84 经度 和 lat 一起定义水平位置。注意经度跨 180 度的区域要特殊处理；当前 KRDU/KSJC/KSMF/KSTL 不涉及。
velocity m/s 地速 这是 ground speed，不是 airspeed。用于轨迹动力学特征可以，但不要直接拿它判断飞机性能极限。 航空注意：风会让地速和空速差很多，进近阶段尤其明显。
heading 度，0-360 地面运动方向 OpenSky 状态向量里的 heading 更接近 track/course over ground，按地理北顺时针计算；它不一定等于机头朝向。 航空注意：侧风时飞机 nose heading 和 ground track 可以明显不同。
vertrate m/s 垂直速度 正数通常表示爬升，负数表示下降。做进近/离场剖面时很有价值；若需要航空常用单位，可近似换算为 ft/min = m/s * 196.85。
callsign 字符串 机组广播的航班呼号 可用于人工识别航班，但可能为空、有尾随空格、或和商业航班号不完全一致。项目中作为辅助展示字段，不作为唯一主键。 航空注意：呼号是 ATC/飞行计划语境里的标识，和 icao24 的飞机硬件身份不同。
onground boolean 是否在地面 对落地/起飞识别有帮助，但可能噪声或缺失。训练 label 应结合机场半径、速度、高度、flights_data4 机场推断共同判断。
alert boolean ATC alert 标志 来自应答机/ATC 语义，表示特殊告警状态。它不是轨迹几何字段，通常不进入首版训练特征。 航空注意：可作为异常运行背景信息，但不能单独解释飞机意图。
spi boolean Special Position Identification 飞行员按下 ident 后可能出现的特殊位置识别标志，方便 ATC 在雷达屏上识别飞机。项目里主要用于审计或异常解释。
squawk 4 位八进制码 ATC 应答机代码 由 ATC 分配或用于特殊状态。它是航空管制语义，不是飞机身份主键。 航空注意：7500、7600、7700 分别常见于非法干扰、无线电失效、紧急情况，但历史数据分析中需要谨慎解释上下文。
baroaltitude m 气压高度 由气压高度源报告，适合保留航空运行中的 pressure altitude/flight level 语义。 不等于 AGL，不等于机场标高，也不等于可直接放进 Cesium 的几何高度。 项目要求：必须独立保存为 baro_altitude_m，不能用 geoaltitude 覆盖。
geoaltitude m 几何/GNSS 高度 更接近空间几何高度，适合 3D 可视化和 WGS84 轨迹对齐，但可能为空。 项目要求：训练样本需要第二高度通道 geo_altitude_m；缺失时进入 quarantine，不要用 baroaltitude 静默填补。
lastposupdate Unix 秒，UTC 最后一次位置更新的时间 用于判断 lat/lon 是否新鲜。位置可能比当前状态时间更旧，做轨迹质量控制时应关注。
lastcontact Unix 秒，UTC OpenSky 最后一次收到该飞机信号的时间 本文查询常用 s.time - s.lastcontact <= 15 过滤 stale row，避免把过期信号当作当前轨迹点。
serials receiver id 数组 接收到该状态向量的 OpenSky 接收机编号 适合覆盖率、接收来源和数据质量审计。它不是飞机属性，通常不要作为训练模型的行为特征。
hour Unix 秒，UTC hour bucket 小时分区键 这是 Trino 查询性能关键字段，不是另一个事件时间。查 state_vectors_data4 时必须用它裁剪分区。
在 trino:osky> 中抽样查看容易误解的状态向量字段
WITH params AS (
  SELECT
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T10:00:00Z')) AS bigint) AS hour_start,
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T10:00:00Z')) AS bigint) AS begin_time,
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T10:15:00Z')) AS bigint) AS end_time,
    35.578659 AS min_lat,
    36.178659 AS max_lat,
    -79.2373 AS min_lon,
    -78.3373 AS max_lon
)
SELECT
  s.time,
  s.icao24,
  s.callsign,
  s.velocity,
  s.heading,
  s.vertrate,
  s.onground,
  s.alert,
  s.spi,
  s.squawk,
  s.baroaltitude,
  s.geoaltitude,
  s.lastposupdate,
  s.lastcontact,
  s.serials
FROM state_vectors_data4 s
CROSS JOIN params p
WHERE s.hour = p.hour_start
  AND s.time BETWEEN p.begin_time AND p.end_time
  AND s.lat BETWEEN p.min_lat AND p.max_lat
  AND s.lon BETWEEN p.min_lon AND p.max_lon
ORDER BY s.time, s.icao24
LIMIT 20;

flights_data4：航班级机场推断字段

一行通常表示 OpenSky 从一段轨迹中推断出的航班级记录。它非常适合给 airport episode 提供 arrival/depart 候选证据，但机场字段是估计值，不是机场运营系统的权威航班表。

字段 类型/单位 直观含义 项目解释和航空注意点
icao24 24-bit 十六进制地址 执行该航班记录的飞机地址 表示这条航班级记录对应的是哪一个应答机/飞机。它负责回答“哪架飞机”，不是回答“哪一个航班号”。 可和 state_vectors_data4.icao24 连接，但必须再加时间条件 s.time BETWEEN f.firstseen AND f.lastseen，否则同一架飞机当天多段航班会混在一起。
firstseen Unix 秒，UTC OpenSky 在该航班记录中第一次看到飞机的时间 不是计划起飞时间，也不保证等于真实离地时间。它受接收覆盖影响，适合作为 join 时间窗下界和轨迹截取线索。
estdepartureairport ICAO 机场码 估计起飞机场 用于 departure 候选标签。字段名里的 est 很重要：这是推断结果，项目应继续用 5 NM crossing、低高度和地面状态验证。 航空注意：ICAO 码如 KRDU、KSJC，不是 IATA 码 RDU、SJC。
lastseen Unix 秒，UTC OpenSky 在该航班记录中最后一次看到飞机的时间 不是计划到达时间，也不保证等于接地时间。可作为 join 时间窗上界和 arrival episode 的搜索范围。
estarrivalairport ICAO 机场码 估计到达机场 用于 landing 候选标签。和 estdepartureairport 一样，它是证据而不是真值；训练样本应保留 label evidence。
callsign 字符串 航班呼号 可辅助人工核对和展示。不同数据行的 callsign 可能为空或格式不稳定；连接和分组时优先使用 icao24 + 时间窗。
track 数组：time, latitude, longitude, altitude, heading, onground 该航班的简化轨迹点序列 适合快速预览航班路径，但不应替代 state_vectors_data4 作为训练 raw rows。 项目注意：track 里的 altitude 是单一高度槽；本项目需要双高度，所以训练点仍从 state vectors 的 baroaltitude + geoaltitude 构造。
estdepartureairporthorizdistance m 起飞机场推断的水平距离残差 可作为起飞机场推断置信度线索；越小通常表示几何关系越贴近，但不要单独作为标签真值。
estdepartureairportvertdistance m 起飞机场推断的垂直距离残差 反映轨迹端点高度和机场附近高度关系。机场标高、气压高度和几何高度语义不同，因此只适合作为推断诊断字段。
estarrivalairporthorizdistance m 到达机场推断的水平距离残差 可用于判断 arrival airport 是否可信。若距离异常大，airport episode 应更依赖 5 NM 几何 crossing 和原始状态向量。
estarrivalairportvertdistance m 到达机场推断的垂直距离残差 适合发现“疑似到达机场但高度不合理”的记录。不要把它和 baroaltitude/geoaltitude 的训练通道混用。
departureairportcandidatescount 整数 起飞机场候选数量 候选数量越多，说明推断歧义可能越大。可用于给 label evidence 标注 confidence/ambiguity。
arrivalairportcandidatescount 整数 到达机场候选数量 用于衡量 arrival 标签是否有多个备选机场。多机场密集区域尤其需要看它。
otherdepartureairportcandidates 候选机场数组 其他起飞机场候选 用于审计 estdepartureairport 的歧义。若目标机场出现在 other candidates，而不是 estimated 字段，样本应降低置信度或进入人工复核。
otherarrivalairportcandidates 候选机场数组 其他到达机场候选 用于审计 estarrivalairport 的歧义。对邻近机场、多跑道终端区和接收覆盖缺口尤其有用。
day Unix 秒，UTC day bucket 日期分区键 这是查 flights_data4 的性能关键字段，不是航班唯一日期语义。查询必须带 f.day = day_start，跨 UTC 日的航班要查相邻 day。
在 trino:osky> 中抽样查看 flights_data4 的推断距离和候选机场字段
WITH params AS (
  SELECT
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T00:00:00Z')) AS bigint) AS day_start
)
SELECT
  f.icao24,
  f.callsign,
  f.firstseen,
  f.lastseen,
  f.estdepartureairport,
  f.estarrivalairport,
  f.estdepartureairporthorizdistance,
  f.estdepartureairportvertdistance,
  f.estarrivalairporthorizdistance,
  f.estarrivalairportvertdistance,
  f.departureairportcandidatescount,
  f.arrivalairportcandidatescount,
  f.otherdepartureairportcandidates,
  f.otherarrivalairportcandidates,
  cardinality(f.track) AS track_points,
  slice(f.track, 1, 3) AS first_three_track_points
FROM flights_data4 f
CROSS JOIN params p
WHERE f.day = p.day_start
  AND (f.estdepartureairport = 'KRDU' OR f.estarrivalairport = 'KRDU')
ORDER BY f.firstseen
LIMIT 10;
实践结论： state_vectors_data4 给训练点的“物理观测”，flights_data4 给机场标签的“航班级证据”。 两者连接时使用 icao24 加 firstseen/lastseen 时间窗，并保留推断字段作为 evidence， 不要把 estimated airport 当作无条件真值。
3 / 项目需要什么

训练目标不是“下载航迹”，而是构造机场附近的可审计 4D episode

Trino 状态向量行 time, icao24, lat, lon, velocity, heading, vertrate, onground, baroaltitude, geoaltitude
机场证据 航班元数据 estdepartureairport / estarrivalairport 区分 landing 和 depart 候选
几何 机场半径 episode 默认 5 NM entry 到 exit；保留 raw index 引用
质量 双高度点 训练点必须保留 baro + geo；缺 geo 进入 quarantine
输出 JSONL 训练层 history_rows / raw_tracks / airport_events / quarantine / manifests
项目问题 需要的 Trino 数据 当前代码入口
机场附近有哪些飞机？ state_vectors_data4 + bbox + hour fetch-profile terminal_all
哪些是落地/离场候选？ flights_data4.estarrivalairport / estdepartureairport fetch-profile airport_ops
垂直剖面要用哪种高度？ baroaltitude 和 geoaltitude 都要，且分开存 history_group_to_dual_altitude_points()
哪些样本可训练？ 双高度非空、时间 gap 合理、5 NM episode 完整 attach_training_points_or_quarantine()
在 trino:osky> 中验证 4 个生产候选机场当天的 arrival/depart 候选量
WITH
params AS (
  SELECT
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T00:00:00Z')) AS bigint) AS day_start
),
airports(airport) AS (VALUES 'KRDU', 'KSJC', 'KSMF', 'KSTL')
SELECT
  a.airport,
  count_if(f.estarrivalairport = a.airport) AS landing_candidates,
  count_if(f.estdepartureairport = a.airport) AS departure_candidates,
  count(DISTINCT f.icao24) AS distinct_aircraft
FROM airports a
CROSS JOIN params p
LEFT JOIN flights_data4 f
  ON f.day = p.day_start
 AND (f.estarrivalairport = a.airport OR f.estdepartureairport = a.airport)
GROUP BY a.airport
ORDER BY a.airport;
在 trino:osky> 中验证 KRDU 终端区 15 分钟内的状态向量密度
WITH params AS (
  SELECT
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T10:00:00Z')) AS bigint) AS hour_start,
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T10:00:00Z')) AS bigint) AS begin_time,
    CAST(to_unixtime(from_iso8601_timestamp('2026-04-19T10:15:00Z')) AS bigint) AS end_time,
    35.578659 AS min_lat,
    36.178659 AS max_lat,
    -79.2373 AS min_lon,
    -78.3373 AS max_lon
)
SELECT
  count(*) AS rows_total,
  count(DISTINCT s.icao24) AS aircraft_total,
  count_if(s.baroaltitude IS NOT NULL) AS rows_with_baro,
  count_if(s.geoaltitude IS NOT NULL) AS rows_with_geo,
  count_if(s.baroaltitude IS NOT NULL AND s.geoaltitude IS NOT NULL) AS rows_with_both_altitudes

5 / 高度语义

本项目必须同时保留 geo altitude 和 barometric altitude

垂直剖面、跑道对齐、进近下滑剖面和模型训练会被高度来源强烈影响。OpenSky 的 baroaltitude 是气压高度，适合和航空运行中的 altimeter/FL 语义关联； geoaltitude 是几何/GNSS 高度，更适合和 WGS84/Cesium 视觉空间对齐。 这两者不能互相覆盖，也不能在缺失时用另一个字段静默填充。

barometric altitude / baroaltitude

来源
ADS-B/Mode S 状态向量气压高度，单位 metres。
项目用途
保留 aircraft-reported pressure altitude，用于 QNH 修正、低高度/落地证据和训练输入。
注意
不等于机场标高，不等于 AGL，不等于 Cesium 里可直接贴地的几何高度。

geometric altitude / geoaltitude

来源
GNSS/geometric altitude，单位 metres，可能为空。
项目用途
用于 3D 空间和 WGS84 轨迹的垂直对齐，并作为训练样本的第二高度通道。
注意
缺失时写入 quarantine；不要用 baroaltitude 或机场标高填补。
当前代码约定： history_group_to_track() 把 baroaltitude 放入兼容 OpenSky track 的 path[*][3]；history_group_to_dual_altitude_points() 再把同一 history row 的 baroaltitude 和 geoaltitude 分别输出成 baro_altitude_m 与 geo_altitude_m，并标记 geo_altitude_match.method = "same_history_row"。

airport_ops 是什么？

airport_ops 是项目里的 --fetch-profile 名称，意思是 airport operations： 只抓取和目标机场起飞/到达相关的航班状态向量。它不是 OpenSky 的一张表。 在 history-db 路径里，代码会调用 traffic.data.opensky.history(..., airport='KRDU')， 请求状态向量字段，并带上 FlightsData4.estdepartureairport / FlightsData4.estarrivalairport 作为 landing/depart 证据。

和它相对的是 terminal_all：后者会再按机场中心 bbox 拉取终端区内所有状态向量， 用来发现没有 KRDU 起降元数据、但穿过机场附近的 pass-through 飞机。

这段 airport_ops / terminal-area 对比 SQL 在验证什么？

它把同一个时间窗里的两类证据放到一起比较：一类是机场附近 bbox 内实际出现过的飞机， 另一类是 flights_data4 里被推断为 KRDU 起飞或到达的航班元数据。 这个检查能帮助判断 terminal_all 里有多少飞机能被 KRDU 起降元数据解释， 以及有多少飞机更可能是 pass-through 或元数据未知。

SQL 部分 作用 为什么需要
params 把人类可读的 UTC 时间和 KRDU 附近 bbox 写成一行参数。 避免手写 epoch 秒；同时保证后面每个 CTE 用同一套时间窗和空间范围。
area 从 state_vectors_data4 找出 10:00-10:15 UTC、KRDU bbox 内出现过的唯一 icao24。 这是 terminal-area 视角：只要飞机实际出现在机场附近，就先纳入候选，不管它是不是在 KRDU 起降。
ops 从 flights_data4 找出当天 estimated departure/arrival airport 为 KRDU 的飞机。 这是 airport_ops 视角：只关心 OpenSky 航班级元数据认为和 KRDU 起降相关的飞机。
LEFT JOIN 保留所有 area 飞机，再尝试匹配它们是否有 KRDU 起降元数据。 没有匹配上的飞机不会丢失；它们正是 possible pass-through 或 metadata unknown 的来源。
最终 SELECT 统计区域飞机总数、带 KRDU 元数据的飞机数、landing/departure 证据数和未知数。 用于判断机场标签证据是否足够，以及 terminal_all 是否发现了 airport_ops 之外的飞机。

输出里 possible_pass_or_unknown_aircraft 不等于“确定 pass-through”。 它只表示：这架飞机在 KRDU 附近出现了，但当天 flights_data4 没有把它标成 KRDU 起飞或到达。 真实标签还要结合 5 NM entry/exit、低高度、onground、高度剖面和时间完整性判断。 另外，这个查询是快速健康检查：ops 只按 UTC day 找 KRDU 起降元数据， 没有要求 f.firstseen/f.lastseen 和 10:00-10:15 的状态向量窗口严格重叠。 精确事件生成仍应使用时间窗 join 和 5 NM episode 逻辑。

  count_if(s.time - s.lastcontact <= 15 AND s.baroaltitude IS NOT NULL AND s.geoaltitude IS NOT NULL) AS usable_dual_altitude_rows
FROM state_vectors_data4 s
CROSS JOIN params p
WHERE s.hour = p.hour_start
  AND s.time BETWEEN p.begin_time AND p.end_time
  AND s.lat BETWEEN p.min_lat AND p.max_lat
  AND s.lon BETWEEN p.min_lon AND p.max_lon;
