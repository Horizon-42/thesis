AeroViz-4D architecture

Airport 4D trajectory and terrain digital twin

This document describes the current frontend architecture after the terrain, procedure, profile, and context deepening work. The project keeps React as the UI shell, CesiumJS as the 3D scene adapter, and typed data modules as the primary domain seams.

UI shell

React overlays

ControlPanel, HUD, FlightTable, ProcedurePanel, profile panel.

Scene adapter

Cesium hooks

Hooks bind app state to viewer lifecycle and entity mutation.

Domain modules

Typed geometry/data

Procedure, terrain, profile, and assessment modules own the rules.

Generated assets

public/data

CZML, runway GeoJSON, procedure details, and local DSM terrain tiles.

State seams

AppProvider internal split

SceneContext - viewer, layer toggles, local terrain status.
AirportSessionContext - airport catalog, active airport, airport camera target.
FlightSessionContext - selected flight and trajectory datasource.
ProcedureSessionContext - branch visibility, annotation, width, display level.
RunwayProfileSessionContext - selected runway and profile view state.

The public useApp() interface remains compatible. Internally, reset rules and ownership are now easier to reason about.

Terrain

Terrain runtime module

flowchart TD
  TL[useTerrainLayer] --> RT[terrainRuntime]
  DL[useDsmTerrainLayer] --> RT
  SI[useSatelliteImageryLayer] --> RT
  RT --> WP[World terrain settings]
  RT --> LP[Local DSM warm policy]
  RT --> NM[No-imagery material and lighting]
  RT --> GS[Globe restore snapshots]

The hooks are lifecycle adapters. Provider priority, focused DSM warmup, streaming settings, no-satellite grayscale material, and render-state restore all live behind one terrain seam.

Procedure modules

RNAV procedure rendering architecture

flowchart TD
  DOC[procedure detail documents] --> PKG[procedurePackageAdapter]
  PKG --> BUNDLE[procedureRenderBundle]
  BUNDLE --> SURF[procedureProtectionSurfaces]
  BUNDLE --> VERT[procedureVerticalGuidance]
  BUNDLE --> SCENE[procedureSceneRenderer]
  SURF --> SCENE
  VERT --> SCENE
  SCENE --> HOOK[useProcedureSegmentLayer]
  HOOK --> CES[Cesium entities]
procedureProtectionSurfaces is the single render source for final OEA, LNAV/VNAV OCS, precision debug surfaces, missed surfaces, missed connectors, and turning missed debug surfaces.
procedureVerticalGuidance owns GPA/TCH final references and branch vertical profile aids outside Cesium.
procedureSceneRenderer owns entity registry, branch lazy rendering, visibility refresh, and cleanup.

Runway profile

Profile analysis seam

flowchart LR
  ENT[Cesium trajectories] --> SAMPLE[useRunwayTrajectoryProfile samples]
  SAMPLE --> ANALYSIS[runwayTrajectoryProfileAnalysis]
  ROUTES[Horizontal plate routes] --> ANALYSIS
  ANALYSIS --> PANEL[RunwayTrajectoryProfilePanel]

Cesium sampling remains in the hook. Route activation, containment classification, selected-flight ordering, trail shaping, and color assignment now live in the analysis module.

Data pipeline

Generated data inputs

flowchart TD
  OS[OpenSky or ADS-B raw data] --> NORM[trajectory normalization]
  NORM --> CZML[generate_czml.py]
  CZML --> APP[useCzmlLoader]
  CIFP[ARINC/CIFP procedure data] --> PROC[preprocess_procedures.py]
  PROC --> PD[procedure detail JSON]
  TIF[GeoTIFF DSM] --> DSM[build_dsm_heightmap_terrain]
  DSM --> TILES[.f32 local terrain tiles]
  RUN[OurAirports runway data] --> RW[runway.geojson]
