# Training 模块

前端的 **Training** 任务页（顶栏 Observe 右边）把第二层模型的"语言"画出来：一架到达航班被读成了
哪一句指令，这句话里每个词允许飞机在哪里（词的包络，也就是"飞行盒"），航迹有没有待在里面。
它不训练模型，不调后端，不写磁盘，只读导出好的 JSON。

词表本身的定义见 `4dTrajectory/ts_transformer/docs/2026-09-23_instruction_vocabulary_design.zh.md`
（下文简称"词表设计"）。本文只写前端这一侧：数据怎么来、每个词画成什么、界面上有什么。

## 1 这个模块回答什么

1. **这架飞机被读成了哪一句话**：每 2 s 一步，六列词（跑道、进近、航向、高度、下降角、速度，顺序与
   `instructions/words.COLUMNS` 相同）。第 0 步六列都有词；之后绝大多数步什么也不说。
2. **每个词允许飞机在哪里**：从发令点开始的包络——航向词的转弯区、转弯可能结束的位置和保持漏斗，截获后的
   走廊，高度词的管子，速度词的过渡和速度带。
3. **航迹有没有待在里面**：每一项都是标注器自己的判定（`Reading.checks`），前端只显示，不重算。

放在 Observe 旁边，是因为两页看的是同一批到达航班：Observe 看"飞机怎么飞的"，Training 看"这条航迹
被读成了什么"。Training 不加载 Observe 的 CZML，也不动共享的 Cesium 时钟。

  五个机场全部建好之后才开始写，中途任何一处拒绝，盘上什么都不留。

### 2.2 `index.json`

索引的格式（`aeroviz-training-index-v1`）不随词表变：新旧集合都列在里面，每一条写着自己的读法
（`readingRule`）和规格 sha（`vocabularySha256`）。所以界面**不用下载任何文件**就知道哪个集合能读：
读法是 `instruction-v2`、规格是 `103a6eae6b90`、类型是 `vocabulary-readback` 的才打开，其余按名字拒读。
`runwaySha256` 是该机场几何的 sha：候选跑道（跑道列的类别就是它们），加上落地判定要读的全部跑道端。

### 2.3 `sample.json`（`aeroviz-training-sample-v5`）

顶层：

- `vocabulary`：读法、规格 sha、标注器 sha、六列的名字和顺序、"不变"（−1）、步长、平滑窗口；**每一列
  的类别都写成表**（航向 72 个角度、高度 181 个目标加"下降至落地"、6 个下降角类及各自的名义角度和范围、
  速度 47 个目标加"未指定"、进近 3 类），界面查表出文字，不自己换算；还有画图和说明要用的容差：
  - 航向：保持 ±4.5°；转弯率 0.5–4.7°/s（下限只管 10° 以上的转弯），坡度不超过 32°，转弯最多比发令晚
    10.5 s 开始；
  - 落地：越过入口时离中线不超过 1000 m（有平行跑道时取到它间距的一半，两条跑道航向差 5° 以内算平行），
    离入口的高度不超过 100 m；
  - 走廊 20 m / 0.45° / ±2°，高度 ±25 m，速度 ±5 m/s，加速度 1.7 m/s²。
- `candidates`：本机场全部候选跑道，每条有入口、真航向、入口高程、长度、**这条跑道自己的落地横向界限**
  （例如 KSJC 平行跑道之间只有 106.7 m），以及画好的跑道线段和延长中线（机场坐标系的米和经纬度各一份）。
- `cohort`：抽样规则与候选池、读过的数量。

每架航班：

- 身份：`datasetId`、`flightKey`（`id_跑道_icao24_落地时刻`）、呼号、机型、跑道、分组、步数；
  截获行、许可行、"未指定"行、截获时离入口的距离。
- `signals`：每步一行。时间、机场坐标系的东/北（米）、经纬度、椭球高（给三维用）、原始信号（航迹、
  高度、地速、垂直速率）、**平滑后的信号**（标注器实际读的：航迹 6 s、高度 10 s、地速 10 s）和由平滑
  地速积分出的水平距离、相对所指跑道的沿航道距离与偏离。两种信号都给，因为平滑本身是读法的一部分。
- `words`：发令事件（行、列、值、为什么发：进入时已生效 / 转弯 / 拆分的转弯 / 补的切入航向 / 许可 /
  新目标 / 两段保持之间 / 新下降角 / 速度交给飞行员），以及每一列每一步生效的值。后者必须等于前者
  逐行往后填，读取时检查。
- `envelopes`：每个词的包络与判定，见 §3。每个转弯（航向词的和截获转弯）除了平面上的转弯区、两条转弯路径、
  平行四边形，还带**航向随时间**的两条曲线（`headingFast` 最快的转弯按时开始，`headingSlow` 最慢的转弯晚
  10.5 s 开始）和它们围成的区域（`headingRegion`）：时间是航班的秒，角度在发令时平滑航迹的展开分支上，
  两条曲线与两条平面路径逐点对应。v5 起不再有 `turnBandDeg` 和截获转弯的 `bandDeg`（那个方框看不出转弯快慢）。

单位只有米、米/秒、度、秒。高度是几何 MSL；只有 `altitudeHaeM`、`lowerHaeM`、`upperHaeM` 三处是椭球高，
由导出器一次换好（h = H + N，EGM96），专给 Cesium 用。

### 2.4 一条原则：前端不算包络

每一个区域、每一条带、每一根管子都在 Python 里由词表自己的函数算好（`instructions/display.py`，
只用 `envelope.py` 和 `labeller/*` 的公开函数；它不在标注器 sha 的范围里，改画法不改句子）；每一个判定
都是标注器的。转弯区和保持漏斗更进一步：画出来的就是标注器判的那一个（两边调用同一个函数）。
前端只检查"账对不对"——长度、行号、每一步的词是不是事件往后填出来的、判定里的计数是不是等于它自己逐行
标记的计数、画转弯区用的转弯率和坡度是不是词表的——然后照数画。前端若再算一遍包络，屏幕上就会有两个答案。

### 2.5 按名字拒读

`trainingSample.ts` 钉住并逐项核对：样本格式名 `aeroviz-training-sample-v5`、读法 `instruction-v2`、规格 sha
全文、六列的名字和顺序、"不变"的值、标注器会写的发令原因列表。对不上就整份拒读，报出是哪一项；不做兼容分支。
格式名不对就不往下读，不管文件里是哪个词表：v4、v3 的文件（v3 是 `instruction_v1` 的样本）按名字拒读。
Python 这一侧的对应常量由 `test_instruction_training_export.py` 与 TypeScript 源码逐字比对。

### 2.6 叠加层：执行器的回放与先验的预测

别的模型对一个集合里这些航班做了什么，写在集合**旁边**，不写进集合：

```bash
# 执行器：从工作树（worktree）里跑——在主工作区，执行器规格的源码 sha 会把 geokit 算进去而拒读（见 ts 的 R13）
python run_ts.py executor_training_export \
    --executor 4dTrajectory/outputs/POOLED/executor/v2_20260924 \
    --replay 4dTrajectory/outputs/POOLED/executor/v2_20260924/replay-val \
    --instructions 4dTrajectory/outputs/POOLED/instruction_language/v2_20260924 \
    --airports-root aeroviz-4d/public/data/airports --set instruction_v2 \
    --airport KMSY --airport KRDU --airport KSJC --airport KSMF --airport KSTL
python run_ts.py prior_training_export \
    --prior 4dTrajectory/outputs/POOLED/prior/v1_20260924 \
    --instructions 4dTrajectory/outputs/POOLED/instruction_language/v2_20260924 \
    --airports-root aeroviz-4d/public/data/airports --set instruction_v2 \
    --airport KMSY --airport KRDU --airport KSJC --airport KSMF --airport KSTL
```

- **清单**：每个机场一个 `training/overlays.json`（`aeroviz-training-overlays-v1`），一条一个叠加层：种类、所画的集合、
  那个集合样本文件的 sha256、文件位置。叠加层文件放在 `training/<叠加层 id>/`，目录已存在或清单里已有同名 id 就拒绝，
  五个机场都建好才写。`index.json` 不动。
- **执行器**（`executor.json`，`aeroviz-training-executor-v1`）：用正式规格把集合里的航班重新飞一遍、判一遍。重飞是必须的：
  正式回放的 `replay.json` 只记了每架航班"哪一类词合不合格"的列表，没有记是哪一条词。重飞后每条判定对回句子里的词，
  并且**每架航班必须和正式回放的那一行一致**：结局、是否按原话飞完、判定列表、不判 / 没说到 / 被取代的词数完全相同，
  越过入口的偏离与高度差在 1e-9 以内（换一批航班一起飞，浮点求和的次序不同，差一个末位），否则导出停下、说出是哪一架。
  evaluation 的判定取正式回放的，不重跑。每条词一个状态：在包络里、出界、不判（转弯被截获接管，或没有转弯也没有保持
  段，或飞出的航迹没过标注器的门）、没说到（航班先结束了）、被取代（同一列两条词落在飞出的同一步，只飞后一条）、
  没有自己的检查（跑道指针、下降角词、"未许可"、"未指定"）。拆分的大转弯各份共用一个判定；执行器离开航向词自己去
  切入航道的那条航向词记为出界。回放不飞的航班（没有识别出机型、机型没有公开进近速度）列出原因，没有航迹。飞出的
  航迹每 2 s 一点，到结局那一行，带 MSL 与椭球高；还附上这个机场与全部机场的回放门表。
- **先验**（`prior.json`，`aeroviz-training-prior-v1`）：检查点必须是这份产物的规格与标注器训练的、不是冒烟试跑、候选跑道表
  与产物相同、状态整份载入。推断用教师强制（每一步看到真值句子在它之前的词），与训练和读数时一样；这条推断路径在全部
  10,540 架 val 航班上复现 `readout.json` 的每步负对数似然到 1e-9。每架航班每列每步：说一个词的概率、若说一个词最可能的
  3 个词（列的取值少于 3 个时更少，例如一个机场的候选跑道）及其概率、真值的概率；每架航班每步的负对数似然（总的和
  分列的，四舍五入前算）。val 的读数随文件一起走，原样照抄。
- **绑定与核对**：叠加层自己写出所画集合的 id、样本的写出时刻、规格 sha；前端逐项核对，并核对每架航班的键、执行器的
  每条词（步、列、值）、先验的步数，对不上整份拒读。`check-publication` 另外核对盘上样本文件的 sha256。

## 3 每个词画成什么（飞行盒）

### 3.1 航向词：转弯区、转弯可能结束的位置、保持漏斗

- **转弯区**：从发令点按较短的方向转到目标 θ，夹在两个极端的转弯之间，都按飞机实际飞的地速飞：
  - **最快的转弯**：4.7°/s，但坡度超过 32° 时按 32°（坡度由转弯率和地速算：tan 坡度 = 地速 × 转弯率 / g），
    按时开始；
  - **最慢的转弯**：0.5°/s，最多晚 10.5 s 开始（晚开始 = 先沿发令时的航迹直飞 10.5 s）；
  - 两者都转到航迹离 θ 不到 4.5° 为止。转弯区是一圈边界：最快的转弯、两个终点、倒着沿晚开始的最慢转弯回到
    晚开始的点，再回到发令点。
  - 画出来的两条**转弯路径**就是这两条边：最快的转弯（按时开始）和最慢的转弯（晚 10.5 s 开始，先直飞一段）。
- **航向图上的同一个转弯**：同样这两个转弯，画成航向随时间变化的两条曲线——最快的那条陡，很快转到目标；
  最慢的那条先平 10.5 s，再按 0.5°/s 慢慢转——允许的航向就在两条曲线之间（楔形）。曲线由 `display.py` 从
  平面路径逐点读出（每一步按前后两行航向的平均值飞，所以每一步的方向给出下一行的航向），不另算一遍转弯。
- **大转弯为什么看起来这么大**：最慢的边界 0.5°/s 在 118 m/s 时转弯半径约 13.5 km，而最快的边界受 32° 坡度
  限制，约 3.0°/s、半径约 2.3 km。一个 150° 的转弯，转弯区就有十几到二十公里，"转弯可能结束的位置"是一条
  十几公里长的带子，都主要来自最慢的那条边界；实际的大转弯在这批航班里平均 1.2–2.1°/s。选中这个词时，
  平面图按它的整个包络取景、两条路径标出名字、航迹上标出实际转弯的起止（标注器读到的离开和到达两行），
  其余的词淡化（§4.5）。
- **转弯可能结束的位置**：一个平行四边形——最快和最慢转弯的两个终点，再把这两点沿发令时的航迹向前挪
  晚开始的距离（地速 × 10.5 s）。界面上画得比转弯区深。
- **保持漏斗**：从这个平行四边形的每一点出发，沿 θ 张开 ±4.5° 的角，扫出的区域（这些点的凸包）。漏斗的
  长度是已飞路程，沿位置点累计，从转弯最后一行之前 10.5 s 起算（不早于发令行）——标注器看到转弯结束也可能
  晚 10.5 s。标注器判的就是这个漏斗：保持段从第一行到最后一行，每一行在不在里面。
- 漏斗画到这个词的保持结束：下一个航向词发出处；最后一个航向词画到标注器的截获转弯开始处。
  拆分的大转弯中间那几份在转到之前就被下一份接替，没有漏斗。进入切片时已经在保持的词没有转弯，漏斗就是
  从发令点张开的那一个角。
- **不判的保持段**：转弯小于 10°（最慢转弯率不适用，多半是风的漂移），或最慢的转弯在航班结束前转不到 θ。
  这两种漏斗照样画出（虚线边），判定里写"不判"。最慢的转弯转不完时，它的路径停在航班结束处（界面上虚线），
  转弯区在那里截断；转角接近 150° 时这样截断的边界可能自己交叉。
- 补的切入航向（航道 ±30°）和拆分转弯的每一份都单独标出。
- 判定：
  - 转弯：单调、转弯率在范围内（平均与最大转弯率、最大坡度）；拆分的各份共用一次检查；
  - 保持：多少行在漏斗里（红边 = 有行在外面）。

### 3.2 进近

- **所有候选跑道**及其延长中线（跑道列的选项）；所指的那条高亮，始终画出。
- **许可**所在的步、**截获转弯**（从最后一个保持段结束、或补的切入航向转到位处，转到跑道航向；转弯区
  同 3.1）及其判定、**截获点**。
- **走廊**：从截获点到入口，半宽 = 20 m + 离入口距离 × tan 0.45°，航迹与航道差 ±2°。截获之后的每一行
  都在走廊里，这是截获的定义，导出时再核一遍。
- **落地与句子的结束**：落地的判定与 harvest 和评估相同——越过所指跑道的入口平面，越过点离中线不超过这条
  跑道的横向界限、离入口的高度不超过 100 m。句子在越过之前结束，界面写出最后一步离入口还有多远。

### 3.3 高度词与下降角词：管子

- 每个高度词一根管子，就是 `labeller.vertical.tube_bounds` 给出的逐行上下沿：从发令点沿下降角类的两条
  边线下降，碰到目标高度后停住，上下各加 25 m；每遇到一个下降角词就从那里重新起算。
- "下降至落地"没有目标，一直到句子结束。
- 下降角词标出类别（平飞 / 下降 1–4 档 / 爬升）、名义角度与范围，以及读出它的那一段的实测角度。
- 画出所指跑道的入口高程。
- 判定：每根管子逐行在不在里面（红色标出不在的行），以及整根是否全部包含。

### 3.4 速度词：过渡 + 速度带

- 有目标的速度词：从发令到第一次进入 V ± 5 m/s 之前是**过渡**——地速夹在起始值和目标之间（各放宽
  5 m/s），并且离起始值不超过 1.7 m/s² × 已过时间；进入之后是 **V ± 5 m/s 的带**。
- "未指定"：飞行员自己的速度，只剩速度词的量程（15–255 m/s），灰色标出。
- 许可所在的步画一条竖线。
- 判定：过渡单调、加速度不超限、带内的行数、整段是否包含。

### 4.4 三维场景

- 航迹（椭球高），和它贴地的**地面投影**：平面上的包络贴在地上，斜着看时空中的航迹和它们错开，要对着投影读。
- 每个高度词一面墙（沿飞机自己的地面航迹，上下沿为管子的椭球高），上下沿另画两条线——±25 m 的墙隔远了
  只剩一条缝。
- 平面上的包络贴地画（它们只约束平面位置，不给高度），各跟自己的开关（§4.1）；默认只有转弯的两条曲线、转弯
  可能结束的平行四边形（画得深）和走廊。贴地的多边形画不出轮廓，每个另画一条贴地边线，带标注器的判定，与平面图
  一致：红 = 判定不过，虚线 = 不判的保持段和截获转弯，点线 = 判了但漏斗起始宽度超过 2 km。
- **保持判定弱**（`TRAINING_WEAK_HOLD_WIDTH_M` = 2 km，读数阈值，不是包络的值）：漏斗从"转弯可能结束的所有
  位置"出发，大转弯后起始就有 12–18 km 宽（KRDU），"每一行都在里面"说明不了航向保持得好不好。点线边、读数
  窗口航向图的标题、句子条头部的计数（"N weak"）都写明；标注器的判定本身不变。
- **图例**：句子条上方、画面右下角，只列当前打开的开关画的东西，每种颜色一行字，可以收起。
- 候选跑道与延长中线贴地；航向词发令点、许可、截获点、句子结束处。
- 最快和最慢的转弯（每个转弯区和截获转弯的两条路径；最慢的是晚 10.5 s 开始的那条）贴地画，颜色跟转弯区的
  判定，最慢的转不完时画虚线；开关 "turns"（§4.1）。选中一个转弯时两条路径的末端标出名字
  （"fastest …" / "slowest …"），选中航向词时航迹上标出实际转弯的起止两点。
- 选中一架航班时相机取景一次，框住航迹和每个转弯区（留 1.5 倍余量，句子条和左栏遮住一部分画面）；之后相机归
  用户，游标从不动它。
- 执行器的回放打开时：它飞出的航迹（青色，椭球高）、贴地的虚线投影、终点和结局标签，图例加一行；开关它不重新取景。
- 静态实体，不接 CZML，不动 `viewer.clock`。

### 4.5 共享游标与高亮

`AppContext.trainingCursorS`（游标）和 `AppContext.trainingColumn`（选中的词类）由句子条、读数窗口和三维共用。
**高亮的是一个词，不是一步**（用户 2026-09-24）：选中那一列在游标处生效的词（`trainingWordAt`）。同一步上
别的列的词不亮——各列的词起止不同，一起亮会把没对齐的几段画成同一时刻。

| 选中的词 | 它自己的包络（三处视图都亮） | 另外 |
|---|---|---|
| 跑道 | 所指的跑道和延长中线 | |
| 进近"许可" | 截获转弯、走廊及中线、截获后的航道带 | "未许可"没有包络 |
| 航向 | 它的转弯区、平行四边形、漏斗、两条转弯路径；航向图上它的楔形和保持带 | 截获之后仍是它自己的，走廊属于许可；两条路径标名字，航迹上标实际转弯的起止 |
| 高度 | 它的管子 | |
| 下降角 | 三维里没有；高度图上它的竖线 | |
| 速度 | 三维里没有；地速图上它的过渡和速度带（或"未指定"段） | |

每个词还把它生效的那几行画成黄色：三维与平面图的航迹上，以及画它那个信号的图上；三维在发令处加黄点和词名。
选中的包络保留本色、加深、边线变黄。游标在同一个词里移动时三维什么都不重画；换词只改材质和线宽，不重建几何。

**其余的淡化**：选中一个词时，别的词的包络（填充、边线、转弯路径、管子）在三维里颜色透明度乘 0.3，在读数窗口
里整体透明度 0.3，候选跑道与航迹不变；取消选中就全部恢复。平面图按选中词的整个包络取景（它的转弯区、
平行四边形、漏斗，或许可的截获转弯），不再只按航迹裁剪——大转弯的最慢边界会伸出航迹很远。

### 4.6 执行器的回放与先验的预测

- **执行器的回放**回答"这套词飞得出来吗"：真值句子从第 0 行交给执行器，每条词在执行器飞到观测飞机听到它的位置时说，
  飞出的航迹画在实测航迹旁边（§4.3、§4.4），每条词的判定画在句子条上（§4.2）。要记住一点：**执行器的每条词是按从它自己
  听到这条词的位置重新画的包络判的**，界面上画的包络是观测航班的，两者不是同一块区域；所以出界的红点要对照悬停里的检查
  读，而不是对照画出来的包络。
- **先验的预测**回答"先验对这句话有多意外"：Prior predictions 窗口上半是游标所在这一步的表——每列真值在这一步说了什么
  （或不变，以及当时生效的词）、先验给真值的概率、给"这一步说一个词"的概率、若说一个词最可能的几个词（与真值相同的
  标青色）；下半每列一条带：说词的概率（列的颜色）、真值的概率（灰），真值在第 0 步之后说的每个词一根竖线，先验排第一
  的词就是它为青色，否则红色。鼠标移动改游标，点一行或一条带选中那一列。**这是教师强制的读法**：每一步都看到真值句子
  在它之前的词，不是先验自己说出一句话；先验自己说、执行器接着飞，是下一步（先验设计 §8 第 1 项）。

## 5 核对

- `npm run check-publication`：读每个机场的 `index.json`，列出的每个集合文件必须存在；别的词表的集合记为
  **警告**（按名字拒读是有意的，删不删是另一回事）；能读的集合用前端自己的 `parseTrainingSample` 读，
  并和索引条目逐项比对（集合名、航班数、规格 sha、机场几何 sha、读法、每组数量、种子）。
- 加 `--server <地址>`：同样的文件从正在运行的开发服务器取，JSON 必须是 JSON（不是 SPA 回退页），能读的
  样本**把服务器返回的内容再用读取函数读一遍**——HTTP 200 不等于"能加载"。
- 加 `--airports-root <目录>`：核对另一个目录（例如导出到临时目录的试跑），不能和 `--server` 同用。
- 叠加层：`overlays.json` 用前端自己的读取函数读，每个叠加层对照它所画集合的样本读一遍，并核对盘上样本文件的 sha256 是
  叠加层记下的那一个（集合重新导出过就报错）；画在界面不读的集合上的叠加层记为警告。加 `--server` 时服务器返回的叠加层
  也再读一遍。

## 6 不做什么

1. 不在界面上改词、重飞。重飞要执行器。
2. 不录入人工核对的判定。那属于带 sha 的产物，不属于浏览器本地存储。
3. 不浏览全体航班。导出是抽样，规则写在文件里、界面上照录。
4. 不改 Observe 和比较视图。
5. 不做多机。

## 7 维护约定

- 本文只描述当前设计。词表换版本（新读法或新规格 sha），界面会按名字拒读新产物：同一次改动里更新
  `trainingSample.ts` 的钉住值、测试、`aeroviz-4d/CLAUDE.md` 与 `35-viewer-reference.md` 的对应条目和本文。
- 格式名跟着文件的形状走：样本或索引的字段一有增、删、改名，Python 的 `SAMPLE_SCHEMA` / `INDEX_SCHEMA` 和
  TypeScript 的 `TRAINING_SAMPLE_SCHEMA` / `TRAINING_INDEX_SCHEMA` 在同一次改动里一起换新名字，盘上的集合重新导出；
  不为"旧文件还能读"或"现在没人读错"保留旧名字。叠加层的三个格式名（`OVERLAYS_SCHEMA`、`executor_training_export.SCHEMA`、
  `prior_training_export.SCHEMA` 与 `trainingOverlays.ts` 里的 `TRAINING_OVERLAYS_SCHEMA`、`TRAINING_EXECUTOR_SCHEMA`、
  `TRAINING_PRIOR_SCHEMA`）同理，由 `test_training_overlays.py` 逐字比对。
- 集合重新导出后，画在它上面的叠加层会被按名字拒读（样本的写出时刻变了）：重新生成叠加层，用新的叠加层 id。
- 长期事实一行写进 `aeroviz-4d/CLAUDE.md` 的索引，全文写进 `aeroviz-4d/docs/35-viewer-reference.md`
  （AV19–AV25）。导出器的说明在 `4dTrajectory/ts_transformer/docs/reference/runners.md`（R11；叠加层 R13）。
- 日志式记录写进仓库的 `docs/CHANGELOG.md`。
