# Training 模块

前端的 **Training** 任务页（顶栏 Observe 右边）把第二层模型的"语言"画出来：一架到达航班被读成了
哪一句指令，这句话里每个词允许飞机在哪里（词的包络，也就是"飞行盒"），航迹有没有待在里面。
它不训练模型，不写磁盘；除了 §4.7 的"实时执行器"（选中一个词，后端现飞这一段）之外不调后端，只读导出好的 JSON。

词表本身的定义见 `4dTrajectory/ts_transformer/docs/2026-09-23_instruction_vocabulary_design.zh.md`
（下文简称"词表设计"）。本文只写前端这一侧：数据怎么来、每个词画成什么、界面上有什么。

## 1 这个模块回答什么

1. **这架飞机被读成了哪一句话**：每 2 s 一步，六列词（跑道、进近、航向、高度、下降角、速度，顺序与
   `instructions/words.COLUMNS` 相同）。第 0 步六列都有词；之后绝大多数步什么也不说。
2. **每个词允许什么**：航向词说"提前量之后航迹在哪个 5° 格子里"，它的包络是一条航向带——从说出后一个提前量到
   下一个航向词，航迹每一行都要在目标 ± 容差以内；截获转弯和截获后的走廊，高度词的管子，速度词的过渡和速度带。
3. **航迹有没有待在里面**：每一项都是标注器自己的判定（`Reading.checks`），前端只显示，不重算。

放在 Observe 旁边，是因为两页看的是同一批到达航班：Observe 看"飞机怎么飞的"，Training 看"这条航迹
被读成了什么"。Training 不加载 Observe 的 CZML，也不动共享的 Cesium 时钟。

### 2.2 `index.json`

索引的格式（`aeroviz-training-index-v1`）不随词表变：新旧集合都列在里面，每一条写着自己的读法
（`readingRule`）和规格 sha（`vocabularySha256`）。所以界面**不用下载任何文件**就知道哪个集合能读：
读法是 `instruction-v3`、规格是 `TRAINING_SPEC_SHA256`、类型是 `vocabulary-readback` 的才打开，其余按名字拒读。
`runwaySha256` 是该机场几何的 sha：候选跑道（跑道列的类别就是它们），加上落地判定要读的全部跑道端。

### 2.3 `sample.json`（`aeroviz-training-sample-v7`）

顶层：

- `vocabulary`：读法、规格 sha、标注器 sha、六列的名字和顺序、"不变"（−1）、步长、平滑窗口；**每一列
  的类别都写成表**（航向 72 个角度、高度 181 个目标加"下降至落地"、6 个下降角类及各自的名义角度和范围、
  速度 47 个目标加"未指定"、进近 3 类），界面查表出文字，不自己换算；还有画图和说明要用的数：
  - 航向：提前量 `headingLeadS`（4 s）和同一个数换成的步数 `headingLeadRows`（2，由规格的 `rows_exact` 换算，界面只核对
    两者一致）、容差 ±4.5°；
  - 截获转弯：开始的判据（朝航道转得比 `turnOnsetRateDegS` 快）、转弯率 0.5–4.7°/s（下限只管 10° 以上的转弯）、
    坡度不超过 32°；自行切入的角度 30°；
  - 落地：越过入口时离中线不超过 1000 m（有平行跑道时取到它间距的一半，两条跑道航向差 5° 以内算平行），
    离入口的高度不超过 100 m；
  - 走廊 20 m / 0.45° / ±2°，高度 ±25 m，速度 ±5 m/s，加速度 1.7 m/s²。
- `candidates`：本机场全部候选跑道，每条有入口、真航向、入口高程、长度、**这条跑道自己的落地横向界限**
  （例如 KSJC 平行跑道之间只有 106.7 m），以及画好的跑道线段和延长中线（机场坐标系的米和经纬度各一份）。
- `cohort`：抽样规则与候选池、读过的数量。

每架航班：

- 身份：`datasetId`、`flightKey`（`id_跑道_icao24_落地时刻`）、呼号、机型、跑道、分组、步数；
  截获行、许可行、"未指定"行、截获时离入口的距离。
- `signals`：每步一行。时间、机场坐标系的东/北（米）、经纬度、椭球高（给三维用）、原始信号（航迹、
  高度、地速、垂直速率）、**平滑后的信号**（标注器实际读的：航迹 6 s、高度 10 s、地速 10 s）和由平滑
  地速积分出的水平距离、相对所指跑道的沿航道距离与偏离。两种信号都给，因为平滑本身是读法的一部分。
- `words`：发令事件（行、列、值、为什么发：进入时已生效 / 按步读出的航向 / 许可 / 新目标 / 两段保持之间 /
  新下降角 / 速度交给飞行员），以及每一列每一步生效的值。后者必须等于前者逐行往后填，读取时检查。
- `envelopes`：每个词的包络与判定，见 §3。航向词每个一条：被判的行（`firstRow` 到 `stopRow` 之前）、目标在航向图
  展开分支上的值和航向带（`targetOnTrackDeg`、`bandDeg`）、每一行在不在带里（`inside`）、标注器的判定（行数和
  在带里的行数）。截获转弯：起止行（许可行、截获行）、航道在展开分支上的值、标注器的判定。v7 起不再有转弯区、
  两条转弯路径、平行四边形、航向随时间的楔形、保持漏斗、拆分的几份和"补的切入航向"。

单位只有米、米/秒、度、秒。高度是几何 MSL；只有 `altitudeHaeM`、`lowerHaeM`、`upperHaeM` 三处是椭球高，
由导出器一次换好，专给 Cesium 用：MSL 加上这架航班所落跑道的"椭球高减海拔"差值（到达清单 `runway_targets` 的
`hae_minus_msl_m`，数据面当初减掉的就是它，`training_files.runway_hae_minus_msl_m`），所以换回来正是飞机报的高度。
2026-09-26 之前用的是 EGM96 当地值，和减掉的那个数不一样（instruction_v3_day_split 五个机场 200 个航班上，
差 −1.1 到 +2.8 m）；那之前导出、现有代码不能重导的集（instruction_v1/v2/v3、box、box_v3、v15_nomerge_noposition
及其叠加层）按用户决定保持原样，仍是旧值。后端现飞（§4.7）也加同一个数。

### 2.4 一条原则：前端不算包络

每一条带、每一行的判定、每一根管子都在 Python 里由词表自己的函数算好（`instructions/display.py`，
只用 `envelope.py` 和 `labeller/*` 的公开函数；它不在标注器 sha 的范围里，改画法不改句子）；每一个判定
都是标注器的。航向带更进一步：画出来的就是判的那一个——被判的行由 `envelope.heading_word_rows` 给出，每一行
在不在带里由 `envelope.heading_words_inside` 一行一行地问（与标注器、执行器的判决是同一个函数），合计必须等于
标注器的计数，否则导出停下。前端只检查"账对不对"——长度、行号、每一步的词是不是事件往后填出来的、判定里的计数
是不是等于它自己逐行标记的计数、航向带的第一行是不是这个词的行加提前量、末行有没有越过下一个词的第一行和许可行、
带是不是目标 ± 词表的容差——然后照数画。前端若再算一遍包络，屏幕上就会有两个答案。

### 2.5 按名字拒读

`trainingSample.ts` 钉住并逐项核对：样本格式名 `aeroviz-training-sample-v7`、读法 `instruction-v3`、规格 sha
全文、六列的名字和顺序、"不变"的值、标注器会写的发令原因列表（`initial`、`per-step`、`clear`、`target`、`step`、
`angle`、`unspecified`）。对不上就整份拒读，报出是哪一项；不做兼容分支。格式名不对就不往下读，不管文件里是哪个
词表：v6（`instruction-v2` 的转弯与保持段）以及更早的文件按名字拒读。
Python 这一侧的对应常量由 `test_instruction_training_export.py` 与 TypeScript 源码逐字比对。

### 2.6 叠加层：执行器的回放与先验的预测

别的模型对一个集合里这些航班做了什么，写在集合**旁边**，不写进集合：

```bash
# 执行器：从工作树（worktree）里跑——在主工作区，执行器规格的源码 sha 会把 geokit 算进去而拒读（见 ts 的 R13）

```

- **清单**：每个机场一个 `training/overlays.json`（`aeroviz-training-overlays-v2`），一条一个叠加层：种类、所画的集合、
  文件位置。叠加层文件放在 `training/<叠加层 id>/`，目录已存在或清单里已有同名 id 就拒绝，
  五个机场都建好才写。`index.json` 不动。
- **执行器**（`executor.json`，`aeroviz-training-executor-v4`）：用正式规格把集合里的航班重新飞一遍、判一遍。重飞是必须的：
  正式回放的 `replay.json` 只记了每架航班"哪一类词合不合格"的列表，没有记是哪一条词。重飞后每条判定对回句子里的词，
  并且**每架航班必须和正式回放的那一行一致**：结局、是否按原话飞完、判定列表、不判 / 没说到 / 被取代的词数完全相同，
  越过入口的偏离与高度差在 1e-9 以内（换一批航班一起飞，浮点求和的次序不同，差一个末位），否则导出停下、说出是哪一架。
  evaluation 的判定取正式回放的，不重跑。每条词一个状态：在包络里、出界、不判（航向词没有自己的行——它的行从执行器
  听到它的那一步加提前量起算，到了执行器听到的许可或它的截获，或者下一个航向词在同一步说出；或者飞出的航迹没过标注器
  的门）、没说到（航班先结束了）、被取代（同一列两条词落在飞出的同一步，只飞后一条）、没有自己的检查（跑道指针、下降角词、
  "未许可"、"未指定"）。航向词在不在包络里就是判决对它的那一条结果（行数、在带里的行数）；执行器离开航向词自己去
  切入航道的那条航向词记为出界。每个被判的航向词还带上它在飞出航迹上的航向带和逐行判定（`heading`，用与样本相同的
  `display.heading_band` 算，合计必须等于判决的计数），每架被判的航班带上判决读到的飞出航迹（`judgedTrackDeg`：
  平滑、切到落地前；它的第 k 步就是导出航迹的第 k 个点，读取时核对）——两者都放在与观测航迹同一个展开分支上。**动力学失败
  的航班不画带**：判决读到了失败的那个状态（可能不是有限值），而导出的航迹有意不含它；这些航班的词照样有判决的状态和检查，
  只是没有航向带和判决读到的航迹。回放不飞的航班（没有识别出机型、机型没有公开进近速度）
  列出原因，没有航迹。飞出的航迹每 2 s 一点，到结局那一行，带 MSL 与椭球高；还附上这个机场与全部机场的回放门表。
- **先验**（`prior.json`，`aeroviz-training-prior-v4`；第三版起前 `firstPredictedRow`（= 8）行只观察、没有预测，每列每步的数组
  从第一个预测步开始；第一个预测步六列都要说；跑道在第一个预测步之后不再换，它的"换词"指标为空）：检查点必须是这份产物的规格、
  标注器与运行日划分训练的、不是冒烟试跑、候选跑道表与产物相同、状态整份载入，并且今天的航迹清单与训练时的相同（落地情况从它读）。推断用教师强制（每一步看到真值句子在它之前的词），与训练和读数时一样；第三版的先验导出时，要核对这条推断
  路径在 val 航班上复现 `readout.json` 的每步负对数似然（第二版核对过：10,540 架，差 1e-9 以内）。每架航班每列每个预测步：说一个词的概率、若说一个词最可能的
  3 个词（列的取值少于 3 个时更少，例如一个机场的候选跑道）及其概率、真值的概率；每架航班每步的负对数似然（总的和
  分列的，四舍五入前算）。val 的读数随文件一起走，原样照抄。
- **绑定与核对**：叠加层自己写出它和所画集合共有的东西——集合 id、规格 sha、候选跑道 sha、机场坐标系；前端逐项核对，并
  核对每架航班的键、执行器的每条词（步、列、值）、先验的步数、画出的每一行高度的 HAE − MSL（等于集合里这架航班的，0.02 m
  以内）、从观测状态飞出的航迹的第一点（就是观测航迹那一行：执行器第 0 行，模型自己的句子第 8 行；增强起点不比），对不上
  整份拒读。不按集合文件的字节或写出时刻绑定：集合用同样的航班重新导出，叠加层照读。导出器写之前同样核对
  （候选跑道与坐标系是它自己产物的，每架航班的高度基准相同）。

2026-09-24 画在 `instruction_v2` 集合上的执行器（规格 `2674ab8c71a9`）与先验（`prior/v1_20260924`）叠加层的发布与
核对记在 `docs/CHANGELOG.md`；它们按名字拒读，v3 的叠加层要等 v3 的执行器规格、回放和先验。

### 2.7 模型自己说的句子（`prior-generation`）

§2.6 的先验预测是教师强制的：每一步都看着真值句子。这里是**模型自己说一整句**——先验设计 §9.1 的单机自由生成——
写在集合旁边，也是一种叠加层：

```bash
# 执行器规格要选现在的执行器代码接受的那一份（2026-09-26 晚是 v10_20260926；更早的都按源码 sha 拒读）
python run_ts.py prior_generation_training_export \
    --prior 4dTrajectory/outputs/POOLED/prior/v3_step1_20260924/full_s1337 \
    --instructions 4dTrajectory/outputs/POOLED/instruction_language/v4_20260924 \
    --executor 4dTrajectory/outputs/POOLED/executor/v10_20260926 \
    --airports-root aeroviz-4d/public/data/airports --set instruction_v3_day_split \
    --airport KMSY --airport KRDU --airport KSJC --airport KSMF --airport KSTL
# 后训练的一轮：--prior …/v3_rl_20260925/grpo_s1337/round_01（landing r1），
#               --prior …/v3_stage2_clip_20260926/aug_s1337/round_03（augmented r3）；每轮一次，名字从检查点读
# --readout <它的正式 val 自由生成>：要求同一份执行器规格、不带程序屏蔽；现在盘上的读数都是更早的规格或带屏蔽，给不了
```

- **怎么生成**：和正式的自由生成读数一模一样（`prior_free_generation.speak_and_fly`）。前 `N_LOOK`（= 8）行是观测；执行器从
  第 8 行观测飞机的状态起飞，先验在第 8 行把六列都说一遍，之后每 2 s 一步：先读执行器飞到哪了，按列的顺序采样这一步的词
  （词表的相容规则、执行器已许可或已截获后不许换跑道，这两样作解码屏蔽），执行器马上照着飞这一步。飞到执行器判它结束
  （落地、越过入口、触地、动力学失败）或超时（观测剩余时间的 1.5 倍）为止。每架航班采 `--samples`（默认 4）个样本，温度 1，
  种子 1337，一个随机数发生器按机场的先后顺序往下用。**只飞正式读数也飞的航班**：自己机型有动力学的（`replay.OWN`）；别的
  （替代动力学、没有动力学、没识别出机型）列出原因，没有样本。结局是执行器判决给的（`judge.outcome_of`，按最后所指的跑道）。
- **每个样本写什么**（`generation.json`，`aeroviz-training-generation-v4`）：说出的词，写成和真值句子一样的事件（行、列、值），
  行号就是这架航班自己的步号（第一个事件在第 8 行，六列都在）；结局、结束时刻、越过入口的偏离与高度差（只有越过入口的
  三种结局才有）、第一步与最后所指的跑道、换跑道次数、复飞词数、结束时是否已许可、屏蔽拿掉的概率（跑道 / 进近 / 下降角
  三列，每步平均）；执行器飞出的航迹，每 2 s 一点，**用这架航班自己的时钟**（从第 8 行的 16 s 起），到结局那一行（动力学失败的
  到它前一行：失败的那个状态可能不是有限值），带 MSL 与椭球高（MSL 加航班所落跑道的 `hae_minus_msl_m`，§2.3）和地速。**不带逐词判定**：判决说的是执行器有没有
  飞在先验所说的词的包络里，不是先验说得好不好；先验的答案是落没落地。
- **词写到执行器停下的地方，航迹写到结局**：`flight_rows` 把一句话数到执行器认为这架飞完的那一步。有两种结局判决读得比执行器
  停得早——越过入口但没截获、失速截断（执行器的"飞完"不含这两种）——这时样本的最后几个词在结束时刻之后。照正式读数的数法
  原样写出（结束时所指的跑道就从这些词读），界面把结束之后的那段涂暗（§4.8）。
- **模型是谁——按名字认，不写标签**：名字是用户定的（后训练设计开头的表）——**base**（只用数据训练）、**landing**（base 按落地
  奖励后训练，第一阶段）、**augmented**（landing 在增广起点上再后训练，第二阶段），某一轮写成 "augmented r3"。导出器从检查点
  配置读出名字：没有 `fine_tuning` 的是 base；有的按训练它的方法给名字（`fine_tuning.schema` 去掉版本号：
  `ts-prior-landing-reward-vN` → landing，`ts-prior-augmented-reward-vN` → augmented；同一方法的各个版本是同一个模型，采纳的
  landing 第 1 轮就是 v1 写的；没有名字的方法拒绝——新阶段的名字先和用户商定，再加进 `MODEL_NAMES`）。`model` 块：`name`、
  `round`（base 为 null）、`run`（放各轮的那个目录，例如 `…/prior/v3_stage2_clip_20260926/aug_s1337`；base 是它自己的目录）、
  检查点 sha256、变体、训练时的提交、`fineTuning`（方法的 schema、起步模型的路径，以及起步模型的名字和轮次——从起步模型自己的
  配置读，所以界面能写"augmented r3，从 landing r1 起步"）。默认叠加层 id 是 `generation_<名字>[_rNN]_<检查点 sha256 前 8 位>`。
  界面按名字给颜色、分组、切换轮次（§4.8）。
- **模型按它训练时的屏蔽说话**：屏蔽分两种（先验设计 §5.1）——词表规则（相容规则、跑道锁定，总是开着）和程序屏蔽（跟着模型走：

  屏蔽和每套读的数据的摘要（`[{name, dataSha256}]`），实时执行器重飞这个样本时带回去核对（§4.7）。
- **正式读数**（`--readout`，可选）：这个模型的正式 val 自由生成（`generation.json`，`ts-prior-free-generation-v5`）里先验与"标注的词"两行的落地比例（全部、
  直线进近、被引导；某一类没有航班时写 null），**这个机场的一份和全部机场合起来的一份**，原样照抄（读数的抽样说"every labelled
  flight"时写 0；别的写法拒绝）；要求它确实是这个检查点（路径从 `4dTrajectory/outputs/` 往后比：
  读数是在工作树里跑的，工作树的 outputs 就是同一棵树）、同一份执行器规格（内容 sha）、同一份句子产物、val、`n_look`、

  失败的早一个周期）；换跑道次数、复飞词数、结束时是否许可与它自己的词对得上；样本数等于声明的数；飞了的航班恰好有这么多样本，

### 2.8 增强起点上的模型句子（`prior-generation-augmented`）

  增强起点飞，写成**另一种叠加层**：种类 `prior-generation-augmented`，格式 `aeroviz-training-augmented-generation-v2`，默认 id

- **增强怎么抽**——和第二阶段训练、它的 val 读数（`val_*_aug_400x4`）同一套代码（`prior_free_generation.augmented_starts`、

  - 绕机场参考点转 δ ∈ [−15°, 15°]、抬高 Δh ∈ [−150, 150] m、加速 1 + κ，κ ∈ [−5 %, 5 %]，均匀抽；

  - 最多抽 10 次，都不行的航班不飞，列出原因。
  - 随机数发生器用 `--augment-seed` 播种（**每个机场重新播种**），按集合里**能飞的航班的顺序**逐架抽，与模型无关、与样本的随机数分开。所以同一个种子、

  - 时限是来源航班观测剩余时间的 **2 倍**（`augment.TIMEOUT_FACTOR`），真实起点是 1.5 倍。
  - 前 8 行没有标注的词：那些词属于来源航班自己的起点，不属于增强后的。
- **每架航班多写两样**：
  - `augmentation`：`rotationDeg`、`altitudeM`、`speedScale`、`draws`（抽了几次）；没有合格的抽法时为 null，这架不飞；
  - `observed`：增强后的前 8 行（第 0–7 行），`tS`、经纬度、MSL 与椭球高——先验看到的就是这一段；样本航迹从第 8 行（增强后的
    起点）开始，三维把两段接起来画。
  - 样本与 §2.7 逐字段相同（词、结局、结束时刻、越过入口、首末跑道、航迹……）。
- **不写正式读数**（没有 `readout` 块）：第二阶段的 `val_*_aug` 读数是另一次抽法，只在 readouts 文档里。
- **绑定与核对**：与 §2.7 相同；另外 `observed` 正好 8 个点、从 0 起每点一步，一架航班的所有样本从同一个起点起飞，增强量在上面的
  范围以内，`augmentDraws` 在 1–10 之间（不在自己动力学上的航班为 null，没抽），`augmentation` 为 null 的航班不飞、界面写明原因
  （"no plausible augmented start in 10 draws"）。
- **先导出哪几个模型**：采纳的三个——base、landing r1、augmented r7，五个机场；别的轮次要看时再导。
- **用 GPU**（`--device cuda`，默认 cpu）：先验（说话的模型）和它采样的随机数发生器放在 GPU 上，和正式读数一样；执行器
  始终在 CPU 上飞（后端现飞也在 CPU 上，这样现飞才和样本逐点相同）。GPU 的随机数和 CPU 的不同，所以同一个种子在 GPU
  上抽出的样本和 CPU 上的不同；用的设备写在 `producedBy.device`。增强量是用 CPU 上的 numpy 抽的，与设备无关。

## 3 每个词画成什么（飞行盒）

### 3.1 航向词：逐行判定的航向带

- **一个航向词说什么**（词表设计 §10.1，`instruction-v3`）：标注器每一行看平滑航迹 4 s（提前量）之后落在哪个 5° 格子，
  相邻几行格子相同就合成一个词，格子一变就说一个新词。所以一个航向词说的是"4 s 之后航迹在这个格子里，并保持到下一个
  词"；一段连续的转弯就是一串按它飞的快慢说出的词。没有保持段、没有拆分、没有补出来的切入航向。
- **它的包络是一条航向带**：从说出的那一行加提前量，到下一个航向词那一行加提前量（最后一个词到许可那一行），这些行上
  平滑航迹都要在目标 ± 4.5° 以内（按圆周差算，4.5° = 半格 2.5° + 起伏余量 2°）。它不约束位置，所以**没有平面上的区域**。
- **没有自己的行**：提前量把一个词的第一行推到许可那一行或之后时（常见于许可前一两步说出的词），这个词没有行可判，
  不画带，判定里行数为 0，句子条头部单独数出来。
- **画成什么**：读数窗口的航向图上每个词一块矩形，横向是它被判的那几步，纵向是目标 ± 4.5°（在平滑航迹的展开分支上）；
  有行在带外时边线红，那几行在航迹上画红（航向图、平面图的航迹、三维的地面投影）。三维里每个词被判的那一段地面投影画成
  航向带的颜色（一个词一个实体，可以单独选中）。观测航迹按构造都在带里——标注器就是按它读的——所以红色主要出现在执行器
  的回放上。
- 判定：多少行在带里（`check.inside` / `check.rows`），全在里面才算这个词合格。

### 3.2 进近

- **所有候选跑道**及其延长中线（跑道列的选项）；所指的那条高亮，始终画出。
- **许可**所在的步：截获转弯开始的那一行，而且不早于在用的航向词已经能碰到航线的那一行（词表设计 §10.1）。
- **截获转弯**：从许可那一行到截获那一行，朝跑道航向转；判定是单调、平均与最大转弯率在 0.5–4.7°/s 之内（下限只管
  10° 以上的转弯）、最大坡度不超过 32°。航向图上画成这段时间的竖条和航道那条虚线，平面图和三维画成航迹 / 地面投影上的
  虚线段，判定不过时是红的。飞机在第 0 步已经在五边上时没有截获转弯。
- **走廊**：从截获点到入口，半宽 = 20 m + 离入口距离 × tan 0.45°，航迹与航道差 ±2°。截获之后的每一行
  都在走廊里，这是截获的定义，导出时再核一遍。
- **落地与句子的结束**：落地的判定与 harvest 和评估相同——越过所指跑道的入口平面，越过点离中线不超过这条
  跑道的横向界限、离入口的高度不超过 100 m。句子在越过之前结束，界面写出最后一步离入口还有多远。

### 3.3 高度词与下降角词：管子

- 每个高度词一根管子，就是 `labeller.vertical.tube_bounds` 给出的逐行上下沿：从发令点沿下降角类的两条
  边线下降，碰到目标高度后停住，上下各加 25 m；每遇到一个下降角词就从那里重新起算。
- "下降至落地"没有目标，一直到句子结束。
- 下降角词标出类别（平飞 / 下降 1–4 档 / 爬升）、名义角度与范围，以及读出它的那一段的实测角度。
- 画出所指跑道的入口高程。
- 判定：每根管子逐行在不在里面（红色标出不在的行），以及整根是否全部包含。

### 3.4 速度词：过渡 + 速度带

- 有目标的速度词：从发令到第一次进入 V ± 5 m/s 之前是**过渡**——地速夹在起始值和目标之间（各放宽
  5 m/s），并且离起始值不超过 1.7 m/s² × 已过时间；进入之后是 **V ± 5 m/s 的带**。
- "未指定"：飞行员自己的速度，只剩速度词的量程（15–255 m/s），灰色标出。
- 许可所在的步画一条竖线。
- 判定：过渡单调、加速度不超限、带内的行数、整段是否包含。

  val 整体的每步负对数似然在它的提示里）、**ⓘ**（说明：怎么读这条、句子在入口前多远结束、行末计数是什么、回放的点是什么意思，
  以及执行器回放这架航班的完整读法——结局、越过入口处、包络内的词数、评估）。回放不再单独占一个小块：每个词的点已经说了它
  （用户 2026-09-27："冗余"）。
- **行末计数**（读真值时；标注器的判定是真值的，模型的句子没有）：每行的右端写这一行的标注器判定（`Reading.checks`）——
  heading "2/3"（在带内的航向词 / 判了的）、altitude（守住的高度管）、speed（守住的速度词），approach 行是截获转弯的 ✓ / ✗；
  runway 与下降角两行没有自己的判定，不写；没有截获转弯（入口时已在五边上）的 approach 也不写。各行的斜杠对在同一个 x 上
  （分子右对齐、"/分母"左对齐，等宽数字），全对时是淡色，有没守住的是红色；提示里是完整读法（没有自己的行的航向词个数、
  截获转弯的两项）。原来头部的判定小块 "heading 2/3 · capture ✓ · …" 挪到这里（用户 2026-09-27）。
- 点一条带：选中它这一列（词类），游标移到它的发令步；再点一次取消。点步号只移游标，选中的列不变。
  只有选中那一列在游标处生效的词亮（黄边、加深），列名变黄——别的列在同一步生效的词不亮（§4.5）。
- 读数核对窗口和先验窗口同一时间只开一个：开一个就关掉另一个。两个窗口读的都是真值句子，所以只在读真值时给出（读模型时
  按钮不出现，开着的窗口收起，回到 Truth 再出现）——否则同一时刻会亮两个不同的词。
- 执行器的回放打开时：每条词左端一个点——青 = 飞在自己的包络里，红 = 出界，空心灰 = 不判 / 没说到 / 被取代，没有自己
  检查的词不画；悬停写出每项检查与原因（航向词：从它听到的那一步加提前量起，多少行在 ±4.5° 以内）。

### 4.5 共享游标与高亮

游标（`useTrainingCursor`）和 `AppContext.trainingColumn`（选中的词类）由句子条、读数窗口和三维共用。**游标是单独的一个
context，`useApp` 不读它**：鼠标在图上移动时，只有句子条（连同两个窗口）和三维的叶子组件 `TrainingScene` 重新渲染，整个界面
不跟着动（原来每移动一下，外壳、两侧面板、航班列表、HUD 都重新渲染一遍）。
**游标和实时执行器的选择属于屏幕上这架航班**（`trainingSelectionKey`：机场 / 集合 / 航班）：换航班、换集合，游标回到 0、
选择清空——不会有上一架的词被重新飞；换之前拿到的设置函数写不进新航班。词类的选择保留（它是偏好，不属于哪架航班）。
**离开 Training 再回来，一切照旧**：面板打开后就一直挂着，在别的任务里只是隐藏（`WorkbenchLeftDock`）——集合、航班、
选中的词、游标、实时执行器的答复（飞完的直接画成落地的样子）都在，什么也不重新下载（原来要重新下载索引、样本——KRDU 的
6 MB——和叠加层，航班回到第一架）。句子条和三维只在 Training 里画。**会话只属于打开它的那个机场**：在别的任务里换了机场，
会话就丢掉，下次进 Training 为那时的机场重新打开——隐藏的面板不在后台为别的机场下载任何东西。
**高亮的是一个词，不是一步**（用户 2026-09-24）：选中那一列在游标处生效的词（`trainingWordAt`）。同一步上
别的列的词不亮——各列的词起止不同，一起亮会把没对齐的几段画成同一时刻。

| 选中的词 | 它自己的包络（三处视图都亮） | 另外 |
|---|---|---|
| 跑道 | 所指的跑道和延长中线 | |
| 进近"许可" | 截获转弯、走廊及中线、截获后的航道带 | "未许可"没有包络 |

| 下降角 | 三维里没有；高度图上它的竖线 | |

每个词还把它生效的那几行画成黄色：三维与平面图的航迹上，以及画它那个信号的图上；三维在发令处加黄点和词名。
**读模型的句子时**，选中的是模型的词：句子条上它的带变黄，三维里它生效的那一段画在**模型飞出的航迹**上（加黄点和词名），

什么都不重画；换词只改材质和线宽，不重建几何。

**其余的淡化**：选中一个词时，别的词的包络（填充、边线、航向词的地面段、管子）在三维里颜色透明度乘 0.3，在读数窗口
里整体透明度 0.3，候选跑道、航迹和红色的出界行不变；取消选中就全部恢复。

### 4.6 执行器的回放与先验的预测

- **执行器的回放**回答"这套词飞得出来吗"：真值句子从第 0 行交给执行器，每条词在执行器飞到观测飞机听到它的位置时说，
  飞出的航迹画在实测航迹旁边（§4.3、§4.4），每条词的判定画在句子条上（§4.2）。要记住一点：**执行器的每条词是按从它自己
  听到这条词的位置重新画的包络判的**。航向词的包络画出来了（航向图上青色边框的带，在它自己的时间轴上）；别的词画的包络是
  观测航班的，出界的红点要对照悬停里的检查读。
- **先验的预测**回答"先验对这句话有多意外"：Prior predictions 窗口上半是游标所在这一步的表——每列真值在这一步说了什么
  （或不变，以及当时生效的词）、先验给真值的概率、给"这一步说一个词"的概率、若说一个词最可能的几个词（与真值相同的
  标青色）；下半每列一条带：说词的概率（列的颜色）、真值的概率（灰），真值在第 0 步之后说的每个词一根竖线，先验排第一
  的词就是它为青色，否则红色。鼠标移动改游标，点一行或一条带选中那一列。**这是教师强制的读法**：每一步都看到真值句子
  在它之前的词，不是先验自己说出一句话；先验自己说、执行器接着飞，是下一步（先验设计 §9）。这段读法和负对数似然的
  含义写在窗口底部的 ⓘ 里。
- 先验读数表里第一步跑道的三条因果规则（`B0_majority`、`B1_active_config`、`B3_same_sector_last`）按名字核对：
  `trainingOverlays.ts` 的 `TRAINING_PRIOR_RULES` 是 `prior.readout.RULES` 的镜像，多一条少一条都整份拒读；它和集合的
  分组名 `TRAINING_STRATA`（`instructions.readout.STRATA` 的镜像）由后端的 `MirrorTest` 逐字比对。

### 4.7 实时执行器：选中一个词，现飞它的一段

**用途**：验证执行器本身——任何一个词，交给执行器从真实的那一刻接着飞，看它飞成什么样、这个词判不判得过。**必须现算**：
每次选中都由后端重新飞一遍，不读执行器的正式回放、不读叠加层（用户 2026-09-25 的要求）。句子条读的是真值还是某个模型的
样本（§4.8），飞的就是那一句的词；下面先讲真值的词，模型的词单列在"模型的词"一段。

**一段是什么**：句子条上的一个色块——某一列的一个词，从它说出的那一步 `row` 到同一列下一个词说出的那一步 `endRow`
（这一列的最后一个词：到句子结束）。**飞到这个词的包络结束的地方 `stopRow`**：一般就是 `endRow`；航向词是 `endRow` 再加一个
提前量（4 s，2 步），因为航向词的航向带本来就从它说出后一个提前量判到下一个航向词说出后一个提前量（词表设计 §10.1）——只飞到
`endRow` 的话，每个航向词都少判最后几行，只持续一步的航向词（约占四成）根本没有行可判。多飞的这一个提前量里，下一个航向词
照句子在 `endRow` 说出，执行器开始转向它，和整句回放里一样。`stopRow` 不超过句子末尾。**这一段在界面上画成淡色虚线的尾巴**
（用户 2026-09-26：飞出的线比色块长一截，"段不对"）：从执行器听到下一个航向词的那个周期起，飞机已经在飞下一个词，只是评判还
算在这个词头上；三维、读数核对的四张图、图例和结果卡都把它和这个词自己的一段分开画、分开写。听到的时刻按执行器自己的词钟：
模型的句子（时间词钟）正好是 `endRow`，真值（航迹词钟）可早可晚一两步——例如 AAL557 在步 7 说的航向词，下一个航向词按句子在
76 s，执行器 74 s 就听到了。

**怎么飞**（后端 `aeroviz_backend/autopilot_segment/`：`segment.py` 哪一段、告诉执行器什么；`fly.py` 重建航班（一个集合的航班一起）、
飞到段尾停；`single.py` 单条执行器——`4dTrajectory/ts_transformer/autopilot/` 一个周期的计算照写成一架航班的纯浮点数，按结果与 torch
执行器核对、钉住它照写的代码（35 号文档 AV26）；`verdict.py` 选中词的判定；`payload.py` 答复；`backend.py` 服务本身）：

1. 初态是观测飞机在 `row` 这一步的真实状态（`flights.flight_inputs(anchor=row)`：这架航班在那一行的 `rollout_context`，
   和任何一次展开读航班的方式相同）。
2. 执行器的第 0 步是 `row` 这一步六列生效的词（句子的第 0 步本来就是"飞机此刻正在做的事"，执行器设计 §2.4），之后是句子里
   `row` 之后、`stopRow` 之前的词，每条词在执行器飞到观测飞机听到它的位置时说（规格的词钟 `track`，执行器设计 §11）。
3. 单条执行器（`single.SingleExecutor`，一次一个 1 s 控制周期）飞，驱动方式与 `executor.fly` 完全相同：每个周期先读
   词钟，一步的词在这一步开始的那个周期听到。`stopRow` 不是句子末尾时：句子后面补一个不说任何词的一步（`stopRow` 本身，让词钟
   能走到那里），**在词钟第一次把某个开始一步的周期放到 `stopRow` 的那个周期之前停下**——在那里说的词不会被听到，段尾之后什么
   也不飞。时限仍是这一段的步数 × 1.5；先到了别的结局（碰地、动力学失败、时限）就按结局报。这与"飞满时限再按词钟截断"相同
   （2026-09-25 在 torch 执行器上 216 段，状态与结束周期一致），只是不再多飞。
4. `stopRow` 是句子末尾（例如跑道指针、许可之后的航向、"未指定"速度）：像回放一样飞到落地或失败。句子最后一步才说的词
   没有可飞的一步，按名字拒绝。
5. 判定用执行器自己的判决（`judge.judge`），读的是这一段的句子（从 `row` 起重新编号），所以每个词的包络从执行器听到它的
   地方重新画——选中的词就从观测飞机说它时的那个状态画。只报选中这个词：航向词 = 它的航向带在飞出航段上逐行在不在

  "已飞 / 全段 s simulated"，并写出倍数、地速、高度、坡度；身后的线随之变长，飞过听到下一个航向词的那一点之后接着长的是淡色
  虚线的尾巴（透明度 0.45，地面投影也更淡）；飞完后整段保留，地面投影为虚线，航向词出界的
  行在地面投影上画红。飞完之后线、飞机和标签都换成静态的——动态的线每帧都要重建，而且只有静态的线才画得出被地形挡住的虚线
  部分。"Replay in 3D" 重放同一个答复，不再请求。不用共享的 Cesium 时钟。
- 动力学在第一个周期就失败的答复只有一个状态，没有线可画：三维、读数图和图例都不画它，结果卡和状态行照常写出结局，读数
  窗口的说明写"no line to draw"。
- **读数核对窗口**：平面图、航向图、高度图（对飞过的距离）、速度图各一条实线，从观测线上的那一点出发，尾巴接在后面画成淡色
  虚线（`components/training/AutopilotLine.tsx`，图例多一项 "autopilot tail"）；选中的是航向词时画出
  判决读到的航向带（出界行红框）和出界的行。

**颜色按判定区分**：在包络内（或不判）是蓝 `#2563eb`（`TRAINING_AUTOPILOT_COLOR`），和执行器回放的青色分开——回放是事先
算好的，这个是现飞的；**选中的词飞出了包络，整条飞出的线就换成醒目的红 `#ff2d2d`**（`TRAINING_AUTOPILOT_OUTSIDE_COLOR`，
比标出界行的 `#f87171` 更响；配色校验：与蓝的色差 41.6、色觉异常下 29.0）——三维的航迹、地面投影、飞机与标签、读数图的线、
结果卡的判定与左边框都一起变（`autopilotColour`）。

### 4.8 模型自己说的句子：和真值怎么区分

用户 2026-09-25 的要求："先验模型产出的词序列要和 ground truth 词序列在视觉上有区分"，并建议底部看板可以切换查看，三维里
真值总是显示、颜色和模型的不同，模型产出按选中的模型来。落实如下：

- **一次只读一句**：句子条头部的标签页（`AppContext.trainingSource`；左栏不再有这个选择）。换模型从它的第 1 个
  样本开始；选中的模型与样本在换航班时保留——一架一架地看同一个模型是常用的读法；模型不飞的航班（替代动力学等）写明
  "not flown (…) — the truth is shown"，句子条画真值，连同真值的整个头部（标注器判定、回放、实时执行器、▶ Fly）。
- **模型的词和真值的词一眼分得开**——靠的是框，不是带本身。一次只读一句，所以带和真值的一样是平涂的色块（斜线加虚线边框
  会让整条看板变乱，用户 2026-09-26）；说明"这是模型的句子"的是：句子条的边框、各行左边一条竖色条（`training-sentence-model-strip`）、
  选中的标签页、头部样本的结局小块，都是模型的颜色。
  - 模型只观测、还没开口的前 8 步是一块淡灰底，写 "observed"。
  - 每一行底边上，**真值在这一列说词的地方一根白色短竖线**：模型换词的位置和真值换词的位置在同一行里对照，不必来回切换。
  - 虚线：模型许可的时刻（进近的颜色）、观测航班句子结束的时刻（白）；实线：模型的航班结束的时刻（模型的颜色），**时间轴上
    在它下面用模型的颜色写出结束时刻**（模型的句子可能比观测的早结束，那一处原本没有刻度）；离它太近的刻度让开，航班飞到横轴
    末端时写在末端、末端的刻度让开。结束之后模型还说了至少一整步的（越过入口没截获、失速截断之后执行器还在飞，§2.7），那一段涂暗，写 "after the end"。
  - 头部的小块换成这个样本的结局："#1: landed on 23R at 263 s (observed 306 s)"，没落地的红色；完整读法（说了多少词、越过入口
    的偏离、首末跑道、换跑道、结束时是否许可、屏蔽拿掉的概率）在提示里。标注器的判定小块、回放小块只属于真值；▶ Fly 和实时执行器
    的状态行两边都有——模型的词照样交给执行器飞（§4.7 "模型的词"）。
  - 横轴：观测航班的长度；读的样本飞得更久（超时的样本最长到观测剩余时间的 1.5 倍）时延长到它结束。读真值时不会被没显示的
    样本压扁；游标停在超出真值的地方时，回到 Truth 画在轴的末端。游标越过模型句子的最后一行时，这一列没有生效的词，不亮。
- **多轮后训练之间切换**（用户 2026-09-26："有 base 和 post-train 的切换，但没有多轮后训练的不同模型的切换"）：
  - 句子条上**每个模型一个标签页**（Truth、base、landing、augmented，按训练顺序）。正在读的模型发布了不止一轮时，标签页旁边是它的
    各轮 "r1 r2 …"；提示里写这一轮的全称（run、从哪个模型起步、方法）和这架航班上它的样本落地了几个。
  - **换轮次保留样本号**：同一架航班、同一个样本号，一轮一轮地比。标签页回到这个模型上次读的那一轮，
    没读过的从第一轮开始；换模型从第 1 个样本开始。详情页的结果表按同样的顺序和名字。
  - 同一个模型有两次训练（例如第二阶段停掉后重跑，两次都有 r1）时，每个标签页和每行都写上 run 的实验目录（"augmented r1 ·
    v3_stage2_clip_20260926"；同一实验目录里的两个种子才写全）；同一轮导出了两次（同一个检查点换了导出设置）时各自单列，用叠加层 id 区分。
  - 分组、排序、起名只在 `trainingModelGroups` 一处；句子条、左栏、结果表、图例、三维标签都用它给的名字。
- **颜色按名字给**（`TRAINING_MODEL_COLOR`，`trainingModelColour`）：base 品红 `#d946ef`，landing 黄绿 `#a3e635`，augmented 树莓红
  `#b82e7a`；同一模型的各轮同色，轮次用文字说。真值用观测航迹本来的近白色 `#e2e8f0`，总是画。前两种是配色校验器在句子条底色
  `#0f131e` 上找到的仅剩的两个空色区：品红与三维里画出来的每种颜色 OKLab 色差 ≥ 14.4（最近的是进近的粉，三维里只是一个点），与
  速度紫 9.2（速度在三维里不画）；黄绿与每种颜色 ≥ 9.5（最近的是贴地半透明的走廊绿和跑道绿）；对比度都 ≥ 5:1。树莓红是在色相 ×
  饱和度 × 亮度上搜索、对这套配色的每种颜色都算过之后最好的一个：正常视觉色差 ≥ 17.7（最近的是实时执行器的出界红；离品红 18.5），
  模拟色盲 ≥ 11.6，但对比度只有 3.3:1——够画线、色块、边框和时间轴上的结束时刻，不够写正文，所以模型的名字和数字一律用正文颜色，
  旁边放它的色块（左栏、结果表、样本小块都改成这样）。一次只读一个模型，两种模型的颜色从不同时画。
- **三维**见 §4.4 最后一条；读真值时一个模型的东西也不画。

### 4.10 增强起点

§2.8 的叠加层在界面上怎么读。原则：它是"模型的句子"的一种，§4.8 的读法全部照用；不同的只有起点，而起点不是真值的。

- **句子条头部多一个开关 `Real start | Augmented start`**：只在集合上发布了增强起点的叠加层时出现，放在标签页前面。
  - 选 Augmented：标签页换成有增强起点叠加层的模型（没有 Truth——真值没从这个起点飞过）；从当前模型的增强起点那份开始，
    它没有就从第一个；样本号保留。选回 Real：回到这个模型的真实起点那份，没有就回 Truth。
  - 这仍是同一个 `trainingSource`（叠加层 id + 样本号），开关只是按叠加层的种类筛标签页。
- **句子条**：前 8 行的灰底写 "observed, moved"；**不画真值的发令短竖线和观测航班结束的虚线**（那是来源航班自己起点的，
  和这个起点比没有意义）；行末计数本来就只属于真值。头部样本小块写结局，后面写增强量："#1: landed on 23R at 312 s · moved
  +7.2°, +84 m, ×1.03"，提示里写全（抽了几次、时限是来源航班剩余时间的 2 倍）。模型不飞、或这架没有合格增强的航班，写明原因，
  句子条画真值（同 §4.8）。
- **▶ Fly 在增强起点上照样能用**（2026-09-27 第二步，用户："开始开发"）：请求里带上这架航班的增强量（`augmentation`，
  答复格式 v7），后端用第二阶段同一套函数把起点挪过去——执行器第 8 行的状态按 `augment_state` 挪（`fly.moved_inputs`，
  与 `prior_free_generation.augmented_inputs` 逐位相同，`AugmentedStartTest` 钉住），句子对照的观测行按 `augment_signals`
  挪，时限用增强起点的 2 倍——飞出来就是导出的那个样本：真实数据上三个模型、三个机场、九个词，与样本最大差 2.9 cm，
  全部来自导出时把增强量四舍五入（转角到 0.0001°，离机场约 20 km 处约 2 cm，每一点相同，不随飞行增长）；导出器此后
  写不取整的增强量，重新导出的叠加层就是 0 m（真实起点本来就是 0.000 m）。读数窗口和先验窗口本来只在读真值时给出。
- **三维**：真值照画（这时它表示"从哪架航班挪过来的"）；**增强后的前 8 行**用模型的颜色画一条虚线，接到样本航迹的起点——
  先验看着的就是这一段；样本航迹、贴地投影、结局标签、其余样本细线都同 §4.4。图例加一行 "moved observed rows"。
- **详情页**的 Models 一节加一张表："from augmented starts"——每个模型在集合的增强起点上落地的样本比例（全部 / 直线进近 / 被
  引导），和真实起点那张并排读；左栏最下面的 Models' sentences 一行末尾加上增强起点的比例。
- **不做**：前端自己抽增强（增强只由导出器抽，前端只画，后端照它给的增强量挪）。

## 5 核对

- `npm run check-publication`：读每个机场的 `index.json`，列出的每个集合文件必须存在；别的词表的集合记为
  **警告**（按名字拒读是有意的，删不删是另一回事）；能读的集合用前端自己的 `parseTrainingSample` 读（每个文件只读一遍，
  sha256 用同一份字节算），并和索引条目逐项比对（机场、集合名、航班数、规格 sha、机场几何 sha、读法、划分、每组数量、种子）。
  一个文件截断了（不是 JSON）就说出是哪个，接着查后面的，不中断。
- 加 `--server <地址>`：同样的文件从正在运行的开发服务器取，JSON 必须是 JSON（不是 SPA 回退页），能读的
  样本**把服务器返回的内容再用读取函数读一遍**——HTTP 200 不等于"能加载"。
- 加 `--airports-root <目录>`：核对另一个目录（例如导出到临时目录的试跑），不能和 `--server` 同用。
- 叠加层（包括模型自己说的句子）：`overlays.json` 用前端自己的读取函数读，每个叠加层对照它所画集合的样本读一遍（按内容
  绑定，§2.6）；画在界面不读的集合上的叠加层记为警告。加 `--server` 时服务器返回的叠加层
  也再读一遍。每种叠加层用它自己的读取函数（新加一种而没给读取函数，编译不过）。

## 6 不做什么

1. 不在界面上改词。重飞只有 §4.7 一种：后端的执行器飞选中那个词的一段；前端不算任何飞行。
2. 不录入人工核对的判定。那属于带 sha 的产物，不属于浏览器本地存储。
3. 不浏览全体航班。导出是抽样，规则写在文件里、界面上照录。
4. 不改 Observe 和比较视图。
5. 不做多机。

## 7 维护约定

- 本文只描述当前设计。词表换版本（新读法或新规格 sha），界面会按名字拒读新产物：同一次改动里更新
  `trainingSample.ts` 的钉住值、测试、`aeroviz-4d/CLAUDE.md` 与 `35-viewer-reference.md` 的对应条目和本文。
- 格式名跟着文件的形状走：样本或索引的字段一有增、删、改名，Python 的 `SAMPLE_SCHEMA` / `INDEX_SCHEMA` 和
  TypeScript 的 `TRAINING_SAMPLE_SCHEMA` / `TRAINING_INDEX_SCHEMA` 在同一次改动里一起换新名字，盘上的集合重新导出；
  不为"旧文件还能读"或"现在没人读错"保留旧名字。叠加层的五个格式名（`OVERLAYS_SCHEMA`、`executor_training_export.SCHEMA`、
  `prior_training_export.SCHEMA`、`prior_generation_training_export.SCHEMA` / `AUGMENTED_SCHEMA` 与 `trainingOverlays.ts` 里的
  `TRAINING_OVERLAYS_SCHEMA`、`TRAINING_EXECUTOR_SCHEMA`、`TRAINING_PRIOR_SCHEMA`、`TRAINING_GENERATION_SCHEMA`、
  `TRAINING_AUGMENTED_GENERATION_SCHEMA`）、高度基准的容差（`DATUM_TOLERANCE_M`）和叠加层的种类列表同理，由 `test_training_overlays.py` 逐字比对。清单里出现界面不认识的种类时只拒这一条，别的照读。
- 集合重新导出后，航班、句子、规格、跑道、坐标系与高度基准都没变，画在它上面的叠加层照读；有一样变了，叠加层整份拒读，

- 长期事实一行写进 `aeroviz-4d/CLAUDE.md` 的索引，全文写进 `aeroviz-4d/docs/35-viewer-reference.md`
