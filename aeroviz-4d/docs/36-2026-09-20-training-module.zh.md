# Training 模块设计（2026-09-20）

前端加一个新任务页，叫 **Training**，放在 Observe 右边。它不训练模型、不算评估，只做一件事：
**把两层模型中间那些看不见的东西画出来** —— 一次进近被读成了哪几句话，这几句话本身意味着什么样的
航迹，以及（等模型训出来以后）模型自己说出来的那句话又意味着什么样的航迹。

这篇是设计文档，写在动手之前。实现按 §7 的步骤走，一步一评审。

## §2 放在哪，为什么

### 2.1 位置

`WorkbenchTopBar` 的任务条从

```
Observe │ Fly │ Optimize │ Compare ‖ Procedures
```

变成

```
Observe │ Training │ Fly │ Optimize │ Compare ‖ Procedures
```

代码上：`AppContext` 的 `WorkbenchMode` 联合类型加一个 `"training"`，`TASK_TABS` 加一项，
`WorkbenchLeftDock` 多一个分支。**不新增第二套模式系统** —— 仓库里已经因为"两套互相打架的 mode"
做过一次合并，不能倒回去。

### 2.2 为什么挨着 Observe 成立

- **看的是同一批飞机。** Observe 回答"真飞机是怎么飞的"，Training 回答"这条真航迹被读成了哪几句话"。
  两页共用顶栏的机场和跑道，也共用同一个航班身份（`flight_key` = `id_跑道_icao24_落地时刻`，
  不是呼号）。从 Observe 选中一架切到 Training，选中状态应该跟着走。
- **Fly / Optimize / Compare 是"造一条航迹出来"，Training 是"这条航迹被说成了什么"。** 它属于
  观测这一侧，不属于求解那一侧。放在 Observe 右边，读起来就是"同一批数据，下一个问题"。
- **它不抢 Observe 的资源。** `src/data/observedTracks.ts` 写明观测航迹的大文件只在 Observe 里加载
  （它会驱动共享的 Cesium 时钟，在别的任务里加载会把那边的播放顶掉）。Training 读自己的抽样文件，
  文件里自带需要的那几十条航迹，所以**不加载 Observe 的那份 CZML，也就不会抢时钟**。

### 2.3 它不是什么

不是"训练控制台"。不启动训练、不调后端、不写任何磁盘文件。它只读已经写好的 JSON。
真要跑训练，是命令行的事。

## §3 屏幕长什么样

三样东西，优先级就是用户给的顺序：

1. **一句话** —— 抽几架飞机，把从它航迹里读出来的指令词显示出来；
2. **词画出来的航迹** —— 只按这几个词、用一套很简单的运动学飞出来的大致航迹，和真航迹并排；
3. **模型说的句子画出来的航迹** —— **2026-09-21 到位**：先验（`prior_s1337`）对每一个事件说的下一条词，
   用同一套运动学、同一批时刻飞出来，画成**第三条紫线**；句子条在**它说错的地方**画紫条。
   注意它是**逐事件问出来的**，不是自由生成（V45）。

句子条是这个模块的主角：一行一类词，横轴是**真实时间**，每个事件画一条竖线，
两个事件之间某一类的词是常数（就画成一条横带）。用户一眼就能看到"这架飞机一共被说了几句话、
在哪几个时刻说的"。它和三维画面用同一个时钟，拖句子条就是拖时间。

**横轴为什么必须是真实时间，而不是"第几个事件"。** 句子现在是**事件序列**：一行对应一个
"有东西变了"的时刻，两行之间的间隔本来就不均匀（§4.4 第一条）。把事件等宽排开会好看，
但那样句子条就和它下面那三张时间图、和 Cesium 时钟对不上了 —— 而"几点几分发的这条指令"
正是这个模块要给人看的东西。所以横轴取真实时间；**每个事件把它的时长词标在旁边**，
这样"隔了多久"既看得见（间距）也读得到（数字）。等宽排列留作以后的一个可选视图，v1 不做。

**句子条要按多大来画**（数全部来自真产物的 `summary.json`，train 6853 架，我开文件核过）：

| 量 | 值 | 对排版的意思 |
|---|---|---|
| 事件总数 | 40 270 | — |
| **每架的事件数中位数** | **4**（p95 **12**） | 旧的等间隔网格是 30 个位置，现在**中位只有 4 行** —— 句子条极短。列可以画得很宽，词直接写在带子上，不用缩写、不用悬停才看得见 |
| 相邻事件的间隔 | 中位 **44 s**，p95 **128 s**，最长 **286 s** | 间隔差到 6 倍以上，**这就是横轴必须按真实时间画的实证**：等宽排开会把 44 s 和 286 s 画成一样宽 |
| 被夹边的间隔 | **0 条**（上限 300 s，最长 286 s） | 上限没有binding。**但 `durationClamped` 字段照样要读、要显示**，它现在是 0 不代表以后是 0 |
| 一架的时长中位数 | 296 s | 配上 4 个事件 ⇒ 平均每 74 s 才有一次指令，句子条大片是空白带 |
| 各类用到的词数 | 旧词表（`plateau-v11`）：航向 36/36、高度 11/11、速度 23/23、跑道 4/4、**时长 131/151**、**终止 2/3** | **整列是旧产物的数，新词表（`segment-v12`）还没有产物**（§1）。新词表的类别数是航向 **72**、垂直 **6**、速度 **16**、跑道 4、时长 151、终止 3；**实际用到几类要等产物重读**。已知**终止的复飞是 0 次**；**垂直的上升档不是** —— 词表那条线 2026-09-21 读出来它在五机场 cohort 上确实被用到（要落进这一档得爬超过 1.5°，那是到达切片里真实的阶梯爬升或高度修正，不是噪声）。所以界面不能把"上升"当成"从未观测到"来画 |
| 终止词的实际计数 | 继续 33 417、**落地 6 853**（每架正好一个，在最后一个事件）、**复飞 0** | 落地数 = 航班数，说明"每句话最后一个事件就是落地"是**结构性的**，界面可以直接依赖它 |

**产物里 `word_counts.terminal` 根本没有 `"2"` 这个键**（不是 `"2": 0`）。所以界面按"这一类存在、
本数据从未观测到"画时，**要自己补这个 0**，不能等着从计数里读 —— 读不到。

**不能把 4 写死**：p95 是 12，长航班更多；句子条仍要能横向滚动或压缩。

**词表改版之后条上多三样东西，一样都不加高度**（用户 2026-09-20 要求过把条的总高压下来）：

- **垂直和速度的带子上写出冗余**（`↓3.1±0.22`、`79±2.4`）。冗余是词的一半意思 —— 词说的就是
  "待在这条带子里"，只写档心等于把这一半丢了。写进原来就有的那行字，不占新行。
- **到达时间窗写在标题行**（`speedBand.arrivalWindowS`）：`arrives 291–309 s`。条的横轴就是时间，
  而速度冗余的后果正好是时间，所以它属于这条条——但**不是画在终止词那一格上**：几何航迹跑到
  观测时长 + 120 s，窗口经常落在右边缘之外，括号会在它最有话说的时候正好被裁掉（V39）。
  没有窗口的时候（任一条边界航迹没到入口）写清是哪一条、为什么，不凑数。
- **垂直行的词一律带箭头**（`↓3.1` / `平飞` / `↑3.0`），**绝不只写带符号的数**：词表里
  **下降为正、上升为负**，读者看见 `−3.0°` 第一反应是下降，正好反了。

```
└───────────────────────────────────────────────────────────────────────────┘
```

**比 PNG 强在哪**（这是用户要求"不要闷头写、要好设计"的落点）：

1. **四张图共一个时间游标**，拖任意一张，平面图上的点和三维里的飞机一起动；
2. **悬停出数**：悬停一条 `▬▬` 说"第 4 条航向指令，目标 +50°（词 5），在 t=138 s 发出，
   t=176 s 稳住，离格子中心 2.1°"；悬停一段 `░` 说它为什么没成词；
3. **点击跳转**：点一条指令，主屏三维把镜头移到它发出的位置，时钟跳到那一刻；
4. **两条航迹在同一张平面图上**（真实实线、词画的虚线），差在哪一眼看得见；
5. **按分层过滤航班**（直线进近 / 雷达引导），和实验里的分层用同一套规则
   （`data/approach_difficulty.py`，`STRAIGHT_TORTUOSITY = 1.05`）；
6. **词的冗余画成带子**（§5.6）：垂直是随距离张开的扇形，速度是一条 ±3 % 的带。
   航向和时长**没有冗余，就不画带子** —— 画了等于凭空发明一个容差；
7. **一张垂直图上两个误差都在**：按**真斜率**还原的那条细线和按**档心**还原的那条之间是
   **档位误差**，扇形的宽度是**解码松量**。两者不是一回事，画在一起才看得出哪个大；
8. **每张图的标题给"在带子里的时间占比"** —— 这是冗余顺便给出的读数：这一架有多少时间真的
   待在它被读出来的那个词的带子里。**它量的是读法，不是模型**（§5.6 末尾）。

## §4 数据从哪来

### 4.1 谁写、写到哪

`aeroviz-4d/public/data` 不进 git（本地产物，由预处理脚本重新生成）。Training 的输入按同样的方式办：
**由一个新的 ts runner 写进去**，路径

```
aeroviz-4d/public/data/airports/<ICAO>/training/
    index.json                       有哪几个抽样集
    <集合 id>/sample.json            这一集的全部内容（航迹 + 句子 + 指令 + 几何航迹）
```

**为什么是 ts runner，不是 `aeroviz-4d/python/` 里的脚本**：那个目录下的 Python **不准 import 建模树**
（`aeroviz-4d/CLAUDE.md` 第一段），而导出必须调标注器（`manoeuvre/instructions.read_instructions`）、
必须通过 checkpoint 重建 cohort 的数据（`experiments/support.rebuild_cohort`）、还要用
`outputs/guidance/` 的常数飞几何航迹 —— 全是建模树。所以放

```
4dTrajectory/ts_transformer/experiments/instruction_sample_export.py
→ conda run -n aeroviz --no-capture-output python run_ts.py instruction_sample_export \
      --vocabulary 4dTrajectory/outputs/KRDU/experiments/two_tier_v3_bprime_20260920/vocabulary_tau10/instruction_vocabulary.json \
      --executor   4dTrajectory/outputs/KRDU/experiments/two_tier_v3_grid_20260918/L60_D60_s1337/checkpoint.pt \
      --out        aeroviz-4d/public/data/airports/KRDU/training/vocabulary_tau10 \
      --flights 40 [--split train]
```

**这就是 2026-09-20 22:44 实际跑的那条命令**（1.5 s，40/40 架重建）。跟原设计差两个参数，
都是 T3 落地时去掉的：**没有 `--cohort`**（checkpoint 自己带 data provenance，再给一个
cohort 文件就是第二处真相），**也没有 `--seed`**（抽样直接取 `hand_check/index.csv` 的前缀，
不复刻随机数，见 V20）。**`--executor` 填哪一个不要猜**：词表产物的
`instruction_vocabulary.json` 里 `source.executor` 写着它自己用的那一个，照抄。

**跑完必须重启前端**（`AV5`）。开着的 vite 看不到新建的目录，`index.json` 会按 SPA 兜底
返回 HTML，前端报的是"收到 HTML 不是 JSON"。这台机器上前端挂在
`start_aeroviz_fullstack.sh` 下面，杀掉 vite 那个进程组、让 supervisor 重起一个即可。

checkpoint 在这里只是"进数据的门"（C25：通过它的 data provenance 重建同一批飞机），不读它的权重。
抽样分层与 B0′ 的人工核同一套：一半直线进近、一半雷达引导，种子给定，短了就报错不偷偷补。

| JSON 字段 | 来源 |
|---|---|

| `sentence.eventTimesS` / `words` | `Reading.event_times_s` / `Reading.words`（`[E, 6]`） |
| `sentence.durationClamped` | `Reading.duration_clamped`（间隔超过 300 s 上限被夹边的条数；**夹了要说，不许无声**） |
| `instructions[]` | `Instruction.to_dict()` 原样，键名转驼峰。垂直词的 `target` 是**那一段拟合出来的真角度**（度，下降为正），`issuedS` / `settledS` 是那一段的**起点和终点**（断点本身就是斜率改变的时刻） |
| `absorbed[].reason` | `ABSORBED_SAME_WORD` / `ABSORBED_SMALL_CHANGE` / `ABSORBED_SHORT_TAIL` 三个之一 |

| `vocabulary.*` | `Vocabulary.to_dict()` 的对应字段，键名转驼峰。**`verticalModesDeg` / `speedCentresMps` 是表，不是"起点 + 步长"**：新档心是在数据上拟出来再圆到一位小数 / 1 m/s 的，没有公式；前端的词数由**表长**算，不由除法算 |
| `vocabulary.verticalLevelToleranceDeg` / `verticalToleranceFraction` / `speedToleranceFraction` | `Vocabulary.vertical_tolerance_deg()` / `speed_tolerance()` 用的三个参数。平飞档给**绝对**容差（百分比乘 0 等于没有容差），其余给**比例** —— 前端那两个镜像函数必须把这条分支也镜过去 |
| `vocabulary.words` | `word_counts(vocabulary, runway_vocabulary)`。前端**另算一遍**（表长 / 除法）并要求两者相等 —— 这才叫受检的镜像，不是第二种说法 |
| `geometric.*` | `manoeuvre/instruction_kinematics.py` |
| **`geometric.verticalBand`** | 垂直词的上下界（§5.6）。**和标称航迹逐位对齐**，共用 `tS` / `toGoM` / `crossM` / `lon` / `lat`：γ 只进高度那一步，水平那几路和停止时刻按构造完全相同。`altHaeLoM` / `altHaeHiM` 是三维那面墙的输入（**HAE**，和 `altHaeM` 同一个基准） |
| **`geometric.speedBand`** | 速度词的上下界，**两条真航迹**（速度改水平位移、转弯半径和穿越时刻）。**只带平面图画得到的那两路**（`toGoM` / `crossM`）加 `endReason` / `endS`：三维不画它们（离标称线不到 100 m），所以不带经纬高；高度和 `finalGapM` 一开始也写了，**评审之后删掉** —— 没有读者的必填字段就是没有人会发现它写错的字段。`arrivalWindowS` 是 `[快的那条穿越时刻, 慢的那条穿越时刻]`，**读者拿它和两条边界的 `endS` 逐个核对**（只查顺序的话，`low` / `high` 写反了看不出来）；**任一条不是 `crossed-threshold` 就写 `null`**，而**两条都到了却写 `null` 也拒绝** —— 界面那句"没有窗口，因为某条边界以 … 结束"会去读 `endReason`，两条都到了就会写出一个不是理由的理由 |
| `geometry`（顶层一块） | `instruction_kinematics.assumptions()`，§5.4 那七条假设 + 常数来自哪几个文件 |
| **`prior`（顶层一块）** | `instruction_sample_export.prior_sentences` + `prior.pt` 自己记的东西。`readout` 是先验那次 run 的 `readings.json` 原样抄过来的——界面印的 NLL 必须是那次 run 报的数，不是界面自己算的 |
| **`flights[].prior.words`** | 先验对这架飞机每一个事件的 top-1 下一条。第 0 行是**真值的开头事件**（给它的），第 k 行（k ≥ 1）是它在位置 k−1 上的回答。`givenEvents` 把这件事写进文件 |
| **`flights[].prior.geometric`** | 同一套 `instruction_kinematics`、**同一批事件时刻**飞出来的，所以它和橙线之间的距离**只有词的差别**。不带 `verticalBand` / `speedBand`（V47） |
| 六类词**每一类每一行都有词** | 缺了就是数据坏了，按 §4.5 ③ 报字段名 |

**高度的基准**：`altHaeM` / `altHaeLoM` / `altHaeHiM` 都是**椭球高**（HAE），名字里写着。
记录是 MSL，Cesium 的 `cartographicDegrees` 读的是椭球高，所以导出器在出口处换一次
（`h = H + N`，KRDU 的 N ≈ −33.5 m，**N 是负的，所以拿 MSL 当 HAE 喂进去线会偏高 33.5 m**，
不是沉进地形）。`heightM` 是"跑道入口以上"的相对高，词表和三张时间图用的都是它。

**文件会大多少**：`verticalBand` 四路 + `speedBand` 两条 × 四路 ≈ 每架多 5 300 个数。
按现在 40 架 4.9 MB 算，涨到 6–7 MB。**这是刻意花的**：走廊是这次词表改版的主要表达对象，
而它在前端算不出来（要重跑运动学，常数只能有一处定义，V5）。

**为什么整条航迹进文件而不是复用 Observe 的 CZML**：Observe 的 CZML 是整机场几万架的大文件，
里面没有跑道坐标系下的量（沿航道距离、横向距离、相对航道的航向），也没有平滑后的信号。
Training 要画的三张时间图全是这些量。
**这是一个刻意的重复：同一条航迹在两个文件里各有一份。** 理由是坐标系不同、用途不同，
而且抽样集是只读快照（它要和某一个词表 sha 绑死）。

### 4.4 词表的四条性质，界面必须体现

这四条是 2026-09-20 当天定下来的，写在这里是因为它们直接决定界面画什么、不画什么。
第四条是**最容易画错的一条**。

**一、句子是事件序列，不是等间隔网格；词是六类。**（2026-09-20 当天第二次改契约；
2026-09-21 第三次改的是**每一类词是什么**，不是这一条，所以这一条仍然成立。
当前读法 **`segment-v12`**。）

以前：每 10 s 一行，一行写"此刻生效的词"。现在：**有东西变了才有一行**，行与行之间的间隔
本来就不均匀。为什么改：等间隔网格会把每条指令往后挪到下一个格子上，挪 0–8 s、平均 4 s，
而且**永远是挪晚**，所以它走了。

六类词，**顺序写死，列是按位置认的**（`instructions.INSTRUCTION_KINDS`，我 import 出来核过）：

| 列 | 类 | 说的是什么 | 几类 |
|---|---|---|---|
| 0 | 航向 | 相对最后进近航道的角度，10° 一格 | 36 |
| 1 | 高度 | 跑道入口以上，1000 ft 一格 | 11 |
| 2 | 速度 | **地速**，10 kt 一格，100–320 kt | 23 |
| 3 | 跑道 | 按机场，从产物里读（KRDU 4 条，见第四条） | 每机场不同 |
| 4 | **时长（新）** | 距**上一个事件**多久，2 s 一格，上限 300 s | 151 |
| 5 | **终止（新）** | 0 继续 / 1 落地 / 2 复飞 | 3 |

**切入词删了**（D73）。它是航向词的影子：4 897 条切入词**全部**与某条航向词同一时刻发出，
其中 78 % 可以从航向词直接推出来。凡是原来画"切入标记"的地方，现在改画**终止词的"落地"**。

**时长词对这个界面特别有用**：横轴不再均匀，所以"隔了多久"必须能读到数，不能只靠间距去估
（§3.1 的横轴决定就是为这个）。

**终止词的"复飞"这一类在这份数据里从不出现** —— 25 km 到达切片只留最后那次成功的进近
（第三条）。图例里**可以**把三类都列出来，但要写明"复飞：本数据中从未观测到"，
**不能写成"模型不肯用它"** —— 一个从没见过的类别和一个模型拒绝使用的类别，是两回事。

**跑道那一列为什么非有不可**（计划的决定 D62）：航向和高度全是**相对某一条跑道**量出来的
（航向相对最后进近航道、高度相对跑道入口），所以一句没有跑道词的话**说不出"去哪条跑道"**；
而且真实管制里跑道本来就是管制员要说出口的一句话。
→ **界面只要显示一句话，就必须同时显示这句话是对哪条跑道说的**，并写明别的类是相对它量的
（§3.1 的右侧读数把跑道排在第一行，§3.2 的窗口标题里也带）。这不是装饰：同一串航向词
配不同的跑道词，指的是完全不同的两条航迹。

**`tokenStepS`（τ = 10 s）这个字段还在，但它不再是句子的格子。** 它留在 spec 里是给标注器
的阈值用的。**界面上不要再把它说成"每 10 秒一个位置"**，那是旧契约。

**执行器听到的只有三类。** `Vocabulary.CONDITIONED_KINDS` = 航向、高度、速度
（跑道、时长、终止都不进执行器的条件向量），三类**摊成 4 个数**
（`CONDITIONING_WIDTH = 4`：航向拆成 cos 和 sin，加高度、加速度）。
→ 以后若要画"执行器被告知了什么"，那是**三类，不是六类**；别把跑道/时长/终止画进去。

**二、跑道词不在词表的 sha 里。** 跑道词的类别集合是**每个机场各一套**，它挂在词表产物的 spec
**旁边**（`runway_idents`），不进 `sha256`；做法和机型词表（`manoeuvre.context.TypeVocabulary`）
一样。为什么这么设计：进了 sha，一份词表就不能通用于五个机场了。
**后果，界面上要认这个后果**：两份 sha 相同的产物，跑道类别集合可以不一样。所以
`instructions.py` 另有一个 `runway_sha256(runway_vocabulary)`（第 350 行），先验的产物里
这两个 sha 是**分开两个字段**存的（`experiments/instruction_prior.py` 第 156–157、166–167 行）。
Training 的 `index.json` / `sample.json` 照抄这个做法：`vocabularySha256` 和 `runwaySha256`
各是一个字段。**只比对其中一个就当成"同一份词表"是错的。**

**注意一个坑**：`runway_sha256` **不是词表产物文件里的一个字段**（`instruction_vocabulary.json`
的顶层只有 `schema / written_utc / spec / sha256 / runway_idents / words / cohort_identity /
counts / source` —— 我开文件核过）。它是一个**函数**，导出器要拿 `runway_idents` 建出
`RunwayVocabulary` 再调它算出来。T3 不要去文件里找这个字段，找不到。

**三、"复飞"这个类别存在，但在这份数据里从不触发。** 这一条量过才定的（结果文档 §13.5）：
复飞在机队里是真的 —— 五个机场 44 622 条航迹里有 42 条（0.094 %，和公开的复飞率同量级，
逐架核过剖面）—— 但**词表是在 25 km 到达切片上读的，切片只留最后那一次成功的进近**，
所以复飞在这个 cohort 里一次也不会触发。它现在是终止词的第 2 类（不是一个单独的词类），
**界面按"有这个类别、但本数据从未观测到"来画**：图例里可以列出，旁边必须写明从未观测到。
不要画成一个永远空着的计数槽，也不要让人读成"模型不肯说复飞"。这是这份数据的一条限制：
**本阶段的句子表达不了"这次不落地"**；要改得动上游的到达窗口，那会改掉每一个 ts 数据集划分，
不在这个模块的范围内。这句限制要写在读数核对窗口的说明里，不然看的人会以为是读漏了。

**同一条规矩也适用于这个模块自己**：一个永远不会被设置的字段、一个永远不会亮的提示条，
就不要建。（用户 2026-09-20 否掉"从 `_superseded/` 导一份临时数据"时，`supersededSource`
标志和它配的红条就一起删掉了，不留在设计里。）

**四、跑道词的类别要从产物里读，绝不能从 `runway.geojson` 读。** 这是最容易画错的一条，
因为两边在 KRDU 就对不上：

| | 有哪几条 | 几条 |
|---|---|---|
| 机场的跑道表（`public/data/airports/KRDU/runway.geojson`、`landings/index.json`） | 05L 05R **14** 23L 23R **32** | 6 |
| **词表产物的 `runway_idents`** | 05L 05R 23L 23R | **4** |

差的那两条不是读漏了，是**上游就没有**：这条线全部建在到达清单
`harvest-arrivals-v5-takeoff-excluded` 上，KRDU 那 14 435 架里只有这四条
（05L 3076、05R 1491、23L 3230、23R 6638）；跑道 14 只有 13 次落地、跑道 32 有 1 604 次，
两条都在上游被排除了。

→ **界面上任何一处列出跑道词的地方（选择器、图例、句子条的跑道行），类别集合都读
`sample.json` 的 `vocabulary.runwayIdents`，不读机场的跑道表。** 画成 6 条会告诉看的人
"模型能说 32"，而它说不出来 —— 这是凭空多给了模型两个它没有的词。
**而且要在看得见的地方写一句**：这里的跑道类别是**到达清单覆盖到的跑道**，不是机场的全部跑道。
（放在句子条跑道行的悬停说明里，或读数核对窗口的说明里。）

这一条对别的机场同样成立，数也各不相同，所以**不要把 4 写死**：`runwayIdents` 有几个就是几个。

## §5 词怎么画成航迹

### 5.1 要解决的问题

一句话说三样：**转到（相对航道）某个角度、按某个航迹倾角飞、减到某个地速**。它不说转多快——
那是机型和动力学决定的，是执行器（第一层）的事（计划的决定 D50）。所以"把词画出来"必须补一套
最简单的运动学：**朝目标转、按给定的角度下降、朝目标减速**，转弯速率受坡度限制。

**2026-09-21 词表改版之后，这三样里只有两样还是"目标"。** 垂直词现在是**航迹倾角**，是一个
**速率**，不是一个要收敛过去的高度：没有误差要闭，直接就是这一步怎么走（`height += step·tan γ`）。
这一条改变了下面每一小节，也是 §5.6 那条走廊成立的原因。

### 5.2 复用了什么

| 量 | 值 | 来自哪里 |
|---|---|---|
| 转弯用的坡度 | 20° | `outputs/guidance/route.py` `ROUTE_BANK_RAD` |
| 转弯速率 | `g·tan 20° / V` | 由上面那个坡度直接算。**不是 `V / route_turn_radius_m(V)`**：那个函数在 40 m/s 以下给半径设了地板，当成速率读就把物理弄反了（定坡度下越慢转得越快）。两者在 40 m/s 以上一致，而词表最慢的档是 44 m/s |
| 重力 | 9.81 | `geometry/flyability.py` `G` |
| 下降角上限 | 6° | 同上 `DESCENT_MAX_RAD`。最陡的垂直词是 4.4°，带上冗余 4.71°，**夹不到** |
| 爬升角上限 | **4°** | 同上 `CLIMB_MAX_RAD`。**2026-09-21 从 2° 改上来的**（词表那条线改的）：上升档是 3.0°，带上冗余到 3.21°，而 2° 的上限意味着**一句合法的话执行器飞不出来**。`test_instruction_kinematics` 有一条测试钉住这个包含关系：**每一个垂直词的档心 + 冗余都必须在上下限之内**。这条不变式正是 §5.6 那条走廊的前提——边界飞不出来，走廊就画不出来 |
| 加减速上限 | 1.0 m/s² | 同上 `ACCEL_MAX_MPS2` |
| 入口高度的地板 | 0 m | `instruction_kinematics.fly()` 自己的一条：角度指令不会自己停，没有地板就会穿过跑道继续下降 |
| 跑道坐标系 | 沿航道距离 / 横向距离 / 相对航向 | `data/approach_difficulty.course_frame_rows`，经 `instructions.course_frame` |
| 每格的中心值 | — | `Vocabulary.heading_centre_deg / vertical_centre_deg / speed_centre_mps`（后两个是**查表**，不是"起点 + 步长"，见 §4.3） |
| 每个词的冗余 | — | `Vocabulary.vertical_tolerance_deg / speed_tolerance`（§5.6） |
| 某一刻生效的词 | — | `Reading.words_at`（取"之前最近的那个位置"，和执行器读词的规则同一处） |

**没有直接复用 `route.build_route`。** 它解的是另一个问题：从当前位姿铺一条转—直—转的路径切到航道上某一点
（Dubins 路径）。这里没有"要切到哪一点"这个输入 —— 句子只给角度目标。所以复用的是它的**常数和半径公式**，
不是它的路径搜索。这一点写明，免得后人以为漏用了。

`route.DECEL_RATE_MPS2 = 0.5` **没有用** —— 那是"路线的速度计划"里减速段的速率，是另一个旋钮；
这里追的是词的速度目标，用的是控制器的加减速上限 1.0 m/s²。两个数不要混为一谈。

### 5.3 一步是怎么算的（dt = 1 s）

状态：跑道坐标系里的位置（沿航道 `d`、横向 `x`）、入口以上高度 `h`、地速 `V`、相对航道的航向 `χ`。

1. 用 `words_at(t)` 取此刻生效的词（跑道、时长两类不参与飞行）；
2. **航向**：目标 `χ* = heading_centre_deg(词)`。最大转弯速率 `ω_max = g·tan(20°)/V`；
   本步转过的角度 = `sign(χ*−χ) · min(|χ*−χ|, ω_max·dt)`（角度差按 ±180° 绕回）；
3. **垂直**：`γ = −vertical_centre_deg(词)`（词里**下降为正**，γ 按爬升为正，所以有这个负号），
   夹进 −6°…+2°，再夹一条地板：`h > 0` 时 `γ ≥ atan(−h / (V·dt))`，`h ≤ 0` 时 `γ ≥ 0`；
   `h += V·dt·tan γ`。**没有要闭的高度误差** —— 词本身就是角度；
4. **速度**：目标 `V* = speed_centre_mps(词)`；`V += clamp(V*−V, ±1.0·dt)`，**放在最后**，
   这样一步是按一个速度飞完的，而不是垂直用旧速度、水平用新速度；
5. 水平位移 **`V·dt`**（不是 `V·cos γ·dt`）沿新的 `χ` 推进，得到新的 `d`、`x`。
   `course_frame` 的 `ground_speed_mps` 本来就是**水平**速率（实测 `|Δ位置|/(V·Δt)` 中位 0.99966），
   而速度词的定义也是地速，所以水平步长就是 `V·dt`，爬升量是 `V·tan γ·dt`。
   把 V 当成航迹速度会少走 `1/cos γ`，6° 上是 0.55 %；
6. 反算经纬高写进文件（用 `geokit` 的换算，跟 CZML 出口同一处定义）。

### 5.4 七条必须写明的假设

`sample.json` 的 `geometry` 块把它们写进文件，界面上也要能看到 —— **一个不写明的近似比没有还糟**：

```json
"geometry": {
  "method": "instruction-kinematics-v1",
  "dtS": 1.0,
  "bankDeg": 20.0, "gravityMps2": 9.81,
  "verticalIsCommandedAngle": true,
  "heightFloorM": 0.0,
  "descentMaxDeg": 6.0, "climbMaxDeg": 2.0, "accelMaxMps2": 1.0,
  "startsAt": "observed-first-row",
  "stopRule": "crossed-threshold or time-cap at the observed duration + 120 s",
  "windModelled": false,
  "aircraftTypeModelled": false,
  "verticalBandFrom": "vocabulary.verticalTolerance",
  "speedBandFrom": "vocabulary.speedTolerance",
  "bandsAreJoint": false,
  "constantsFrom": ["outputs/guidance/route.py", "outputs/guidance/controller.py",
                    "geometry/flyability.py"]
}
```

**这一块是 `instruction_kinematics.assumptions()` 原样**，字段一改这里就要跟着改 —— 它自己的
docstring 说了"界面会显示它"，所以它是个有人读的契约，不是注释。`heightGainS` / `terminalWordStops`
两个字段**已经没有了**：前者随着"垂直词就是角度"作废（没有要闭的高度误差），后者是设计里写了
但没有采用的那条停止规则（见下面第 6 条末尾）。

1. **起点取真航迹的第一行**（位置、高度、地速、航向）。句子里没有"从哪儿开始"这一项，词全是相对量。
   **后果要说清楚：两条线的起点按构造就是重合的，所以它们之间的差是"词没说出来的那部分"，
   不是某个模型的误差。** 界面上这句话要写出来，不能让人看成模型评估。
2. **（这一条没有采用，实际的停止规则是第 6 条那两条；留着是因为它解释了字段为什么长成那样。）**
   **终止词决定什么时候停，跑道/时长两类不参与飞行。** 终止词说的就是"这一句到此为止"，
   所以积分到**终止词读到"落地"的那个事件**就停 —— 这比旧的"过入口平面、或者句子末尾再加一个 τ"
   干净得多，因为它是句子自己说的，不是我替它定的。跑道词只定坐标系（本数据里是常数），
   时长词只说事件之间隔了多久（积分用真实时间，不需要它）。
   **切入词已经删了**（§4.4 第一条），原来画切入标记的地方改画"落地"。
3. **不建风模型。** 词说的是**地速**（ADS-B 没有空速），风已经在这个数里了 —— 这一条对这里反而有利。
4. **不分机型**：坡度固定 20°，不按机型改。
5. **管制员说话比航迹动早几秒**，这几秒航迹里没有，读不出来（`instructions.py` 的模块说明已写明）。
   所以词画出来的航迹相对真航迹会**系统性地晚一点**开始转，这是读法的性质，不是画法的缺陷。
6. **终止（T5 落地时改过两轮，这一条是现在的写法）**：两条，先到者写进 `endReason` ——

   - `crossed-threshold`：**朝里**穿过入口平面**并且在最后进近上**。两个条件缺一不可：
     - 「朝里」是**一次穿越**（上一步在入口前面、这一步到了后面），不是一个状态。40 架里有 **17 架**
       进到 25 km 切片时**已经在入口平面另一侧**，把它当状态判，它们的几何航迹第一步就结束了。
     - 「在最后进近上」用的是 `course_frame_rows` 给每一观测行判 `established` 的**同一条规则**
       （横偏 < 500 m 且航迹与航道夹角 ≤ 30°）。**只看平面是错的，而且仓库为此付过一次代价**
       （2026-09-09：雷达引导的下风边平行于航道、横着好几公里，从那里穿过 `d = 0`，
       按平面切的记录中位横偏 8.7 km）。第一版这里就是只看平面：**40 架全报「到达」，其中 14 架
       落在中心线外 2 km 开外，10 架在最后一条航向词飞出来之前就被截断了**。
   - `time-cap`：观测时长 + 120 s 的硬上限，**由 `fly` 自己施加**，因为 `geometry` 块把这条规则
     写进了产物——让调用方自带上限，那句话就对不上了。

   `finalGapM` 是停下来时**离入口的水平距离** `hypot(to_go, cross)`。**注意它的口径**：
   在 `crossed-threshold` 下沿航道分量按构造接近 0，所以那一栏基本就是横偏；
   要读「两条线差多少」请用 `meanGapM` / `gapP95M`，它们是整段的。**不偷偷延长航迹去凑到入口。**

7. **一句话画出来的是一族航迹，文件里带的是这一族的边界**（§5.6）：`verticalBandFrom` /
   `speedBandFrom` 说这两条边界是拿哪个冗余画的，`bandsAreJoint: false` 说它们**是分开的两对**，
   不是 2×2 的联合包络。不写这三个字段的话，屏幕上那条走廊没人能说清是谁画的、宽在哪儿。

   **原设计里的另外两条没有实现，理由写在这里**：
   - 「过了句子最后一个位置再加一个 τ」是等间隔网格时代的写法。改成事件序列之后，
     最后一个事件中位落在航迹结束前 **145 s**（326 s 的进近），按它停等于让线在离跑道十几公里
     的空中断掉，而断掉的理由和词没有关系。
   - §5.4 第 2 条写的「积分到终止词读到『落地』的那个事件就停」是同一个位置（终止词就挂在最后
     一个事件上），同理没有采用。**终止词说的是「这句话以落地结束」，不是「飞到这里为止」** ——
     词一直生效到入口，句子条上那条画到航迹末端的带子说的就是这件事。（这一条有测试钉住，
     因为它被写过一次又反过来，没有测试会被悄悄翻回去。）

### 5.5 它是诊断，不是模型的答案

这条是用户的既有规则（记忆条目 *no-procedure-answer-as-model-fix*，以及计划 §5.2.3 的
"规则制导只作基线与诊断，不作模型的修法"）。界面上这条线的图例文字必须是
**"按词用规则画出来的（基线）"**，不能只写"预测"或者把它和模型输出画成同一种样式。
颜色上：真实白、规则橙（实线细）、模型紫（虚线）—— 和比较视图的配色约定不冲突。

### 5.6 一句话画出来的是一条走廊，不是一条线（2026-09-21 词表改版）

新词表给**垂直**和**速度**两类词各带了一个**冗余**（`Vocabulary.vertical_tolerance_deg()` /
`speed_tolerance()`）：词不是一个点目标，是一条带子，执行器待在带子里就算照做了。

| 词 | 档心 | 冗余 | 半宽 |
|---|---|---|---|
| 垂直·平飞 | 0° | ±0.1°（绝对；百分比乘 0 等于没有容差） | — |
| 垂直·下降 | 1.4 / 2.4 / 3.1 / 4.4° | ±7 % | ±0.10 / 0.17 / 0.22 / 0.31° |
| 垂直·上升 | −3.0°（复飞用，但**本数据里也真的出现**：爬超过 1.5° 就落进这一档，到达切片里的阶梯爬升和高度修正都算） | ±7 % | ±0.21° |
| 速度 | 16 档地速 44…157 m/s | ±3 % | ±1.3（44 档）…±4.7（157 档） |
| 航向 / 跑道 / 时长 / 终止 | — | **没有冗余** | — |

所以一句话说出来的不是一条航迹，是一族航迹。界面要画的是这一族的边界。

**这一族怎么画，取决于哪一类的冗余积到哪根轴上**（词表计划 §1.3 就是按这个分的）：

- **垂直的冗余积到高度上**：`δ × 飞行距离`。画成**随距离张开的扇形**（时间图）和**一面墙**（三维）。
  半宽按 `s·(tan(γ+δ) − tan γ)` 算（我推的式子，不是量出来的）：平飞 1.75、1.4° 档 1.71、
  3.1° 档 3.81、4.4° 档 5.41 **米每公里**。25 km 的切片上 3.1° 档就是两边各 95 m。
- **速度的冗余积到到达时间上**：≈ `D·δ/v²`。画成**沿航迹的前后括号**和一个**到达时间窗**。

**用户原来的提议是「整条曲线按速度下界画一条、上界画一条，同色系不同饱和度」，照做 —— 但那两条
线不是读数的地方。** 线要画（平面图里画，同色低饱和），因为速度确实会改平面形状：航向词是按
**时刻**生效的，快的那架开始转弯时已经多走了一段（200 s、70 m/s 的一段就是 ±420 m），
而且它的转弯半径还大 6 %（`r ∝ V²`；70 m/s、20° 坡度上 1372 m 的半径差 82 m）。
问题在于**这两样在图上都表现成「同一条路稍微错开一点」**：两条线基本贴着标称线走，
看上去像把线加粗了。而速度冗余真正的后果是**到入口早晚几秒**——这个数在一张静态平面图上
**根本没有对应的东西**。只给那两条线，读者会得出「速度这一类的松量无害」这个错结论。
所以：**线照画，数写在时间轴和读数里**（句子条末尾的到达时间窗、速度图上的带子、
游标处的前后括号）。

反过来，垂直的冗余在平面图里是**恒等于零**的（见下），所以平面图上永远只有速度那一族，
高度图和三维里永远只有垂直那一族。**一根轴上只画会动那根轴的那一类。**

#### 垂直的上下界不用重飞，速度的必须重飞

`fly()` 里一步是这么走的：`step_m = speed·dt`，转弯速率 `g·tanφ/V`，
`to_go -= step_m·cos χ`、`cross -= step_m·sin χ`，停止判据只看 `to_go / cross / χ`。
**γ 只进 `height += step_m·tan γ` 这一处**。所以：

- **γ 变，水平那几路和停止时刻按构造逐位相同** ⇒ 上下界只是**另外两路高度**，
  产物里多 `heightLoM` / `heightHiM`（加三维那面墙要的 `altHaeLoM` / `altHaeHiM`），
  不是两条航迹。三路高度在同一次积分里一起出，**不新开两次积分**。
- **速度变，水平位移、转弯半径、穿越时刻全变** ⇒ 必须真的重飞两遍。两条角点航迹**只带跑道
  坐标系那几路**（`tS` / `toGoM` / `crossM` / `heightM`）+ 三个标量，**不带经纬高**：
  三维里它们离标称线不到 100 m，画进去只是把线加粗，而那面墙已经在那儿了。
- 两条角点航迹**只改目标速度，不改起始速度** —— 起点仍是观测第一行（§5.4-1），
  两条线和标称线按构造同一个起点。

#### 带子一次只画一类，不画联合包络

文件里写的是 γ± 一对、v± 一对，**不是 2×2 四个角点**。要回答的问题是**归因**——这条走廊有多少
是垂直词的松、多少是速度词的松——联合角点把两者混在一起，只剩一个上界的意思。图例要写明
「这是一类词的松量，不是全部松量的包络」。

#### 扇形在高度 0 处收口，那是执行器的地板，不是词表的冗余

`assumptions().heightFloorM = 0`：执行器到了入口高度就改平，不穿地。所以两条界线都会在地板上
合拢，**扇形最宽的地方在落地之前，不在入口**。图例要写明这一句，否则「到入口就没有不确定性了」
是个假象。

#### 垂直图上同时有两个误差，正好能比大小

垂直词是**按「高度对累计水平距离」的分段拟合**读出来的（词表计划 §2.3），所以它的图必须画在
它被读出来的那套坐标里——和「观测图一律用 `course_frame`」是同一条规矩。一张垂直图上画三样：

1. **实测高度**（观测行）；
2. **按词还原的高度**：每一段从它自己的起点起锚，按**档心**的角度推出去（`h(t) = h(t_a) −
   tan γ_词 · [x(t) − x(t_a)]`，`x` 是累计水平距离），**每个断点重新起锚** —— 不重新起锚的话
   前一段的误差会一路抹到后面，而标注器本来就是分段拟合的；带**扇形**（γ ± 冗余）；
3. **按真斜率还原的高度**：同一条式子，角度换成 `Instruction.target`（拟合出来的真角度），细线。

这样一张图上两个误差各自可读：**2 和 3 之间是档位误差**（把真角度圆到档心的代价，词表计划
§1.3 量到中位 34.7 m、p95 194.6 m 的那一个），**扇形的宽度是解码松量**（执行器被允许偏多少）。
两者不是一回事，画在一起才看得出哪个大。**3 还是 §2.6 那条自检的图形版**：真斜率还原的终点
高度误差必须是 0。

#### 冗余顺便给出一个读数：在带子里的时间占比

冗余的定义就是「算不算照做了」的判据，所以它天然能回答：这一架飞机有多少时间**真的**待在它被
读出来的那个词的带子里？按类算（速度按值、垂直按扇形），在两条线都还在飞的那一段上算，写在
每张图的标题里。**它量的是读法，不是模型**：占比低说明这一段的平台/分段粗，不说明谁飞错了。
这个数在前端算，不进产物。

#### 读数容差不是解码冗余

`course_tolerance_deg = 2.0°`、`speed_tolerance_mps = 2.5 m/s` 是**读词的时候**判平台用的，
和这里的冗余是两个数、两个用途。**界面上只有冗余画成带子**，读数容差只出现在悬停文字里。
航向和时长**没有冗余**，它们的图上就**不画带子** —— 画了等于凭空发明一个容差。

## §6 v1 不做什么

写清楚，免得后面有人以为忘了：

1. **不能在界面上改一个词再重飞。** 那需要把 §5.3 的运动学搬进浏览器（等于制造第二份定义），
   或者给后端加一个端点。**第二条路是 v2 的方向**（`aeroviz_backend` 加
   `POST /training/fly-sentence`，收一串词返回一条航迹），v1 不做。
2. **不做人工核的判定录入**（一致 / 漏读 / 误读）。那是实验产物，要进带 sha 的 artefact，
   不能进浏览器的本地存储（本地存储只在这台浏览器里，Claude 和别人都读不到）。
3. **不浏览全体**。B cohort 是 train 6853 / val 1404 架；导出是**抽样**，份额和种子写在
   `index.json` 里，界面上明写"这是 40 架的抽样"。不做无声的截断。
4. **面板三（模型说的句子）v1 只有占位**，因为阶段 B3′ 还没跑，没有产物。占位要说清楚在等什么。
5. **不做 τ = 5 s 的对照**（计划的 B4′）。两个 τ 只是两个集合，等有了产物自然就能并排看。
6. **不改 Observe、不改比较视图**。Training 只新增文件，不动既有任务页的行为。
7. **不做多机**（阶段 C 之后的事）。
8. **不做演示模式的特别排版**（`presentationMode`），v1 沿用左坞 + 底栏。
