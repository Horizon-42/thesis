AeroViz-4D airport preprocessing

当前机场数据处理管线

这份文档描述 AeroViz-4D 现在的机场静态数据管线：机场与跑道、RNAV/RNP 程序、航图索引、障碍物、航路点，以及机场局部地形。 航迹 CZML 属于后续轨迹数据管线，当前总脚本默认跳过，只保留可选生成入口。

Browser contract: public/data/airports/<ICAO> Terrain contract: local-terrain/heightmap Charts and CIFP are source data Trajectories optional

One command

总入口脚本

./preprocess_aeroviz_airport.sh KRDU
默认范围
机场静态资产 + 局部地形。轨迹数据默认不生成。
主要输出
aeroviz-4d/public/data/airports/<ICAO>/

Run order

总脚本执行顺序

  1. 机场基础资产：用 OurAirports 生成 `airport.json`、`runway.geojson`，并更新 `airports/index.json`。
  2. 航图源缓存：若 `data/RNAV_CHARTS/<ICAO>` 没有 PDF，则下载 FAA RNAV/RNP 航图。
  3. 程序资产：从 CIFP 生成 `procedures.geojson`、`procedure-details/`、`charts/index.json`。
  4. 障碍物：按机场所在国家/州选择 DOF 文件，过滤指定半径内障碍物。
  5. 航路点：从 OpenNav 页面抓取并筛选机场周边点位。
  6. 航迹：默认跳过；设置 `GENERATE_TRAJECTORIES=1` 才会尝试用本地 CZML 输入生成 `trajectories.czml`。
  7. 地形源：检查 `data/usgs_tnm_elevation/<ICAO>` 或已有 `local-terrain/sources`；两者都缺失时调用 TNM 下载器。
  8. 局部地形：TNM 源走 `preprocess_usgs_tnm_terrain.py`；已有 GeoTIFF 源直接走通用 Node heightmap 构建器。
  9. 契约校验：校验必需 JSON 与地形 metadata，确保前端可直接加载。

Current alignment notes

和旧管线的关键差异

地形运行时路径已经从 `dsm/heightmap-terrain` 切换到 `local-terrain/heightmap`。 `dsm` 只应作为历史或源数据命名出现，不再作为前端运行时包名。
当前地形预处理入口是 `preprocess_usgs_tnm_terrain.py`。 它会把 TNM DEM/DSM 源规整到 `local-terrain/sources/`，再调用 Node heightmap 构建器发布浏览器 tiles。
已有 `local-terrain/sources` GeoTIFF 仍然是一等输入。 对 CYVR 这类已有本地源的机场，总脚本可以跳过 TNM 下载并直接调用通用 Node heightmap 构建器。
航迹数据后续会独立更新。 总脚本保留 `GENERATE_TRAJECTORIES=1` 兼容入口，但默认不再把轨迹作为机场静态数据管线的一部分。
OpenNav 和 TNM/FAA 下载步骤依赖网络。 若本地已有源数据，脚本优先复用缓存，减少重复下载。

Operator quick reference

常用运行方式

标准机场静态管线

./preprocess_aeroviz_airport.sh KRDU

包含轨迹 CZML

GENERATE_TRAJECTORIES=1 ./preprocess_aeroviz_airport.sh KRDU

只用已有地形源

DOWNLOAD_TERRAIN=0 ./preprocess_aeroviz_airport.sh KRDU
