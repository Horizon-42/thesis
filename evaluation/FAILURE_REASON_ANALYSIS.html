技术附录 A：Observed threshold-event v6 fitting 模型 展开查看精确 predicates、窗口、robust seed、OLS 与 uncertainty 公式

适用范围：这个 fitter 只用于 observed ADS-B 航迹。optimized 和 predicted 航迹不经过它；它们按后述 terminal-state 规则直接进入 evaluation。fitter 的唯一输出是与政策无关的跑道阈值面三维事件，不包含 LPV/LNAV-VNAV 类型、判决门限或 verdict。

按时间排序的 ADS-B HAE 样本 → 宽松机场着陆结构筛选 → 选择跑道与真实 inbound pass → 在该 pass 内进行一次稳健三维最终段拟合 → observed-threshold-event-v6 → evaluation 读取已序列化事件，不重新拟合

A.1 Bracket 只选择跑道与物理 pass

对每条跑道检查连续样本对。候选必须从阈值前严格向阈值后运动：

before.s < 0 ≤ after.s after.s > before.s after.time > before.time |interpolated cross-track| ≤ 1000 m |interpolated height above threshold| ≤ 100 m

其中 1,000 m/100 m 是排除无关飞越的结构范围，不是 approach pass 门限。每条跑道保留绝对横向偏移最小的候选；不同跑道最优分数差小于 50 m 时标为 ambiguous。

A.2 ADS-B 位移与速度完整性

位置速度使用 lastposupdate，而不是可能重复旧位置的 state-row time：

0 < Δlastposupdate ≤ 30 s 0 < reported ground speed ≤ 200 m/s |position speed − mean reported speed| ≤ 25 m/s 0.5 ≤ position speed / mean reported speed ≤ 1.5

这些值只筛查源数据跳跃。25 m/s 是五机场 accepted-control 差值 p99=22.62 m/s 的向上取整；它不是航空器进近性能标准。

A.3 选定 pass 的上下边界

合法 bracket 的阈值前样本成为显式 pass_anchor_index。算法从 anchor 反向寻找最近一次真实 along-track 反转，并只在该连续 inbound run 内寻找拟合样本。100 m 容差相对已接受后缀的最小 along-track 位置计算，因此是总退回上限，不会在每个样本重新获得 100 m。若后一次 pass 从 −100 m 才恢复接收，它在 −300 m 内边界之前没有样本，事件会变成 unavailable，不会借用早期 approach。

没有 source-valid bracket 时，系统仍可用同一个 robust final-segment fitter 做相对跑道 assignment；它同样只能使用选中的最终 inbound pass。Bracket 的插值位置会写入审计字段，但其角色明确标记为 runway_and_pass_anchor_not_event_estimator。

A.5 不确定度与 unavailable

候选窗口中最大的 1.96 × intercept standard error 作为 statistical 95% 项；各候选截距相对 primary 的最大变化作为 window-sensitivity 项。垂直有效 95% margin 为两者之和；横向还使用 max(10.5 m, statistical + sensitivity) 的模型下限。事件将有效 margin 除以 1.96 后保存为 sigma。

这些是不确定度诊断，不是 verdict gate。如果选定 pass 没有满足样本数/跨度的候选、拟合与着陆结构不相容，或事件/跑道周期指纹失配，结果为 unavailable 或被拒绝；系统不会降低门限、切换旧算法或从另一段航迹借样本。

B.2 跑道坐标与垂直参考

s = 相对 LTP 阈值面的有符号 along-track（阈值前为负） x = 相对跑道中心线的有符号 cross-track（右侧为正） desired altitude MSL = LTP elevation MSL + published FAS TCH z = trajectory altitude MSL at s=0 − desired altitude MSL

TCH 是标称路径在阈值处的高度，不是误差容差。Observed 必须同时通过事件内 runway-data fingerprint 与当前 assessment context 的跑道、周期、坐标、航向和 HAE/MSL datum 一致性检查，防止把旧周期拟合结果套到新跑道框架。

B.3 LPV 主标准

横向

B_guidance = 0.5 × LPV lateral FSD B_runway = 0.5 × runway width B_lateral = min(B_guidance, B_runway) pass ⇔ |x| ≤ B_lateral

FAA Order 8260.58D Formula 3-1-1 的阈值 course-width 下限示例为 106.75 m，因此 half-FSD 为 53.375 m；实际判决使用当前 FAS 值。跑道半宽是项目的几何保护项，确保被评价的导航参考点不在跑道边缘之外；它不声称机翼或起落架整体均被包含。

垂直

LPV one-sided minimum FSD = 15 m ICAO normal-operation fraction = 0.5 B_vertical = 0.5 × 15 m = 7.5 m pass ⇔ −7.5 m ≤ z ≤ +7.5 m

15 m 来自 RTCA DO-229D §§2.2.4.4.4、2.2.5.4.4 的 angular/minimum-clamped LPV scale；0.5 来自 ICAO Doc 9613 Fifth Edition, Volume II, Part C, Chapter 5, Section B, §5.3.3.1.1.1(b)。这不是由本数据集调参得到，也不是 WCH、TCH 范围或 SBAS alert limit。

B.4 唯一 fallback：RNP APCH LNAV/VNAV（approved Baro-VNAV）

B_lateral = min(0.15 NM = 277.8 m, 0.5 × runway width) B_vertical = 22 m pass ⇔ |x| ≤ B_lateral AND |z| ≤ 22 m

±22 m 来自 ICAO Doc 9613 §5.3.4.4.7。只有 assessment context 明确确认 approved Baro-VNAV 并提供权威阈值路径高度时才启用垂直 gate；否则 vertical 为 indeterminate，overall 仅在 lateral fail 时为 fail，其余为 indeterminate。Pure LNAV 没有批准的对称垂直路径误差 gate，因此不是三维 verdict fallback。

B.5 三值合成与 point-estimate 原则

component pass ⇔ 有 estimate 和 bounds，且 lower ≤ estimate ≤ upper component fail ⇔ 有 estimate 和 bounds，但 estimate 越界 component indeterminate ⇔ estimate 或适用 bound 不可用 overall fail ⇔ lateral 或 vertical 任一为 fail overall pass ⇔ lateral 和 vertical 都为 pass overall indeterminate ⇔ 没有 fail，但至少一个 component 为 indeterminate

判决使用 inclusive point estimate。报告中的 estimate ± 1.96σ 只描述 estimator/data quality；置信区间跨越 gate 不会把合法 point estimate 变成 indeterminate，也不会把已越界点改成 indeterminate。所有坐标、时间、宽度、FSD、bounds、sigma 与 deviations 必须为有限数；NaN/Infinity 必须拒绝，不能依靠比较结果“自然通过”。

结果边界：本报告回答“轨迹导航参考点在 LTP 阈值面是否符合所选 LPV 或 LNAV/VNAV 几何基准并位于跑道横向范围内”。它不证明整段 FAS conformance、实际机组选择的 approach mode、航电 integrity、障碍面净空、operator stabilized-approach policy、touchdown point 或完整机体/起落架 containment。

正式判决中，主要失败原因是垂直越界。 9,843 个 fail 中，9,154 个（93.00%）仅垂直失败，607 个（6.17%）横向和垂直同时失败，只有 82 个（0.83%）仅横向失败。因此共有 9,761 个 fail（99.17%）涉及垂直分量。

6. 判决条件与“原因”的边界

vertical_error = threshold-event altitude − (LTP elevation + published TCH) vertical pass ⇔ −7.5 m ≤ vertical_error ≤ +7.5 m lateral pass ⇔ |signed cross-track| ≤ min(½ LPV lateral FSD, ½ runway width) overall fail ⇔ 任一适用 component fail overall pass ⇔ lateral pass AND vertical pass otherwise ⇔ indeterminate

正式失败原因是上述分量越界；这是本报告可以直接、确定地统计的内容。物理根因可能包括真实飞行偏差、最终段样本选择、拟合模型、外推、ADS-B 高度/位置时间对齐等。仅凭 verdict 不能把这些根因互相替代。

当前 uncertainty 字段是诊断信息，不改变 point-estimate verdict。因此本报告没有把置信区间重叠边界重新分类。
