8 The artefact and its identity

The labeller writes the sentence artefact. It is a directory with the spec, the signals of each flight, the candidate runways, the sentences, and the closed-loop sentences for each split and each Δ. The formal artefact is instruction_language/v12_20261005 with the executor spec executor/v17_20261005. Both are read-only, with a checksum file.

The split is by operating day (a flight’s day is its landing day, UTC − 9 h), and the file of the split is committed. KAUS is a held-out test airport. Its data are not in the live training data.

8.1 What an identity binds

The rule of D21 is: an identity binds the format (what the words and the payloads mean) and the data rules (the sealed test days). Code is identified by what it does on fixed inputs, never by a hash of its source bytes. Data are identified by their flights, never by the bytes of a manifest.

  • The vocabulary: the spec sha. It is the format.
  • The labeller: a conformance check. The artefact holds a reference sample. The check labels it again with the code on disk and requires the same words, strata and refusals.
  • The executor: a conformance check on its reference tracks (section 5.6).
  • The closed-loop reading: its own conformance check, within the tolerance of the executor check.
  • The flights: the stored signals. A consumer that rebuilds a flight from the harvest compares it row by row.

Each check runs every time, in the process that uses the code. There is no passed record and no digest of code. Why? The earlier design named the passed records by a digest of the code. A change in a file that moved no track still refused every runner until the checks ran again. The user called a code fingerprint a bad design (D73). A code change that stays within the bounds opens everything, and nothing is retrained.

The package rules are enforced by a test: instructions/ imports neither autopilot/ nor prior/. autopilot/ and prior/ import instructions/ and not each other. The runners join them.

The artefact also tells a reader which fields a model must not read (D82): the landed runway, the landing time, the capture row, the go-around rows, the stratum, the outcome, and the errors of the closed-loop reading. They use later rows. They are for readouts and selection, never inputs. The reader gives them apart from the rows. A flight whose observed track has a faulty point (a jump, a held position, a reversal of more than 120°) is marked when the artefact is read (D111).
