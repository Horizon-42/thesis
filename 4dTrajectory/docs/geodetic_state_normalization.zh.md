# 测地状态归一化（Geodetic State Normalization）

> 适用对象：`4dTrajectory/optimization/casadi_direct_collocation_optimizer.py` 中的
> `*Normalized` 求解方案（`hermiteSimpsonNormalized` / `trapezoidalNormalized` /
> `rk4Normalized`），后端名 `casadiDirectCollocationNormalized*`，前端 Dynamics
> 选项 **“Geodetic RHS (normalized, robust)”**。

本文解释：**为什么测地动力学的直接配点会在某些问题上不收敛**，**什么是状态归一化**，
**几种归一化方案（直接缩放 2a / 2b 与"度量+重心化"方案 1）的区别**，以及
**为什么当前采用的方案 1 最稳健**。所有结论都附带可复现的实验数据。

---

## 0. 一句话结论

测地 NLP 把 **经纬度用弧度**当决策变量，与米级的高度、米/秒级的速度混在一起；位置导数里
的 `1/(R_M+h)` 因子使位置缺陷（defect）行比高度行小约 6–7 个数量级，**约束雅可比病态**，
IPOPT 在较难的问题上会耗尽迭代预算而失败。

把**位置改写成"距目标的米数"**（方案 1：度量化 + 重心化），动力学方程**完全不变**（在
缺陷内部精确重建真实经纬度），但决策变量与缺陷残差都变成米制、数量级一致，雅可比良态，
求解就稳健了。这是一个**精确的变量代换**，不改变物理、不改变最优解。

---

## 1. 背景：直接配点在解什么

直接配点把轨迹离散成一串**状态节点** `x_k` 和**控制段** `u_k`，并通过"缺陷方程"
（defect）逼迫相邻节点满足动力学：

```
defect_k = x_{k+1} - x_k - ∫ f(x,u) dt  == 0     (Hermite–Simpson / 梯形 / RK4)
```

IPOPT 求解的变量向量 `w = [u_0..u_{N-1}, x_1..x_{NM}, (T)]`。

测地方案的状态是

```
x = (lat, lon, h, V, ψ, γ)     —— lat/lon 用【弧度】
```

连续测地 RHS（`make_geodetic_dynamics_model`）的位置运动学是

```
lat_dot = V·cos(γ)·cos(ψ) / (R_M + h)
lon_dot = V·cos(γ)·sin(ψ) / ((R_N + h)·cos(lat))
h_dot   = V·sin(γ)
```

注意 `1/(R_M+h) ≈ 1/6.4e6`。

## 2. 病根：数值条件（Conditioning），不是初值

### 2.1 量级失衡

| 状态分量 | 典型值 | 典型导数 |
|---|---|---|
| lat, lon | ~0.6 / −1.4 **rad** | ~**1e-6** rad/s |
| h | ~1800 **m** | ~10 m/s |
| V | ~85 **m/s** | ~1 m/s² |
| ψ, γ | ~1 **rad** | ~0.01 rad/s |

缺陷残差 `x_{k+1}-x_k - …`：位置行是**弧度量级（~1e-6）**，高度行是**米量级**——同一个约束
向量里相差约 6 个数量级。

### 2.2 行内耦合（关键，常被忽略）

只看"行的量级差"还不够，真正难缠的是**同一行内**的展布。看 lat 缺陷行对各变量的偏导：

```
∂(lat 缺陷)/∂lat_k ≈ −1                        （自身项，O(1)）
∂(lat 缺陷)/∂V     ≈ (h/6)·cos γ cos ψ/(R_M+h) ≈ 1e-7   （耦合项）
```

**一行里就横跨了约 7 个数量级**。这个 `1e-7` 正是 `1/(R_M+h)` 带来的。约束雅可比因此严重
病态，IPOPT 的 KKT 线性系统求解、步长计算都受影响——在较难的问题上（长时间窗 + 较细网格）
直接 `Maximum_Iterations_Exceeded`。

### 2.3 实证：病根是条件数，不是初值

free-time 求解先用 `T=max_duration` 解一个固定时间 NLP 当种子，再缩 `T`。当用户把到达时间
设得远大于实际需要时（如 1000 s，而航段只要 ~250 s），种子是一条**巨大的盘旋圈**
（最小速度 × 1000 s ≈ 108 km 弧长，而 HEAVE→RW05L 直线只有 9.6 km）。

> 最初我们试过"把种子时域收紧"来回避——它确实能让症状消失，但那是**绕过现象、没治根**：
> **保持同一个过长种子不变**，只要把条件数修好，求解就能在 ~80 次迭代内收敛。所以根因是
> 条件数。（被弃用的种子方案见 git 历史与本仓 changelog。）

## 3. 归一化的统一框架

引入对角缩放 `c` 与偏移 `b`（都是 6 维向量），令优化变量 `z` 与物理状态 `x` 满足

```
x = b + c (.*) z          （逐分量；(.*) 表示逐元素相乘）
```

- 物理→优化：`z = (x − b) ./ c`
- 优化 RHS：`ż = f(x) ./ c = f(b + c.*z) ./ c`（`b` 为常数）

不同的 `(c, b)` 选择就是不同的归一化方案。**注意**：要让缺陷残差也变成良态，缺陷必须建立在
**缩放后的 RHS `ż`** 上（即把 RHS 输出也除以 `c`），而不仅仅是缩放变量——否则只动了雅可比的
"列"，没动"行内耦合"。

## 4. 三种方案对比

下面三种都属于"归一化"，但效果差别很大。

### 方案 2a：纯对角 O(1) 缩放（只缩 h、V）

```
c = (1, 1, 3000, 100, 1, 1),   b = (0,0,0,0,0,0)
```

把高度、速度缩到 O(1)；**经纬度仍是弧度**（弧度本身就 ~O(1)，所以"缩到 O(1)"对它们几乎没动）。

- **能改善**：把高度行的量级从 ~米拉到 O(1)，与角度行可比，缓解了"行的量级差"。
- **改不了**：位置那一行的 `1e-7` 耦合（`∂lat缺陷/∂V`）依旧在——因为弧度位置 + `1/(R+h)`
  没动。单一的"每变量一个缩放因子"**无法同时**平衡 lat 行的耦合又让 V 保持合理：要平衡
  lat 行需要 `s_V/s_lat ≈ 1e7`，但那会把 V 缩成 8e-6，毁掉 V 行。**行内展布是矩阵的结构属性，
  对角缩放保持每行的相对展布不变。**
- **后果**：在 HEAVE→RW05L 主失败例上能解，但**不稳健**——见 §6，它在 `N=5, md=250` 上
  和基线一样把固定时间种子误判为 `Infeasible`（假不可行）。

### 方案 2b：度量缩放但**不重心化**

```
c = (1/R, 1/(R·cos lat0), 1, 1, 1, 1),   b = (0,0,0,0,0,0)
```

位置缩成米制（`z_lat = lat·R`），但没有减去参考点。

- **能改善**：位置变成米制，缺陷残差也变米制，行内 `1/(R+h)` 被吸收，雅可比良态。
- **隐患（理论上的）**：`z_lat = lat·R ≈ 0.6 × 6.4e6 ≈ 4e6`，绝对值巨大。缺陷
  `z_lat_{k+1} − z_lat_k` 是两个 ~4e6 的数相减得到 ~几十米——理论上有"灾难性抵消"风险。
- **实测**：双精度有 ~16 位有效数字，4e6 相减 ~10 m 只丢约 6 位、还剩 ~10 位，**并不灾难**，
  所以 2b 实测能解。但它白白把变量放大到 4e6、毫无好处，**不优雅且边界更脆**。

> 教训：我曾断言 2a/2b "行不通"——**实测推翻了我**：三种都能解 HEAVE 主例。结论必须用实验
> 检验，不能只靠纸面推理。

### 方案 1：度量缩放 + 重心化（**当前采用**）

```
c = (1/R, 1/(R·cos lat_t), 1, 1, 1, 1)
b = (lat_t, lon_t, 0, 0, 0, 0)        —— 锚定在【目标点】
```

即把位置写成**距目标的米数**：

```
n = (lat − lat_t)·R                  （北向米；c_lat = 1/R）
e = (lon − lon_t)·R·cos(lat_t)       （东向米）
```

`h, V, ψ, γ` 不变（`c=1, b=0`）。

**为什么 1 优于 2a / 2b——三件好事同时成立：**

1. **变量米制**：`n, e` 是 O(km)，与高度同级——不是弧度 ~O(1)+导数 ~1e-6。
2. **缺陷残差米制**：`n_{k+1}-n_k-…` 以**米**计，与高度缺陷同级。
3. **行内耦合自动 O(1)**：归一化后位置导数变成

   ```
   ṅ = V·cos γ·cos ψ          ←  1/(R_M+h) 消失了！
   ```

   于是 `∂ṅ/∂V = cos γ cos ψ ≈ O(1)`，`∂(n缺陷)/∂n ≈ 1`——**整行都是 O(1)，无需任何额外缩放**。
   这是 2a 永远做不到的：2a 没改 `1/(R+h)`，行内耦合还是 1e-7。

4. **无大数抵消**：`b = 目标位置`，所以 `n, e ~ O(1e4) m`（航段跨度），不是 2b 的 4e6——
   相减干净。**重心化**正是 1 比 2b 多出来的那一步。

> 可以这样理解：**唯一能平衡 lat 行的对角因子就是"按 R 把位置缩成米"，但那样不重心化就会有
> 大数抵消（=2b 的隐患）；加上重心化把数值拉回 O(1e4)，就成了方案 1。所以方案 1 = 正确的缩放
> 因子 + 重心化，是 2 的"做对了的版本"。**

## 5. 关键：这是【精确变量代换】，不改物理

方案 1 与 `localEnu` 有本质区别：

| | 决策变量 | 动力学 RHS | 是否改物理 |
|---|---|---|---|
| `localEnu` | 弧度测地 | **平面切向** point-mass（固定切平面近似） | **改**（30 km 漂 ~335 m）|
| **方案 1（normalized）** | 米制（距目标） | **同一套精确测地 RHS** | **不改**（机器精度）|

实现上，缺陷里先把 `z` 精确重建回真实经纬度再喂给测地 RHS：

```
lat = lat_t + n / R
lon = lon_t + e / (R·cos lat_t)
xdot = f_geodetic(lat, lon, h, V, ψ, γ)      # 完全相同的 RHS
ż    = xdot ./ c                              # 把位置导数缩回米制
```

因为 `(n,e) ↔ (lat,lon)` 是**仿射（线性）映射**，且 `c`、`lat_t` 是常数，所以这只是把 IPOPT
优化的"数字"换了刻度，**向量场一模一样**。结论：

- **不改变动力学**——前向积分归一化坐标系，与直接积分测地 RHS 逐点一致（见 §7 的 Compare 验证）。
- **不改变最优解/目标**——在测地方案也能解的良性问题上，归一化方案给出**完全相同**的轨迹
  （相同到达时间、相同终端状态）。这一点由单元测试
  `test_normalized_scheme_matches_plain_geodetic_on_a_benign_problem` 守护。

## 6. 实验数据（可复现）

测试问题：KRDU **H05LZ HEAVE → RW05L**（约 180° 转弯 + ~1700 m 下降，直线跨度 ~9.6 km），
A320，几何 RHS Hermite–Simpson。

**单例（N=10, md=1000 s）**：

| 方案 | 结果 | 迭代 |
|---|---|---|
| baseline（弧度测地） | **FAIL** `Maximum_Iterations_Exceeded` | 3000 |
| 方案 1（米制+重心化） | OK | 83 |
| 方案 2a（对角 h,V） | OK | 77 |
| 方案 2b（米制无重心化） | OK | 80 |

→ 三种归一化都能解主失败例；**我"2 行不通"的预判被实测推翻**。

**稳健性扫描（N × 到达时间窗）**：

| 用例 | baseline | 方案 1 | 方案 2a |
|---|---|---|---|
| N=10 md=250 | OK 40 | OK 67 | OK 29 |
| N=10 md=500 | OK 266 | OK 90 | OK 43 |
| N=10 md=1000 | **FAIL 3000** | OK 83 | OK 77 |
| N=5 md=250 | **冷启动 Infeasible** | OK 43 | **冷启动 Infeasible** |
| N=5 md=500 | OK 46 | OK 63 | OK 28 |
| N=5 md=1000 | OK 132 | OK 38 | OK 127 |

**决定性用例 `N=5, md=250`**：baseline 和 2a 都把固定时间冷启动种子误判为 `Infeasible`
（**假不可行**——方案 1 证明它可行）。2a 失败是因为它**留着弧度经纬度**；只有把**位置变量本身
变成米制**（方案 1）才把冷启动也调理到能找到解。

**结论**：三种都能解主例，但只有**方案 1 六例全过**（baseline 4/6，2a 5/6），迭代数稳定在
38–90，因此选方案 1。

锚点用**起点**还是**目标**都一样稳健（最难两例：N=10/1000 → 83 vs 89；N=5/250 → 43 vs 42），
代码里锚定**目标**以复用 `localEnu` 已有的 `target_state` 参数管线。

## 7. 如何在 Compare 模式里验证"不改动力学"

`*Normalized` 是**优化器 NLP 的坐标代换**，不是新的动力学模型。要直观确认它不改物理，可在
**Pilot 的 Dynamics Compare 模式**里把它作为一个系统一起前向积分：归一化系统在**米制坐标**里
对**同一套测地 RHS**做 RK4，再换回测地坐标。因为是精确仿射代换，它会与几何 RHS 系统（C）
**逐点重合到机器精度**（误差 < 1 mm，即 ~1e-9 量级）——这就证明归一化既不改**动力学**、也不改
**目标**。

> 实现见 `dynamics_comparison.py` 的归一化系统与 Compare 后端/前端；该系统对 B（再锚定参考）的
> 误差与 C 相同（亚毫米），对 C 的误差 ~0。
