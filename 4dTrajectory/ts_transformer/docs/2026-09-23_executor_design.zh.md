# 执行器设计（2026-09-23）

**一句话**：执行器是一个只按动力学飞词的自动驾驶。给它此刻生效的六列词、飞机的当前状态和候选跑道的几何，
它算出推力、坡度、载荷因子，交给现有的点质量动力学积分，得到下一时刻的状态。它不读任何程序数据。

词的定义见[指令词表](2026-09-23_instruction_vocabulary_design.zh.md)（已冻结，规格 `08ad64abb53e`），
总体框架见[两层模型框架](2026-09-23_two_tier_framework.zh.md)（本文是阶段 3，回放门是阶段 4）。

## 1 执行器是什么，不是什么

**输入**（每个控制周期）：

- 飞机状态：位置、高度、速度、航迹、爬升率、质量（动力学自己的状态）；
- 此刻生效的六列词：跑道指针、进近、航向、高度、下降角、速度（词表 §2）；
- 候选跑道的几何：入口位置、真航向、高程（与标注器同一份，产物的 `candidates.json`）；
- 本机性能：机型的动力学参数（与 ts 控制路径同一套：`aero_params`、最大推力）和该机型公开的进近速度（§3.4）。

**输出**：这个控制周期的指令（推力比例、坡度、载荷因子），积分后的新状态，以及执行器自己的模式
（在飞航向 / 已截获航线 / 下降中 / 已改平 ……）和饱和记录。

**不是什么**：

- 不读程序：没有 FAF、下滑道、CIFP 航段、高度限制。航线只来自跑道几何（入口 + 真航向）。
- 没有风：动力学里没有风，词是地面航迹和地速，执行器飞的就是它们。
- 不学习：全是写死的控制律。可调的只有 §5 列出的几个参数，它们在 train 上定、在 val 上判。
- 确定性：同一句话、同一个初态，飞出同一条轨迹。

## 2 放在哪

新包 `4dTrajectory/ts_transformer/autopilot/`（框架文档 §2）：

```text
autopilot/
  frames.py      动力学状态 ↔ 机场坐标系；每架航班的候选跑道换算到它自己的动力学坐标里
  schedule.py    句子 → 每个控制周期生效的六列词（张量，整批航班）
  lateral.py     航向词：转弯与保持；许可加入：在容差内朝航线修正、截获、沿线飞
  vertical.py    高度 + 下降角：按角度下降/爬升、截获目标高度、保持、下降至落地
  speed.py       速度词：跟踪目标地速；"未指定"：本机型的进近速度
  hook.py        以上三者拼成一个 command hook（`outputs/dynamics/hooks.CommandHook`）
  events.py      截获、落地、失败的判定与记录
  replay.py      真值句子 → 整批回放（阶段 4 的门用它）
```

- **动力学用现有的**：执行器实现成一个 command hook，交给 `outputs/dynamics/rollout` 积分。所以它飞的是
  ts 控制路径同一套点质量方程、同一套机型参数、同一个控制量的界（`outputs/envelope`）、同一个失速下限
  （`outputs/constraints/speed_floor`，裕度 1.10）。动力学配置取控制路径现行配方 `simple-v3` 的那一对：
  `point-mass` + `scaled-transport-chart-velocity`，推力按 `thrust-fraction`（§9 第 1 项）。
  `outputs/guidance/PlanGuidance` 就是这样一个 hook（按规则飞它自己的航线），执行器与它并列，互不 import。
- **依赖方向**：`autopilot/` → `instructions/`（词、包络、几何）、`outputs/dynamics`、`outputs/envelope`、
  `outputs/constraints/speed_floor`；不依赖 `prior/`，`instructions/` 也不依赖它。
- **坐标**：动力学状态在"以本机着陆跑道入口为原点"的东北天坐标里（`RolloutStateView.chart`）。每架航班的
  候选跑道在开飞前一次换算到这个坐标里（经纬度中转），此后执行器只在这个坐标里算。输出时再换回机场坐标系，
  和信号、句子逐行对齐。

## 3 每类词怎么飞

控制周期 1 s（§9 第 5 项）：每个周期开头读一次状态和生效的词，算出指令，保持 1 s。词在 2 s 网格上生效，
第 r 行的词从 2r 秒那个周期起生效。标注器把词的发令时刻放在动作开始的那一行（转弯开始、下降开始、减速
开始），所以执行器一收到词就立即开始动作，不加反应延迟。

### 3.1 航向词：按较短方向转到 θ 并保持

```text
Δ = wrap180(θ − ψ)                       ψ 为当前地面航迹；较短方向由 wrap180 决定
r = clip(Δ / τ_ψ, ±r_max(V))             期望转弯角速度
φ = atan(V · r / g)，|φ| ≤ φ_turn         协调转弯的坡度
```

- `φ_turn` 是执行器的转弯坡度上限，取数据里转弯的典型值：转角 ≥ 30° 的转弯各自最大坡度的中位数 **24°**
  （train，p25 19°、p75 27°）。它在词表的坡度范围 4°–32° 之内。
- `τ_ψ` 决定小修正有多"软"：大转弯被 `φ_turn` 限住，小修正的坡度约为 `V·Δ/(g·τ_ψ)`。建议 8 s，在 train 上
  定（§5）。
- 大转弯拆成的几条词、盘旋都不需要特殊处理：每条词都是绝对航向且转角 ≤ 150° + 容差，较短方向就是标注器读出的
  方向；续发的那条在飞机还在转时到达，转弯不会中途改平。

### 3.2 许可加入：截获所指跑道的延长中线并沿线飞

执行器有一个自己的状态"已截获"（词表 §2.2：截获是执行器的状态，不是一个词）。

1. **许可之前**：只飞航向词，飞过延长中线也不截获。
2. **许可之后、截获之前**：飞航向词；如果按名义航向 θ 在入口之前碰不到航线，而 θ 的容差 ± 4.5° 之内有一个
   航向碰得到（`instructions.envelope.heading_converges`，与标注器同一个判断），就朝航线偏 4.5° 飞。这就是
   词表 §6 第 5 条的要求：标注器判"收敛"时允许了容差，执行器截获时也用同一个判断。
3. **开始截获**：离航线的横向距离 ≤ 转弯提前量 `R·(1 − cos Δχ)` 时开始转（Δχ 为航迹与跑道航向之差，
   `R = V² / (g·tan φ_turn)`），或者已经在截获走廊的宽度之内。
4. **截获之后**：沿延长中线飞，用 L1 路径跟踪律：瞄准航线上前方 `L1 = max(V·T_L1, L_min)` 处的点，横向加速度
   `a = 2 V² sin η / L1`（η 是速度方向与视线的夹角），坡度 `atan(a/g)`，不超过 `φ_turn`。这与
   `outputs/guidance/PlanGuidance` 跟航线用的律相同；实现时把它抽成两者之下的一个共用函数，不复制公式，
   执行器与 PlanGuidance 仍然互不 import。
5. **跑道指针**：航线是指针所指的那条候选跑道的。许可之前换指针，就换航线；许可之后换指针在标注里已被拒绝
   （词表 §2.1 的相容规则），执行器也拒绝。

### 3.3 高度与下降角

| 生效的词 | 执行器 |
|---|---|
| 目标 T + 平飞 | 保持 T |
| 目标 T + 下降档 k | 按该档的名义角度 γ_k 下降；接近 T 时截获，改平并保持 T |
| 目标 T + 爬升 | 按爬升的名义角度 1.22° 爬升；接近 T 时截获，改平 |
| 下降至落地 + 下降档 k | 按 γ_k 一直下降到落地判定，不改平 |

- 名义角度就是规格里各类的中心：下降 0.91°、2.12°、3.06°、4.41°，爬升 1.22°。下降途中换角度词，就换 γ。
- **截获目标高度**：`|h − T| ≤ V·|sin γ|·τ_h` 时转入高度保持；保持律 `γ_c = clip((T − h)/(V·τ_h), ±γ_max)`。
  τ_h 建议 12 s（与 PlanGuidance 的高度增益同值）。
- **从航迹角到载荷因子**（`thrust-fraction` 配方的第三个控制量）：
  `n = [cos γ_c + (V/g)·(γ_c − γ)/τ_γ] / cos φ`，限在执行器自己的范围 0.7–1.5 之内（在可飞包线
  0.5–2.0 之内留出余量）。τ_γ 建议 3 s。
- 方向与目标矛盾的组合不会出现：标注器的相容规则已经排除，执行器遇到时拒绝（说明句子不是这份词表写的）。

### 3.4 速度

- **目标地速 V**：`V̇_c = clip((V − v)/τ_V, −a_nom, +a_nom)`，推力由 `V̇ = (T − D)/m − g·sin γ` 反解：
  `T = m·(V̇_c + g·sin γ) + D`，换成推力比例，限在控制量的界里。`a_nom` 取数据里速度过渡段的典型斜率（在 train
  上量，§5），并且不超过词表的上限 1.7 m/s²。没有风，地速 = 速度 × cos γ，执行器直接按地速跟踪。
- **"未指定"**：飞行员按本机型自己减速。执行器的目标是**本机型公开的进近速度**（没有识别出机型的航班没有这个值，
  不回放，§6）：`aircraft/reference_speeds`
  （FAA 飞机特性数据库的进近速度，按最大着陆重量给出，每个数都有出处），按本机质量换算
  `V_app(m) = V_pub·√(m / MALW)`，再从指示空速换成真空速 `V_app·√(ρ0/ρ(h))`（ISA，无风时就是地速）。
  以 `a_nom` 从当前速度向它变化。机型取**本机真实的识别结果**（scenario 的 `resolved_typecode`），不取动力学
  替代机型。
- 失速下限照旧：速度不低于 1.10 倍失速速度，由现有的 `speed_floor` 通过推力保证；压到下限的步数计数。

### 3.5 复飞

进近列 = 复飞：取消许可和"已截获"，横向保持所指跑道的航向，纵向按爬升类爬升到生效的高度目标，速度保持
当前值。训练数据里没有复飞，这一条只有单元测试，回放门不涉及。

### 3.6 落地与失败

| 结果 | 判定 |
|---|---|
| **落地** | 已许可、已截获，并沿航道越过所指跑道入口，离中线不超过 100 m（与标注器的落地判定相同） |
| 没截获就越过入口 | 越过入口时还没截获（或没有许可） |
| 落地前过低 | 在入口之前，高度低于入口高程 |
| 超时 | 飞了观测时长的 1.5 倍还没落地 |

失速下限、坡度上限、推力饱和不是失败，是计数：每架报出它们各占多少步（与 PlanGuidance 的诊断同一套写法）。

## 4 包络：执行器自己也要在盒子里

- 执行器的界都在词表的包络之内：坡度 ≤ 24° < 32°；加速度 ≤ `a_nom` ≤ 1.7 m/s²；下降角取类的中心，
  在类的范围之内。
- 飞完之后，用**标注器的同一套检查**判执行器自己的航迹：航向词的转弯单调与坡度、截获转弯、高度词的管子
  （`vertical.tube_bounds`，从执行器自己的发令点起算）、速度词的带。执行器的航迹不在自己收到的词的包络里，
  说明执行器或动力学有问题（例如一边减速一边按 4.41° 下降时推力不够），这要单独报出，不能混进"与观测的误差"。

## 5 参数

| 参数 | 值 | 来源 |
|---|---|---|
| 控制周期 | 1 s | 选定（§9 第 5 项） |
| 转弯坡度上限 φ_turn | 24° | 量出：转角 ≥ 30° 的转弯最大坡度的中位数（train） |
| 航向时间常数 τ_ψ | 8 s（候选 5 / 8 / 12） | 在 train 的回放上定 |
| L1 前视 T_L1 / 最短 L_min | 8 s / 500 m | 与 PlanGuidance 相同 |
| 航迹角时间常数 τ_γ | 3 s | 选定 |
| 高度截获与保持 τ_h | 12 s | 与 PlanGuidance 相同 |
| 载荷因子范围 | 0.7–1.5 | 与 PlanGuidance 相同（可飞包线 0.5–2.0 之内） |
| 速度时间常数 τ_V | 10 s | 选定 |
| 名义加速度 a_nom | 待量 | 量出：速度过渡段斜率绝对值的中位数（train），不超过 1.7 m/s² |
| "未指定"的目标 | 本机型公开进近速度，按质量与密度换算 | `aircraft/reference_speeds` |
| 失速裕度 | 1.10 | 包里现有的值 |

**定参数的顺序**：量出的先量；三个候选值的参数（τ_ψ）只在 train 的一个固定抽样上比较，按 §6 的指标选，
选定后写进一份执行器规格（和词表规格一样带 sha），**val 只用来判门，不用来调**。

## 6 回放门（阶段 4）

**问题**：把真值句子交给执行器，它能不能把飞机飞到所指跑道上。

- **输入**：产物里每一架已标注的航班。初态 = 信号第 0 行（位置、高度、航迹、地速、爬升率）加上数据平面给这架
  航班的质量和机型参数；词 = 这架航班的句子，逐行生效；句子最后一行之后词保持不变，直到落地或失败。
- **人群**：val 全部，按机型的动力学分三组（val 的 10,625 架里量过，逐架按 icao24 识别）：

  | 组 | 架次 | 说明 |
  |---|---|---|
  | 有自己的动力学 | 7,806（73.5 %） | 识别出的机型在 OpenAP 或预设里有参数；**只有这一组进门** |
  | 动力学用 A320 代替 | 2,469（23.2 %） | 识别出了机型，但它没有动力学参数，数据平面用了 A320（`aircraft_fallback_used`）。最多的是 BCS3 403、P28A 305、CRJ7 191、E55P 170、BCS1 127 |
  | 没有识别出机型 | 350（3.3 %） | 也用 A320 飞；没有机型就没有公开进近速度，"未指定"段无法飞，不回放 |

  分机场差别很大：KRDU 34 % 用 A320 代替（P28A 教练机最多），KSJC 26 %，KSTL 17 %，KMSY 15 %，KSMF 6 %。
  用 A320 的气动去飞 P28A 的进近速度会被失速下限顶住，量出来的是替代机型的误差，不是执行器的，所以第二组只报
  不判（§9 第 2 项）。这个缺口不只影响执行器：ts 的控制路径也用同一套动力学参数。
- **门**（每个机场分开报，直线进近 / 雷达引导分开报）：
  1. **落地率** ≥ 95 %：按 §3.6 落在所指跑道上；
  2. **执行器自检** ≥ 95 %：执行器自己的航迹在它收到的词的包络里（§4）的词的比例。
- **与观测的差别**（报出，不设门）：
  - 落地时刻之差（执行器 − 观测）；
  - 按时间对齐的位置误差 ADE / FDE，和按路径对齐的误差（chamfer、Fréchet，与 ts 的读数同一套：只看时间对齐的数会
    把节奏误差读成路径误差）；
  - 每条词发令时刻的横向、垂直、速度误差（词把航迹钉住的地方）；
  - 失败的分类（§3.6）与饱和计数。
- 门没过，先看失败分类，再决定改执行器还是回头看词表；不在 val 上调参数。

## 7 与后面阶段的接口

- **先验（阶段 5）**：生成时，先验每 2 s 读一次执行器的状态，说下一步的六列词。执行器每 2 s 在机场坐标系里
  给出与信号同一套量（E、N、MSL 高度、航迹、地速、垂直速率，以及到每条候选跑道的相对量），所以先验在训练时读
  信号、生成时读执行器，读的是同一种东西。
- **整批、可在 GPU 上跑**：hook 按批计算（[航班数] 的张量），回放 1 万架航班、每架几百个控制周期，一次积分完成。
- **闭环（阶段 6）**：执行器不可学习；闭环再训只训先验，执行器当作环境。

## 9 需要确认的六项

1. **动力学配置**：用控制路径现行配方 `simple-v3` 那一对（点质量 + `scaled-transport-chart-velocity`，推力比例）。
   另一个选择是一阶滞后模型（执行机构有惯性，转弯滚转更像真的），代价是多三个时间常数。建议先用点质量，
   回放门显示转弯时机有系统误差时再换。
2. **用 A320 代替的航班不进门，单独报**：val 的 23.2 %（KRDU 34 %）。建议如此；另一个选择是把它们也算进门，但那时
   的误差说的是 A320 气动，不是执行器。**更根本的办法是补机型的动力学覆盖**（例如 BCS1/BCS3、CRJ7、E55P 用相近机型
   的参数，P28A、C208、PC12 这类用轻型机的预设），但那是 `aircraft/` 与 `flight_scenarios` 的改动，会改变 ts 所有
   数据集的动力学，需要你单独决定；主工作区里正有人在改 `aircraft/` 的机型识别。
3. **"未指定"的速度来源**：用公开的进近速度（有出处，不是从要判的数据里拟合的）。另一个选择是从 train 上量每个
   机型最后几公里的速度，更贴近数据，但门就部分地在判它自己拟合过的东西。建议用公开值。
4. **门的两条线**：落地率 ≥ 95 %，执行器自检 ≥ 95 %，都是每个机场分开看；与观测的误差只报不判。
5. **控制周期 1 s**（每个 2 s 的词步里两次）。2 s 也能飞，但转弯和高度截获的离散误差会大一些。
6. **转弯坡度 24° 取自数据的中位数**；τ_ψ 在 train 上从 5 / 8 / 12 s 里选，val 不参与。
