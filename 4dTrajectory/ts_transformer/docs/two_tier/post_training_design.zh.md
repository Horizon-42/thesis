# 后训练设计（两层模型：先验说词，执行器飞）

**一句话**：预训练让先验学会"管制员在这种情况下一般说什么"（teacher forcing）。后训练让先验自己说词、执行器照着飞，只看飞出来的
结局来改先验：落地了就加强这句话，没落地就减弱；同时把会让飞机违反程序高度的词先屏蔽掉——FAF 以内低于 LPV 下滑道的下沿、切入前低于
决断高度、切入前跌破入口高度之后再爬升——飞出来的航迹再查一遍。

## 1 后训练做什么，按什么顺序

1. **按落地强化（单机，§2）**：先验自由地说，执行器飞到结局；同一架航班说几句，落地的相对没落地的得到加强。带一个把模型拉回
   起点的项和 teacher forcing 数据项。
2. **程序高度作硬约束 + 起始状态扩充（单机，§3–§5）**：
   - 从训练集航班的起始状态出发，加一点随机变化，得到"情况相似、但不在训练集里"的起始状态；靠终点奖励、拉回 base 模型的项和
     第一阶段那样的数据项来训练，提高没见过的情况下的落地能力（用户 2026-09-25；数据项用户 2026-09-26 加回）。
   - 为了不让模型完全自由发挥，程序高度作为硬约束，做成屏蔽：最后进近段 LPV 下滑道的下沿（用户 2026-09-25，参考优化器的做法），
     切入前的决断高度和"跌破入口高度之后不爬升"（用户 2026-09-26）——说出来会违反它们的词不许说。屏蔽照顾不到的，由飞出来的航迹再查
     一遍，违反下滑道下沿的这架就算失败（§3.5）。RNAV 在 FAF 以外的高度限制和 MVA 原本也要做，在标注数据上量过之后不做（§7、§3.7）。
   - 每轮一半是真实起点（第一阶段那样），一半是扩充起点（用户 2026-09-26）。
3. **间隔作为生成时的筛选和屏蔽（多机，先验设计 §9 第 5 步）**：不作损失。门槛取规章的最小间隔（FAA JO 7110.65 的雷达间隔和尾流
   间隔，原文在 `docs/literature/arrival_separation/`），并以记录数据里本来就有的低于最小间隔的比例作参照——比数据"更安全"就离开了
   数据。屏蔽要在同一步里按顺序（例如按落地顺序，前机先说）算，才能看到别的飞机这一步选了什么；预训练仍是各架同时说。
4. **多机的强化**：奖励用间隔与落地，拉回项同第 1、2 项；不用只有间隔的奖励。

**各阶段共同的规矩**：

- 闭环就是先验设计 §9.1 的单机自由生成：每架航班的前 `N_look` = 8 行用观测的位置，执行器从第 8 行的观测状态起飞；先验每 2 s
  按"跑道 → 进近 → 航向 → 高度 → 下降角 → 速度"的顺序逐列采样，带词表的相容规则屏蔽和跑道锁；执行器飞到判定结束。
- 训练只用训练集运行日；选轮用内部选择集运行日；验证集每个阶段只在定稿后读一次；**测试集运行日一架都不读**。
- 每个阶段的门先只记录（与先验设计 §9.1 相同），不设通过线。

## 2 第一阶段：按落地强化（单机）

- **为什么**：让先验自由地说，只看结局——落地了，就提高这句话里各个词的概率；没落地，就降低。这正对准"说到飞机落地"这个目标，
  也不需要回答"闭环轨迹偏开之后标注此刻该说什么"（CAT-K 就败在这里，§6）。信号是现成的：验证集自由生成里，每架航班说 4 句，
  591 架（30 %）是有的落地、有的没落地（读数文档 §5.2）。
- **起点**：base 模型。
- **每一轮**：
  1. **自由生成**：从训练集运行日抽航班（有自己动力学的，与回放门同一组），每架从第 `N_look` 行的观测状态起飞，先验说 `K` 句
     （温度 1，与先验设计 §9.1 完全相同的屏蔽与跑道锁），执行器照着飞到判定结束。
  2. **奖励**：落地（执行器判定的 `landed`）并且落在"机场此刻的落地方向"上的跑道，得 1；其余结局（超时、偏出跑道、未截获、
     触地、动力学失败，或落在反方向的跑道上）得 0。**机场此刻的落地方向**：第一个预测步之前 30 分钟里有落地的跑道（与输入里的
     落地情况同一来源，去掉本机自己的落地、去掉测试日），与其中任何一条航向相差小于 90° 的跑道都算；这 30 分钟里没有落地时，
     任何跑道都算。不要求落在观测的那条跑道上——那是数据项的事。
  3. **同一架航班的几句互相比**（GRPO 的做法；R1Sim 在 CAT-K 之上用过，`docs/literature/trajectory_as_language/` C3）：每句的
     "优势" = 它的奖励 − 同一架航班 `K` 句奖励的平均。全部落地或全部没落地的航班，优势都是 0，不参与更新——只在有对比的航班
     上学，本来就会落地的航班不被推向更确定。
  4. **损失**，三项相加：
     - **奖励项**（截断的比，PPO / GRPO 的做法，2026-09-26 加）：这句话每一步六列所说的每个词（含"不变"）取
       −min(r · 优势, clip(r, 1 − ε, 1 + ε) · 优势)，r = 现在的模型给这个词的概率 ÷ 这一遍开始时（采这些句子的那个模型，冻结一份）给的概率，
       ε = 0.2；一句里求和，除以这句的步数。一遍开始时 r = 1，第一次更新与"− 优势 × 对数概率"逐位相同；之后一个词的概率在一遍里朝优势的
       方向变了 20 % 以上，它就不再推（读数文档 §15：不截断时，没落地的句子把几乎每步都采到的"不变"一路往下压，压得越低推得越狠，一遍
       之内离 base 冲出去；截断后一直平，只有 0.1 % 的词被截断）。一句话里所有步用同一个优势（分不清是哪一步说错了，这是这种做法的代价，
       靠句数平均掉）。概率用模型不加屏蔽的分布（屏蔽掉的概率每步只有约 0.06 %，读数文档 §5；第二阶段按屏蔽后的分布，§5），训练时关掉
       dropout（模型内部的随机屏蔽）：打分用的就是采样时的那个分布，拉回项量的是权重变了多少，不是 dropout 的噪声（第一次更新时它正好是 0）。
       landing 是在截断之前训出的（当时的奖励项是"− 优势 × 对数概率之和"）；
     - **拉回项**：β × 这句话上，模型与 base 模型（就是起点）的差异（按采到的词估计的 KL 散度，GRPO 的做法）——防止为了落地离开原来的说法；
     - **数据项**：λ × 训练集运行日的 teacher forcing 负对数似然（与预训练相同的损失，每次更新配一批）——防止忘掉真实的说法。
  5. 每轮在这一轮的句子上过一遍（只用当前模型生成的句子，不累积：奖励项要求句子来自正在训练的模型）。
- **选哪一轮**：每轮之后在内部选择集上自由生成（每机场 200 架 × 2 句，每 64 架一批，每轮同一批航班、同一个种子；第 0 轮因此与
  CAT-K 的第 0 轮逐位相同），先排除"护栏"变差的轮：落地在观测跑道上的比例比起点低 2 个百分点以上，或每架的航向词数比起点多 20 %
  以上；剩下的里面落地率最高的一轮胜出，差 1.5 个百分点以内取更早的。同时列出 teacher forcing 下选择集每步的负对数似然、落地时刻
  与观测之差、落在反方向跑道的比例。
- **验证集**：选定的那一轮只读一次（每机场 400 架 × 4 句，与先验设计 §9.1 的验证集读数同一批航班、同一个种子），与 base 模型在同一
  代码上的验证集重读（读数文档 §6）并排。
- **不做的**：不用落在观测跑道上作奖励（那会把"强化落地"变回模仿）；不加间隔项（单机没有别的飞机，到多机时再加）；不用价值网络
  （奖励只有句末一个，同组比较已经给出基线）。
- **代码**：runner `experiments/prior_landing_reward.py`（runners R19），奖励 `prior/landing_reward.py`，训练 `prior/train.py`
  `RewardTuner`。

## 3 第二阶段（一）：程序高度作硬约束

### 3.1 为什么是屏蔽，而且是硬的

- 用户的规矩：从程序算出来的航迹不能当模型的答案（不当目标、不当奖励）。屏蔽不告诉模型该说什么，只把"说了就会让飞机违反程序高度"
  的词拿掉，剩下的仍由模型自己选——它是可行性，不是答案。词表设计 §5.1 本来就规定程序规则"只做屏蔽和评估"。本阶段屏蔽三条
  （§3.3）：FAF 以内不低于 LPV 下滑道的下沿（用户 2026-09-25，参考优化器的做法）；切入前不低于跑道的决断高度；切入前跌破入口高度之后
  不许再爬升（用户 2026-09-26）。跌破入口高度本身不罚——记录里 13.5 % 的真实航迹切入前低于入口高度 40 m 以上；不许的是"降下去再
  爬回来"，记录里 0.7 % 的航班这样飞（读数文档 §14）。RNAV 进近在 FAF 以外编码的高度限制和 MVA 都不屏蔽（§7、§3.7：记录里分别有
  10–14 % 和 28.5 % 的真实航迹不满足）。
- 文献（`docs/literature/procedure_hard_constraints/notes_B.md` §2.2、§7）：每一步把"安全的动作集合"交给学习者的做法叫前置屏蔽
  （Alshiekh 2018）；屏蔽在训练和使用时都要开着——只在使用时开，模型没见过屏蔽把它带进去的状态（Geiger & Straehle 2022）；训练和
  使用都开时，最宽松的正确屏蔽不损失性能（Oh & Fisac）。所以本阶段的训练、选轮、验证集读数都开着屏蔽，以后用这个模型时也开着——由模型目录里的 `procedure_masks.json` 保证：本阶段的 runner 在每一轮的目录里写下 `procedure-altitudes-v2`，打开模型时一起读出，说话时默认就用它（先验设计 §5.1）。
- 屏蔽只看"此刻说这个词会怎样"，照顾不到以后的所有情形。照顾不到的，由飞出来的航迹再查一遍（§3.5）：违反了这架就算失败，奖励为 0
  ——这就是用户说的"屏蔽不行时作为奖励的一部分"，只用在屏蔽之后剩下的情形上。

### 3.2 约束从哪来

- **下滑道**：入口高程 + 入口跨越高度 TCH + d · tan(下滑角)，d 是沿航道到入口的距离；TCH 与下滑角是这条跑道公布的（harvest 的跑道
  数据，执行器和 evaluation 读的同一份，执行器设计 §5.2，`autopilot/runway_data.py`）。23 条跑道公布的是 LPV，KRDU 32（3.5°）与 KSMF 35R
  公布的是 LNAV/VNAV，垂直路径是同一种，evaluation 也按同一种判（evaluation EV2），这里同样处理。
- **下沿**：下滑道以下 60 m，即优化器的下沿 `DEFAULT_GLIDEPATH_BELOW_M`（`optimization/approach_constraints/segments.py`；4dTrajectory
  索引 K7：下滑道窗口只在 FAF 以内约束）。ts 包不能导入优化器的包，常数照抄并注明"必须一致"，由测试核对。
- **FAF 以内的扇形**：FAF 以内（0 ≤ d ≤ d_FAF）并且在 LPV 扇形里。FAF 是 FAA CIFP 编码的 RNAV(GPS) 进近的 FAF（前端的
  `procedure-details/<uid>.json`，读取器 `flight_scenarios.procedure_final.procedure_skeleton`，仓库根目录），离入口 7.7–15.1 km；
  25 条候选跑道都有这份文件，文件的入口与候选跑道的入口相差 ≤ 0.2 m（超过 150 m 就拒绝，与优化器相同）。LPV 扇形是
  `flight_scenarios/fas_geometry.py`（FAA Order 8260.58D Formula 3-1-1，用这条跑道的长度）：入口处半宽 107 m，10 km 处约 400–460 m（随跑道长度）。
- **切入**：飞机第一次进入这条跑道 FAF 以内扇形的那一行；在它之前叫"切入前"。按此刻生效的跑道算（换了跑道，就按新跑道的扇形重新看）。
- **入口高度**：下滑道在 FAF 处的高度 = 入口高程 + TCH + d_FAF · tan(下滑角)。
- **决断高度 DA**：跑道公布的决断高度（23 条 LPV、KRDU 32 与 KSMF 35R 的 LNAV/VNAV），进近图上的数，按入口存在
  `trajectory_data_process/config/runway_thresholds.json`（`published_minima`），读取器 `Runway.decision_height_above_threshold_m`
  （仓库根目录 `trajectory_data_process/harvest/airports.py`，已换算成入口以上的米数）；多数在接地带上方 61 m，最高 125 m。它是飞行员决定
  落地还是复飞的高度：切入前的飞机不该比它低。
- **气压高度与几何高度**：LPV 的下滑道由卫星导航给出，是几何路径，和我们的几何 MSL 高度直接可比（我的读法）；两条 LNAV/VNAV 跑道
  用气压垂直导航，与几何高度的差约为"离机场的高度 × 当天气温偏差 / 273"（词表设计 §2.4），FAF 附近气温偏差 ±20 K 时约 ±40 m。
  仓库里的 METAR 只有风（`data/metar/`），这一版直接比较，差别由容差吸收，并在标注数据上量（§3.6）。

### 3.3 三条约束

对这一步生效的跑道（这一步跑道列采样之后），设 d = 沿该跑道航道到入口的距离（入口前为正），xt = 离延长中线的横向距离，h = 飞机此刻
的高度：

1. **下滑道下沿**：在 FAF 以内的扇形里，高度不低于 下滑道高度(d) − 60 m；
2. **决断高度**：切入前，高度不低于 DA；
3. **跌破之后不爬升**：切入前，飞机到此刻为止有一行（含前 8 行观测）低于 入口高度 − 15 m，并且此刻生效的许可不是复飞，那么从此刻到
   切入不再爬升。

其他地方没有下限：FAF 以内但在扇形以外、切入之后的扇形以外，都不约束（雷达引导的空域管 MVA，§3.7）。

KRDU 05L 的例子：FAF（WEPAS）离入口 10.3 km，那里下滑道高 671 m——这就是入口高度——下沿 611 m；离入口 3 km 处下滑道高 287 m，下沿 227 m；
DA 182 m。一架切入前在 640 m 平飞的飞机（低于 671 − 15 = 656 m）从此不许再爬升，高度词只能在 [DA − 15, 此刻高度 + 15] = [167, 655] m 里选。

### 3.4 屏蔽规则（每一步，跑道列与许可列采样之后）

词的容差都是 15 m（半档：让含有界限的那一档仍可说）。

1. **FAF 以内扇形里的高度词 T**：只许 `T ≥ 下沿 − 15 m`。为什么够：执行器下降中和到达后都不低于 T − ε（ε = 25 m，词表设计 §2.4、
   §2.5）；下滑道朝跑道只降不升，所以此刻合法的 T，飞机沿航道往跑道飞时一直合法。
2. **"下降至落地"**：飞机此刻已经在扇形里、并且低于下沿 − 15 m 时不许说（先说一个不低于下沿的高度，爬回来）。不做"从此刻到入口的直线
   够不够高"的预判：选择集上它会屏蔽 4.2 % 的标注词，而那些飞机实际并没有低于下沿（读数文档 §8）。
3. **切入前的高度词 T**：只许 `T ≥ DA − 15 m`。
4. **跌破之后**（§3.3 第 3 条成立时）：高度词只许 `T ≤ h + 15 m`；下降角列不许说"爬升"档。"下降至落地"不受这条限制：执行器在下滑道
   延长线的下沿以下时平飞等它，不爬升（执行器设计 §5.3.2 第 5 步）。
5. **高度列的"不变"**：生效的那个词在此刻已经不满足第 1–4 条里适用的任何一条（例如进入扇形时生效的目标低于那里的下沿，或跌破之后
   生效的目标比飞机高 15 m 以上），就屏蔽"不变"，先验这一步必须说一个新的高度词。第一个预测步本来就屏蔽"不变"。下降角列的"不变"不加
   屏蔽：生效的是"爬升"档而目标已不高于 h + 15 m 时，飞机最多再爬 15 m。
6. 其他列：只有词表原来的相容规则，不加新的屏蔽。
7. 屏蔽之前模型放在被屏蔽的词上的概率照样记下（与先验设计 §9.1 记录相容规则屏蔽的做法相同，按列记）：看它自己学会了多少，也看它是不是
   越来越依赖屏蔽。

**总有词可说**：第 3、4 条同时生效而飞机低于 DA − 30 m 时，没有平飞高度可选；这时"下降至落地"仍然允许（第 2 条只在扇形里生效），它要
配的下降档不被第 4 条屏蔽。

规则写在先验这边（模块 `prior/procedure.py`：下限、切入与跌破的判定、每条规则），读的是先验本来就读的执行器位置与高度、跑道列、许可列、
高度列与下降角列的词和候选跑道的几何；执行器一行不改（执行器只接受词）。

### 3.5 飞出来的航迹再查一遍

- **下滑道下沿**：每飞完一步（2 s），查这一行：在扇形里、高度 < 下沿 − 40 m（15 m 半档 + 执行器的 25 m 容差），也就是比下滑道低 100 m
  以上，就结束这架，结局记为"低于下滑道下沿"，奖励 0。在 runner 里查，不改执行器的判定。执行器 v10 在"下降至落地"下已不会低于下滑道
  下沿（执行器设计 §5.3.4），这条查的是屏蔽预见不到的其他情形；照标注的词飞，训练集 400 × 5 架里还剩 4 架被结束，都是数据本身（读数
  文档 §13）。
- **第 3、4 条不另查航迹**：平飞目标不低于 DA − 15 m，执行器守住目标 − 25 m，所以平飞不会低于 DA − 40 m；"下降至落地"下执行器不低于
  下滑道延长线的下沿，它离入口 2–3 km 以外都高于 DA（DA 在入口以上 61–125 m）。更近、又在扇形以外的地方没有这个保证——读数里数切入前

  跌破之后又爬升 30 m 以上的句子：只在第一个预测步起、第 4 条生效的连续几行里，比这段里最低的一行高多少（观测的前 8 行只决定跌破没有，

## 4 第二阶段（二）：起始状态扩充

### 4.1 起始状态是什么

一架航班的起始状态 = 观测的前 8 行（位置、高度、航迹角、地速、垂直速度、时刻）+ 执行器在第 8 行的初始状态（位置、高度、速度、
航向、航迹倾角、质量）+ 航班的背景（机场、运行日与进入时刻——决定输入里的落地情况和奖励的落地方向——、机型与动力学）。

### 4.2 怎么变

从训练集运行日的一架航班（有自己动力学的，与回放门同一组）出发，对 8 行和执行器初始状态做**同一个**变换：

- **绕机场转 Δφ**：Δφ 在 ±15° 里均匀取。离机场的距离不变（仍在 25 km 的进入圈上），航迹方向跟着转，所以"朝机场飞"的关系不变；
  ±15° 在 25 km 处约 ±6.5 km 的弧长，进场的方向变了，但还是同一类进场。
- **高度平移 Δh**：±150 m 里均匀取（5 个高度档；约为 1,000 ft 垂直间隔的一半）。
- **速度缩放 1 + κ**：κ 在 ±5 % 里均匀取；地速、垂直速度和执行器的速度乘同一个系数，前 8 行的位置和高度都以第 8 行为中心按同一个系数
  拉伸（p_i' = p_8 + (1 + κ)(p_i − p_8)；高度 h_i' = h_8 + Δh + (1 + κ)(h_i − h_8)），2 s 一行的间隔不变——先验从相邻两行读出的
  速度和爬升率与执行器的状态一起放大。第 8 行不动（只转、只升），第 0 行沿原路移开约 κ × 前 8 行飞过的距离（5 % 时约 100 m）。
- 不变的：机场、运行日与进入时刻（所以落地情况和"机场此刻的落地方向"是源航班的）、机型、质量与动力学。

### 4.3 合格检查（不合格就重抽，连续 10 次不合格就换一架源航班）

- **高度**：第一个预测步（第 8 行，执行器起飞的那一行）变换后的高度，在这个机场训练集航班同一行高度的 1–99 百分位之间（只用来判断
  "情况相似"，不进模型）；
- **速度**：变换后的空速不低于执行器的失速下限——这架航班的质量、变换后高度的空气密度下，1.10 × 失速速度（执行器设计 §2.2 的同一个
  系数与公式）；
- **换源航班**：训练时每轮先抽 1.25 倍所需的训练集航班作池子，按池子的顺序取每个机场前 400 个合格的起点，放弃的源航班由池子里的下一架
  顶上（池子不够就报错停下）；选择集与验证集的读数航班是固定的，放弃的去掉并计数，不顶替；
- **读数**：每个机场的起点数、每个起点平均抽了几次、重抽过的起点比例、放弃的源航班数（训练写在每轮的 `sentences.json`，选择集写在
  `config.json`，连同每个扩充起点的变换）。

### 4.4 数据规矩

扩充的起始状态只从训练集运行日的航班造。内部选择集上另造一套固定的扩充起点（固定种子，每轮相同），专门读"没见过的情况"；
验证集同样造一套，定稿后只读一次。测试集运行日一架都不读。

### 4.5 时限

- **扩充起点**：源航班从第一个预测步到落地的观测时间 × 2.0（`prior/augment.py` `TIMEOUT_FACTOR`）；**真实起点**仍按执行器规格的
  × 1.5（回放门的约定）。训练、选择集和验证集的扩充起点都用这个时限。
- **为什么放宽**（用户 2026-09-26）：转 ±15° 让起点沿 25 km 的进入圈最多移 6.5 km，要飞的路可以比源航班长。第一阶段模型在选择集的扩充
  起点上超时 11.1 %，真实起点 2.5 %（执行器 v10，读数文档 §14）。同一批扩充起点把时限放到 3 倍重读一次：按 1.5 / 2 / 2.5 / 3 倍能落地的
  分别是 85.6 / 87.2 / 87.9 / 88.3 %；3 倍仍超时的 8.4 % 里 88 % 已许可进近、每架说 27 个航向词（落地的 18 个）——多数超时不是时限太紧，
  是飞机在绕。2 倍拿回放宽能拿回的大半（1.6 / 2.7 个百分点），剩下的留给奖励去学。

## 5 第二阶段（三）：训练与读数

- **起点**：第一阶段选定的那一轮（第一阶段的提升由此带进来）。**拉回的对象**：base 模型（用户 2026-09-25 确认）——各阶段都拉回
  同一个 base，说法不会一个阶段一个阶段地漂走。拉回不是退回：它按"离 base 多远"罚一个量，与落地的奖励相抵；带拉回项时最好的模型是
  "base 的说法里，把能落地的句子的概率放大"，所以为落地做的改变被保留，被拉回的只是与落地无关的漂移。**拉回项单独拴不住**（读数文档
  §9）：没有数据项时，固定的 β = 0.04 第 1 轮就离 base 0.29、许可 / 复飞词说到标注的 2.6 倍；让 β 按距离预算自动调，弱了模型冲出去，
  强了连第一阶段的提升一起拉掉。所以本阶段和第一阶段一样带数据项（用户 2026-09-26）。
- **每一轮的起点**：3,000 个，**每机场 400 个真实起点 + 200 个扩充起点**（用户 2026-09-27）：真实起点是训练集运行日的航班从自己的起点飞
  （第一阶段那样），扩充起点每个来自随机抽的一架训练集航班、一次新的变换（§4）。两种各自抽，互不重叠：每轮先抽 1.25 × 600 架的池子，

  之后又爬升 30 m 以上的句子（§3.5）；每架每列的词数；落地时刻与观测之差；落在反方向跑道的比例；每轮训练前离 base 的距离（真实 / 扩充
  分开）。

## 6 不采用：闭环监督微调（CAT-K）

- **做过什么**：每架航班同时飞 4 个分支，都由先验自己说词，每 20 s 留下离观测航迹最近的一支，其余换成它；把标注的词按"标注说词的
  那些行"对齐到留下的这条链上作目标（说早、说晚各容忍 10 s，许可进近一直要求到说出），只用链上的数据训练，8 轮（代码 `dev-prior-v3`
  `e760ab1d`：runner `prior_closed_loop`，`prior/relabel.py`；runners R18）。
- **为什么不采用**（读数文档 §6）：文献里闭环监督微调的收益大且复现过（先验设计 §11），但那里一个词就是 0.5 s 的一段运动，"让车回到
  真实位置的词"可以从当前状态直接算出来。我们的词是交给执行器的目标，效果要十几秒才显出来，目标只能取"标注在那个时刻说了什么"；
  而链离观测越飞越远（留下的分支 220 s 时中位数偏 1 km），标注"此刻许可、此刻转向"在链上的飞机那里往往不成立。模型学成"早许可、
  少说话"：验证集上直线进近 94.0 → 99.7 %，被引导的 83.3 → 81.0 %（偏出跑道 4.8 → 9.5 %），航向词只有标注的一半；teacher forcing
  负对数似然 0.284 → 0.452，8 轮后 1.114。按落地强化只看结局，不需要这种对齐。
- **代码**：已归档（用户 2026-09-25）到 `archive/closed_loop_sft_2026_09/`（分支 `dev-prior-fast` `e5f18692`，README 说明搬了什么）；
  逐行编码（`Prior.extend`）、`chain_record` 留在活代码里，自由生成和第一阶段用到它们。

## 7 不做的

- 不用程序算出的航迹作目标或奖励（不奖励"离下滑道近"）：屏蔽只拿掉不可行的词。
- **RNAV 进近在 FAF 以外编码的高度限制**（过渡段、IF、FAF 的"不低于"）不做屏蔽，也不进奖励（用户 2026-09-25）。选择集上量过（读数文档
  §8）：三种划法（只按沿航道距离 / 离航段 1 NM 以内 / 只对已许可的飞机）会屏蔽 10–15 % 的标注高度词、结束 10–14 % 的重飞（这些重飞都
  落了地）；观测航迹低于过渡段下限的 12.4 %、低于 IF→FAF 段 FAF 高度的 4.7 %。记录里的飞机多数由雷达引导，比过渡段和 IF
  的高度低；有垂直引导的进近从下滑道下方切入、过 FAF 时低于 FAF 高度也常见。这些高度只约束沿程序飞的飞机，数据里分不出谁在沿程序飞；
  罚它就是把模型从真实飞法推开。
- 不做"下降至落地"的直线预判（§3.4 第 2 条）。
- MVA 不屏蔽、不作奖励，只作读数（§3.7：记录里 28.5 % 的真实航迹切入前低于它 40 m 以上）；不屏蔽上限（25 km 以内没有编码的上限）；
  不屏蔽下滑道上沿。
- 切入前的第 3、4 条规则不另查航迹，只作读数（§3.5）。
- 词表设计 §5.1 的其他几条（切入角、切入点离进近门的距离、切入时不高于下滑道、9,260 m 以内不指定速度、3,048 m 以下的速度上限）
  这一阶段不做；要做时按同样的办法（屏蔽 + 事后查）加。
- 不改执行器。
