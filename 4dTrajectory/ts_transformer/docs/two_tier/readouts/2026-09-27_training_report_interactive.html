§0摘要

写法

摘要最后写，却放在最前面。它要让只读这一段的人拿走五样东西：问题、做法（一句）、主要的数连同它的对照、结论、最大的局限。

这一段会随着你往下读数慢慢填满——这正是写报告的顺序：先有数，再有摘要。

问题：能不能训练一个模型，像进近管制员一样每 2 s 说一行指令词，让规则执行器照着飞、把飞机带到跑道上，同时说话的方式不离开真实管制员？

结果：预训练得到的 base 模仿得很好，验证集每步负对数似然 ，最强的基线是 ，低了 %；但让它自己说、执行器照着飞，只有 % 的句子落地。第一阶段后训练只奖励“落地”，得到 landing：落地 %，在真实航班语境下说的话几乎没变。第二阶段加上程序高度约束和从没飞过的扩充起点，得到 augmented：扩充起点落地 → %，真实起点 → %，略降，但在事先定的 1 个百分点线以内，按规则采用。

局限：后训练只用了一个训练种子；执行器的结局分类把“太高”和“偏到侧面”记成同一种；测试集还没打开，这里所有的数都在验证集上。

§1问题与做法

写法

问题要写成数据能回答的形式。“模型好不好”回答不了；“落地率比 base 高多少、说话方式离标注多远”回答得了。

同时写下什么结果算成功——最好在跑之前。本报告里每个阶段的选轮规则和判定线都是跑之前写定的。

模型分两层。上层是先验（一个 330 万参数的 Transformer），每 2 s 说一行词，一行六列：跑道、进近（许可 / 复飞）、航向（5° 一档）、高度、下降角（档位）、速度。下层是执行器，一套只读词表的规则，把这一行词变成飞机每 1 s 的动作。先验看不到未来：每一步只给它此刻以前知道的东西（位置、过去的运动、候选跑道、此前 30 分钟的落地情况、自己已经说过的词）。

训练分三步，每一步产出一个模型，名字就是它学到的东西：

  1. 标注的句子从真实航迹读出的词
    44,362 架训练航班
    →
  2. 预训练逐步预测下一行词
    →
  3. base会模仿
    →
  4. 第一阶段落地才给分
    →
  5. landing会落地
    →
  6. 第二阶段程序高度 + 扩充起点
    →
  7. augmented陌生起点也会落地

两类指标，缺一不可：

  • 负对数似然（teacher forcing 下）：把真实的上文喂给模型，只考它下一步。模型给“标注里真实说的那个词”的概率是 p，损失就是 −ln p；六列加起来，按步平均。0 表示每次都百分之百猜中，越小越好。它量的是“像不像管制员”。
  • 落地率（自由生成下）：让模型自己说、执行器照着飞，看飞机有没有在它说的那条跑道上落地。它量的是“说的话管不管用”。一句话从第 8 行（前 16 s 只观察）开始说，每架航班说 4 句。

§2数据与划分

读法

四个集各管一件事：

  • 训练集：训练。
  • 内部选择集：选变体、选轮次，可以看很多遍。
  • 验证集：每个选定的模型只读一次，报告的数都来自它。
  • 测试集：封存，最后才开。

一个数被用来“挑”过，它就不再是没见过的数据上的成绩。

五个机场、90 个运行日（一天从 UTC 9 时切开，让一个运行日落在当地的一个白天和夜里）。按天划分，不按航班：同一天的航班共用跑道构型和天气，按航班划分，验证集里就会有“模型在训练时已经见过当天”的航班。划分写进了仓库（data/day_split_20260924.json），任何人重跑都是同一份：测试 14 天、验证 14 天、内部选择 9 天，其余是训练集。测试日的航班连标注都没做。

这 架是标注器接受的航班：验证日合格的到达有 10,757 架，标注器拒绝了一些（地速不可能、最后不在五边上……）。报告里的“多少架”要写清楚数的是哪一层。

读法

验证集读数和训练曲线的最低点是同一个数：早停用的就是验证集，保留的是 28 个 epoch 里验证集最好的那个。所以这个数被“挑”过一次，略偏乐观——很小，但要知道。这正是测试集要封存的原因。

对照是两个不用学习的基线，从模型自己的训练航班里数出来、按同一口径算：重复上一条（每一步都说和上一步一样的词）和只看上一个词（按训练集里“上一个词是 x 时下一个词”的频率猜）。

跑道单独看：它只在第一个预测步说一次，在总的负对数似然里几乎看不见（每架约 190 步里的 1 步），所以要单独报。对照是三条不用学习的规则：B0 机场最常用的跑道、B1 此前 30 分钟用得最多的、B3 同方向上一架落的那条。

第 1 步的门过了：每一列都低于两个基线；还没建立在五边上的航班上，跑道命中率 %，赢 B1（69.60 %）和 B3（72.08 %）。

让 base 自己说：自由生成

负对数似然低只说明“在真实上文里猜得准”。真正要用时，上文是模型自己说出来、执行器飞出来的，和训练时见过的不一样。于是在验证集上每机场抽 400 架（种子 1337），每架从第 8 行起让 base 说 4 句（温度 1），执行器照着飞，时间上限是观测剩余时间的 1.5 倍；同一批航班另用标注的词飞一次作对照。

失败的样子（读数文档 §5.2）：没落地的句子平均说 47.0 个航向词，落地的只有 12.4 个——绕来绕去直到超时，许可给得很晚。执行器飞出的路径一旦和观测不同，base 读到的就是训练时没见过的位置，于是一直修正航向。这是后训练要解决的问题。

§4实验二　第一阶段后训练：landing

写法

做法写到能照着重做：奖励是什么、损失有几项、各项的系数、每轮多少数据、跑几轮、怎么选轮。选轮规则直接引用 choice.json 里存的原文，读者可以自己核对。

做法：每轮从训练集运行日抽每机场 400 架（换种子），每架让模型说 8 句、执行器照着飞。落地得 1 分，否则 0；同一架航班的 8 句互相比，比这 8 句平均好的那几句加强、差的减弱（这类做法叫 GRPO）。损失还有两项把模型拴住：0.04 × 离 base 的距离（KL 散度），和 1 × 数据项（在真实航班上 teacher forcing，也就是继续做预训练的事）。8 轮，每轮在内部选择集上读一次（每机场 200 架 × 2 句，每轮同一批航班、同一个种子）。

选轮规则（v3_rl_20260925/grpo_s1337/choice.json 的 rule）：护栏以内（落在观测跑道上的比例不低于第 0 轮 − 2 个点；每架航向词不多于第 0 轮的 1.2 倍），选择集落地率最高的一轮；与最高相差 1.5 个百分点以内的，取最早的。

选择集落地率（2,000 句）与最高相差 1.5 个百分点以内

出处：v3_rl_20260925/grpo_s1337/choice.json 的 landed（第 0 轮就是 base）。9 轮都在护栏以内。

读法

为什么是“1.5 个点以内取最早”？选择集 2,000 句上，落地率 96 % 左右时的抽样波动约 ±0.9 个百分点（95 %）。差不到这么多的两轮分不出高下，就取训练更少、离 base 更近的那一轮。

验证集读一次

写法

百分点和百分比不是一回事。83.3 % → 93.9 % 是“提高 10.6 个百分点”，也是“相对提高 12.8 %”。报告里两个比例相比，用百分点；要说相对变化，写明“相对”。

它是不是靠“怪说法”换来的落地？看两个数：说了多少航向词、在真实语境下还像不像管制员。

这个提升是不是碰巧

base 和 landing 在同一批航班、同一个句号（同一个随机数序列）上各说了 4 句，可以一对一配对。只数“一个落地、另一个没落地”的对：b = 只有 base 落地，c = 只有 landing 落地。如果两个模型一样好，b 和 c 应该差不多；z = (c − b) ÷ √(b + c)，|z| 大于 2 左右，差别就不太可能是抽到的句子碰巧好。

在同一个执行器 v10 上（v3_reread_v10_20260926/ 的 val_base_400x4 和 val_stage1_400x4），8,000 对里 b = 163、c = 803。

§5实验三　第二阶段后训练：augmented

要解决的两件事：一，先验说的话要守程序规定的高度（不能让飞机在五边上低于下滑道太多）；二，只在真实航班的起点上练，模型可能只会飞“见过的进场”。

做法（后训练设计 §3–§5）：

  • 程序高度屏蔽（procedure-altitudes-v2）：说词时把违规的高度、下降角词的概率置零——FAF 以内不低于公布下滑道 − 60 m；切入五边前不低于决断高度；跌破入口高度后不许再爬升。
  • 扩充起点：把真实起点绕机场转 ±15°（25 km 处约 ±6.5 km 的弧）、高度 ±150 m、速度 ±5 %，均匀取；时间上限放到观测剩余时间的 2 倍。
  • 每轮每机场 200 个真实起点 + 200 个扩充起点，每个 8 句；从 landing 起，拉回 base；损失与第一阶段相同，另加截断的比（ε = 0.2，下面说为什么）；8 轮。

判定

事先定的判定线（用户 2026-09-27 同意，在读验证集之前）：第 7 轮真实起点的落地率不低于 landing − 1 个百分点，就采用。

读法

三种“不确定度”，量的东西不同：

  • 区间：同一个模型，换一批句子，落地率会晃多少。
  • 配对 z：这两个检查点在这批航班上是不是真的不同。
  • 种子线：同一个训练方法换个种子，结果会差多少。

本阶段量了前两种，没量第三种。所以能说“第 7 轮比 landing 在真实起点上差，是真的”，不能说“这个方法一定会让真实起点变差 0.9 个点”。

读法

这张表里的“太高”在执行器的判定里记作“越过入口偏在跑道外”——判定没有把“在中线上但太高”和“偏到侧面”分开。一个结局名下藏着两种失败，读分类统计时要知道。

最低引导高度（MVA）：一个没有公平对照的数

MVA 是管制员引导飞机时不能低于的高度，按扇区公布。它只作读数，不作约束：真实航迹切入前就有 28.5 % 低于它（多数时候飞机已按公布的程序飞，不再受 MVA 约束，ADS-B 分不出是哪一种）。

§6局限

写法

局限不是谦虚的套话。每一条写清楚：它会让哪个数偏向哪边，或者让哪个结论说不了。

  1. 后训练只有一个训练种子。配对 z 说明检查点之间的差别是真的，说明不了方法本身的稳定性。
  2. 预训练的验证集参与了早停。验证集负对数似然是 28 个 epoch 里挑出的最低点，略偏乐观。
  3. 选轮在选择集上比了多次。选中那一轮的选择集读数偏乐观，所以结论只用验证集的数。
  4. 结局分类太粗。“太高”和“偏到侧面”记成同一个结局；说一条跑道、飞到平行的另一条，被藏在“超时”里（读数文档 §16，landing 约 0.12 %）；没有平行跑道的机场，落地的横向判据是 1,000 m，偏松。
  5. 执行器版本在报告期间变过（v7 / v8 → v10）。跨版本的数不并排；§5′ 的表都在 v10 上。
  6. 扩充起点的 MVA 比例在验证集上没有公平对照。
  7. 每架航班的 4 句相关。按句子独立算的区间偏窄。
  8. 只有五个机场，测试集未开封。留出机场 KAUS 还没读，所以这里没有“换一个机场还行不行”的证据。

§7结论与下一步

结论：预训练得到的 base 模仿得好，但闭环下只有九成落地，失败的样子是说个不停的航向词。只奖励落地的第一阶段把落地率提到 97 %，而说话方式反而更接近标注。第二阶段在程序高度约束下，把扩充起点的落地率提高了约 4.4 个百分点，代价是真实起点约 0.9 个百分点（事先定的线以内），采用第 7 轮作为 augmented。

§8附录

A　读一个数的七步

  1. 找出处：哪个文件。报告里的每个数都应该能指回一个文件。
  2. 读文件头：集、模型、执行器、屏蔽、种子、样本量。
  3. 找对组：模型说的（prior）还是标注的（labelled）；全部（all）还是分组；真实起点还是扩充起点。
  4. 对单位：文件里的比例是 0–1 的小数，报告里写百分数；“每步”还是“每架”。
  5. 找对照：同一批航班、同一口径的另一个数。没有对照的数只是一个数。
  6. 问不确定度：换一批句子、换一个种子，它会动多少。
  7. 只说数据撑得住的话：事实和读法分开写，读法标明是读法。

B　写报告的清单

  • 摘要有问题、做法、带对照的主要数字、结论、最大的局限
  • 问题能用数回答；成功的标准在跑之前写下
  • 数据划分写清楚每个集的用途，以及哪个集没被碰过
  • 配置能让别人重现：数据产物、代码提交、种子、超参数
  • 选择规则在跑之前写定，报告里引用原文
  • 每张表写明集、样本量、每个数是什么的比例
  • 并排的数口径一致；不一致的格子加注
  • 比例相比用百分点
  • 写出不确定度，并说明它量的是哪一种变化
  • 分组看，别让总数盖住某一组的退步
  • 负结果也写，写清楚为什么失败
  • 局限写清楚会让哪个数偏向哪边
