# 最平两档"下降至落地"的飞法：候选对比（2026-09-27，执行器 v11 第 3 步的测量）

**一句话**：截获后按最平两档"下降至落地"时，现行飞法比真实飞机陡（最平一档 1.80° 对 1.19°）。量了五种改法：

- "下滑道下方平飞"（`join_from_below`）一点代价都没有，但改善有限；
- "档的中心角 + 按飞机自己的高度判够不够得到入口"（`class_centre_own_reach`）角度对上了，但后段偏高、越过入口高 11–12 m、
  75 % 的航班落地时离开词的管子；
- 其余三种过入口太高，落地掉 13–15 个百分点，不能用。

要用户选（§3）。

路径相对 `4dTrajectory/`。执行器设计 §5.3、§16 第 1 条；先验读数 §12–§13；进度报告 P0 第 2 条（用户 2026-09-27 选"模式标记 + 改最平一档
的飞法，先设计、单独量"）。

## 1 做法

- **runner**：`prior_glidepath_diagnosis`（R22，分支 `dev-executor-v11` `48d12bbc` / `8f9256ce`）。每种改法只把 `Vertical.rate` 的一两行在进程里
  换掉（不改执行器源码和规格）。
- **读数**：
  - 截获后每一档最长一段"下降至落地"里，执行器与真实飞机的下降角，以及执行器每分钟比真实飞机多丢的高度；
  - 进 FAF 时的高度差；
  - 落地的过入口高度；
  - 回放门的航班（从第 0 行飞、判词）上的落地与词在包络内。
- **样本**：训练集回放门的原样本（自有动力学，每机场 400 架，种子 1337），执行器是 v11 到第 2 步为止的代码（p = 5°/s），开发用规格
  `outputs/POOLED/analyses/shallow_class_law_20260927/executor_dev_7369cfb9`（不是正式 v11）。
- **产物**：`diagnosis_train_400/`（现行 + 前三种）、`diagnosis_train_400_own_reach/`（后两种），`run.sh`、`run2.sh`。

**五种改法**（都只改截获之后、词的管子里的瞄准；截获之前和离开管子去落地的一步不变）：

- **类中心**（`class_centre_in_tube`）：飞这一档的名义角度，不陡于到越过点的连线。
- **下方平飞**（`join_from_below`）：在被指跑道公布下滑道的下方时平飞（管子允许的最缓），在下滑道上或上方时照现行飞法——
  像真实飞机那样从下方切入下滑道。
- **下方平飞 + 上方类中心**（`join_from_below_centre`）：下滑道下方平飞，上方飞类中心。
- **类中心 + 自己的高度判可达**（`class_centre_own_reach`）：同类中心，但"还够不够得到入口"按飞机自己的高度判（现行按管子的下沿判），
  够不到才离开管子去越过点。
- **下方平飞 + 上方类中心 + 自己的高度判可达**（`join_from_below_centre_own_reach`）。

## 3 读法与建议

- **类中心单独用不行**：管子的下沿够得到入口时飞机自己已经够不到，11–12 % 过入口太高（先验读数 §12 在 v9 上看到的同一件事）。
- **自己的高度判可达修好了"太高"，代价换了地方**：
  - 中段飞得像真实飞机（最平一档 0.98° 对 1.19°，每分钟不再多丢）；
  - 之后一直偏高（进 FAF 比真实飞机高 23 m），要到"刚好够得到"时才离开管子；
  - 以最陡一档的下沿冲向越过点，越过点落在允许高度的上沿（中位 28.3 m；现行飞法中位 16.8 m，就在公布的 TCH 上；高出约 11.5 m，在 evaluation 的 ±22 m 以内）；
  - 四分之三的航班落地时离开词的管子——句子最后一段不再是照词飞的。
- **下方平飞**：
  - 只在飞机低于公布下滑道时改动，那里平飞正是真实飞机做的事，所以一点代价都没有；
  - 但改善有限：最平一档的角度差只缩小约六分之一（1.80° → 1.70°，真实 1.19°），每分钟多丢的高度少约三分之一（69 → 44 m）；
    剩下的差距在执行器已在下滑道上方的那些段里。
- **我的建议**：v11 用**下方平飞**（没有代价、有改善、行为可解释）；"类中心 + 自己判可达"在角度上更像，但把问题从"中段偏低"换成
  "末段偏高、离开管子"，要用它就先在正式回放门上量 evaluation（越过点偏高能不能过）再定，这次不做。
