### 1.2 这一阶段（2026-09-25 – 09-27）解决的问题

- **一轮之内的漂移**：第二阶段重启时模型一遍之内离 base 冲出去（最大 5.96）。离线检查定位到奖励项没有重要性比和截断；加上 PPO / GRPO 的
  截断比（ε = 0.2）之后每遍最大 ≤ 0.021（读数 §15、§17）。
- **程序屏蔽和模型绑在一起**（先验设计 §5.1，契约 C35）：词表规则和程序屏蔽分开；每个模型目录记着它训练时开的程序屏蔽
  （`procedure_masks.json`，绑定检查点和程序数据的摘要），`load_prior` 一起读出，生成默认用模型自己的。重构前后逐位相同；30 个现有模型
  已补记录。另一个会话已把它接进训练视图的导出和后端的实时飞行。
- **切入前的规则**：决断高度作下限、跌破入口高度后不许再爬升（硬约束，屏蔽 0.22 % 的标注词）；MVA 只作读数（真实航迹 28.5 % 低于它）。
- **诊断**（都只读、逐句复现存下的读数）：
  - 扩充起点 MVA 比例高——对照本身不完全可比，加上五边之外早说"下降至落地"（读数 §14）；
  - 说一条跑道、飞到平行的另一条（landing 验证集 0.12 %）——判定只看被指跑道，平行跑道上的失败被藏在"超时"里（读数 §16）；
  - 第二阶段真实起点为什么掉——**部分退回 base 的老毛病**："下降至落地"说得晚、说时太高，越过入口时仍高；判定把"太高"也记成
    "越过入口偏在跑道外"（读数 §17）。
- **执行器 v10**：照标注的词重飞被判低于下滑道下沿 49 → 4 架（剩下的是数据本身），落地不变（读数 §12–§13）。
- **模型的名字**：base → landing → augmented（用户定）。
