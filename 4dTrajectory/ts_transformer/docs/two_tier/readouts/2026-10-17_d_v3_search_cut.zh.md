## 2 读法

1. **v3 的数和 v2 自己读的 85.0 % / 13.1 % 不能直接比。** D 阶段的 select 窗口和读数的随机数都从活动的种子来
   （`multi_train.selection_windows`、`readout_numbers`），D162 要求新活动换种子，所以 v3 读的是另一套窗口
   （4,334 架，v2 是 4,498 架）。同一个 v2 第 11 轮模型，在 v2 的窗口上 85.0 % / 13.1 %，在 v3 的窗口上
   86.5 % / 11.5 %：光换窗口就差 1.5 / 1.6 个百分点。读法核对：同一个脚本加上轮次参数，在 v2 自己的窗口上读 v2 第
   11 轮（`multi/check_readout_v2_r11_20261017/`），结果和活动记下的读数逐项相同（4,498 架，降落 3,823，失去间隔
   588，其余各类也相同），所以起点那一行和各轮是同一种读法。
2. **12 轮没有可测的改进。** 最好的第 9 轮比起点降落 +0.3、失去间隔 −0.4 个百分点；D216 在同类读数上配对差的
   90 % 区间宽约 ±1 个百分点，这个差在噪声内。各机场有升有降（KSMF 失去间隔 −1.9，KMSY +1.1）。
3. **第 0 轮先变差（−1.0 / +1.1），之后 6 轮才回到起点水平。** 第 0 轮也有一次梯度尖峰（最大梯度范数 154），KL
   0.121、被裁剪 0.82 %，都比 v2 第 11 轮高很多。Claude 的读数：计入词少了约三分之一（截掉事件后的尾巴），而损失按
   一次更新的计入词平均，所以每个词在更新里的分量变大，每步走得更远，尖峰也更容易出现。
4. **第 11 轮坏了。** 一次更新的梯度范数到了 670（第 0 轮 154、第 4 轮 31，其余轮 5.5–17），KL 跳到 0.912，降落掉到
   83.0 %。D 的训练没有梯度裁剪：C 阶段有 `clip_norm`（post-training D168，默认不裁），D 的 `MultiSettings` 没有
   这个设置，D 的训练调用也没传；B 阶段训练先验时按 1.0 裁。第 11 轮的模型不能用。dev-two-tier 上也一样：D 的
   `multi_train.py` 从 10-07 05:06 建立（`2b370d37`）起就没有裁剪，任何分支上都没有提交加过或删过它；D168 当天
   14:57 的设计（`e3b56fce`）只加给 C，并写明“阶段 D 的活动用默认值，直到它的设置里有这一项”，之后没人补上。C 被
   选中的活动（seg60、`post_seg60_b21`）也是不裁剪；只有学习率 3 倍的三个对照和两个价值函数活动用 1.0。旧版（已归档
   的 v3）先验训练按 1.0 裁，多机调参器也裁。
5. 和 §9–§10 合起来看（Claude 的读数）：往回多找 64 秒，只对那 40 % 被指挥得够早的飞机有用；截掉尾巴以后，留下的
   信号仍然只在事件前一两分钟，速度类的处理来不及。所以这三处改动没有把失去间隔降下来，不意外。

## 3 两个种子的读数为什么差 1.5 个百分点

同一个模型（v2 第 11 轮）在种子 2035 的窗口上 85.0 % / 13.1 %，在种子 2036 的窗口上 86.5 % / 11.5 %。数据：
`multi/select_sets_2035_2036_20261017/`（两个种子的窗口清单，不飞模型）、`multi/diagnose_v2_r11_20261016/per_window.jsonl`
（种子 2035 窗口上的逐窗口结果，和活动记下的读数逐项相同）。

1. **两套窗口几乎不重合。** 每个机场的 select 池有 658（KMSY）到 1,914（KRDU）个锚点，每个时长抽 100 个；两套共有的
   锚点每格只有 2–12 个（共 32 / 500，6 %）。所以这是两次几乎独立的抽样。
2. **按窗口重抽样，两套独立窗口的降落率之差，标准差 0.93 个百分点，90 % 范围 ±1.5 个百分点**（失去间隔 0.90 / ±1.5）。
   实际差 1.5 / 1.6 个百分点，约 1.6 倍标准差，大约 9 次里出现 1 次。不是读法的错，是读数本身的抽样误差。
3. **KRDU 贡献最大**：80.6 % → 84.7 %（+4.1），KRDU 单独的标准差是 2.05 个百分点，约 2 倍。其他机场有升有降。
4. **每个窗口几架飞机只解释一小部分。** 失去间隔随窗口里受控架数上升（1 架 4.8 %、3 架 11.3 %、5 架 15.5 %、8 架及以上
   23.7 %）；种子 2036 的窗口受控飞机少 164 架（4,334 对 4,498）。按种子 2035 的（机场、架数）比率换到种子 2036 的窗口
   组成，预计 85.3 % / 12.8 %：组成只解释 +0.3 / −0.3 个百分点，其余约 1.2 个百分点是哪些交通场景被抽中。
5. **结论**：D 阶段不同种子的活动之间不能直接比读数，只能在同一套窗口上比；v3 各轮和起点是同一套窗口、同一套随机数，
   这个比较成立（§2 第 2 项）。原因在设计上：C 阶段有和训练种子分开的 `select_seed`（`post_train.py:198`，从另一个活动
   起跑时要求相同，`post_train.py:1847`），D 阶段的 `MultiSettings` 没有，select 窗口和读数随机数都从训练种子来，而
   D162 要求新活动换种子。
