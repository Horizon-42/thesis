## 1 为什么改

- **D 没有梯度剪裁。**
  - 梯度剪裁（D168）在 10-07 只加进了 C 的 `Settings`。post-training §9 第 10 项写的是 "stage D's campaign takes the defaults until its settings name them"，D 的设置一直没写它。
  - v3 第 0 轮有一次更新梯度范数 154，第 11 轮有一次 670；第 11 轮的 KL 跳到 0.91，读数降到 83.0 %。
- **每个 D 活动读的是另一套 select 窗口。**
  - D 的 select 窗口和读数随机数都取自训练种子，D162 又让每个活动换一个种子。
  - 种子 2035 和 2036 的两套窗口只有 6 % 相同。在两套窗口上读同一个模型，读数相差可到 ±1.5 点（v3 读数 §3）。
  - 结果是：不同活动的数无法逐窗口配对比较。

## 2 D 一次更新的损失（未改，先说清楚改的是哪里）

- 每轮先用当轮开始时的模型说话、打分，再在这一轮的组上做一遍更新：每次更新 4 组，v3 第 0 轮共 132 次更新。
- 一个窗口的奖励 W 是它所有受控飞机奖励之和（D141）。一个组里每个续说的优势是 A = W − 组内平均，不除以标准差（`post/branches.py:152`）。GRPO 除以组内标准差 [7, §4.1.2]，我们没有。
- 概率比 r = 现在的模型说这个词的概率 ÷ 说话时模型说这个词的概率 [1, §3]。
  - 第一次更新前 r = 1。之后模型每更新一次，同一个词的 r 就离 1 更远一点。
  - 同一轮里后面的更新，用的是前面已经改过 100 多次的模型。
- 每个词的损失是 PPO 的剪裁比代理 [1, eq. (7)]，ε = 0.2：

```
L_词 = −min( r·A , clip(r, 1−ε, 1+ε)·A )
```

  PPO 原文里 ε = 0.2 在比较的 11 种设置中得分最高 [1, §6.1 表 1]。另外两项是拉回 base 的 KL 项（系数 0.04）和教师强制的数据项。三项都按计数行平均（D115）。

## 3 四项改动

四项都是活动设置，默认值就是改之前的行为。没有这些字段的旧记录按默认值读，旧记录一条都没改。审查人核对过：在默认值下，损失、梯度、步长和读数与改之前逐位相同。

### 3.1 梯度范数剪裁 `--clip-norm`

- **做什么**：每次更新算出整个梯度 g 后，如果它的范数 ‖g‖ 超过上限 τ，就把 g 按比例缩成 τ·g/‖g‖。方向不变，只是变短；没超过就不动。
  - 这就是 Pascanu 等的算法 1 [3, §3.2]。他们建议看训练中梯度范数的平均值来选 τ，并说结果对 τ 不敏感。
  - 它只限制一次更新走多远，不改变往哪个方向走。
- **在 RL 里常用吗**：常用，但通常不被当作主要因素。
  - PPO 参考实现 openai/baselines 用 `max_grad_norm = 0.5`，Huang 等列为核心实现细节第 11 条 [6]。
  - Engstrom 等也把它列为 PPO 的代码级优化之一（第 9 条，0.5），但没有单独做消融 [4, §3]。
  - Andrychowicz 等做了大规模比较：剪裁"带来小幅提升，具体阈值差别不大"，结论是"也许略有帮助，但属次要" [5, §3.3，图 34]。
  - 大模型 RL 框架默认都开：verl actor 的 `grad_clip` 默认 1.0 [8]，transformers 和 TRL 的 `max_grad_norm` 默认 1.0 [9]。
- **我们的取值**：τ = 20，是 Claude 定的，用户可以改。
  - v3 第 1–10 轮每次更新的范数平均是 2.0–3.4；每轮最大的一次是 5.5–16.5，只有第 4 轮是 30.6。
  - 所以 20 截掉的是第 0 轮的 154、第 11 轮的 670 和第 4 轮那一次，其余更新不受影响。
  - 上面那些框架的 0.5 或 1.0 不能直接搬过来：我们的损失按计数行平均，量级和它们不同。按 Pascanu 的办法 [3]，阈值应从自己观测到的范数统计来定。
- **代码**：
  - 剪裁本身：`post/loss.py:408` `clipped_step`（`torch.nn.utils.clip_grads_with_norm_`），与 C 的 D168 是同一段。
  - 设置：`experiments/multi_train.py:248` `MultiSettings.clip_norm`，必须为正，或者不设（不剪裁）；命令行参数在 `:976`。
  - 每轮的范数均值、最大值和被剪裁的更新比例照旧写进 `round.json` 的 `pass`。

### 3.2 双重剪裁 `--dual-clip`

- **问题**：PPO 的剪裁对正负优势不对称 [1, §3 和图 1]。
  - A > 0（这个续说比组里平均好）：r 超过 1 + ε 后就不再往上推，有上限。
  - A < 0（比平均差）：r 低于 1 − ε 后不再往下压；但 r 往上走（模型反而更愿意说这个坏词）时没有上限。这个词的损失是 r·|A|，r 越大，它在梯度里的分量越大。
  - PPO 原文没有用文字说这一点，它只能从 eq. (7) 和图 1 看出来 [1]。明确指出的是 Ye 等：r·Â ≪ 0 时会带来"大而无界的方差" [2]。
- **在我们这里怎么出现**：
  - 一个说话时概率很低的词（比如 0.001），经过同一轮里前面的更新，概率可能变成 0.01，r = 10。
  - 它的分量是 10·|A|，一个词就能把一次更新拉偏。
  - 这是 v3 尖峰的一个可能来源，还没有证实。§3.4 的记录就是为了看清楚这一点。
- **做什么**：Ye 等的双重剪裁 [2, eq. (5)]。对 A < 0 的词，再加一个下界 c·A（c > 1）：

```
A < 0 时：L_词 = min( −min( r·A , clip(r, 1−ε, 1+ε)·A ) , −c·A )
```

  当 r > c 时，这个词的损失固定为 c·|A|，梯度为零。也就是：现在说这个坏词的概率已经是说话时的 c 倍以上，就不让它再拉动更新。A ≥ 0 的词，以及 r ≤ c 的词，都不受影响。
- **取值**：c = 3，同样是 Claude 定的，用户可以改。
  - 这是 Ye 等用的值，原文写 "ε and c are set as 0.2 and 3, respectively" [2, System Setup]；verl 的 `clip_ratio_c` 默认也是 3.0 [8]。
  - 要注意：Ye 等的数据来自多个不同策略（"trajectories are sampled from various sources of policies"），比我们一轮说一次话、再更新 132 次更偏离当前策略。所以 3 对我们是否合适，要看 §6 的记录：被挡住的词有多少。
- **代码**：
  - 损失本身：`post/loss.py:189` `_surrogate_words`。被挡住的词是 `held = (a < 0) & (loss > −c·a)`，这些词的损失换成 −c·a。
  - 传递路径：经 `surrogate`（`:217`）和 `update_step`（`:276`）传到 `experiments/post_train.py:1570` `train_pass`。
  - 设置：`multi_train.py:249` `MultiSettings.dual_clip`，必须大于 1；命令行参数在 `:978`。
  - `update_gradients`（只给已归档的 runner 用）不带双重剪裁。

### 3.3 读数种子 `--select-seed`

- **做什么**：select 窗口的抽取和读数用的随机数，改为取自 `readout_seed`：设了 `select_seed` 就用它，没设就用训练种子，也就是旧行为。
  - 训练抽样仍用训练种子。
  - 这和 C 的 `Settings.select_seed` 是同一个做法（D146、D162）。
- **为什么**：几个活动用同一个读数种子，就读同一套窗口、用同一套随机数。读数之差就只来自模型，可以逐窗口配对，配对区间约 ±1 点，不再有两套窗口之间 ±1.5 点的差。
- **代码**：
  - `multi_train.py:307` `readout_seed`；`:477` `selection_windows`（随机数发生器取 `[readout_seed, 1 << 31]`）；`:508` `read_batch`。
  - D 的训练集导出：`experiments/multi_training_export.py:130`、`:134`，写出的 `select_seed` 就是 `readout_seed`。
  - 命令行参数在 `multi_train.py:981`。
- **测试**：同一个读数种子，窗口相同（`test_multi_train.py`）；训练种子变、读数种子不变时，读数逐窗口相同而训练批次不同（`test_window_behaviour.py`，审查人用改坏的代码确认过这个测试会失败）。

### 3.4 每次更新的记录 `update_rows`

- **做什么**：`round.json` 的 `pass` 里新加 `update_rows`，每遍一个列表，每次更新一行（`post/loss.py:420` `update_row`）。C 的分支方法也写这一项。一行有：
  - `grad_norm`：剪裁前的梯度范数；
  - `words`：计数的词数；
  - `surrogate`、`kl`：代理损失和 KL 项；
  - `ratio_max`：最大的 r；
  - `weight_max`：梯度还在流动的词里最大的 r·|A|；
  - `advantage_max`：最大的 |A|；
  - `dual_clipped`：被双重剪裁挡住的词数。
  - 后四项来自 `post/loss.py:135` `Extremes`，多片段的一次更新按片段合并（取最大值，词数相加）。
- **为什么**：以前每轮只记均值和最大范数，看不出尖峰来自哪里。有了这一行，就能分清尖峰来自一个 r 很大的词，还是一个 |A| 很大的组。
