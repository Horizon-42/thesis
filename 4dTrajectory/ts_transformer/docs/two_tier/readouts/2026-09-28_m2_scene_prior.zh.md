## 3 怎么读（我的读法）

- **scene 没有学会用别的飞机**：它在有前机、忙的步上并不比 base 好，M1 的差距原样还在；切掉飞机之间的注意力，词的分布几乎不动
  （KL 最大 0.008，航向列在有前机的步上）。看见别的飞机反而略差一点（scene − 单独 在速度、航向列有标的步上 +0.0003 到 +0.0012）：边特征那一路学到的
  东西在选择集上不成立。
- **它整体比 base 差，主要不是因为看见了别的飞机**："单独"读法同样比 base 差 0.0033，只比 scene 好 0.0008。差在训练本身。最可疑的是批的大小：
  scene 每批被问到的步约为 base 的 1/3.7，学习率相同，每轮更新 3.7 倍次；它 14 轮就停了，停时训练集上每步 0.2477（base 停时 0.2485，
  差不多），val 却差 0.0038——同样拟合到训练集的程度，推广得更差。这是推测，没有验证。
- **M1 的那块差距本身可能大半学不到**：看得见前机的模型也没有把它缩小。一种可能是有前机时管制员什么时候给速度词，本来就更难从过去的状态
  里看出来（时机的噪声），不是缺了信息；另一种是模型在这个配方下学不出来。现在分不开。
- 种子：设计说"有前机的步上差距小到要分辨种子噪声时再训第二个种子"。这里不是小的正差，是没有改进、整体更差；base 两个种子之间 val 只差
  0.0001，scene 的 0.0038 远在种子噪声之外，第二个种子不会改变结论。

## 4 三条路（用户 2026-09-28 选了第 1 条，设计 §9 第 21 项）

多机后训练（M4）按设计从"M2 选中的模型"起。第一次训出的 scene 整体比 base 差、又没用上别的飞机，不宜当起点。三条路：

1. **对齐批的大小再训一次**（推荐先做）：梯度累积 4 批再更新一次，使每次更新被问到的步与 base 相当，其余不动；GPU 约 2–3 小时。
   分开两件事：整体差是不是批的大小造成的；批对齐以后有前机的步上是否开始比 base 好。要改 runner（加一个参数，测试、审查）。
2. **不再做场景预训练，交互交给后训练**：M4 从 base 起，加上边特征那几层并初始化为零（开始时与 base 逐位相同），让带间隔奖励和屏蔽的
   后训练去学用别的飞机。要改设计（§6.1 M4 的起点）。
3. **照现在的 scene 往下走（M3）**：不推荐，它整体比 base 差。

如果第 1 条之后仍然没有改进，走第 2 条。

## 5 按 base 的批大小再训一次（设计 §6.5 第 6 步）

- **改了什么**：只改一处——每 4 批累积一次梯度再更新（`--accumulate 4`，分支 `dev-multi-aircraft` `a7abbe86`，opus 审查过）：每轮 494 次更新、
  每次约 1.67 万个被问到的步，base 531 次、约 1.56 万步；预热按更新数算。其余与第一次完全相同（同一种子、同一数据、同一网络）。
- **训练**：`outputs/POOLED/prior/m2_scene_20260928/scene_acc4_s1337`，第 19 轮最好（共 22 轮，早停），val 每步 0.2667（第一次 0.2681，base 0.2643），
  2.6 小时。读数 `outputs/POOLED/traffic/scene_readout_acc4_20260928/`，读法与 §1 相同。

五个机场仍然都是 scene 比 base 差（KMSY 0.0003 到 KRDU 0.0042）。切掉飞机之间的注意力，词的分布几乎不动（KL 最大 0.0074，航向列在有前机的步上）。

**怎么读（我的读法）**：

- 批的大小解释了整体差距的一部分（0.0041 → 0.0029），也解释了"看见别的飞机反而略差"——再训后 scene 与"单独"只差 0.0001。剩下的 0.0029
  仍远在种子噪声（0.0001）之外，原因没有查（它 19 轮就停，停时训练集每步 0.2523，base 停时 0.2485）。
- **交互仍然没学到**：有前机的步上没有一处比 base 好，M1 的差距原样还在，切掉注意力词几乎不变。两次训练、两种批大小结论相同，所以不是批的
  问题：在 teacher forcing 下，看得见别的飞机并没有让这份数据里的词更好预测。
