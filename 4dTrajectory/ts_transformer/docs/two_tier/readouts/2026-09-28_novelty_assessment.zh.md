# 两层模型的新颖性评估与投稿建议（2026-09-28）

**一句话**：单看任何一个部件都不新——自回归的"运动词"模型、强化学习后训练、解码时屏蔽、飞机之间的注意力，在自动驾驶里都已成熟。
新的是**组合和对象**：只用公开 ADS-B（没有语音记录）从航迹读出管制指令句子，在句子上训练"管制员的语言模型"，交给物理执行器飞，
再在真实记录的进场上闭环强化。本地文献和网络检索都没有找到做同一件事的航空工作。**值得发表**，建议拆成两到三篇（§7）。
与自动驾驶的异同是论文里最需要讲清楚的一节，本文 §3 专门写。

## 1 我们的工作是什么（写论文时的一段话）

每 2 s 一行、六列指令词（跑道指针、进近许可、航向、高度、下降角、速度；每列要么"不变"，要么一个新词）。

| 部件 | 做什么 | 关键数字（出处） |
|---|---|---|
| 标注器 | 从 ADS-B 航迹反推每一步管制员说了什么 | 训练集约 99 % 的航班读得出句子（[标注读数](2026-09-23_instruction_labels_readout.zh.md) §1） |
| 执行器 | 只按词和点质量动力学飞，保证飞得出来 | 回放门（照标注的词飞）：落地 训练 99.63 % / 验证 99.90 %（[v11 读数](2026-09-27_executor_v11_readout.zh.md)） |
| 先验 base | 因果 Transformer，只用过去的信息，teacher forcing 训练 | 每步负对数似然 0.2643，每列赢两个基线；还没建立在五边上的航班，跑道前 1 命中 81.5 %（规则基线 69.6 / 72.1 %）（[先验读数](2026-09-24_prior_readouts.zh.md) §4） |
| 自由生成 | 先验自己说、执行器飞 | 验证集落地 90.2 %（§5） |
| 后训练 landing | 按落地强化（截断的比 + 拉回 base 的 KL + 数据项） | 90.2 → **97.2 %**；直线 94.0 → 99.0 %，被引导 83.3 → 93.9 %；teacher forcing 负对数似然不变（§7） |
| 后训练 augmented | 扩充起点 + 程序高度屏蔽 | 扩充起点 86.8 → 91.2 %，真实起点 97.2 → 96.3 %（§17） |
| 闭环监督微调（CAT-K） | 试过，不采用 | 被引导 83.3 → 81.0 %，负对数似然 0.284 → 0.452（§6，[后训练设计](../post_training_design.zh.md) §6） |
| 多机 M2 | 场景预训练（teacher forcing） | 没学会用别的飞机：0.2868 对 base 0.2839（[M2 读数](2026-09-28_m2_scene_prior.zh.md)） |
| 多机 M3 | 起点模型在真实场景里指挥一架 | 失去间隔 11.5 %，照标注的词飞 4.9 %，记录 2.6 %（[M3 读数](2026-09-28_m3_free_generation.zh.md)） |

数据：OpenSky，美国 5 个机场，72,574 架到达，跑道周围 25 km；按运行日划分，测试集 14 天封存；另有留出机场 KAUS。

## 2 结论：哪些新，哪些不新

| 部件 | 最接近的已有工作 | 新颖性 |
|---|---|---|
| 从 ADS-B 读出逐步的指令句子 | Pham 等 2020（航路，按规则读出动作，再用树模型分类）；雷达引导 / 等待的事件检测（IEEE 2022）；DLR Helmke、ATCO2、HAAWAII 一系都用语音做标签 | **中高**：没有人做逐步、多列、带跑道和进近许可的句子，也没有人用"执行器照着能飞回落地"检验标注 |
| 自回归指令模型（先验） | 自动驾驶：MotionLM、Trajeglish、SMART；航空：Tolstaya 2019（逆强化学习 + Dubins 规划器，没有离散指令） | **高**（在航空里） |
| 在真实记录的进场上闭环强化 | 自动驾驶：Peng 2024、SMART-R1、RLFTSim、R1Sim；航空：Bluebird 在数字孪生里从零训练 PPO（航路，没有预训练先验） | **高**：航空里明确的空白 |
| 规章写成解码屏蔽（CIFP 下滑道下沿、决断高度、7110.65 间隔） | 约束式解码（Geng 2023）、SaFeR 2026 | 低到中：方法常规，用在航空规章上是工程贡献 |
| 按运行日划分；按航班划分时跑道构型泄漏 | 航空轨迹预测里少见 | 方法论加分项 |
| 多机：teacher forcing 学不到交通 | 自动驾驶有同样的发现（Makansi 2022） | 在航空里是有价值的负面结果；要等闭环多机做出正面结果，才能单独成为主贡献 |

## 3 与自动驾驶相似工作的异同（重点）

### 3.1 对照总表

"步长"是一个词管多长时间；"闭环"指训练或评估时模型的输出会改变它下一步的输入。自动驾驶的数字都出自本地文献的 README
（`docs/literature/trajectory_as_language/`、`multi_agent_interaction/`、`manoeuvre_tokens/`），那里有页码。

| 工作 | 词是什么 | 步长 / 词表 | 训练 | 后训练与奖励 | 约束 | 评估 | 数据 |
|---|---|---|---|---|---|---|---|
| MotionLM（ICCV 2023） | 相邻两点的位移 (Δx, Δy)，均匀分档 | 0.5 s / 169 | teacher forcing | 无 | 无 | 开环预测榜（WOMD） | WOMD 103k 场景 |
| Trajeglish（ICLR 2024） | 状态到状态的变化，k-disks 聚类 | 0.1 s / 384（离散化误差约 1 cm） | teacher forcing + 加噪 | 无 | 无 | WOSAC 闭环 8 s | WOMD |
| SMART（NeurIPS 2024） | 0.5 s 的一段轨迹，k-disks | 0.5 s / 512–2048 | teacher forcing | 无 | 无 | WOSAC | 220 万场景，10 亿个词 |
| TrafficSim（CVPR 2021） | 连续潜变量（不是词） | 0.5 s | 闭环训练，穿过可微仿真反传 | 碰撞损失 | 采样时拒绝碰撞 | 闭环：碰撞 5.92 → 1.28 %（闭环）→ 0.50 %（加碰撞损失） | ATG4D |
| CAT-K（CVPR 2025） | 同 SMART | 0.5 s / 2048 | teacher forcing | **闭环监督微调**：在前 K 个词里选离真实下一状态最近的滚出去，目标是"让车回到真实位置的词" | 无 | WOSAC 真实度 0.7591 → 0.7702，胜过大 14 倍的模型 | WOMD |
| Peng 等（ECCV 2024） | MotionLM 的加速度词 | 0.5 s / 169 | teacher forcing | REINFORCE，奖励 = −位移误差 − λ·碰撞 | 无 | 碰撞似然 0.544 → 0.863，其中 91 % 在 λ = 0 时就得到 | WOMD |
| SMART-R1（ICLR 2026） | 同 SMART | 0.5 s | teacher forcing → CAT-K | 奖励 = WOSAC 真实度指标，KL 拉回 | 无 | 0.7734 → 0.7746；PPO / DPO / GRPO 单独用都**低于**监督微调 | WOMD |
| RLFTSim（CVPR 2026） | 同 SMART | 0.5 s | teacher forcing | REINFORCE，奖励 = 真实度指标，KL 拉回 | 无 | 0.7804 → 0.7830；只用"碰撞 + 出路"奖励反而降到 0.7786 | WOMD |
| R1Sim（RA-L 2026） | 同 SMART | 0.5 s | teacher forcing / CAT-K | GRPO，奖励 = 不碰撞 × 离真值近 | 无 | 在 CAT-K 之上 +0.0001 | WOMD |
| Plan-R1（arXiv 2025） | 运动词（自车规划） | 0.5 s 级 | teacher forcing | GRPO，**规则奖励**（安全、可行），KL 拉回；其他车由冻结的预训练模型推演 | 无 | 发现标准 GRPO 的归一化会把罕见的安全违规淹没 | nuPlan |
| SaFeR（arXiv 2026） | (加速度, 转向) | 0.5 s / 3969 | 冻结的先验 | 无 | **解码时屏蔽**：可行域之外的词不许说 | 去掉屏蔽，可解率 0.865 → 0.527 | WOMD + nuPlan |
| **我们** | **管制指令**：六列，每列"不变"或一个目标值 | **2 s / 每列 4–183 类**，每列只在 1–2 % 的步上换词 | teacher forcing | **GRPO 式截断的比，奖励 = 落在机场此刻的落地方向上（0 / 1）**，KL 拉回 base + 数据项 | **解码时屏蔽**：词表相容规则、程序高度、间隔 | 执行器飞到结局（约 5 分钟）；落地率 90.2 → 97.2 % | 5 机场约 4.5 万架训练航班 |

### 3.2 相同的地方（我们从自动驾驶借来的）

1. **把轨迹当语言、预测下一个词**：因果 Transformer，teacher forcing 预训练（MotionLM、SMART）。
2. **同一步里各智能体同时说**，只看上一步为止的一切（MotionLM 式并行解码；先验设计 §5）。
3. **时间注意力和智能体之间的注意力分开做**（SceneTransformer、SMART）；边特征既作注意力偏置，也加进被读取的值（MTR++、QCNet，先验设计 §6）。
4. **后训练的配方**：组内比较的优势（GRPO）、截断的比（PPO）、KL 拉回预训练模型（SMART-R1、RLFTSim）。
5. **约束写成解码时的屏蔽**，不写进损失（约束式解码、SaFeR）。
6. **评估要闭环**：模型自己说、自己飞，按结局判（WOSAC 的思路）。

这些借用要在论文里明说，不能当成我们的贡献。

### 3.3 不同的地方（我们的贡献在这里）

**① 词的含义不同：运动片段 对 指令。**
自动驾驶的词是 0.1–0.5 s 的一小段运动，由聚类或均匀分档得到，说了就立刻决定下一时刻的位置。我们的词是**管制员会说的话**——一个目标
（"航向 270""下降到 900 m""许可进近"），效果要十几秒到几十秒才显出来，中间由执行器按动力学去实现。所以：
- 词可解释，能与管制规章、程序对上（屏蔽可以直接照规章写，§3.3 ⑥）；
- 句子极稀疏：每列 98 % 以上的步是"不变"；
- 一个词和"下一时刻在哪"之间隔着一个执行器，这一点决定了下面 ③④ 两处差异。

**② 标签从哪来：确定的量化 对 反推。**
自动驾驶的词从轨迹**确定地**量化出来，量化误差可以直接测（Trajeglish 约 1 cm）。我们的词是从航迹**反推**管制员说了什么：一个没有真值的
逆问题（录音不在数据里）。我们的检验是回放门——照标注的词飞能不能落回原跑道（99.9 %）——这证明词**自洽、够用**，但不证明它就是
管制员当时说的话（§6 第 1 条）。这是自动驾驶那边不存在的一整层工作，也是审稿人最会追问的地方。

**③ 词到轨迹之间有一个物理执行器。**
自动驾驶里"词 → 下一状态"是运动学渲染（加上位移）。我们的执行器是自动驾驶仪式的控制律加点质量动力学，保证飞得出来（转弯率、坡度、
推力都在包络里）。模型只负责"说什么、什么时候说"，不负责飞行物理。这让先验的输出空间小、可解释，也让可飞性不必由模型去学。

**④ 闭环监督微调在我们这里失败，在自动驾驶是最大、复现过的收益。** 这是一个有价值、可以讲清楚原因的对照结论：
- CAT-K 能成立，是因为"让车回到真实位置的那个词"可以从当前状态**直接算出来**（0.5 s 的位移）；
- 我们的词效果要十几秒才显，"此刻该说哪个词才能回到记录"算不出来，只能拿"标注在那个时刻说了什么"作目标；而闭环链离记录越飞越远
  （220 s 时中位数偏 1 km），标注的"此刻许可、此刻转向"在链上的飞机那里往往不成立；
- 结果模型学成"早许可、少说话"：被引导 83.3 → 81.0 %，teacher forcing 负对数似然 0.284 → 0.452（[后训练设计](../post_training_design.zh.md) §6）。
- 推论（可以写进论文）：**词的作用时间远长于一步时，闭环监督微调的前提不成立，只看结局的强化学习才合适。**

**⑤ 强化学习是主力，奖励是"完成任务"，不是"像数据"。**
自动驾驶里强化学习只加一点点（R1Sim 在 CAT-K 之上 +0.0001；SMART-R1 里 PPO / GRPO 单用都不如监督微调），奖励多是"真实度"指标，
手工的安全奖励甚至降低真实度（RLFTSim）。我们的强化学习带来了主要收益：落地 90.2 → 97.2 %，被引导的进近 83.3 → 93.9 %，而 teacher
forcing 负对数似然不变（没有离开数据）。奖励是可以直接验证的结局（落没落地、落在哪个方向），更接近大语言模型里"可验证奖励的强化学习"
（数学题对不对），而不是自动驾驶的"像不像人"。KL 拉回 + 数据项保住了"像管制员"。

**⑥ 约束来自成文规章，可以精确写成屏蔽。**
自动驾驶的约束（不碰撞、不出路）大多只能在飞出来之后检查，或用学出来的可行域近似（SaFeR）。航空有成文、可引用的规章与公布程序：
CIFP 的下滑道与决断高度、FAA 7110.65 的间隔与尾流标准。我们把它们直接写成"哪些词不许说"（程序高度、两条间隔屏蔽），每一条都能引用
到条款（先验设计 §5.1，多机设计 §3）。

**⑦ 时间尺度与评估不同。**
WOSAC 只滚 8 s，按与记录的分布相似度打分。我们一次滚到落地（约 5 分钟、约 150 步），按执行器判定的结局打分（落地、超时、偏出跑道、
失去间隔……）。航空没有公认的闭环基准；这既是缺口（审稿人会问怎么比），也是机会（§7 的数据集论文）。

**⑧ 交互弱，而且在 25 km 内看得到的很少。**
驾驶场景一次上百个智能体、0.1 s 级的相互让行；我们的场景只有 1–3 架（p90 2–4），排序大多在 25 km 以外完成，交互是按规章间隔的
"前后机"关系。我们的 M1、M2 都表明 teacher forcing 学不到交通（与 Makansi 2022 在行人数据上的发现一致）；M3 给出闭环下的差距
（11.5 % 对记录 2.6 %）。交互要在闭环里用间隔奖励学，这与 TrafficSim、Peng 的结论方向一致，但我们的"碰撞"是规章里的间隔，不是几何重叠。

**⑨ 数据量小一个到两个数量级，划分更严格。**
WOMD 约 49 万个场景；我们约 4.5 万架训练航班。我们按运行日划分、测试日封存，因为按航班划分时跑道构型会泄漏（跑道意图研究 R1：KSJC
30L 关闭的两天，按航班划分训练出的模型只判对 55–57 %，规则基线 97–98 %）。自动驾驶的基准按场景随机划分，没有这个问题。

### 3.4 自动驾驶里还有、我们可以借的

| 做法 | 出处 | 用在哪 |
|---|---|---|
| "去掉所有邻居"的归因检验 | Makansi 2022 | 已在 M2 用（切掉飞机之间的注意力）；论文里作为标准检验写出 |
| 按真实度指标做奖励、留一法的基线 | RLFTSim | 多机强化时防止"比数据更安全"（多机设计已按记录的失去间隔率作参照） |
| 同一步内按次序解码 | Trajeglish | 间隔屏蔽需要知道同一步里前面的飞机刚说了什么时 |
| 其他智能体用冻结的预训练模型推演；罕见违规不被 GRPO 归一化淹没 | Plan-R1 | 多机 M4：别的飞机怎么动、失去间隔这种罕见事件的奖励怎么进优势 |
| 公开基准的评估协议（多次采样、多项指标加权） | WOSAC | §7 的数据集 / 基准论文 |

## 4 航空里已有的相关工作

本地已读（有页码）的见 `docs/literature/multi_agent_interaction/README.md` §2.D；本次新找到的见
`docs/literature/controller_instruction_learning/README.md`。

| 工作 | 做什么 | 与我们的关系 |
|---|---|---|
| Pham, Alam, Duong 2020（*Complexity*） | 新加坡航路，ADS-B 约 15 s 一点；只用每架航班进出扇区的两点，速度、高度、航向变化各按阈值读成 {−1, 0, +1}（每轴每架一个动作），再用分类器预测，三轴同时对 69.5 % | **唯一只靠航迹读动作的先例**，但粒度比我们的 2 s 指令流粗得多；没有生成模型和执行器 |
| Pérez-Castán 等 2026（*Applied Sciences*） | 西班牙 ENAIRE 数据；指令来自**记录**（雷达回放 + 录音的人工标注，以及读管制席位输入的 ROSETTA 工具），只学"是不是为了分离"这一意图，事件级六类，分类器 | 指令不是反推的；分类器 |
| Zhang, Zhang, Tay & Shankar 2022（IEEE ITSC） | 小 CNN 在航迹 + SID/STAR 栅格上识别等待与雷达引导事件，需要 500–1,000 条人工标注 | 事件级，没有带时刻的指令 |
| Bastas & Vouros 2022；Vouros 等 2023 | 用 ENAIRE **记录的**冲突解脱事件（5 s，速度改变、直飞），预测管制员何时反应（F1 ≥ 0.985），动作类型只有 F1 0.59 / 0.66；不飞预测结果；另一篇在仿真里从零做强化学习 | 同一难点（"数据只显示效果不显示原因"）；航路、开环 |
| Tolstaya 等 2019（IROS） | 西雅图三天的进场，约 30 s 一点；逆强化学习学航路代价，搜索规划器逐架开环规划 | 真实终端区进场 + 规划，但没有指令、没有策略、没有后训练 |

| Carvell 等 2026（AIAA） | 小指令词表（转 ±10°），推理时合并成一条许可 | 离散指令词表的先例，仿真器里、没有记录数据 |

## 5 为什么值得发表

1. 航空里第一个"从公开监视数据学管制员说话，并能自己把飞机指挥落地"的系统，每一层都有可检验的门（标注 → 回放 → 先验 → 闭环）。
2. 有一个清楚的、可推广的对照结论：**词的作用时间长于一步时，闭环监督微调失败、结局强化成功**（§3.3 ④⑤）。这对自动驾驶的读者也有意思。
3. 有航空特有的方法：规章写成屏蔽、按运行日划分避免跑道构型泄漏。
4. 负面结果诚实可用：teacher forcing 学不到交通（M2），为什么交互要在闭环里学。

## 6 薄弱环节，按优先级

1. **标注的词是不是管制员真说的**：现在只有自洽检验。现成的公开数据不够用（TartanAviation 是通用航空小机场的塔台频率、没有转写，§4）；
   可行的是录我们五个机场之一的**进近频率**（LiveATC）几天，用 ATCO2 一系的语音识别模型转写，抽几百架对照"许可进近、转向、下降"的
   时刻和数值。这一条补上，论文可信度提升最大。
2. **外部基线**：落地率是我们自己定义的、执行器也是我们自己的。至少对照：单层 control 模型、规则引导（`outputs/guidance/`）、
   优化器、一个开环生成模型（如 FlowATC）；同时报 evaluation 的通用判定和几何 / ADE 指标。
   其中"连续片段代替指令词"的对照（不用标注器、其余不变）设计在 [连续片段对照实验](../continuous_segment_ablation_design.zh.md)。
3. **泛化到没见过的机场**：KAUS 留出机场上的自由生成与落地率。
4. **范围只有最后约 25 km、约 5 分钟**：论文里明说能学到什么、不能学到什么（排序大多在范围之外）。
5. **种子**：landing、augmented 目前各只有一个种子；主表要有第二个种子或说明噪声线。
6. **多机**：M4（闭环间隔奖励）若把 11.5 % 明显压向记录的 2.6 %，就是第二篇论文的主结果。
7. **数据许可**：若发布句子产物，先确认 OpenSky 的使用条款是否允许再分发派生数据。
