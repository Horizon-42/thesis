# 多机 M3：起点模型在多机闭环里指挥一架（2026-09-28）

**一句话**：起点模型——augmented 加上输出为零的交通注意力，说的词与 augmented 相同到舍入——在真实场景里指挥一架、其余照记录回放，
**11.5 % 的样本因失去间隔被结束**（目视读法）；同一批航班照标注的词飞 4.9 %，照记录走 2.6 %。把别的飞机和两条间隔屏蔽都拿掉让它单独说
（再放回同一场景里判）是 12.3 %：屏蔽只挡掉一点。失去间隔几乎都出在**被引导的进近**上（21.6 %，直线进近 4.0 %）：它的句子让它落地的时间
比记录早晚最多约两分钟（p10 −111 s、p90 +121 s，照标注的词飞只有 −36 s / +21 s），挤进了别的飞机按记录排好的次序里。它看不见别的飞机，
这在意料之中；这正是 M4 的奖励要教它的，信号足够多。**扩充场景**（§4）上更难：失去间隔 23.9 %（单独 25.8 %），
插一架到它前面的场景 37.6 %，插得比规章间隔还近的 63.6 %。

设计：[多机设计](../multi_aircraft_design.zh.md) §6.1 M3 一行、§6.6 第 4 步、§7；上一步：[M2 读数](2026-09-28_m2_scene_prior.zh.md)。

## 1 量法

- **模型**：augmented（第二阶段第 7 轮，`outputs/POOLED/prior/v3_stage2_clip_20260926/aug_s1337/round_07`）加上每层一个交通注意力
  （`prior.model.with_traffic`，输出层为零）：它说的词与 augmented 相同到舍入（设计 §2.5、§6.6 第 1 步）。执行器 v11
  （`outputs/POOLED/executor/v11_20260927`），指令产物 v5（`outputs/POOLED/instruction_language/v5_20260926`）。
- **航班**：内部选择集（9 个选择日），每机场按种子 1337 抽 400 架有句子、执行器飞得了的航班，共 2,000 架（执行器飞不了、没有抽的 285 架：
  没有机型动力学 143、只有替身动力学 117、认不出机型 23、机型没公布进近速度 2）。每架的场景 = 同一段时间落同一机场的所有航班
  （有句子的 6,843 架、背景 69 架；没有机型的 88 架不放进场景），平均每架身边 3.0 架。
- **四种读法**，都放回同一个场景、从第一个预测步起判：
  - **场景里的模型**：模型每步说一行、执行器飞 2 s，其余飞机照记录回放；屏蔽全开（相容规则、程序高度、两条间隔屏蔽——速度词、进近许可）；
    每架 `K` = 4 次；
  - **单独的模型**：同一个模型，场上只有它、没有间隔屏蔽（= 单机的自由生成），飞出来的航迹再放回场景里判；每架 4 次；
  - **照标注的词飞**：执行器照这架的标注词飞（执行器的底线），每架 1 次；
  - **记录**：这架的观测航迹，每架 1 次。
- **判法**：目视读法（C36）下失去间隔、且这一架要负责（邻机照记录走、不会让路，只问这一架，设计 §3.4），这一架被结束；IFR 读法并排记。
  第一个预测步就已经失去间隔的样本不是模型造成的，不计（场景、单独各 8 个，来自 2 架；标注 2、记录 1）。
- 代码：`experiments/traffic_free_generation.py`（R31，分支 `dev-multi-aircraft` `a0c31f3c`，干净的树，opus 审查过）；产物
  `outputs/POOLED/traffic/free_generation_20260928/`（`free_generation.json` 汇总，`flights.jsonl` 每个样本一行）；79 分钟。

## 3 怎么读（我的读法）

- **起点模型不会保持间隔，这在意料之中**：交通注意力输出为零，它看不见别的飞机；两条屏蔽只管速度词和进近许可，挡不住它的航向和
  下降时机把它带到别的飞机的位置上。失去间隔是记录的约 4 倍、标注词的约 2.3 倍。
- **问题在被引导的进近上**：直线进近 4.0 %，只比照标注的词飞（3.8 %）多一点；被引导的 21.6 %。被引导时它的句子让落地时间在记录的
  ±2 分钟里散开（标注的词只散开约半分钟）——管制员引导一架飞机的时候是按前后的飞机排好的，模型说的是"这类飞机通常怎么被引导"，不管
  它此刻排在谁后面。这是个时序问题，不是飞得不稳：其他结局（超时、过入口太高、偏出跑道、低于下滑道下沿）合计 3.6 %，场景与单独差不多。
- **大多数失去间隔只差一点**（最近时中位是要求距离的 98 %）：多半是追上了前机、或者挤到了别人的前面，差几秒。奖励"落地且不失去间隔"
  能给的信号很多：记录没有问题的航班上仍有 10.5 % 的样本失去间隔，同一架的 4 个样本里常常有的失去、有的不失去（1–3 个失去的 395 架）——
  这正是按同一架比优势需要的。
- **KRDU 的 IFR 读法高得多**（19.5 % 对目视 12.3 %）：KRDU 平行跑道多、身边飞机多，IFR 读法不承认目视进近许可下的平行进近；训练用目视读法
  （C36），IFR 只并排看。
- **M4 要改的不是屏蔽**：屏蔽已经处处硬用、几乎不挡词；要靠交通注意力学会看前后的飞机、据此选航向和速度。

## 4 扩充场景

同一批航班，每架的场景按三种做法之一扩充后再读一次（设计 §5、§6.6 第 5 步；扩充种子 7919，只读"场景里的模型"和"单独的模型"两种——挪了起点的
没有记录可比）：D 挪前机（同一跑道或按一条跑道算的前机整段挪 −60 … 60 s）346 架、B 挪起点（第二阶段的做法，时限 × 2.0）815 架、A 插一架
（同一跑道 / 单跑道对 / 相关平行跑道的一架有句子的航班，放在进近时钟上它之前 g × 规章间隔，g ∈ [0.5, 2]）839 架；2,000 架都在 10 次内抽到合格的，
没有漏掉的。产物 `outputs/POOLED/traffic/free_generation_aug_20260928/`（分支 `de9a539a`，干净的树，107 分钟）。平均每架身边 4.0 架。

| 目视读法 | 样本 | 失去间隔 | IFR 读法 | 落地 | 单独的模型：失去间隔 |
|---|---|---|---|---|---|
| 合计 | 7,997 | **23.9 %** | 26.5 % | 70.7 % | 25.8 % |
| D 挪前机 | 1,384 | 16.9 % | 18.3 % | 78.6 % | 19.1 % |
| B 挪起点 | 3,260 | 12.9 % | 14.6 % | 79.2 % | 14.2 % |
| A 插一架 | 3,353 | 37.6 % | 41.5 % | 59.2 % | 39.8 % |

（这里的"落地"是没有被失去间隔结束的落地；分做法的样本数按每架 4 句算。）

细分（场景里的模型）：

- **A 按插得多近**：g < 1（一开始就比规章间隔近，要靠说话拉开）63.6 %；1 ≤ g < 1.5 30.5 %；g ≥ 1.5 20.5 %。结束它的那次失去间隔 935 / 1,260 是和
  插进来的那架。
- **D 按挪的方向**：前机往前挪（更早，拉开）12.0 %；往后挪（更晚，更近）22.8 %。结束它的 113 / 234 是和被挪的那架。
- **按进近方式**：直线进近 D 12.2 %、B 7.6 %、A 30.2 %；被引导 D 22.2 %、B 20.5 %、A 47.2 %。
- 分机场（场景里 / 单独）：KMSY 18.8 / 21.9 %，KRDU 24.7 / 26.0 %，KSJC 23.0 / 26.1 %，KSMF 25.4 / 27.2 %，KSTL 27.8 / 27.7 %。
- 两条屏蔽起作用的步：进近许可 3.9 %、速度 1.6 %（真实场景 2.7 %、1.05 %）；场景比单独少失去间隔 1.9 个百分点（真实场景 0.8）。

**怎么读（我的读法）**：扩充场景做到了设计要它做的——把"要让"的情形变多：A 里一开始就太近的那三分之一，六成多以失去间隔告终，而起点模型看不见
那架飞机，屏蔽也只挡住一小部分。B 与真实场景相近（12.9 % 对 11.5 %）：挪起点改变的是自己的航迹，不是交通。M4 的奖励在扩充场景上有大量对比
（同一场景 4 句里有的失去、有的不失去），这是选轮的主读数（设计 §6.2：扩充场景上"落地且没有失去间隔"的比例）。
