# 多机 M4：交通后训练，一架由模型指挥（2026-09-29）

**一句话**：8 轮交通后训练跑完（11 小时 22 分钟），**按规则选中的仍是第 0 轮，也就是起点模型**。原因有两个。
第一，扩充场景的奖励最多只比第 0 轮高 0.014（第 7 轮），没超过平手容差 0.015。第二，第 6、8 轮真实场景的落地率比第 0 轮低了 1 个百分点以上，
被护栏排除。失去间隔确实在降：同一批抽样逐句配对比，从第 0 轮到第 8 轮，真实场景净降 1.05 ± 0.54 个百分点，扩充场景净降 1.80 ± 0.63 个百分点
（第 7 轮时 2.70 ± 0.60）。降得最多的是交通冲突摆在眼前的两类扩充——插一架（35.7 → 30.9 %，第 7 轮）、挪前机（20.6 → 16.8 %，第 6 轮）。
代价是真实场景的落地率一点点往下走（0.946 → 0.932–0.938），两头相抵，真实场景的奖励没涨（0.842 → 0.838）。真实场景里失去间隔集中在少数航班上：
第 0 轮两个样本都失去间隔的 73 架占了全部失去间隔的 60 %，这些航班照管制员实际说的词飞也有 35.6 % 失去间隔（照记录飞 16.4 %）。
模型几乎从不说复飞（每轮选择集 0–1 句）。

设计：[多机设计](../multi_aircraft_design.zh.md) §6.2、§6.6 第 6 步（细节第 1–13 条）、§7；上一步：[M3 读数](2026-09-28_m3_free_generation.zh.md)。

## 1 量法

- **起点**：augmented（第二阶段第 7 轮，`outputs/POOLED/prior/v3_stage2_clip_20260926/aug_s1337/round_07`）加上每层一个输出为零的交通注意力，
  说的词与 augmented 相同到舍入（设计 §2.5、§6.2）。拉回对象 base（`v3_step1_20260924/full_s1337`）。执行器 v11（`outputs/POOLED/executor/v11_20260927`，
  sha256 `33300cd6…`），指令产物 v5（`outputs/POOLED/instruction_language/v5_20260926`）。
- **每轮训练**：训练集运行日，每机场 200 个真实场景 + 200 个扩充场景（插一架 A、挪起点 B、挪前机 D 各约三分之一），每个场景说 8 次，共 16,000 句；
  奖励 1 = 落在机场此刻的落地方向上、且没有因失去间隔（目视读法）被结束。一遍更新：截断的比 + 0.04 × 拉回 base + 1 × 数据项（M2 的场景样本）；
  交通注意力学习率 3e-4，其余 1e-5（设计 §6.2、§8）。
- **每轮读数**（内部选择集）：每机场 200 架 × 2 句，真实场景和各自一个固定的扩充场景。**每轮用同一串随机数说**（有意这样，让各轮可以直接比）：
  同一架航班的同一个样本，每轮抽到的是同一组随机数，结局只随模型变而变——第 0–8 轮里真实场景 87.6 %、扩充场景 83.1 % 的"航班 × 样本"每轮结局都一样。
  所以轮与轮之间按句配对比，不是重复抽样。
- **选哪一轮**：先排除护栏变差的轮（真实场景落地率比第 0 轮低 1 个百分点以上等，设计 §6.2），剩下的按扩充场景奖励最高，差 0.015 以内取更早的。
- **代码**：正式运行 `experiments/traffic_reward.py`（R32），分支 `run-m4-traffic-20260929`（= `dev-m4-speed` `3976acbd`，4 个说话进程，设计 §6.6 第 12、13 条），
  产物 `outputs/POOLED/prior/m4_traffic_20260929/traffic_s1337/`。读数 `experiments/traffic_reward_readout.py`（R33，分支 `dev-m4-readout` `9b744b5b`，
  干净的树，opus 审查两遍），产物 `outputs/POOLED/traffic/m4_readout_20260929/traffic_reward_readout.json`；真实航班照标注的词飞、照记录飞的结局取自
  M3 的 `free_generation_20260928`（同一执行器、同一指令产物，记录的读数与运行自己的记录读数逐位相同：999 架里 26 架失去间隔）。
- **时间与资源**：共 11 小时 22 分钟（第 1 轮连同建数据和第 0 轮读数 98 分钟，之后每轮 82–85 分钟）；显存峰值 7.63 GB（共 8.19 GB），

## 3 怎么读（我的读法）

1. **学到了一点，但没学到能被选中的程度。** 扩充场景的失去间隔确实降了（配对 −1.8 到 −2.7 个百分点，3–4.5 倍标准误），主要在插一架、挪前机——冲突
   就摆在眼前的场景。选择规则的平手容差 0.015 是从单机第二阶段沿用来的（那里比的是扩充起点的落地率），M4 最好的一轮差 0.001 没过线。
2. **真实场景几乎没变，而且落地在一点点变差。** 真实场景失去间隔净降 1.05 ± 0.54 个百分点（约 2 倍标准误，边缘），落地率降了 0.7–1.4 个百分点，
   奖励不涨。交通注意力的输出一直在变大（第 4 层 0.012 → 0.038），它在学东西，但学到的更多是在扩充场景里"让开"，也碰掉了一点落地。
3. **真实场景有一块很难靠这一架自己改掉。** 两个样本都失去间隔的 58–73 架航班，照管制员实际说的词飞也有 36–40 % 失去间隔：别的飞机照记录回放、
   不会让路，现实中管制员是同时调几架的。这正是"窗口内由模型指挥"（设计 §6.6 第 7 步）要回答的。这些场景 8 句往往全失去间隔，对训练也没有信号。
4. **一轮挪得太少、信号摊得太薄。** 每轮 KL 只有 0.008–0.01；奖励只在一句的最后给，整句 125–177 步都分到同样的分数，而决定会不会失去间隔的
   多半是冲突前几步的速度词或转弯。
5. **复飞用不上**：数据里 0 次，模型几乎不说，奖励上复飞和失去间隔同样得 0（设计 §6.6 第 8 步）。
