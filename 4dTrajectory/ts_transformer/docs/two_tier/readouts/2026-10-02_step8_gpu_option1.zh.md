## 0 几个词先说清楚（全文同一个意思）

- **窗口**：一个机场里一段 20 分钟的到达流量。窗口里**被指挥的飞机**由模型替它说话、执行器照词飞；**照记录回放的飞机**按真实记录飞，不会因别人的改变而变。
- **窗口样本**：把整个窗口说一遍。一个窗口一轮说 8 个样本（编号 0–7）。**句子**：一架被指挥的飞机在一个窗口样本里说的全部词。
  一架飞机有 8 句（每个样本一句）。一步 = 2 s；"自己的第几步"从这架飞机被模型接手的第一个预测步算起。
- **进近列**的三个值：未许可 / 许可加入（下面简称"许可"）/ 复飞。转换只许：未许可 → 许可 → 复飞 → 许可（设计第 6 条）；所以复飞之后进近列只能再说"许可"，不能说"未许可"。
- **种类**：真实 = 原样的窗口；扩充窗口三种：A 窗口里插进一架被指挥的飞机；B 挪一架的起点；C 把流量压紧。
- **失去间隔**：判定（目视读法，设计 §3.2）因为间隔不够把这架飞机判为结束；这一句的奖励 0，也不再给复飞的 S / H / Q。
- **落地（本文的两种）**：①"落地"（表里写"落地"）= 执行器自己飞出来的结局是落地——被判失去间隔结束后仍让它飞完也算；`history.json` 里的 `landed` 是这个，分母是全部句子；
  ②奖励 1 的"落地"= 落地、落在机场此刻的落地方向上、没被判结束。两者数目不同（例：第 1 轮训练句子，①78.37 %，判定结局为落地的 75.11 %）。
- **落在观测跑道**：落地的句子里，落在这架真实航班实际落的那条跑道上的份额（分母是落地的句子）。
- **奖励**：没说复飞的句子：奖励 1 的落地 = 1，否则 0。说了复飞的句子（设计第 9 条）：失去间隔或坠毁 = 0；否则 0.48·L + 0.14·(S + H + Q)，最多 0.9。
  **S** 间隔：复飞 30 s 后到重新截获为止与所有别的飞机的最小间隔余量 m，S = min(1, max(0, m − 1))；
  **H** 离开进近高度：复飞后在 1.25 × T_需 以内爬到进近高度得 1，到 2 × T_需 线性降到 0（T_需 = 执行器自己的复飞爬升从复飞那一刻的状态爬到进近高度要的时间）；
  **Q** 回到进近：只在 S 和 H 都大于 0 时给，复飞到重新截获 ≤ 421 s 得 1、线性降到 598 s 得 0；**L** 再落地：奖励 1 的落地为 1。
- **试探样本 / 代说**（设计第 10 条）：每架飞机 8 个样本里编号 4–7 的 4 个是试探样本。试探样本里，一架由模型说话、已许可、已截获、高度在进近高度以下、还没复飞过的飞机，
  在它上一步与别的飞机的最紧余量低于 1.5 的那一步，复飞这个词由闭环替它说（**代说**），之后的词仍由模型说；一句最多代说一次。选择集读数从不试探。
  **没代说的试探样本**：试探样本里这个条件一直没出现的。
- **试探增益**（代说的句子才有）= 这句的奖励 − 同一架飞机不试探的几句（样本 0–3）的平均奖励。为正才学代说的复飞词（加一项按增益加权的交叉熵）。
- **三组优势**（选项 1）：一架飞机的 8 句分成三组——不试探的 4 句、试探了但没代说的、代说了的——每句的优势 = 它的奖励 − 本组的平均；一组里奖励都一样，这一组不进训练。
- **配对标准误**：同一架飞机、同一个样本编号在两轮里各有一句（选择集每轮用同一批窗口、同样的随机数流），两轮奖励之差的均值，标准误 = √(两轮结局不同的句子数) ÷ 句子数（选轮规则用的算法，
  [`traffic_reward.paired_difference`](../../../experiments/traffic_reward.py)）。同一架飞机的 2 句当作独立的，所以偏窄。
- **p25 / p50 / p75**：从小到大排好后 25 % / 50 % / 75 % 处的值。

## 4 强制复飞之后发生了什么

这一节只看**代说了复飞的句子**（第 1 轮 487 句、第 2 轮 443 句）和模型自己的句子。第 2 轮的句子由第 1 轮的模型说，窗口与第 1 轮不同，**不配对**；

- **与 CPU 测试比较要小心**：CPU 测试的 H 平均是 0、Q 是 0，这里是 0.38–0.41 和 0.29–0.30——**不是模型变了**。CPU 测试 T3 用的代码是 `7c2556c9`（选项 1 的 `3a62fc3a` 和之后的 `534c9cca` 都还没有）：
  奖励的 H 那时按"只走梯度 200 ft / 海里要的时间"算，刚过最后进近定位点的飞机只有几秒，比执行器停住下降本身还短；`534c9cca`（用户 2026-10-02 定）改成按执行器自己的爬升算（下降转爬升的十几秒算在内），
  并让没落地的复飞也给 S / H / Q（CPU 测试里过入口太高的 8 句 S / H / Q 全是 0；这里这类句子第 1 轮 74 句，S 平均 0.47、H 0.68、Q 0.64）。
  所以奖励、S / H / Q、L 的数不能与 CPU 测试比；**词的数**（§4.3）可以比。

1. **选项 1 在训练信号上做到了设计要的**。同一批代说句子，优势为负的从 79.7 % 降到 34.9 %（第 2 轮 76.1 % → 33.2 %），平均优势从 −0.29 回到 0；

## 6 数据里不一致或要当心的地方

- **`landed` 有两种数**（§0）：`history.json` / `sentences.json` 汇总里的 `landed` 是执行器自己的结局（含被判失去间隔后仍飞完的），不是判定结局为落地的份额；第 1 轮训练句子 78.37 % 对 75.11 %（3,299 句）。
  选择集的"落地"和护栏用的是前者。`landed_on_observed_runway` 的分母是前者里落地的句子，不是全部句子。
- **`sentences.npz` 的词要按 `counted` 截断**：被判失去间隔结束的句子（第 1 轮 800、第 2 轮 707 句）里 `said` 的长度大于 `counted`（后面是飞机沉默继续飞的步数），其中 218 / 177 句在结束那一步还存着一个执行器没有飞的词。
  `forced` 也有 1 句 / 轮落在 `counted` 的位置上（代说发生在飞机被判结束的那一步，奖励 0，训练时算作 −1）；它们仍计在 `said_by_a_probe` 里（487 / 443）。
- **选择集每轮 `left_out_starting_in_a_loss` 不同**（真实 5 / 9 / 7，扩充 9 / 5 / 7）：起点就在失去间隔里是别的飞机的词造成的，每轮会变，所以每轮计奖励的句子数不同，配对取两轮都有的（640–700 句）。
- **两个巧合**（我核过，不是错）：两轮的真实训练窗口各有 247 架被指挥的飞机（航班 id 重合 0 个；分机场是 34 / 55 / 60 / 47 / 51 对 50 / 57 / 42 / 51 / 47，不同）；
  两轮的 100 个扩充训练窗口里 A / B / C 的个数都是 33 / 32 / 35（候选池里的个数不同：41 / 45 / 39 与 42 / 36 / 47）。
  扩充的种类每个窗口是随机抽的，我没有查这两个相同的数有没有别的原因。
- 第 1 轮 549 个"窗口 × 飞机"对应 548 个航班 id，第 2 轮 524 对 521：同一个航班在两个重叠的窗口里各出现一次，正常。
- 起点已在失去间隔里的句子（68 / 35）不计奖励；它们的飞机整架不进训练（23 / 22 架），所以进训练的句子里没有它们。
- `config.json`、`choice.json` 里的路径指向运行时的工作树 `.claude/worktrees/step8-events-run/…`，不是现在的目录；`run.sh` 的 `$R`（pid 文件和日志的目录）是 `…/step8_probe_test_20261002.run`，而 `--out` 直接写 `…/step8_probe_test_20261002/window_s1337`；现在的 `run.log` 在后一个目录里（我没核它是怎么搬过来的；`SHA256SUMS` 与文件一致）。
- 没有发现数值上互相矛盾的地方：`history.json` 的汇总与 `sentences.json`、`readout.json` 的逐句行重算相等（训练的奖励 / 失去间隔 / 落地、进了训练的句子数、优势、增益；选择集的奖励、失去间隔、落地、观测跑道、`against_round_0`）。
