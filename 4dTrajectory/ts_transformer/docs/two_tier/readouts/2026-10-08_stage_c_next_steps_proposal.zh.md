## 3 诊断（只读数，不训练）

建议做法：新写一个 runner `experiments/post_diagnose.py`（`python run_ts.py post_diagnose …`），复用
`post_train.selection_windows`、`read_batch`、`round_model`、`counted_ends`，加三个选项，都只用于读数：

| 选项 | 默认 | 作用 |
|---|---|---|
| `--temperature T` | 1.0 | 说话的温度（`prior/speaker.py` 已有 `temperature` 参数；需要从 `WindowLoop` 一路传下去）。只在这个 runner 里可设；训练和 `selection_readout` 不暴露这个选项 |
| `--traffic-off` | 关 | 读入 checkpoint 后，把每个 `TrafficAttention.out` 的 weight 和 bias 置零（与 D116 起点的零输出同一做法），模型其余部分不变 |
| `--per-window` | 开 | 每个窗口写一行：窗口 id、机场、结局、奖励、复飞数、`loss_step`、`other`、`loss_reads_fault`，以及 G1 的分类字段 |

draw 0 用读数自己的随机数：在温度 1、交通模块开时，结果必须与该轮 `round.json` 的 `selection_readout` 一致，
不一致就按名字拒绝（与 `post_ceiling` 的检查相同）。这同时检验 runner 本身。

### G1 失败拆解

**问题**：起点的失败约 80 % 是丢间隔（11.7 / 14.3）。这些丢间隔集中在哪里？有多少从一开始就救不回来？

**做法**：在 C10 第 8 轮上跑 `--per-window`（温度 1，交通开），对每个丢间隔的窗口，从 `WindowResult` 和窗口的场景算：

1. **对方是谁**：同跑道的前机（对方在被指挥机之前落地在同一跑道）／同跑道的后机／平行或其他跑道的进近／不落地的飞机。
2. **发生在哪**：`loss_step` 时刻被指挥机到跑道入口的距离，分段 0–10、10–20、20–40、> 40 km。
3. **发生在何时**：`loss_step` 距第一个预测步的秒数，分段 < 60、60–120、120–300、> 300 s。
4. **开局时是否已经冲突**：在第一个预测步时，与对方按记录航迹外推（双方都不改变速度）的最近距离是否已经低于间隔标准。
5. 与 C15 上限读数（`ceiling_20261007`）的"32 次全都丢间隔"的窗口取交集。

另外在 C10 第 8 轮上，对**一轮 train 的抽样**（`draw_round` 用 C10 的种子、某一轮，真实/A/D/B 各 1,000）跑一次同样的
拆解，按窗口类型分开。select 只有真实窗口，看不出 A/D/B 的差别。

**输出**：`g1_failures.json`（各类计数与占比，按机场），`per_window.jsonl`。

**判定（建议）**：
- 若"开局已冲突"加"32 次全丢"的窗口占丢间隔的 ≥ 40 %：这部分不是训练能解决的，把它们从目标里剔除，重新估计可达上限；
  这时优先检查窗口的抽取规则（D113 只剔除"开局就在丢间隔里"的窗口）。
- 若某一类对方或某一距离段占丢间隔的 ≥ 50 %：后续 T1 的塑形和 G2 的分析都对准这一类。
- 若 train 抽样里 A 或 D 窗口的丢间隔率是真实窗口的 2 倍以上：报告给用户，考虑调 D103 的平移范围。

### G2 交通模块消融

**问题**：模型到底有没有在用交通信息？

**做法**：C10 第 8 轮，`--traffic-off`，温度 1，读 select。对照：同一轮交通开（= 该轮记录的读数），以及 C10 `start`
（交通模块本来就是零输出：它与第 8 轮交通关的差别，就是 prior 本体在后训练里学到的东西）。

**输出**：三者的落地、丢间隔、平均奖励，按机场；第 8 轮交通开减交通关的配对差值和 95 % 区间。

**判定（建议）**：
- 交通关只比交通开低 < 2 个百分点（区间包含 0）：模型基本没在用交通信息。**暂停一切 RL 方法上的实验**，
  瓶颈在"看见"：token 的特征（D117）、交通模块的容量、学习率（交通模块 1e-4）。给用户写一份关于这方面的提议。
- 低 ≥ 5 个百分点：交通信息在起作用，瓶颈在信用分配，按原计划走 D170 / D171，再加 T1。
- 介于两者之间：报告数值，由用户定。
- 附带记录：第 8 轮交通关对 `start` 的差值，说明 prior 本体在后训练里移动了多少。

### G3 温度扫描

**问题**：85 % 对 99.3 %（32 次至少落地一次）的差距，是模型最可能的说法就不对，还是采样的熵太大？

**做法**：C10 第 8 轮，交通开，温度 0.5、0.7、1.0（1.0 = 读数自检），读 select。

**输出**：每个温度的落地、丢间隔、复飞、平均奖励；相对温度 1 的配对差值和区间；句子的平均长度（行数）。

**判定（建议）**：
- 温度 0.7 比温度 1 高 ≥ 3 个百分点：差距的主要部分是熵。两条路交用户定：
  (a) 部署时降低温度（这改变 D125 / P39 的"温度 1"，是用户的决定）；
  (b) 训练侧让分布变尖，例如提高对已落地句子的利用。这时 C17 停住的原因需要重新看。
- 低温反而更差或持平：最可能的说法本身有问题，熵不是瓶颈；训练侧保持 D170 / D171。
- 注意：低温下复飞（go-around）的概率也会变，复飞数要单独报告。

### G4 PIPO 的离线信号检查

即 `docs/post_training/PIPO_feasibility.md` §7 的 step 0：用 C10、`post_lr3`、`post_branch16` 的 `round.json`，
算每轮首遍说话的平均奖励 µ_r 和窗口 K = 3、4、8 的 ξ_r，看 ξ_r 的符号与 select 读数的实际变化是否一致。
**先确认** `round.json` 的 `speaking` 记录能否直接给出首遍的平均奖励；不能的话，从首遍的结局计数算，并写明方法。
**判定（建议）**：符号一致的轮次 < 70 % 就不实现 PIPO。纯读文件，不需要 GPU。

### 诊断的代价（估计）

一次 select 读数在 C10 上约 12 分钟（随说话 worker 数变化）。G1（含一轮 train 抽样）、G2 两次、G3 两次，共约 5–6 次读数，
约 1–1.5 小时；G4 只读文件。新 runner 加测试约 200–300 行（Claude 的估计）。

## 4 训练侧的候选（等诊断结果和用户批准）

三个候选都通过新的 campaign 设置实现，默认值等于现在的行为；只用于 `--method branch` 和以后的 `value`，
在 `--method landed` 下按名字拒绝。

### T1 用间隔裕度做势函数塑形（改变 D30，需要用户决定）

**为什么**：丢间隔是主要的失败，但在丢间隔发生之前，奖励没有任何信号。

**做法**：在每个说话的行 t 上加塑形项 F_t = Φ(s_{t+1}) − Φ(s_t)，其中
Φ(s) = −w · clip((S_min − d(s)) / S_min, 0, 1)，d(s) 是被指挥机与它负责的所有他机之间当前的最小间隔，S_min 是间隔标准。
γ = 1 时各行的 F 逐项抵消，整句的总和只取决于起点和终点的状态，理论上不改变最优策略（势函数塑形，Ng et al., 1999）。

- 在分支方法里，奖励是整句的，塑形项可以在每个分支组里按"分支点之后"求和后加到句子奖励上；在 D171 的价值方法里直接加到 δ_t。
- 设置：`shaping_weight`（默认 0 = 现在的行为）、`shaping_scale_m`（S_min 的取值，用分离判定的同一常数，不另定数）。
- 注意：Φ 中的 clip 是一个有界的近似，作为显式设置写进 campaign 记录。
- **前提**：G1 显示丢间隔在发生前有一段可观察的逼近过程（即"开局已冲突"的占比不高）。

### T2 困难窗口回放

**为什么**：每轮约 85 % 的窗口首遍就落地，只贡献了一个计数；有信号的分支组只占一半左右。

**做法**：每轮从前几轮**首遍失败**的 train 窗口里按比例 ρ 重抽（同一个窗口用新的随机数），其余照常抽。
- 设置：`replay_share`（默认 0 = 现在的行为）、`replay_rounds`（回看几轮）。窗口来自 train 日，select 读数不受影响。
- 每轮的记录里写明回放窗口的数量和来源轮次（有界覆盖必须写出来）。
- **风险**：训练分布偏向困难窗口，可能牺牲容易窗口；读数要按 G1 的分类分开看。

### T3 锚点权重消融（单机数据项 1.0 / 拉回 base 0.04）

**为什么**：调大学习率时，surrogate、拉回、数据项三项的梯度同比例变大，损失的驻点不变。所以三倍学习率没有效果，
并不能排除"被锚点拉住"这一解释，只有改变它们的相对权重才会移动平衡点。C17 观察到约一半的梯度在拉回单机说法，
而单机数据里没有避让交通的行为。
**反面证据**：`post_lr3` 离 base 更远以后，丢间隔反而升到 13.0 %。所以 T3 是一个便宜的检查，不是主攻方向。

**做法**：把 `post/loss.py` 的 `DATA_WEIGHT`、`KL_WEIGHT` 变成 campaign 设置（默认 1.0 和 0.04）。
第一个实验：数据项 0.25，其余同 C10，从 C10 第 8 轮出发，4 轮。

### 共同的停止规则（与 2026-10-07 的实验相同）

最后一轮的 select 落地率不高于起点 85.7 % + 1.2 = 86.9 % 就停，不续跑；越过了再按 D157 续跑。
