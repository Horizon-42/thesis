# L0 结果：解码器要输出多少个操作参数（KRDU，2026-09-07）

承接 `2026-09-07_latent_intent_design.zh.md` §六 L0。问题只有一个：**N 段分段常值控制要多宽，才能
把一条真实观测航迹复现出来？** 答案定 L1/L2 解码器的输出宽度。这是一个 oracle 测量——拟合看得见整
条真值未来、被给定真实总时长——**不是模型预测**；预测侧的数字要到 L1 才有。

产物：`4dTrajectory/outputs/KRDU/experiments/l0_control_basis_20260907/`（`oracle_basis.txt/.json`，
逐航班拟合出的控制表 `basis_fit.json`）。代码：`control/oracle/basis.py` +
`run_ts_control_basis_oracle.py`（`8262343`、`145d319`）。

## 一、设置

- 队列：`control_procedure_20260905/A_control_v3_pred_val` 的验证集（Phase 0 同队列、同锚点
  seq_len−1 = 59），按 seed 0 均匀抽 **400 架**（雷达引导层约 150 架）；分层来自
  `approach_difficulty.strata_masks`。
- 每架、每臂：以 `fixed_dt_position_ade_m`（2 s 真值网格上的 3-D 位置 ADE）为目标，直接打靶穿过
  现有可微 RK4 rollout（一阶滞后点质量、`scaled-transport-chart-velocity` 后端，均从参考臂的
  config 继承），初值 = 真值航迹的逆动力学在段中点采样；**总时长给定**。
- 轴：N ∈ {4, 8, 16, 32, 64} × 段时长 ∈ {uniform, free（N 个 softmax 自由数）}。
- 优化：Adam，**按宽度缩放的起始速率** `0.08/N`，余弦退火到 5 %，1200 步，逐航班梯度裁剪 20，
  逐航班保留各自最优步。标定过程与三档固定学习率的数字见设计文档 §六 L0 的引文块。
- 读数：`ADE`/`FDE` = `common_physical_time_flight_metrics`（与所有 campaign 同口径）；`fitADE` =
  拟合目标本身；`seedADE` = 逆动力学初值直接飞出来的误差；chamfer / Fréchet；`tail` = 最后 10 %
  预算买到的相对改善（收敛判据；退火下"最佳步在末尾"恒为真，不能用）。

## 二、结果（雷达引导层 ADE 均值，m；全部臂 tail p50 ≈ 0.4–1.2 %，即收敛）

| N | 自由数 uniform / free | uniform | free | free 增益 | 全体 uniform | seed（逆动力学初值飞出来） |
|---:|---:|---:|---:|---:|---:|---:|
| 4 | 12 / 16 | 1290 | 1002 | −22 % | 547 | 7850 |
| 8 | 24 / 32 | 555 | 488 | −12 % | 242 | 6381 |
| 16 | 48 / 64 | 330 | 315 | −5 % | 142 | 4095 |
| 32 | 96 / 128 | **203** | **191** | −6 % | 88 | 2537 |
| 64 | 192 / 256 | 91 | 81 | −11 % | 41 | 1375 |

相邻宽度的对数斜率（uniform）：4→8 1.22，8→16 0.75，16→32 0.70，32→64 1.16——不是干净的幂律，
16–32 之间有一段平台，之后再陡。

## 三、读法

1. **门按字面不通过，走预注册的"否则"分支。** 门是"N ≤ 16 且雷达引导 ADE ≤ 200 m"；N=16 两臂在
   315–330 m。第一个进 200 m 的宽度是 **N=32**（free 191 明确达标、uniform 203 在噪声内）。
   **N\* = 32**。
2. **搜索空间的缩减是 2.7 倍，不是设想的 10 倍。** 32 段 uniform = 96 个数，对照 control 头的 257
   （64×3 控制 + 64 时长 logits + 1 总时长）。设计文档 §一 把"缩小搜索空间"当目标写的时候预期
   8–16 段；实测说明真实航迹需要 32 段才能在 200 m 内复现。这条要照实进论文。
3. **表示不是瓶颈。** 203 m 对照本机看不见的 962 m 意图不确定性是 21 %；N=64 的 91 m 是 9 %。
   所以模型预测不准（C_pred 雷达引导 2197 m）不是"控制画不出这条曲线"，而是"不知道管制员会怎么
   引导"——这正是把宽度压下来、把建模能力放到隐变量与场景条件上的依据。
4. **自由段时长只在宽度不足时值钱，之后停在 5–11 %。** 增益 −22 % → −12 % → −5 % → −6 % → −11 %：
   衰减后不归零，在大 N 上又略回升（64 段时时长自由度多、每个都能微调）。在 N=32 上多花
   32 个数买 6 % 不值，**L1 用 uniform**，不加时长分配头；优化器"每相自由时长"那条经验在段数
   足够时不迁移。
5. **现在的模仿教师照单飞出来离真值 2.5–7.8 km。** `seed` 列就是 simple-v3 模仿项的教师（真值
   航迹的逆动力学），开环积分后误差沿 rollout 累积——这是 `2026-09-07_control_training_review`
   §三 缺陷 B 的数字形式。同宽度拟合后的控制表（`basis_fit.json`）飞出来只差 88–433 m，是一个严格
   更好的教师。**用户决定（2026-09-07）：先跑 L1 主线看轨迹误差损失够不够，教师留作对照臂**；
   若要用，须补跑训练集拟合（KRDU 约 1 万架，N=32 单臂 ≈ 15 h），且文件带宽度与配置戳。
6. **N=32 与 N=64 的取舍是权衡，不是拐点。** 64 段再买 2.2 倍（203 → 91），但缩减只剩 1.3 倍。
   按设计目标（缩小搜索空间、表示误差远小于意图不确定性）取 32；L1 同时跑 N=64 臂把这个权衡
   在预测侧量一次。

## 四、测量本身的教训（已进代码与设计文档）

- **这个测量唯一能给的错误答案是"N 不够"，来源是欠优化。** 固定学习率 0.05 下 N=8 与 N=64 只差
  6 %（1236 vs 1167），看起来"宽度无关"——全是假象；0.002 下 N=64 到 141 而 N=8 有 71 % 还在
  改善。三点改动：余弦退火、`lr = base/N` 的宽度缩放（手调每个宽度会把宽度与调参混淆）、
  `tail_gain` 收敛判据。**没有收敛证据的 ADE(N) 形状是优化器的形状。**
- review 抓到的 blocker：分层掩码按队列排序建、却按 series 顺序 zip，1404/1404 位错位——被判定的
  雷达引导层会变成随机子集，长度相同所以不报错。现在 `summarise` 按键查找，并有三键连接的测试。
- 测量代码是代码：库进包带测试、运行器放顶层、`docs/` 只放文档；`strata_masks` 单一来源化。
