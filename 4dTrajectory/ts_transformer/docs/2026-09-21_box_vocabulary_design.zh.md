# 指令词表与允许包络

**一个 token 表示一条明确指令。指令给出目标，冗余规则把目标转换成允许区间。**

模型选择的是“相对发令时的航向向左或向右转多少度并保持”“保持哪个速度”“下降到以机场高程为零点的
哪个目标高度并保持”。高度目标允许为负。包围盒是这些指令在给定
冗余下允许的状态范围，用于标注、检查和显示。执行器既要知道目标，也要知道允许偏差。

相关量测保存在 `2026-09-21-instruction_vocabulary_plan.zh.md`、
`2026-09-21_vertical_word_method.zh.md` 和本文件 §4 中。量测中的档位与编号不能直接当作新指令字典。

航向、地速、高度及有符号横向距离的分布，以及整数目标集合的待审核建议，见
[指令目标分布与整数词表建议](2026-09-22_instruction_dictionary_distribution.zh.md)。这些候选尚未替换本设计中的待定项。

## 1 这份词表说什么

一句话是一串**指令事件**。每个事件给出当前的航向、高度、速度目标，以及跑道、持续时间和结束方式，
共六类词：
**航向、高度、速度、跑道、时长、结束**。

设计分为三层：

- **字典**：每个 token 唯一对应一个指令及其参数，例如“左转 30° 并保持”“保持地速 V”。
- **允许包络**：根据指令参数、冗余规则和段内进度，计算允许的上下界。
- **执行与检查**：执行器跟踪目标；包含检查判断是否超出允许偏差，高度段末还要判断是否完成下降。

航迹处于允许区间内，不等于指令只要求“任选区间内一个值”。目标始终是字典中明确给出的值。
词表设计需要同时权衡目标分辨率、指令数量、目标跟踪误差和允许包络宽度，不能只追求包含率。

## 2 词表

每个事件按下面的顺序保存六个整数。**编号在每一类内部从 0 开始**，同一个数字放在不同列，含义不同。

```text
[航向编号, 高度编号, 速度编号, 跑道编号, 时长编号, 结束编号]
```

| 列号 | 类别 | token 解码后的指令 | 字典中的参数 | 类别数 |
|---|---|---|---|---|
| 0 | 航向 `heading` | 相对本条指令发令时的 heading 转 Δ 度并保持 | 有符号整数转角；正为左、负为右、0 为保持原方向，度 | 整数转角集合待定 |
| 1 | 高度 `altitude` | 本段内下降到相对机场高程 T 米并保持 | 相对机场的有符号整数高度，米 | 需按机场高度基准核定 |
| 2 | 速度 `speed` | 保持目标地速 V | 明确的目标速度，m/s | 由目标速度集合决定，待定 |
| 3 | 跑道 `runway` | 指定目标跑道及所属机场 | `机场:跑道号` | 随数据集确定 |
| 4 | 时长 `duration` | 当前事件持续 D 秒 | 0、2、4……600 秒 | 301 |
| 5 | 结束 `terminal` | 继续、落地或复飞 | 固定的结束动作 | 3 |

**dictionary 是 token 到上述指令的映射。** token 在模型内部仍然可以是整数，但这个整数必须能直接
解码出动作、目标值和单位。它不以“第几个允许区间”为语义，也不需要先恢复区间才能猜出目标。

航向、速度的目标集合确定后，应在字典定义中列出具体指令值或明确的等差序列，供人直接阅读；
冗余和上下界另用公式表达。当前的 65 个航向区间和 22 个速度区间是 `box-v3` 的类别数，
不自动成为新指令字典的大小。不能未经确定就用区间中点、取整后的中点或旧模型的目标集合替代新字典。

### 2.1 语义

1. **先定义指令，再定义冗余。** 每个数值 token 对应固定的指令参数。转向词固定的是转角 Δ，
   结合发令时 heading 才得到这次执行的目标方向；同一指令生效期间参考不变。调整允许偏差不会改变
   指令参数或本次目标。字典和冗余规则分别保存，一起参与实验规格的版本校验。
2. 转换出的允许区间必须有界，并检查对声明量程的覆盖。允许区间是否重叠、重叠时怎样标注，需要
   在目标集合确定后明确；不能为了让区间恰好相接而静默移动指令目标。
3. **量程外拒绝**，不夹到边档、不装进"大于 X"。但**拒绝只留给物理上不可能的值，不用来处理少见的
   值**：一条 4,900 m 进场、或高空 200 m/s 地速的航迹是正常的，量程必须盖住它；一行 11,000 m/s 的
   地速是坏行。量程按"不可能"定，不按分布的分位数定。
4. 执行器接收明确目标及对应允许偏差。包含检查和三维显示使用同一转换接口，不能各自推导另一套
   上下界，也不能只把上下界交给执行器而省略目标。

数值指令按参数值排序并从 0 编号，编号在字典冻结后固定。转向的 +180° 和 −180° 虽然终点方向相同，
但分别要求左转和右转，是不同指令，不能去重；同理不能把 +200° 简化成 −160°。
边界归属和多候选选择属于标注规则，不改变 token 的指令含义。

当前标注器先平滑信号，再读词：航向先展开角度、做 6 秒滑动平均，再折回 `[-180°, 180°)`；
高度和地速做 10 秒滑动平均。窗口行数为 `round(窗口秒数 / 采样间隔) + 1`，两端用端点值填充。
因此，现有包含检查针对平滑后的信号；显示的原始 ADS-B 行不一定逐行在盒内。

新转向标注必须从物理速度还原模型 heading，保留沿时间展开的角度。发令时 heading 只能使用当时
已知的模型状态或观测估计；居中平滑的未来行只能用于离线分析，不能泄漏到执行器的发令参考中。

**转向完成后的目标容差按转角幅度的 5% 计算，并加 ±1° 地板；速度仍用目标值的 ±5%。**
航向目标容差不是转弯过程中每一行都必须满足的区间。高度采用目标平面上方的单侧坡度冗余，
其上界与目标档位的间距分别定义，不再直接套用围绕目标的 ±5 %。

### 2.2 航向：相对发令时 heading 转向并保持

**一个航向词表示：以本条指令发令时飞机的 heading 为参考，向左或向右转 Δ 度，然后保持转到的方向。**
Δ 是字典中的有符号整数：正值左转，负值右转，0 表示保持发令时方向。它不是相对跑道的角度，
不是机场 ENU 的绝对方位，也不是滚转角、转向率或“每个时间步再转 Δ 度”。

例如，“左转 30° 并保持”“右转 15° 并保持”“保持当前方向”分别对应 Δ = +30°、−15°、0°。
这些例子说明词的含义，不提前冻结完整目标集合。此前相对跑道的 76 值候选不直接沿用；
新的整数转角集合应结合多时段转角分布、指令完成时间及动力学可执行性核定，并保留左右两侧和 0。

#### 与动力学 heading 的对应

当前点质量动力学的 `GeodeticState.psi` 就是这里使用的 heading，单位为**弧度**，采用当地地理 ENU
约定：东为 0，北为 π/2，向左转时增加。字典中的 Δ 用度保存，交给动力学时才转换成弧度。
模型通过下列关系把 heading 转成物理速度：

```text
东向速度 = V × cos(gamma) × cos(psi)
北向速度 = V × cos(gamma) × sin(psi)
psi = atan2(北向物理速度, 东向物理速度)
```

代码依据是 [enu_rhs](../../../aerodynamic_model/torch_dynamics.py) 和
[transport_chart_state_to_geodetic](../../../aerodynamic_model/torch_transport_chart_dynamics.py)。
点质量与带执行器滞后的后端共享这一速度方向语义。当前模型没有独立的机头偏航状态或单独的风速状态，
因此这里“相对飞机姿态”具体落实为**相对模型的水平 heading**，不声称恢复了真实飞机的机体偏航姿态。
ADS-B 标注里的 heading 由运动轨迹拟合；存在风偏时，真实机头朝向与地面航迹方向可能不同。

`psi` 属于飞机所在位置的当地 ENU，而前一份转角统计采用固定机场 ENU；二者的轴会因位置变化产生
小差别，不能当作逐点完全相同。正式标注应使用与执行器相同的模型 `psi`。
速度通道是 chart 导数，也不能直接把 `atan2(ndot, edot)` 当作物理 heading：应沿用
[states_from_channels](../data/channels.py) 撤销坐标旋转与速度缩放，再计算 `psi`。
转向率与可达性同样读取实际动力学后端，包含其坐标运输项，不另写一套固定转向率替代。

#### 指令的参考、完成与冗余

```text
航向 token i → 转 Δ[i] 度并保持
psi0 = 本条航向指令发令时的模型 heading
本次目标 heading = wrap(psi0 + radians(Δ[i]))
wrap 将弧度角折回 [-π, π)
已完成的有符号转角 = degrees(展开后的 psi(t) - 发令时展开的 psi0)
目标容差半宽 δ = max(1°, 0.05 × abs(Δ[i]))
转向完成及保持检查：abs(已完成的有符号转角 - Δ[i]) ≤ δ
```

`psi0` 在这条航向指令内固定。比如发令时 heading 为 40°，指令左转 30°，本次目标就是 70°；
飞到 50° 时，目标仍是 70°，不能重新算成 80°。Δ = 0 不代表对齐跑道，更不代表位于跑道中线上。

转向要保留左右方向和展开角度，不能只用最短圆周角差判完成。目标显示可以折回一个方向圆，
但 +180° 与 −180°、+200° 与 −160° 的转向指令仍不同。保持阶段的方向区间围绕本次目标计算，
跨角度零点时按圆周区间表示，容差取决于 Δ 的幅度，不取决于绝对 heading 数值。

**转弯过程允许从起始方向逐渐趋近目标，不能从段首就要求飞机已进入最终目标容差。**
本航向指令段结束前应完成转向；提前完成后保持。转弯过程包络、允许偏离程度与段长的数值关系仍待
确定，目标容差公式本身不能证明整段可执行或自动提供过程包含率。

高度、速度变化切出的事件不能重新设置 `psi0`。执行上下文须保存航向指令的起点、原始参考和完成状态。
连续两次“左转 30°”又是两次不同的指令，不能因 token 相同而合并。六列事件如何明确区分“延续原指令”
与“重新下达相同转角”仍待编码规则确定；在解决前，不能沿用按 token 相等直接做游程合并的办法。

### 2.3 速度

速度指**地速**，由水平速度分量的长度计算，单位 m/s。它不是空速，也不是管制指令中的指示空速。

**指令定义：保持目标地速 V。** 速度 dictionary 保存明确的目标速度集合，目标及允许区间受
30–250 m/s 的设计量程约束。具体速度列表及间距待确定，不由一张边界表的区间编号代替。

```text
速度 token i → 保持地速 V[i]
冗余半宽 δ = 0.05 × V[i]
下界 = max(30 m/s, V[i] - δ)
上界 = min(250 m/s, V[i] + δ)
```

例如，若字典选入“保持 100 m/s”，其允许区间就是 95–105 m/s，执行器的目标仍是 100 m/s。
这个例子说明转换关系，不提前决定目标列表。量程截断只改变允许范围，不移动指令目标。

量程选择应覆盖正常航迹，不能简单按分位数排除少见值。此前使用 35–180 m/s 时拒绝了 55 架，
其中 46 架有异常地速，另外 9 架是强顺风下的正常高空航迹。这里的地速范围是数据词表的取值范围，
不用于定义飞机的失速速度或空速性能限制。

### 2.4 高度：下降并保持，目标下界 + 单侧坡度上界

**一个高度词表示：在本高度指令段内下降到目标高度 T 并保持，最迟在段结束时完成。** T 是目标平面，
也是整段不可穿越的下界。冗余只允许航迹处于目标平面上方给定的斜坡包络内。

目标使用相对**机场参考点 MSL 高程**的有符号高度。机场高程由
[airport_reference_point](../../../flight_scenarios/runway_target.py) 返回的 `elevation_m` 提供，
来源为 `trajectory_data_process/config/runway_thresholds.json` 的机场级记录；不读取某一跑道入口高程作为
词表零点，也不叠加入口飞越高度 TCH。

```text
H_airport = 机场参考点的 MSL 高程
实际相对高度 h = 飞机 MSL 高度 - H_airport
目标高度 T = 高度字典中的明确整数值，米
本次目标平面的 MSL 高度 = H_airport + T
高度 token i → 本段内下降到 T = H[i] 并保持
```

例如，机场高程为 100 m MSL，“下降到相对机场 600 m 并保持”对应的目标平面是 700 m MSL。
同一机场换跑道不会移动这个平面。T = 0 是机场参考高程平面，不是入口 gate，也不等同于沿途地表；
负 T 仅表示低于机场参考高程，不能据此判断是否低于地面。

动力学的 `altitude` 仍使用 MSL 米，气动计算和实际跑道目标也仍使用其物理高度。改变的是词表的
相对高度表达，不是把动力学高度清零。使用任意 chart 时，可由 `frame.alt0 + u` 恢复 MSL 高度，
再减去 `H_airport`；不能继续直接取相对 `series.target_chart` 的垂直坐标作为新标签。

入口 gate 自身在新基准下的高度，以及已有统计到新基准的转换为：

```text
H_gate = 所选跑道入口 MSL 高程 + TCH
入口 gate 的机场相对高度 = H_gate - H_airport
新相对高度 = 旧 gate 相对高度 + H_gate - H_airport
```

不同跑道的偏移可以不同，不能把旧的多机场高度直方图整体平移一个常数。原来 gate 相对高度为 0 的
点，换成机场基准后通常不再是 0。落地仍按所选跑道的实际 gate 与终点条件判定，不要求落在机场高度
词 T = 0 上；MSL 与原始 ADS-B 椭球高的转换仍只在既有数据入口执行一次。

**整数高度集合 H 及其类别数待按新基准核定。** 既有 `box-v3` 的 61 值梯子和统计报告中 65 个整数
候选都基于旧 gate 高度，不能只更换参考系名称就视为新字典。原设计的 −150–6,000 m 仅作为待复核
量程，须按机场高度重算分布、负值与端点覆盖，并与单侧包络一起验证。保留有符号目标，不强行截掉负值。
目标间距决定分辨率，不直接定义段末允许区间。

用纯文本写出约束：

```text
目标：在本高度指令段内下降到 T，并保持 T
下界 = T
上界 = T + 坡度包络在当前位置给出的非负高度余量
段内包含：T ≤ 实际高度 ≤ 当前上界
段末完成：T ≤ 段末实际高度 ≤ 段末计算出的上界
```

**可以提前下降到 T，随后保持到本段结束。** 航迹不得低于 T；不能用“之后还能爬回目标”解释低于
目标的行。最迟在段末进入规定的完成区间，才算完成本条指令，不能把未完成的下降交给下一段。
完成允许存在由上界规定的正高度偏差，不要求段末精确等于 T。

上界随向段末推进而收紧，段末上界仍由同一套冗余规则计算。**坡度角、段末余量及其计算关系尚待
数值规格确定**：若直接使用 `上界 = T + 剩余距离 × tan(坡度角)`，段末剩余距离归零，上界就等于 T，
这会要求精确到达，不能同时声称还保留非零段末冗余。不能未经核定把现有双侧 ±5 % 改成上侧 5 %，
也不能用下一档目标代替这个上界。现有 1.5° 的量测仅供选择上界坡度时参考（§4.1）。

读法与显示必须遵守以下要求：

- 距离使用**本高度指令段内到段末的剩余航迹长度（地速积分）**，不使用沿航道投影。投影在下风边
  可以增大，不能据此计算下降进度。
- **高度指令段结束就是完成期限**。航向或速度变化只会切出新的事件盒；同一高度词跨越这些事件时，
  仍使用同一个高度段末端，不在每个事件边界重新开始下降。
- 三维目标参考面的物理高度为 `H_airport + T`，与下界重合。下降过程的航迹高于这个平面是符合语义的；包络是否过宽
  仍需单独量测，不能用包含率代替。
- **单侧包络与目标梯子的组合必须重新验证覆盖**，包括负高度、量程端点与单行段。
  双侧区间铺满不证明单侧区间也铺满，不能继续宣称读法必然成功。

**垂直词仍是高度目标，坡度是允许偏差的边界。** 航迹处于斜上界以下不保证实际下降角受到同样限制，
也不单独保证到达后的保持行为；这些由执行器跟踪目标并在回放中检查。这里定义下降并保持，
爬升与复飞的指令能力仍需保留，其方向对应的包络另行定义。

### 2.5 跑道、时长、结束

**跑道**指定落地目标、中线和入口 gate，其所属机场提供高度参考高程。它不再定义航向词的零方向，
跑道入口 gate 也不再定义高度词的零平面。类别名称为 `机场:跑道号`，按字符串排序后从 0 编号。
编号依赖本次数据包含哪些跑道，读取时必须使用产物携带的 `runway_idents`，不能跨数据集假定编号不变。

```text
跑道序列 R = 数据集中所有“机场:跑道号”去重后按字符串排序
跑道词 i 对应 R[i]
类别数 = R 的长度
```

当前标注器为一架航班的所有事件写入同一个跑道编号。跑道类别集合不进入词表规格的 sha，
而是单独随产物保存。

**时长**写在它所描述的当前事件上，表示这组词从当前事件开始生效多久。共 301 档：

```text
编号 d = 0…300
解码时长 = 2 × d 秒，即 0、2、4、…、600 秒
标注编号 = floor(实际保持秒数 / 2 + 0.5)
```

这相当于取最近的 2 秒档，恰好在中间时向上取整。产物还保存实际的 `hold_s` 和 `event_times_s`；
当前 2 秒采样网格上的时长可以精确编码。超过编号范围会报错。0 秒档是真实存在的类别，
最后一行新开事件时可能用到，不是填充符或结束符。

同一高度词连续生效的各事件合成一个高度指令段；其结束时刻也是该下降指令的完成期限。
一条转向指令跨事件继续生效时，也保留原来的起点、heading 参考和完成期限；它与重新下达同值
转角必须区分，相关事件续行编码见 §2.2 的未定项。

**结束**描述当前事件完成后是否继续这句话：

| 编号 | 名称 | 含义 |
|---|---|---|
| 0 | `continue` | 继续，还有后续事件 |
| 1 | `landed` | 以落地结束 |
| 2 | `go-around` | 以复飞结束 |

设计上，落地结束应与进入终点盒子的判定一致。当前 `read_boxes` 对到达航迹直接把最后一个事件标为
`landed`，之前全为 `continue`；它还没有实现终点判定，也不生成 `go-around` 样本。
3 个类别已经预留，并不表示三种结果都已实现或验证。

### 2.6 sha 里有什么

实验规格必须同时标识字典和冗余规则：

- token 的指令类型、明确目标值、单位、坐标基准及编号顺序；
- 相对转向使用模型 `psi`、发令参考固定规则、左右转向与角度展开约定，以及指令续行/重发的事件语义；
- 高度使用机场参考点 MSL 高程的定义；具体机场高程及源文件指纹随数据上下文绑定，不能静默变更；
- 航向、速度冗余，高度单侧上界与段末余量的计算规则；
- 量程、时长编码、标注规则、段末完成判据及转换接口的语义版本。

跑道类别集合单独随数据集保存并绑定，通用规格的 sha 不包含具体机场跑道列表。
改变冗余需要更新规格版本，但不应静默改变 token 对应的目标值。改变目标集合则需要更新字典映射。
新指令语义使用新的读法标识与 sha，现有 `box-v3` 区间编号不能直接按指令编号解释。

### 2.7 指令到允许区间的转换接口

接口分为解码和计算允许范围两步。下面是设计约定，尚不是仓库里已经提供的函数：

```text
decode_instruction(kind, token_id, dictionary) → instruction
allowed_region(instruction, context, redundancy) → region
```

`instruction` 必须包含明确的动作和参数：相对发令 heading 的有符号转角 Δ、地速 V，或相对机场高程
的目标高度 T，以及相应单位和参考系。跑道、时长、结束 token 分别解码为目标跑道、持续时间和结束动作，
不生成数值容差区间。

`context` 提供机场 MSL 高程、所选跑道几何，以及各条指令的起止时刻、当前进度。
航向还需要本条指令发令时的 `psi0`、展开角度进度和延续/重发身份；高度还需要到段末的剩余航迹长度。
`redundancy` 提供独立的容差参数。`region` 保留指令参数、本次目标及派生边界：高度同时能还原为 MSL
目标平面；航向支持转弯阶段和保持阶段，最终方向区间按圆周表示，完成检查仍保留有符号转角。

数据标注、包含检查、执行器约束和三维显示调用同一转换规则。模型预测指令 token；执行器解码并
跟踪该指令的目标，同时遵守允许包络。显示端既可显示明确指令，也可显示对应区间。
改变显示方式、当前位置或冗余参数，都不能重新定义这个 token 所说的目标。

## 3 读法

### 3.1 三类怎么切

- **航向**：以每条候选指令段的起点 heading 为参考，使用展开后的模型 `psi` 计算有符号转角，
  选择字典中的 Δ，再检查转弯过程、段末完成与完成后的保持。不同起点的相同 Δ 是不同指令；
  其他维度切出的事件只是延续时，则不能重设参考。标注须连同航向段边界一起确定，不能只读逐行区间。
- **速度**：先从字典中选择明确的目标指令，再用转换接口检查观测是否落在其允许范围内。
  在字典与冗余固定后，把连续生效的同一速度指令合并为一段。不能直接沿用区间编号作为标签。
  多个指令都能包含观测时，需要明确目标选择和保持规则；没有指令能包含时，应报告覆盖缺口，
  不能临时移动目标或扩大容差。这些标注细则随目标集合一起确定。
- **高度**：从段末向前贪心**最长延伸**。一个目标可行，要求整段不低于 T、不超过逐行上界，且
  段末满足完成区间。新增一行破坏任一条件时停止延伸；不能以容许下一段接手为理由放过未完成的段。

事件时刻取三类指令开始、结束或重新下达时刻的并集，不能只检测 token 数值是否变化。
每个事件保存指令 token，并按待定续行规则关联到实际指令段；检查和显示时再解码、计算包络。
目标切换过程是否满足包含与可执行性要求，需要在回放中验证，不能因目标已定义就假定飞机可以瞬时转向或变速。

### 3.2 从末端反着读

高度段的**末端是完成期限**，因此从最后一行确定可完成的候选目标，再向前延伸。对一个固定段末，
每行剩余航迹长度确定；下界检查覆盖整段，单侧上界与完成检查使用同一套规则。
合并相同高度词的相邻段时也必须重新确认这些条件。新读法的实现、复杂度与读数待单侧上界规格确定后验证。

### 3.3 终点盒子

旧相对跑道/gate 读法中，句子结束时的分布为（v1 读数）：航向落在航道那档 **99.5 %**，高度落在最低两档
**97.2 %**，速度落在相邻三档 **93.1 %**。这些是现有读法的依据；新指令字典下需要重新确认终点
目标及允许区间。终点边界取公布的决断高（逐跑道 61.0–129.1 m）还是数据读出的范围，仍待确定。
最后一个高度段同样必须完成，不能仅凭航迹结束就跳过段末检查。
新转向词的 Δ = 0 只表示保持发令方向，不能替代对齐跑道的判定；相对机场高度 T = 0 也不能替代
入口 gate 高度。终点判断先恢复本次方向目标与 MSL 高度，再与所选跑道的物理终点条件比较。

### 3.4 链条条件

"航迹在自己的盒子里"不够，**相邻两个盒子要接得上**：第 k 个盒子整个落在"能在 T 秒内飞进第 k+1 个
盒子"的集合里。链条成立时，"这句话能落地"是构造出来的，回放门从一次实测变成一次检查。

高度必须同时检查**上一段完成**与**下一段可接入**。各段分别包含自己的观测航迹，不证明整个允许
区间都能接入下一段；单侧坡度上界也不能替代执行器的下降率约束，因此链条条件不能宣称自动满足。
v1 实测速度和高度的词 100 % 只跳隔壁、航向 83.4 % 只跳隔壁，是现有读法的量测。
新字典需要按指令目标变化及其派生包络重新检查三类转移，不能用旧区间编号是否相邻代替。
相对转向尤其依赖发令状态：相邻两条 Δ 相同并不表示目标 heading 相同；链条检查必须带入各自的
起点 heading 与指令身份，并采用动力学实际转向能力。高度之间的比较统一使用机场参考高程或恢复后的 MSL。

## 4 读数

本节保留现有区间词表、双侧高度楔形及相关对照的量测依据。它们用于比较词数、覆盖与包络宽度，
**不代表相对飞机 heading 转向、相对机场高度及单侧下降包络的结果**；新读法尚未生成或验证产物。

### 4.1 楔形对平板：同样的末端精度要多少词（KRDU 6,851 架）

**同一把梯子下楔形的盒子只会比平板宽**（平板盒 + 楔形张开），所以"盒子更小"不是它的卖点。它的
价值是**末端精度与词数解耦**：平板的盒子处处一样宽，要末端紧就得整把梯子都细；楔形只在段末收紧。

| 末端精度 | 目标数 | 平板 词/架 | 楔形 γ 1.5° | 楔形 γ 2.5° |
|---|---|---|---|---|
| ±5 % | 44 | 29.0 | 24.0 | **8.0** |
| ±2.5 % | 86 | 53.0 | 42.0 | **14.0** |
| ±1.25 % | 171 | 88.0 | 67.0 | **24.0** |

γ_down 是这一维唯一的旋钮，代价写在中段盒高上（±5 % 梯子、γ_up 1.0°）：

| γ_down | 词/架 | 中段盒高 p50 / p95 |
|---|---|---|
| 1.0° | 27.0 | 126 m / 544 m |
| 1.5° | 24.0 | 148 m / 920 m |
| 2.0° | 16.0 | 197 m / 1,709 m |
| 2.5° | 8.7 | 288 m / 2,891 m |

**覆盖率与盒子宽度必须成对引用**：γ 越大句子越短、包围盒越宽，取到极限就是"一个词覆盖整条进近、
什么也没说"。**可用区间在机群自己的下降角以下。**机群下降段的中位是 2.98°，包络张开的速率一旦追上它，一个词
就盖住整条进近：实测 γ 3.0° 每架只剩 2 个高度词，而包围盒中位 740 m、p95 3,840 m——覆盖率拉满、
指令什么也没说。现有双侧读法取 **1.5°**；单侧设计仍需重新量测长段的包络宽度。

### 4.1b 冗余在句子里实际起了什么作用（KRDU 6,834 架）

航向和速度是**铺满**的盒子，所以冗余就是盒宽，没有第二个参数（高度有两个：梯子的 p 和张开率 γ）。

| | 速度 | 航向 |
|---|---|---|
| 生效中的盒宽 p50 | 9.50 m/s（p5 6.4、p95 14.2） | 2.00°（p95 14.8） |
| 航迹占了盒子多少 p50 / 贴边(>0.9) | 50.3 % / 10.1 % | 33.1 % / 10.7 % |
| 词/架 | 8.0 | 20.0 |

**速度的冗余在花到达时刻。**它允许的到达时刻散布是 **p50 28.2 秒、p90 55.9 秒**（整条进近上按
`∫ dD·δ/v²` 积出来，全宽）。3 NM 的雷达间隔在 83 m/s 上约 **69 秒**——也就是说速度盒一家就吃掉了
将近一半的间隔预算。这是 ±5 % 最该被权衡的地方，不是词数。

**航向的冗余有一大半时候不是百分比，是那个 1° 地板。**56.3 % 的行落在离航道 ±10° 以内，盒宽就是
2°；只有 38.4 % 的行在 |ψ| > 45°，百分比才真正把盒子放宽（p95 14.8°）。

**而且百分比并不省词**：这套 20.0 词/架，均匀 5° 格 21.0，同样 65 类的均匀格（5.5°）19.0。它买的
不是更短的句子，是**分辨率的位置**——航道附近 2°（旧 §8.4 量过那一段的分辨率决定落不落得下来），
而不是到处 5.5°。

## 5 未定项

### 5.1 水平方向没有绝对界

高度楔形是绝对的位置界。航向盒和速度盒只给**位移**界，随时间张开（v1 实测：航向盒每秒张开横向
走廊 p50 1.72 m/s、p95 18.0 m/s，一段 40 秒就是横向半宽 69–720 m）。所以水平包围盒是一个被起点和
跑道两头捏住的漏斗，不是盒子；单靠后向漏斗，25 km 外半宽约 14 km。

要水平也绝对，需要一个**位置维度**（离中线多远的盒子，或"在哪条 leg 上"）。旧词表里唯一那个绝对
的水平界是"保持中线"，它只是一个二值状态、只在最后加入航道那一段出现——它本该是一个维度上最里面
的那一格。

**为什么横向不能照抄垂直的楔形。**收拢的包络只对**慢**状态有意义 —— 它的宽度就是"每米航迹能纠正
多少"：

| | 每米航迹的张开率 |
|---|---|
| 高度（γ 1.5°） | tan 1.5° = **0.026** |
| 横向（30° 切入角） | sin 30° = **0.5**，快 19 倍 |
| 航向 | ω/V：25° 坡度下张满整圈只要 48–82 秒 |

照楔形的办法给**航向**做漏斗，实测（400 架 KRDU）每架只剩 **1 个**航向词，而 **87.6 % 的行包络张满
360°** —— 一个词允许飞机朝任何方向，不是收拢，是什么都没说。

三类指令及位置约束对应不同的允许范围：

| | 从指令或约束计算出的允许范围 | 状态 |
|---|---|---|
| **慢状态**：高度 | 固定目标下界 + 向段末收紧的单侧坡度上界 | 语义已定，待实现 |
| **快状态**：航向 | 发令 heading + 有符号转角形成目标；转弯过程包络与完成后方向容差分开 | 转角集合、过程包络与续行编码待定 |
| **快状态**：速度 | 围绕明确目标地速的容差区间 | 语义已定，目标集合与转换接口待实现 |
| **位置**：离中线的距离 | **固定走廊**（RNP / established 的 500 m），不是可达集 —— 横向的可达漏斗在 25 km 外半宽约 14 km，太宽 | **未做** |

明确的航向指令仍然只给方向目标，不能单独约束横向位置。“跟踪航道中线”的现有指令能力需要保留，
其位置词如何并入新字典及如何转换为走廊，仍需在位置维度设计中确定。

### 5.2 最短保持

现有区间读法在边界处抖动就会换词。v1 五机场实测：保持时长中位 **4 秒**，
**36.3 % 的盒子保持不到 4 秒**。新字典需要定义何时继续保持同一目标、何时换成另一条指令。
可比较允许区间重叠配合迟滞、最短保持时间、调整目标间距三种方式，但都需重新检查覆盖与包含；
不能只为减少换词而忽略指令允许的偏差。

### 5.3 优先级

先用模型 `psi` 核定整数转角集合、转弯过程包络和航向指令续行编码；按机场 MSL 高程重算高度分布，
核定整数高度集合、单侧上界和段末余量；同时确定明确速度集合，形成可以直接读出指令的
dictionary。实现 §2.7 的转换接口，再更新标注、模型输入输出、执行器和显示。
