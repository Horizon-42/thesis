## §5 实验阶段与门

### 5.2 阶段 B：指令词表的第二层（2026-09-20 重写，用户尚未看过；意图码版本作废，读数留作证据）

**问题**：A2 说雷达引导航班穿不过跑道入口的主要原因是没转基边、转晚了、末段形状错——都是"什么时候转、转到哪"的决策，历史里没有。阶段 B 问：把进近写成一串**管制指令**（每 τ 秒一个词：航向目标、高度目标、速度目标、切入航道），一个学出来的第二层能不能**说出**一串让执行器安全到达跑道入口的指令——不是复述真飞机说过的话，而是在自己飞偏之后仍能说对下一句。执行器仍从 L60_D20 起（D30），词表自建（5.2.1），两层都做后训练（5.2.2），程序与多机怎么进来见 5.2.3 / 5.2.4。

#### 5.2.0 三个改变（对 2026-09-19 版本）

1. **词表**：不再用编码器把 20–60 s 的真值段压成一个码，改为从航迹里读出来的**管制指令**——绝对目标，不含变化率，每 τ = 5–10 s 一个位置（D50–D54）。为什么：指令就是真实的生成过程；绝对目标与飞机偏在哪无关，执行器只要跟踪；"切入航道"这个词带位置锚，能把偏掉的飞机拉回航道；平台段读目标比斜率读变化率稳一个量级。
2. **两层都做后训练**：执行器在自己飞出的历史上再训（D49）；先验先在真值句子上预训练，再在执行器飞出的历史上再训（D55）。为什么：两层现在都是"在真值上训、在自己的输出上评"（§10 第 1 条），这是 v2 失败的诊断（09-18 §1.1），v3 没治。
3. **解码带目标**：部署时先验每个位置给 K 个候选指令，各交给执行器飞一段，按部署时拿得到的目标打分（到跑道入口的推进、对航道的对准、可飞性、先验概率），选一条（D56；Q6 落地）。为什么：现在的 top-1 是"最像真飞机会说的"，不是"最能到跑道入口的"；连真值码都换不来穿越，说明缺的是选择，不是信息。

#### 5.2.1 词表怎么建（D50–D54、D62–D65、D71）

**词是什么**：一条指令只改一项，目标是绝对值。**六类**——2026-09-20 用户把跑道加成第五类（D62），
同日把「结束」从先验的一个二值头改成第六类词（D72）。

> **2026-09-21：下表的高度与速度两行正在复核，数已经量完但一条都没定（D76 / D77，`docs/2026-09-21_vertical_word_method.zh.md`）。**
> 两行描述的是**代码现状**，不是被验证过的设计：高度 1000 ft 一格在真实的平飞层上**等同随机取整**
> （均值 235.3 m… 见 H5），速度 10 kt 一格同样等同随机取整（实测 1.34 / 1.28 / 2.46 m/s，与"均匀分布"

**为什么没有切入词（D73）**。原来有一类「以某角度切入航道」，2026-09-20 去掉。量出来它是航向词的影子：
4897 条切入词 **100 % 和某条航向词在同一时刻发出**，一条都没有自己的时刻，所以在事件流里它从不产生自己的
事件；取值上 78 % 能从航向词直接推出，余下的差别是格子边界的舍入（航向目标 30.4° 落进 30° 那一格，按格子
推是「≤30°」，按真实目标是「30–45°」）。而且按 D50 自己的规矩它本来就不该是词：管制员说的是「左转航向 250，
切入航道」——**角度是他给的航向的后果，不是他说出口的目标**。D59 要用的切入角改为打分时从航向的**连续目标值**
算，精度反而更高，那 411 例的舍入差正好消失。

**随之退出 spec 的两个数**：`established_cross_track_m` 与 `established_track_tolerance_deg` 本来在 spec 里，
是因为切入词靠它们判「在不在航道上」。切入词一走，它们不再决定任何一个词，按仓库的规矩（决定不了答案的
东西不该进身份）从 spec 移出。它们仍是 `approach_difficulty` 的那一处定义，读数照旧用。

**跑道为什么是一个词，而不是坐标系（D62）**。其余四类全是相对某条跑道量出来的角度和高度，所以没有跑道词的句子
说不出"去哪条跑道"；而真实管制里跑道就是管制员说出口的一句话。词的形式是一个分类槽，类别集合按机场绑定，做法
同机型词表（`manoeuvre.context.TypeVocabulary`）——**因此它不在 spec 里、不进 sha**，否则一份词表就不能通用于五个
机场。它是**每个位置一列**，所以句子能表达中途改（D64，FAA 原文允许）；但标注器写的是常数，因为晚改只有
1 / 44 622、早改这份数据分辨不了（结果文档 §13）。

**为什么没有复飞词（D63）**。复飞在机队里是真的（44 622 架里 42 架），但词表是在 25 km 到达切片上读的，切片只含
最后那次成功的进近：把复飞航班与 cohort 求交得到 8 架，它们在 cohort 里最低点之后的爬升**全是 +0 m**。这个词只会
是一个恒为 0 的字段，按仓库的规矩（永远不触发的词比没有更糟）不加。**这是 cohort 的一条限制：本阶段的句子表达不了
"这次不落地"**；要改得动上游的到达窗口，那会改掉每个 ts 数据集划分，不在本阶段范围内。数在结果文档 §13.5。

**句子是什么**（D52，2026-09-20 重写为事件流）：一句话是一串**事件**，每个事件是"在此刻，这几项目标变成了
什么"。事件里带六个字段：距上一条事件多久（时长词），以及跑道、航向、高度、速度、结束各自此刻的值。第一个
事件在 t = 0，把五项一次说全；之后每个事件只出现在**真的有东西变了**的时刻。没有"保持"这个词——什么都没变的
时刻根本不是事件，不占 token。

**为什么不是等距网格。** 旧设计每 τ = 10 s 一个位置、每个位置写此刻生效的值。量下来它有两个毛病：274 230 个
位置里 88.2 % 和上一个完全一样（4.1 倍于事件数的 token，绝大多数在学"跟上一格一样"）；而且每条指令的时刻被
**往后挪 0–8 秒、均值 4 秒、永远偏晚**（38 111 条非初始指令上均匀分布），按进场 270 kt 算平均多飞 557 m、最多
1112 m，3°/s 的转弯平均多转 12°。这个偏置是单向的，闭环里会累积，而且会被读成模型误差。事件流把它去掉：时刻
就是标注器读出的那一行，分辨率是 ADS-B 自己的 2 秒。**剩下的两项时间残留不是表示法造成的**——ADS-B 2 秒一行
是数据的分辨率；"偏出半个容差才算离开"是一个**定义**，读和执行两边同用，自洽，不产生误差（它只让我们的时刻
系统性地晚于真实电台发话，而我们从不做那个比较）。

**怎么从航迹里读出这些词（标注器，B′-dev1；规则是 D53，现为 `plateau-v11`，sha `c7a4f4239f52`）**：

1. **一段稳住不动的航迹就是一条指令的目标**（下面叫 level）。航向（6 s 平滑）、入口以上高度和地速（各 10 s 平滑）三路
   分开看：一个量在容差里（航向 ±4°、高度 ±30 m、地速 ±2.5 m/s，都不到半档）保持 ≥ 20 s，且这 20 s 拟合斜率把它带走的
   量不超过半个容差，就算一个 level。缓慢下降、缓慢减速、下降途中的小停顿都不算。
2. **两个 level 之间是机动，不管快慢**：目标 = 到达的那个 level 的中位数，按档取词；**发出时刻** = 信号离开紧挨着它前面
   那个 level 的那一行；settled = 新 level 开始。
3. **什么不成词**（都记在 `absorbed` 里、统计里计数）：到达的还是原来那个词；变化不到最小量（5° / 500 ft / 10 kt）**且**
   没守住 40 s、或与当前指令的目标差不到一个容差；末尾读不出来的短尾。
4. **结束词**（D72）：最后一个事件标「落地」，其余标「继续」。「复飞」这个值标注器**从不发出**——25 km 到达切片里只有最后那次成功的进近（结果文档 §13.5），所以预训练里它 0 次，任何门槛都不能把它算进去。
5. **跑道词**（D62）：预训练阶段直接取该航迹被指派的跑道；能不能中途改见 D64，改点怎么定由 B0′′-a 量完再写。
6. **时长词**（D71）：一个事件的时长 = 它与上一个事件之间的秒数，按 2 秒一格取词。第一个事件的时长格是 0。
7. 把所有"有东西变了"的时刻排成序列，就是句子；最后一个事件之后是落地。
8. **人工核（B0′）**：随机 300 架（直线 / 雷达引导各半，从 train 里抽），把读出来的指令画在航迹上逐架核。
   前四类词已核过五轮，定稿 v9（一致率 136/150 = 0.907，结果文档 §12.2）；跑道词已穷举核过 8257 架、零不合格
   （§14.1）；**时长词不必另核**——它是两个事件时刻之差，那两个时刻已经在前四类的核里看过了。
9. 词表是带哈希的产物：版本、档位、阈值、读法的版本号、读的时候用的 cohort 身份、每类份额都在文件里；执行器与先验的
   checkpoint 记住这个 sha，对不上按名字拒绝。

**执行器怎么吃**（B′-dev2）：`plan_conditioning` 新值 `instruction`——条件向量加上执行器这一段（Δ 秒）内各
采样时刻生效的指令（Δ/τ 个时刻，每个时刻四个字段：航向目标的 cos / sin、高度目标、速度目标、切入标志，按格
中心值）；训练与真值指令读法用真值句子，先验读法用先验说的。**τ 现在只是执行器自己的采样步长**，不再是句子的
形状——句子是事件流，τ 只决定"在这一段里问几次现在生效的是什么"。执行器读词走的是 `Reading.words_at(时刻)`，
那是一次查询，事件流同样能回答（在事件时刻上 searchsorted），所以**执行器这一侧不因 D52 的改写而变**。
跑道、时长、结束都不进条件向量：跑道是执行器已经工作在其中的坐标系（D62），时长是句子内部的节奏（执行器
按自己的 Δ 走），结束是先验说给调度看的、不是执行器要跟的目标。其余同 D30 的配方。

#### 5.2.2 两层怎么训、怎么"会说话"（D49、D55–D58、D66、D67）

**先验训练时的输入与 ground truth**（一个样本 = 一架飞机的整句话，也就是它的事件序列）：

| | 内容 |
|---|---|
| 事件 k 的输入 | 这个事件的六个词各一个嵌入，相加（跑道、航向、高度、速度、时长、结束）；这个事件时刻的状态 token（六个数：位置 e/n/u 相对**机场基准点**、地速、航向的 cos/sin）；事件序号 |
| 上下文（一个 token，每个事件可见） | 机型 |
| 事件 k 的 ground truth | 事件 **k+1** 的六个词。**没有单独的落地标志**——落地是最后那个事件自己的结束词（D72），所以最后一个事件没有目标 |
| 损失 | 每类词一个交叉熵，只在有下一个事件的位置上算。**没有单独的落地项**（D72） |

三点要写明。

**先验不预测轨迹**：每个事件时刻的真实状态是直接喂给它的，它只说下一句。

**预训练是 teacher forcing，但这本身不是问题**——普通 LLM 预训练就是 teacher forcing，给真实前文预测下一个词。
把它单独写出来会让人以为这里有什么特别的，没有。真正特别的在部署那一端，而且是**两重**落差：LLM 生成时只有
自己的词回灌，而我们这里先验说词、**执行器去飞**，先验下一步看到的状态是执行器飞出来的，不是真飞机的。词的
回灌那部分和 LLM 一样；**上下文里有一个会漂的外部系统，这部分 LLM 没有**。更具体地说：预训练时每个事件的状态
是真飞机当时在哪，部署时是我们的执行器飞到了哪，而执行器已知会漂——阶段 A 量过，逐轮误差线性涨、每轮约 110 m。
冲着这两重落差去的是 D49 与 D55 那两步后训练，不是 D61。

**时长与结束和其余四类同为 softmax**，所以生成时可以取 top-K、可以采样；这正是 D56 的目标导向解码和 D61 的
自由生成需要的东西，回归头给不了。而 D61 用自由生成而不是逐词准确率，理由和 LLM 用生成而不是困惑度来评估
是同一个：**逐词准确率不检验整段话是否成立**。

**预训练（两层都在真值上）**
- 执行器：D30 配方 + 指令条件，真值指令，随机锚点，180 epoch，两 seed。
- 先验：因果 Transformer（D46 起点：宽 128、4 层），输入与 ground truth 见上表，val 上选模。

**跑道头要求把跑道从输入里拿走（D66）**。现在跑道是三重给定的：状态 token 的原点是那条跑道的入口、跑道航道是
一个显式上下文 token、跑道词本身也在输入里。在这三样都在的情况下加跑道头不是预测，是抄。所以三处一起改：
状态原点换成**机场基准点**（各机场入口离中心 0.3–3.6 km，状态位置尺度 20 km，即 ≤ 18 % 的平移）；**去掉跑道航道
上下文 token**（状态里的航向是绝对的，航道方向必须由**跑道词**提供，否则答案还在输入里）；跑道词进输入也进输出。
于是第 0 个位置的跑道预测只看机场相对位置、绝对航向、速度、机型——正是 `r11_lift` 的那组特征，可以直接与它比。
代价：另外四类头要自己从跑道词还原出相对入口的位置与航道方向，可能退，退多少得跑了才知道。

**中间状态给不给，做成消融（D67）**。每个位置都喂真实状态，先验就只需要"看一眼雷达说下一句"，从不需要对整句话
负责。同一份数据训两版——每位置给状态 / 只在第 0 个位置给——用自由生成读数比。完全不给状态不成立：同一句话从不同
起点出发意义不同。

**后训练 1：执行器闭环再训（D49，B2′）**
- 为什么：执行器从没见过自己飞偏的历史；逐轮误差线性涨（每轮约 110 m）。
- 做什么：CAT-K 式引导——在 train 上用预训练执行器闭环飞，每段开 K 个分支（真值指令及其相邻格），各飞一段，
  只留段末离真值最近的那支继续；把飞出来的历史切成训练窗口，标签 = 同一绝对时刻真值的下一段。不加引导的微调
  比不微调还差（0.6361 对 0.7581），引导着才有用（0.7616），依据见 D49。
- 怎么判：无 token 读法的 established / 雷达 ADE 对预训练执行器（相对门 A3 行）；逐轮误差是否不再线性涨。
- 不过怎么办：份额、轮数各消融一次；仍不过则结论"闭环再训在本数据量下无效"，后续步骤仍在预训练执行器上做。
- 机制（B′-dev4，2026-09-20 写清，未建）：(1) 飞——用 `lockstep.fly` 的骨架在 train 上闭环飞，每轮每架开 K 个分支：真值指令与其相邻档（航向 ±1 档、高度 ±1 档、地速 ±1 档，切入不变；K = 7 起点），K 份 forecast 一批算，保留段末（Δ 秒后）离同一绝对时间真值最近的那支继续；每轮记下被选分支的指令与偏离；(2) 切窗口——每轮的锚点上取飞出历史的最后 L 秒作输入窗口、同一绝对时间真值的后 Δ 秒作目标（`dataset.target_horizon_s` 那份契约）、真值指令作条件，写成一张表（像归档的 `plan_head_2026_09/rolled.py` 的 `RolledWindowTable`：flight、锚点时刻、历史、目标、指令）；(3) 混合——训练时 `WindowContext.override(i, epoch_seed)` 按份额把一个真值窗口换成同一航班的一个飞出来的窗口，**替换窗口带真值目标**（现在的 override 只换历史、目标为零，是 plan 路径的用法，要扩）；份额起点 0.5，消融 0.25 / 0.75；(4) 再训——从预训练 checkpoint 起（`train` 要加"从 checkpoint 起训 N 个 epoch"的入口），N = 18（预算 180 的 10 %），lr 同预训练的末值；两 seed。读数：无 token 读法与真值指令读法各一份，相对门 A3 行；逐轮误差曲线对预训练执行器。
- 没解决：K 与相邻档范围；飞的时候执行器是否每轮都用预训练权重（CAT-K 是固定的预训练模型只飞一遍，再训的时候不再飞）——起点按 CAT-K：只飞一遍，不反复迭代。

**后训练 2：先验闭环再训（D55，B3′ 内）**
- 做什么（同样 CAT-K 式）：在 train 上用执行器闭环飞，每个位置在先验 top-K 的候选指令里挑一个交给执行器飞一段，留落点离真值下一个状态最近的那个继续，飞出来的状态序列配同一绝对时间的真值下一指令为标签，再训若干 epoch。K 要对词表大小扫一遍：CAT-K 在 2048 词上 K = 16–64 都平、K = 5 变差；我们每个字段只有 8–36 档，K 取 {2, 4, 8} 各读一次（D55）。
- 怎么判：先验读法的门 B；先验读飞出历史与读真值历史两种读法的差是否缩小。

**目标导向解码（D56，B3′）**
- 做什么：每个位置从先验分布取 K 个候选指令（起点 K = 4），各交给执行器飞 Δ 秒（束深 1；束深 2 作消融），打分只用部署可得项：先按程序与可飞性**屏蔽**（D59；SaFeR 的做法——掩码换来的是可解率不是精度），剩下的候选按先验概率与向跑道入口的推进（沿最后进近航道的 to-go 减少）、对航道的对准（横向距离、航向差）打分；文献里没有可抄的权重（DTPP 的代价是学出来的，SaFeR 只做掩码），起点 = 各项归一化后等权，权重作消融（D56）；选最高分的候选飞。上限读法：同一套候选用真值打分（minADE_K）——它说明"候选里有没有对的"。
- 怎么判：门 B（相对无 token 基线）；上限读法对 top-1 的差说明选择环节值多少。

- 机制（B′-dev5，2026-09-20 写清，未建）：lockstep 新协议 `prior-decode`：(1) 每轮先验读到此刻的句子（已说过的词 + 飞出历史在各位置的状态 token；第一轮的词 = 真值读出在锚点时刻生效的四个词，也就是"管制员刚说过的"）→ 四个头的分布 → 联合 top-K 候选（`_joint_ranks` 的同一种排序：每头 top-8 的乘积里取前 K，K = 4 起点）；(2) K 个候选各作执行器的指令条件飞 Δ 秒（K × 航班一批算）；(3) 掩码——可飞性（`geometry.flyability.required_controls` + `flyability_summary` 对飞出来的状态，不全可飞的候选去掉）与程序（D59：切入角门槛待用户；低于 OCS 的高度目标；航道外侧走向——`outputs/guidance/route` 的规则一处定义）；全被屏掉时退回先验 top-1 并记一次"无可行候选"；(4) 打分——先验联合对数概率、向跑道入口的推进（段末 to-go 的减少）、对航道的对准（段末横向距离与航向差）；各项在候选间归一化后等权（起点），权重作消融；(5) 选最高分的候选飞出，它的词写进句子作下一轮的输入。上限读法：同一套候选用真值下一状态的距离打分（minADE_K）。读数：门 B；每轮记候选数、被屏掉的数、选中候选与真值指令的一致率。
- 没解决：K；束深 2（两轮联合打分）作消融；先验在执行器每轮的锚点上读词——先验的位置是 τ 网格、执行器的锚点不在网格上（`Reading.words_at` 的规则：取之前最近的位置）。

**RL 微调（D58）：本阶段不做。** 驾驶领域在 CAT-K 之后再做 RL（R1Sim）只多 +0.0001；只有奖励里有"离真值远近"表达不了的东西时才值得——间隔（阶段 C）、指定到达时刻（CTA）。到那时再列。

**读数与门**：闭环协议不变（§3.1：从第 29 行起、B cohort 1404 架、两 seed、三分组、预算规则）；相对门用 §3.3 B 行；**门 B1（真值指令上限）改为"两项 established 不差 + 任一项超线"**（§10 第 5 条；旧规则放行了主指标掉一半的配置，D57）。真值指令读法里指令按**执行器位置**取（与飞机现在最接近的真值行所在位置的生效指令），不按时间（§10 第 3 条）。
#### 5.2.3 与 procedure 的结合

- **坐标系就是程序的**：航向相对最后进近航道、高度相对跑道入口，切入词直接是程序的动作；同一词表在任何跑道上读出同样的句子。
- **程序作为语法与掩码**（解码时，不进损失）：违反程序的候选指令在打分前屏蔽——切入角 > 45°、低于该处 OCS 的高度目标、航道外侧的走向；规则只有一处定义（`outputs/guidance/route` 的六条路线规则与 OCS 几何，D5 的结论是程序不进训练损失）。规则制导（`outputs/guidance/`）只作基线与诊断，不作模型的修法（用户规则）。
- **程序的固定点**（IAF / IF / FAF）可作句子里的锚 token 或打分里的路标：先不做，B3′ 读完再定（D59）。

#### 5.2.4 与多机交互的结合（阶段 C 之后；框架承接 09-18 §2.8）

- 指令词表让多机层与管制员的实际操作同形：前机的指令序列就是管制员对前机说的话，后机的先验读它作上下文；间隔规则（`inference/runway_schedule.py` 一处定义，`docs/literature/arrival_separation/`）作用在**候选指令**上——后机某条指令交给执行器飞出来的那一段，若对前机已提交的段违反间隔，该候选在打分前屏蔽；掩码约束的是指令，飞出的实际间隔由门读。
- 场景 = 同一机场、切片时间重叠的到达（KRDU：p50 3 架邻机，六成航班的同跑道前机在切片里，09-18 §2.8 的量）；同跑道按预计到达顺序串行提交；边特征（相对位置、同跑道 / 平行、到达时钟差、尾流类别、间隔余量）作机间注意力的偏置；切分按运行日（T4）。
- 先量上限（C0，最便宜）：不建图，把前机的**真值**指令序列作为上下文喂给单机先验，读雷达引导层的变化；差大于 seed 线才值得建层。
- 具体臂与门在阶段 C 之后写（D60）。

#### 5.2.5 步骤（每步：为什么 → 做什么 → 怎么判 → 不过怎么办）

**顺序（用户 2026-09-20 定）：第二层先训、先读，再回到 B1′ / B2′。** 理由是用户的：执行器这一层原则上可以用一个
常规的自动驾驶或制导程序直接解出来（仓库里已经有一个规则跟踪器 `outputs/guidance/PlanGuidance`，自己飞自己的航路；
让它执行"航向 270 / 高度 3000 / 速度 180"这样的指令目标只差一层很薄的转换），所以执行器不是这项研究的主张所在。
主张是第二层：模型能不能**说出**一串把飞机带到跑道入口的指令。这个顺序成立，是因为第二层自己那份读数是自洽的——
每类的 perplexity、top-1、该换词时没换的比例、不该换时乱换的比例，都是拿它自己和两个基准比（`hold_baseline`：
一个永远保持、从不说话的模型，外加一个 bigram），不依赖 B1′ 给出的执行器上限。

**执行顺序：B0′′（加跑道词、重做词表产物）→ B3′ 的前半（第二层自己训、自己读）→ B1′ → B2′ → B3′ 的后半
（接执行器解码、门 B）→ B4′。** 步骤编号不改，因为全文都在引用。B0′′ 排在最前面不是多一道手续：加词就是换词表，
而一个实验要读的结构必须在它开跑之前定死，所以第二层不能在旧词表上先训。B0′′ 的两项量测已完成（结果文档 §13），
结论是**只加跑道词**；剩下的是代码、重做产物、跑道词的人工核。
**待定**：第二层自己这一段要不要一条门槛（D61）；D66 的三处改动与 D67 的消融排在哪一步。

  - **D51 给的理由不成立。** 它写的是「目标离档中心 p95 都在半档以内（128 m）」。分档用四舍五入，任何一个数离自己那一档的中心必然不超过半档——这是算术恒等式，永远不会失败，所以它什么也没测到。仓库自己的规矩：一个永远不会咬人的界比没有界更糟。
  - **～~第一处改法：入口穿越不该是高度指令~～ 2026-09-21 撤回，我判错了。** 原话是「标注器把飞过入口那一段读成平台，那是落地，结束词已经在说」。查了发令时刻之后不成立：那条指令的目标高度 p50 **57 ft**（与公布的入口穿越高 TCH 50–60 ft 吻合，51.5 % 落在 40–80 ft），但它**发出的时刻**是实际高度 p50 **3057 ft**、距入口 p50 **8.2 NM**，**90.4 % 在 3 NM 以外**。它是最后那道下降许可——飞机离开最后一个平飞层、开始连续下降到跑道的那一刻——是一条真指令，时刻也对。它之后高度词一直保持 0 档到落地，这正是「最后一个事件的高度词 6853/6853 全是 0」的来由。**留着，不动标注器。**
  - **仍然成立的那一半**：这条指令的**高度值是退化的**（永远 ≈ TCH），它承载的信息在时长词（什么时候发）和跑道词（去哪条）里，不在高度值里。所以**定档宽时要把它排除**，理由是它是个常数、会把误差指标粉饰得好看（含它全队均值 141.5 ft，不含 235.3 ft），**不是因为它是假的**。它是 KRDU cohort 上 8,212 / 8,257 架各一条、没有一架两条。
  - **第二处改法：剩下的真实层按 200 ft 分档。** 去掉那一条之后剩 **33,124 条**，在它们上面现行的 1000 ft 档 **等同随机取整**——均值 235.3 / p50 240.9 / p95 472.0 ft，而均匀随机的参照是 250 / 250 / 475。500 ft → 112.4，250 ft → 62.4，**200 ft → 50.9（51 词）**，100 ft → 26.3（101 词）。真实层落在入口以上 1600–3700 ft，只有 24.7 % 在整五百上、15.3 % 在整千上，因为格子锚在入口而管制指定的是 MSL。
  - **锚到 MSL 不是解法（量过才否的）**：全队几乎不动（500 ft 档上 87.6 → 83.2 ft）。它救 KRDU（205.6 → 63.2）和 KSTL，却弄坏 KSJC（73.8 → 93.7）和 KSMF。逐机场看，现行档从 73.8（KSJC）到 205.6（KRDU），差距跟着入口高程走。
  - **D76.b 高度是下限还是目标（2026-09-21 用户提出，未决）**：程序数据里五个机场 1,070 条带高度的进近腿，**80.1 % 是 `+`（等于或高于，即下限）**、14.4 % 是「等于」。但词是从飞出来的平台读的，读到的是飞机实际稳住的高度，也就是管制「下到并保持」的证据——按 D50 它是目标。两者要对上，而粗格子会在这里造出违规的指令：**四舍五入到最近档，1000 ft 格下 34.4 % 的指令被压到实际高度以下（压低时均值 160 ft、最多 500 ft）**；改成只向上取则平均抬高 **468 ft**，等于每条都飞高一截。200 ft 格两头都还行（压低均值 51 ft / 抬高均值 102 ft）。**这是独立于精度的第二个、更硬的理由。** 没测的一条：「低于飞机保持的高度」不等于「低于公布的下限」，飞机保持的层本就可能高于下限一截；要判真违规，得把每条指令对到最近定位点的公布下限上。取整方向（最近 / 向上）与是否把词改成下限语义，一起定。
  - **D76.c 档宽的依据变了：高度词是「锚」，不是「尺」（2026-09-21 量测，未决）**：全文见 `docs/reference/defaults.md` H7。**分段怎么切、档位怎么拟、以及最坏那一段为什么误差大，写在 `docs/2026-09-21_vertical_word_method.zh.md`（全文单位为米）——那份文档也订正了本条里「误差沿途累积、正负不抵消」这个机制解释：同号比例在最坏 1 % 和其余都是 5 %，真正的机制是一段长航段的梯度卡在两个档中间，单段即占终点误差的 56 %。**三件事一起改了这一项的问法。
    - **非均匀确实赢，前提是细格放在层所在的那一带**（用户两次坚持，我两次用错形状去量、两次报了「非均匀没用」）。把格心直接拟到数据上（Lloyd-Max，留一格给那条退化的下降许可）：11 格 235.3 → **134.4**，21 格 112.4 → **72.7**，41 格 62.4 → **35.5**，而 **26 个拟合格（53.3 ft）打败 41 个均匀格（62.4 ft）**，每类中位样本从 242 涨到 1,275。格心密集在 **1500–3200 ft**、两头稀疏，正是用户说的形状。代价：格心成了数据的一部分，要和 sha 一起冻死，cohort 一变就想重拟；`altitude_centre_m` 变成 26 项查表。
    - **下降角能稳住，而且是双模的**（我先前说它「散且带噪」是错的）：用标注器同一套平台规则读，11,199 段、中位保持 32 s，和高度平台同量级；但 13.0 % 是平飞，9,723 段真下降的四分位只有 **2.70–3.22°**（p50 3.01）。飞机在**整条进近**上只做两件事：平飞，或按约 3° 降。那是一个比特，而高度词已经在说它。
    - **整个去掉高度词（用户提出）被尾巴否掉，不是被中位数否掉**：用「平飞/下降 + 时长 + 真实地速」还原整条剖面——单段中位下降 473 ft、误差中位 **−2.1 ft**、|误差| 中位 **43.5 ft**（3° 这个常数比我预期准得多）；但整条累积 |误差| 中位 **153.4 ft**、**p75 299 ft、p95 1,189 ft**。**（2026-09-21 同日订正：这三个数被我标错了名字——它们是「各平台内部误差之和」，两个平台之间的过渡段一行都没算，不是端到端的剖面误差。让指令铺满航迹重算——每条指令从它自己的事件起生效到下一条为止，过渡段归前一条管，这才是闭环里真实的语义——没有高度词时端到端的终点高度误差是 中位 218.1 ft、p95 1,442.6、p99 2,327.7。结论方向不变且略强，但这三个数不是端到端的。另有一条只有端到端才看得见：最坏值不随任何选择改变，因为一架全程不改平的飞机一次锚都触发不到。）** 中位数过了事先定的线，尾巴没过。结构原因：绝对目标的误差有上界（半格），速率的没有、还会逐段累积；中位数好看是因为正负抵消（中位 +4.7 ft）。而且这是**下限**——用的是真实地速，闭环里速度也是预测出来的词，两个误差相乘。
    - **所以档宽的问法变了**：段内形状 3° 已经给到 43 ft，高度词的活是**封住漂移**而不是报精确值。当锚用的格子可以比当尺用的粗，这也顺带缓解 H5 那个类样本不足（200 ft 档在 KRDU 单训下中位每类只有 9 条）。**待定**：按「锚」重取档宽、均匀还是拟合、以及 cohort（KRDU 单训还是五机场合训，后者把每类样本量抬一个量级）——三件要一起定。
  - **代价**：两处都动产物——换 sha、B0 重建、每一句话都变，队列必须停到改完（仓库规矩：实验要读的结构在开跑前定死）。**没解决**：200 ft 与 250 ft 之间按什么取（51 词对 41 词，均值 50.9 对 62.4）；去掉入口那一条之后，每架的高度指令从 2.0 条降到约 0.78 条，句子会变短，D61 判「最后一个事件」的含义要跟着复核。
- **D77 垂直角度不做词，做判据（2026-09-21 用户提出、量测后定）**：用户问「为什么不用类似航向角一样的垂直角度范围，就像 LPV 规定一样，在给定执行段内不能大于某个角度」。量完的结论是**当判据成立，当词不成立**，两条理由出自同一批数（H6，13,043 条指令 / 7,486 架）。
  - **先分清两个角**，我先前的读数把它们混过，这里写死：**位置角** = `atan(入口以上高度 / 沿航迹到入口的距离)`，问的是「我在不在公布的下滑道上」；**航迹倾角** = 飞机速度矢量和水平面的夹角，问的是「此刻降得多陡」。
  - **当词不成立：它在有意义的那一段几乎不变。** 上了航道之后（航道 ±30°、侧偏 < 1 NM、入口之前）位置角 p50 **3.05°**，减去该跑道公布的下滑角是 **+0.04°**，**88.5 % 落在 ±0.5° 内**。按 0.1° 分档，近九成样本挤在三个档里，模型学到的最优解就是永远输出第 0 档——和现在「永远输出高度词 0」是同一个病，换了单位而已。
  - **它变的那一段没有意义。** 还没上航道的 **40.1 %** 指令，同样 0.1° 分档要 **598 个词**才盖得住 p1–p99（p95 高到公布下滑角以上 **14.69°**），因为飞机在下风边、基边上，到入口的直线不是它要飞的那条路，中间有转弯。所以「全程一个角度尺、远场读成大角度」这个更省的变体**被量测否掉**。
  - **随之省下一笔成本**：不做分段换单位的词，`Vocabulary.altitude_centre_m` 仍是一个转换，判据、执行器的 `plan_conditioning=instruction`、前端配色、条件向量归一化都不用动。
  - **航迹倾角不能当判据；不能当词的理由 2026-09-21 改写。** 当判据不行：同一批时刻 p50 **2.52°**、四分位 1.75–3.47°、**9.4 % 在平飞**、89.9 % 在下降，真实下降是一段平一段陡凑出来的（样本：4131 ft / 12.8 NM 以 5.53° 猛降追回航道；3043 ft / 12.8 NM 以 0.00° 平飞等下滑道降下来接）。**当词不行的理由原来写的是「散且带噪」，那句话不成立，已作废**：用标注器同一套平台规则读，它稳得住——11,199 段、中位保持 32 s。真正的理由是**双模**：13.0 % 的段是平飞，9,723 段真下降的四分位只有 **2.70–3.22°**，所以它能表达的是「平飞 / 约 3° 下降」一个比特，而高度词已经在说这一位（下一个目标更低即下降，相同即平飞）。量测见 H7(b)。
- **D78 D61 的垂直判据改成「位置角对该跑道公布的下滑角」（2026-09-21，待用户定；不动产物）**：D61 原来的垂直项是「最后一个事件的高度词 = 0 档」。D75 已经说明那个词判不了决断高（一格 1000 ft，25 条跑道的决断高 200–423 ft 全在第 0 档里）；D76 又要把高度词换掉。所以这一项改成物理量：**最后一段用位置角对该跑道公布的下滑角比**，标准取自 D77 量出的真值分布（真值 p50 +0.04°、±0.5° 内 88.5 %）。
  - **公布下滑角逐跑道取，永远不写死 3°**——KRDU 32 是 **3.50°**；25 条跑道都有值，只有 KRDU 14（无仪表进近、不在任何清单里）没有。来源是 CIFP path point / 进近图的运行腿，已在 `Runway.published_glidepath_deg` 里。
  - **这条不改词表、不换 sha、不重建产物**，所以可以先于 D76 做。**没解决**：容差取 ±0.5°（真值 88.5 % 命中）还是取公布的 ±22 m 换算值，两者要在同一批真值上并排读一次再定。

- **D62 跑道是第五个词（2026-09-20，用户定）**：见 5.2.1。前四类词全是相对跑道说的，等于把"去哪条跑道"这条指令藏进了坐标系，而管制员是要说出口的。词的形式是一个按机场绑定类别集合的分类槽（同 `context.TypeVocabulary`），第一个位置就说，其余四类词相对当前生效的跑道词。为什么：D50 说词要是管制员真会说的话；跑道指定就是其中一句。代价：词表变了、sha 变、B0′ 产物重做（前四类读法不动，那五轮人工核仍作数）。没解决：跑道词能不能中途改，见 D64。
- **D63 复飞是结束词的一个值，不是单独一类（2026-09-20 用户定，两次修正后的结论）**：术语是复飞（missed approach / go-around），程序里的点是 MAPT 与 MAHF，两者我们的 CIFP 处理里都有，所以目标就是 MAHF。**量出来的事实**：机队里复飞是真的（44 622 架里 42 架，剖面逐架核过），但**在建模用的 cohort 里一次都不触发**——词表读的是 25 km 到达切片，切片只含最后那次成功的进近，8 架在 cohort 里的复飞航班最低点之后的爬升全是 +0 m（结果文档 §13.5）。**我一度据此写成「不进词表」，那是我把自己的论证当成了用户的决定，用户纠正了两次。** 用户的理由更强：基座训完之后 RL 可以**构造**复飞的局面（执行器到不了跑道、安全约束触发、阶段 C 的冲突），而词表里没有这个词，模型连表达都做不到，RL 想探索都探索不了；而加一类词会改 `INSTRUCTION_KINDS`、改嵌入与头的形状、改 sha，**旧 checkpoint 全部作废**——今天加跑道词就是这么发生的。所以它进词表，但不是单独一类：它是**结束词的第三个值**（D72），和「落地」共用一个头。没解决：预训练里它 0 次，**任何门槛都不能把它算进去**；那个头能学到的只有继续 vs 落地。将来若要给它一点信号，有一条不动 cohort 的路——那 42 架真复飞的**完整航迹**可以单独作一小批补充样本，不动到达切片、不动数据集划分。
- **D64 跑道词可以中途改：机制保留，不设门槛，并写明这份数据分辨不了它（2026-09-20 依 FAA 原文定，量测后补数）**：真实管制里改跑道是常规做法，写在三个地方——**7110.65BB 4-7-1 b**（跑道号在初次联系时或尽早给出，"或此后任何一次跑道变更"若在距跑道过渡航路点 10 NM 以内才发出，就必须改为雷达引导至最后进近）、**3-10-5 c**（落地许可里改跑道有专门用语 "CHANGE TO RUNWAY (number), RUNWAY (number) CLEARED TO LAND"）、**4-8-7 侧移机动**（side-step；AIM 5-4-19：间距 ≤ 1200 ft 的平行跑道）。逐条引到段：`docs/literature/runway_assignment/README.md`。所以跑道词必须可改；改的那一刻之后其余各类词换参考系。**量出来了**（结果文档 §13）：**最后进近阶段跑道完全分得开**——按公布的航道宽度 ±350 ft（AIM 1-1-18 d 4：入口处总宽 700 ft）读，44 622 架里 44 592 架对上自己那条跑道，**只有 1 架**对到别条，所以**晚改（side-step）在这份数据里基本不存在**。远处那一栏 5.70 % 只是**重新指定次数的上界**，不能读成"管制员改了跑道"，而且我们那个 ±500 m 走廊在 KSJC（平行间距 213 m）和 KSTL（392 m）根本分不开平行跑道。结论：**机制保留，先验学不到，不设门槛，不算进读数的成败**，并在文档里写明这份数据分辨不了它。
- **D65 跑道词的可达性判定：用几何，且只在后训练与解码里用（2026-09-20 用户定）**：跑道词可改之后，先验可能在距入口 3 km、高 800 ft 时说"改去 32"，物理上到不了。**用几何**，不用执行器：`outputs/guidance/route.py` 的 `_shortest_to_join` 已经给出"能不能用转-直-转接上这条跑道的切入位姿"，接不上返回 `None`，再加一条"要掉的高度除以那条路径的弧长不超过下降梯度上限"。执行器回答的不是同一个问题（飞 Δ 秒只说明这 Δ 秒可飞），而且它依赖权重、每个 epoch 要重算，KRDU 上是每 epoch 1650 万次滚动，按 200 epoch 算约 2000 倍于几何。**只在后训练与解码里用**：基座预训练加屏蔽会把那一项 softmax 的支撑集改小，于是每类 NLL 不再与 bigram、"永远保持"可比，而 D61 的门槛正是拿它们比的——会悄悄废掉第二层自己那份读数；预训练也不需要它，真值从不说到不了的跑道。文献一致（SaFeR 在**冻结**的先验上做可行性屏蔽，去掉它碰撞率 0.761 → 0.827、可解率 0.865 → 0.527）。**与 D59 不是一回事**：D59 是程序屏蔽（这样飞合不合规矩），D65 是可达性屏蔽（够不够得着），作用对象也不同。没解决：下降梯度上限；速度能不能减下来要不要一并判。
- **D66 跑道头要求把跑道从输入里拿走（2026-09-20 用户定）**：三处一起改——状态 token 的原点换成机场基准点、去掉跑道航道的上下文 token、跑道词进输入也进输出。详见 5.2.2。为什么：不改的话跑道是三重给定的，跑道头不是预测而是抄。改完第 0 个位置的跑道预测只看机场相对位置、绝对航向、速度、机型，正是 `r11_lift` 的特征组，可直接与它比（方向层 96–99 %、KRDU 左右层 73–75 %）。没解决：另外四类头要自己还原相对入口的位置与航道方向，退多少得跑了才知道。
- **D69 跑道词的类别来自到达清单，于是清单的版本成了先验身份的一部分（2026-09-20 重建词表时发现）**：KRDU 有 6 条跑道，但词表只读出 **4 类**（05L / 05R / 23L / 23R）。不是 bug：到达清单 `harvest-arrivals-v5-takeoff-excluded` 在 KRDU 只含这 4 条，14（13 次落地）和 32（1604 次）在上游就被排除了。两条后果要写明：(1) **本阶段的句子说不出 32**，跑道词的覆盖面是清单的覆盖面，任何"模型能说出去哪条跑道"的结论都带着这个范围；(2) 根 CLAUDE.md 的 Open Items 说，重建成 `harvest-arrivals-v6-published-vertical-path` 会加回 KRDU 32（+1876 架）——那不只是改数据集划分，它会**改变跑道词的类别集合**，于是 `runway_sha256` 变，**此前训的每一个先验都作废**。D62 之前重建只动划分，现在它动身份。**已定（用户 2026-09-20）：接受现在的类别，不重建到达清单、不动训练数据。** 因此本阶段一切关于「模型能说出去哪条跑道」的结论都带着这个范围：KRDU 的句子说不出 32，KSMF 说不出 35R。结论里必须写明，不能默认读者知道。
- **D68 跑道那一列在 D66 之前读不出技能（2026-09-20 复核发现）**：标注器把跑道词写成每架常数，而同一个词又是输入的一列，于是 `top1["runway"]` ≈ 1.0、`change_share` = 0、联合 top-K 里跑道那一位是白给的；而且 `next`（选 epoch 用的那一项）现在是**五个**交叉熵之和，与 D62 之前的任何数都不可比。**引用这些数的读数必须写明这一点**，否则跑道那一列会被读成技能。D66 改完之后重新看。另外一条要记的成本：联合 top-K 的候选张量随跑道类别数增长（KRDU 6 条 → 约 1.2 万个候选，每块约 100 MB，原来约 17 MB），4060 上够用，但大批量评估前要知道。
- **D67 中间状态给不给，做成消融（2026-09-20 用户提出）**：同一份数据训两版——每个位置都给真实状态 / 只在第 0 个位置给——用自由生成读数比。为什么：每位置都给，先验只需"看一眼雷达说下一句"，从不需要对整句话负责，而"模型要能说话"要求的是后者。没解决：完全不给不成立（同一句话从不同起点出发意义不同）；消融排在门 B1 之后还是之前。
- **D60 多机层**：阶段 C 之后，按 5.2.4；切分按运行日。

## §8 队列与成本

### 8.2 阶段 B（2026-09-20 重写；RTX 4060）

- **GPU**：执行器每臂 12–15 min；闭环飞 train 一遍约 7 min；闭环再训一轮约 25 min / seed；先验预训练 5 min；先验闭环再训（含飞 train）约 15 min；目标导向解码读数每份 10–20 min（K = 4，每轮四倍 rollout）。第一版（KRDU、两 seed、τ = 10 s、含 B2′ 与 B3′）约 1 天 GPU；τ 消融再加半天。
