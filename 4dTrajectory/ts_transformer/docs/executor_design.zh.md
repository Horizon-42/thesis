# 执行器设计

**一句话**：执行器是一个自动驾驶。它每秒读一次飞机状态和此刻生效的词，把词翻译成"想要的变化率"，由点质量动力学
方程精确反解出推力、坡度、载荷因子，交给现有的动力学积分一秒。它不读程序数据，不学习，也不从数据里量任何参数。

词的定义见[指令词表](2026-09-23_instruction_vocabulary_design.zh.md)，总体框架见[两层模型框架](2026-09-23_two_tier_framework.zh.md)。
本文是框架的阶段 3（执行器）和阶段 4（回放门，§11）。代码在包 `ts_transformer/autopilot/`（`autopilot/README.md`），
§14 是关键代码的索引。

## 1 原则与参数来源

**只用词表**（用户，2026-09-24）：执行器的每个参数都从词表规格推出，或是写明的固定选择；要靠从数据里挖出的参数才能
飞好，就说明它不能泛化。词表以外，执行器只读下面这些公布的、与数据无关的东西：

- 候选跑道的几何（句子产物里的 `candidates.json`：入口位置、跑道航向、入口高程）；
- 被指跑道**公布的入口跨越高度 TCH**（FAA CIFP，harvest 的跑道数据；"下降至落地"在这里越过入口，§5.3）；
- 每架航班的动力学：机型的气动参数与装机推力，质量取机型**公布的最大着陆重量**（§2.4）；
- 机型**公布的进近速度**（"未指定"速度飞它，§6）。

参数的来源只有五种，§10 的总表逐个标出：

| 来源 | 含义 | 例子 |
|---|---|---|
| 动力学方程 | 精确反解，没有可调的数 | 由想要的变化率算坡度、载荷因子、推力（§3） |
| 词表规格 | 冻结的规格里已有的数 | 转弯率范围、坡度上限、各下降档的角度、容差、切入角、提前量 |
| 推导 | 由稳定性、临界阻尼、几何或包络推出 | 横向增益、截获提前量、改平起点、γ̇ 上限 |
| 公布数据 | 跑道和机型的公布值 | TCH、最大着陆重量、进近速度 |
| 固定选择 | 写明理由的设计选择，记进规格 | 控制周期 1 s、τ_γ = 2Δt、γ̇ 上限取下限的 2 倍、超时系数 1.5 |

**为什么不从数据量快动态**：观测的速度、航迹、爬升率是数据平面对位置做 15 s 居中最小二乘拟合得到的
（`flight_scenarios/start_state.py`），比 15 s 快的动态（压坡度、回正、改平）在数据里被抹平了，量出来的主要是拟合窗口。
这类参数都按 §9 从词表推出。

## 2 动力学与接入

### 2.1 状态、控制量、方程

执行器飞的是 ts 控制路径自己的点质量动力学（`aerodynamic_model/torch_dynamics`；运输坐标版本多一个坐标系转动项，
量级约 1e-3 °/s，下面略去）：

```text
状态  x = (位置, 高度 h, 空速 V, 航向 ψ, 航迹倾角 γ, 质量 m)
控制  u = (推力 T, 坡度 φ, 载荷因子 n)

ḣ  = V sin γ
V̇  = (T − D) / m − g sin γ
ψ̇  = g n sin φ / (V cos γ)
γ̇  = g (n cos φ − cos γ) / V
ṁ  = 0
```

- **阻力** `D = ½ρV²S·C_D`，`C_D = C_D0 + k·C_L² (+ 接近失速时的附加阻力)`，`C_L = n m g / (½ρV²S)`，ρ 按 ISA；
  气动参数是每架航班机型自己的（`aero_params`）。`C_L` 超过 `C_L,max` 时方程把载荷因子截住（失速）。
- **没有风**：地面航迹 = ψ，地速 = V cos γ。词说的是地面航迹和地速，二者一致。
- **角度约定**：动力学里 ψ 是数学约定（正东为 0，逆时针为正），所以**正坡度向左转**；词说罗盘航迹（真北为 0，顺时针），
  χ = 90° − ψ。两者只在 `frame.py` 里相遇。

### 2.2 控制量的界

| 量 | 界 | 出处 |
|---|---|---|
| 推力 | `T = δ_T · T_max`，`δ_T ∈ [−0.2, 1.0]`（负推力代表襟翼、起落架、减速板的阻力，干净构型的极曲线里没有） | `outputs/envelope.py` |
| 坡度 | 执行器按词表的坡度上限 32°（动力学允许 45°） | 词表 `turn_bank_max_deg`；`geometry/flyability.Envelope` |
| 载荷因子 | 可飞包线 `[0.5, 2.0]` | `geometry/flyability.Envelope` |
| 失速 | 速度参考不低于 `1.10 · V_stall(n)` | `outputs/constraints/speed_floor`，控制路径的同一个裕度 |

### 2.3 积分

- 动力学配置取控制路径现行配方 `simple-v3` 的那一对：`point-mass` + `scaled-transport-chart-velocity`，推力按
  `thrust-fraction`（`plant.EXECUTOR_DYNAMICS`）。执行器飞出的因此就是 ts 控制路径能产生的那种轨迹。
- 每个控制周期用控制路径公开的积分函数 `rollout_control_endpoints` 积一段（零阶保持，段内 RK4），段末状态交给下一段。
  点质量后端不调用 command hook，所以执行器不嵌在一次 rollout 里；这与 hook 是同一个计算：hook 也是每段开始时拿到状态，
  积分器本来就在段的边界重新开始。段与段之间以大地坐标交接，两次坐标换算互为精确逆运算。
- **控制周期 Δt = 1 s**，每个 2 s 的词步里两段。

### 2.4 每架航班的输入

- 用数据平面给句子产物里的航班重建 `FlightSeries`（`data.dataset.build_series`，产物记录的到达清单和构建配置；两者变了
  就拒绝）。重建出的航班必须与产物存的信号逐行一致、跑道与机型相同，否则拒绝（`flights.require_same_flight`）。
- 由它读出初态（位置、速度矢量、质量）、气动参数、装机推力、积分坐标系（`outputs/dynamics/context.rollout_context`）。
  回放从句子第 0 行起飞；闭环从先验的第一个预测步起飞（`flight_inputs(anchor=…)`）。
- **质量**：ADS-B 里没有真实质量。每种有动力学的机型都按**公布的最大着陆重量**飞（`flight_scenarios/build.py`，
  `aircraft/aircraft_sets.landing_mass`；FAA 飞机特性数据库的进近速度就是在这个重量下定义的）。B737 取 Boeing 737-700
  的 58,604 kg（FAA 那一格 66,043 kg 是 737-7 的）；OpenAP 的最大着陆重量对 C550、B38M、B37M、A20N、B752 不对，不用。
- 状态读进各律时，位置换到机场坐标系（与标注器同一个投影），候选跑道、词的目标、包络都在机场坐标系里算。

## 3 一个控制周期

**外环**把生效的词翻译成三个想要的变化率：罗盘航迹变化率 χ̇*（§4）、航迹倾角变化率 γ̇*（§5）、空速变化率 V̇*（§6）。
**内环**把 §2.1 的后三个方程反过来解（`geometry/flyability.py` 判定可飞时用的同一个反解，这里正着用）：

```text
A = −χ̇*·V cos γ / g            （= n sin φ；负号来自罗盘与数学约定相反）
B =  γ̇*·V / g + cos γ           （= n cos φ；B ≤ 0 按 0 读，不从零转弯的符号编出坡度）
φ = atan2(A, B)
n = B / cos φ                   （先定坡度，再由 B 定载荷因子，保证 γ̇ 正好是要的）
T = m (V̇* + g sin γ) + D(V, n, h)
δ_T = T / T_max
```

阻力用动力学自己的函数在这个 n 下算，反解与积分共用一个极曲线，内环没有可调参数。

每个周期的顺序（`executor.Executor.cycle`）：

1. 横向律给 χ̇*，纵向律给 γ̇*；
2. 反解定坡度和载荷因子：坡度截在 32°、每秒最多变 p，载荷因子截在包线里（`inverse.attitude`）；
3. 速度律在这个载荷因子的失速下限之上给 V̇*（`speed.Speed.rate`）；
4. 反解定推力，截在推力的界里（`inverse.thrust`）；
5. 积分一个周期（`plant.Plant.step`）。

第一个周期的坡度不受变化速度限制：第 0 步的词写的是飞机进入切片时已经在做的事，正在转弯的航班应当接着转。

**零阶保持**：控制量在 1 s 内不变而 V、γ 在变，一段结束时的变化率与想要的略有出入，下一段的外环会修正。所以 §4、§5 的
时间常数都不小于 2Δt。

**一架航班什么时候结束**（本周期末）：已截获且越过所指跑道的入口平面；在入口前低于入口高程；状态非有限或空速 ≤ 0；
到了时限。整批在每架都结束时停。结局在事后由判定读出（§8）。

## 4 横向

先说两个量：**坡度 φ** 是机翼相对水平面的倾角，倾斜的升力提供转弯的向心力；**转弯率 r** 是航迹每秒转多少度。平飞协调
转弯时 `r = g·tan φ / V`，转弯半径 `R = V / r`。同一个坡度，速度越大转得越慢。

### 4.1 航向词

`instruction-v3` 的航向词逐行标注，一条只转一两格（5° 一格），并**提前 L = 4 s** 说出（词表设计 §10.1）：一条词说的是
"L 秒后航迹在这里"。所以执行器听到它之后，要正好在 L 秒后转到它（`lateral.word_rate`）：

```text
剩余时间 = 听到这条词的时刻 + L − 现在，至少 2Δt        （过了期限按 2Δt 追，即保持）
收得住   = sqrt(2 g p |e| / V)                         以这个转弯率转，坡度按 p 收回时正好转完 e（小坡度近似）
|χ̇*|   = min(|e| / 剩余时间, 收得住, r_max)，方向随 e
```

- **误差 e 从生效的词量起**（`Lateral.word_error`）：第一条词取较短方向；之后每来一条新词，目标在原来的目标上再转
  `wrap180(θ_新 − θ_旧)`，沿飞行展开。连续转弯是一串相隔几秒的词，每条都在执行器还没转到上一条时说出，执行器一直
  压着坡度转；盘旋按第一条词定下的方向一直转，执行器落后时也不会因为"较短方向"反过来转。
- **每行只在行首听一次**：航向词、许可、跑道指针每 2 s 一行只在行首那个周期听到，判定也从这一行起算（§8.2）。
- **"收得住"**：执行器不知道哪一条词是转弯的最后一条，所以每条词都按"可能要停在这里"来转。
- **r_max** 是词表的最大转弯率 4.7°/s；多数速度下坡度上限 32° 在反解里先起作用。
- **为什么不用一阶律 `e / τ_ψ`**：转弯结束时最后一条词说出后目标不再往前走，一阶律只按指数逼近，过 L 秒还剩约 37 % 的
  误差，转弯的最后一两条词必然出包络；只按剩余时间而没有"收得住"，又会冲过转弯的最后一条词（2026-09-24 两轮代码
  审查）。

### 4.2 执行器自己的转弯

执行器自己决定的转弯——自行切入、复飞、沿线跟踪——不由词定节奏，用一阶律（`lateral.rate_for_error`）：

```text
χ̇* = sat(e / τ_ψ, ±r_max)          τ_ψ = L = 4 s
```

它不需要"收得住"的限制：p·τ_ψ 等于词表的坡度上限（§9），`e / τ_ψ` 只在坡度上限先起作用的地方才超过收得住的转弯率。

### 4.3 许可之后、截获之前

许可之后、截获之前照飞航向词。按 θ 在入口前碰不到航线、而 θ ± 4.5°（航向容差）之内有航向碰得到时，把 θ 朝航线偏 4.5°
（`envelope.heading_converges` 的镜像，与标注器同一个判断）；偏了仍在这条词的包络之内。偏了也碰不到时，按词表的切入角
30° 自己切入航线——这是标注器插入切入词时用的规则（词表 §2.2）。这出现在执行器不在观测飞机的位置时（转弯比观测的宽、
改出后与五边平行）；此时已离开这条航向词的包络，判定照实报（模式 `intercepting_off_word`）。

### 4.4 截获

"已截获"是执行器自己的状态，不是词。设 y 为离所指跑道延长中线的横向距离，Δχ 为航迹与跑道航向之差，V 为地速。

**什么时候开始**：已许可、未截获、在入口前，并且

```text
朝航线飞（y 与 sin Δχ 异号），且
|y| ≤ V/r · (1 − cos|Δχ|)          圆弧，r = √(r_min · r_max) ≈ 1.53°/s（词表转弯率上下限的几何平均）
      + V sin|Δχ| · t_roll / 2      压坡度期间按一半时间直飞算，t_roll = |atan(V r / g) − φ| / p
      + V r τ_ψ² / 2                回正的指数尾巴（§4.2）
```

或者已在截获走廊的宽度之内（词表 §2.2），立即截获。按下限 0.5°/s 规划时转弯卡在包络边上（train 500 架里 17 条截获出
包络），几何平均时 4 条（用户 2026-09-24 选定）。许可比这个提前量早到时，执行器照飞它的词（必要时偏 4.5°），到了再转。

**怎么转**：每个周期按"从当前位置出发、正好切到线上"的圆弧重算转弯率，朝跑道航向转：

```text
r_arc = V (1 − cos|Δχ|) / |y|
|χ̇*| = min( max(r_arc, r_min), g·tan 32° / V, r_max, |Δχ| / τ_ψ )
```

中途减速（半径变小）或压坡度晚了，都不会停在线外或冲过线。下限 r_min 防止在走廊里、离线较远处开始的截获转得比任何词
都慢（它会先转到航向、再由沿线跟踪收拢）。

**交给沿线跟踪**：航迹离跑道航向在走廊的航向容差（2°）之内，或者不再朝航线飞（已越过中线：许可来得晚，或坡度上限让
转弯慢了）。

### 4.5 沿线跟踪

把横向距离换成一个想要的航向，交给 §4.2 的一阶律：

```text
θ_line = 跑道航向 − sat(k_y · y, a)
k_y    = 1 / (4 V τ_ψ)
a      = 走廊外：切入角 30°；走廊内：走廊航向容差的一半（1°）
```

**k_y 的推导（临界阻尼）**：在线附近线性化，`ẏ = V·Δχ`，航向环 `τ_ψ·Δχ̇ + Δχ = Δχ*`，代入得
`τ_ψ ÿ + ẏ + V k_y y = 0`，临界阻尼要求 `1 = 4 τ_ψ V k_y`。横向误差以时间常数 2τ_ψ 衰减；真实的航迹还滞后于坡度，会越过
中线几米，都在走廊宽度之内。走廊要求航迹离跑道航向不超过 2°：走廊内只用一半去修横向偏差，另一半留给航向环自己的滞后。

### 4.6 跑道指针与复飞

- 航线是跑道指针所指那条候选跑道的延长中线。许可之前换指针就换航线；许可或截获之后换指针，标注里已被拒绝，执行器
  同样拒绝（报错）。闭环里说话的一方用 `Executor.runway_locked` 知道此刻能不能换。
- **复飞**（进近列）：取消"已许可"和"已截获"；横向飞所指跑道的航向（§4.2）；纵向有高度目标时用高度保持律去它（最多按
  爬升类的角度爬），生效的是"下降至落地"时按爬升类的角度爬，直到来了新的高度词；速度保持当前空速。复飞时航向词的
  目标重新以当前航迹为起点，之后的词从那里量。

## 5 纵向

### 5.1 航迹倾角内环

```text
γ̇* = sat((γ_ref − γ) / τ_γ, ±γ̇_max)
```

- **τ_γ = 2Δt = 2 s**：内环只负责让 γ 跟上外环给的 γ_ref，越快越好，限度是 1 s 的零阶保持；留一倍余量。
- **γ̇_max**：飞机从平飞转入按某档下降时，航迹角只能以有限速度变化，变过来之前飞机高于这一档管子的上沿，最多高出
  `V γ_lo² / (2 γ̇)`。要它不超过管子的容差 ε = 25 m，需要 `γ̇ ≥ V γ_lo² / (2ε)`，γ_lo 取最陡一档的下沿（现行规格
  3.74°）。执行器取这个下限的 2 倍（§9）：`γ̇_max = 2 · V γ_lo² / (2ε)`，100 m/s 时约 0.98°/s。

### 5.2 高度与下降角：四种模式

| 生效的词 | 模式 | γ_ref |
|---|---|---|
| 目标 T + 平飞 | 保持 | 高度保持律（§5.5） |
| 目标 T + 下降档 k | 按角度下降，到了改平 | −γ_k（该档的名义角度：现行规格各档中心 0.92°、2.13°、3.06°、4.41°），离 T 还有改平距离时转入保持（§5.4） |
| 目标 T + 爬升 | 按角度爬升，到了改平 | +1.32°（爬升类的名义角度），同样改平 |
| 下降至落地 + 下降档 k | 按角度下降到落地 | §5.3 |
| 复飞 + 下降至落地 | 爬升 | +1.32°，直到来了新的高度词（§4.6） |

来了新的高度词或角度词，已截获的目标就放开，按新词重来。方向与目标矛盾的组合在标注里已被拒绝，执行器遇到时同样
拒绝；"下降至落地"配的不是下降档也拒绝。

### 5.3 下降至落地

#### 5.3.1 越过点

"下降至落地"的意思是落在被指跑道上，在入口处越过**公布的 TCH**。入口处**允许的高度**是 TCH ± 高度容差的内半（25 m 的
一半，12.5 m），且在落地条件（入口上方 0–100 m）之内。

**管子**：从生效的那条高度词或角度词说出的位置起，按该档两条边线的角度下降，± 高度容差，沿飞过的路程（标注器
`labeller.vertical.tube_bounds` 的读法）；执行器取它的内半（两边各留容差的一半，`TUBE_MARGIN_SHARE = 0.5`）。

**越过点**取 TCH 挪进"管子延伸到入口处"与允许高度的交集里；没有交集时取允许高度里离管子近的一端。

#### 5.3.2 飞法

每个周期：

1. **朝越过点的角度**：截获中线之前，取这一档的名义角度，但不陡于到越过点的直线（直线是最短的路，下风边上不会下到
   地上）；截获之后，取沿中线到越过点的角度。
2. **限在管子里**：把这个角度限在这一档两条边线的角度之间，再加高度保持律把飞机拉回边线以内的修正。
3. **什么时候离开管子**：只要从管子出发、在平飞与最陡一档的下沿（3.74°）之间飞还够得到入口允许的高度，就一直留在管子里；
   够不到了（只在截获之后、不在复飞中）才离开管子，直接朝越过点飞（模式 `aim_left_tube`）。为什么不在"这一档延伸到入口
   够不到"时就离开：标注在每条角度词处重新起管子，下降角在进近中途变陡或变缓的航班，任何一档单独都够不到入口，但后面的
   词会把它带过去。
4. **不低于越过高度**：截获之后，下降不陡于"朝越过高度的高度保持律"与"到越过点的直线"中较陡的一个，所以入口前不会低于
   越过高度。

#### 5.3.3 选这条规则的依据（train 500 架，每机场 100，按 `time` 说词，2026-09-24，当时的规格最陡一档下沿 3.73°）

| 飞法 | 落地 | 越过高度超出 TCH ± 22 m | 高度词合格 | 全部词合格 | 照句子飞完 |
|---|---|---|---|---|---|
| 这一档延伸到入口够不到就离开管子 | 500 | 0 | 86.9 % | 97.2 % | 70.2 % |
| **够不到允许高度才离开（按最陡一档的下沿算）** | **500** | **0** | **95.1 %** | **97.9 %** | **82.2 %** |
| 按最陡一档的上沿 10° 算"够得到" | 500 | 19（都偏高） | 96.4 % | 98.0 % | 83.8 % |
| 截获后不设"不低于越过高度" | 491（9 架触地） | 0 | 96.0 % | 98.0 % | 82.0 % |
| 只用高度保持律作限制（不取与直线中较陡的） | 500 | 19（入口前约 1 km 内下不去） | 95.0 % | 97.9 % | 82.0 % |
| 越过点直接取 TCH（不挪进管子） | 500 | 0 | 94.5 % | 97.9 % | 81.4 % |

两架合成直线进近（下降角 2.1° → 3.3° → 4.3° 变陡，3.9° → 2.8° → 2.0° 变缓），落地词每行都在包络内。

#### 5.3.4 已知问题：平缓档下截获后偏陡（先验读数 §12）

照标注的词重飞训练集（每机场 400 架，种子 1337），2.45 % 在 FAF 以内低于下滑道下沿 100 m 以上（后训练第二阶段的检查）。
被判的 49 架里 41 架真实飞机在同一位置就在下滑道上；执行器从同一高度出发，一路比它低，被判时低 143 m（中位数）。

原因在第 2 步："下降至落地"配最平一档（−0.5°–1.52°）或第二档（1.52°–2.59°）时，真实飞机多是在五边上、下滑道下方，
基本平飞等下滑道从上方下来接住它；截获之后，从下滑道下方看越过点的连线约 2–3°，比这一档陡，执行器就贴着管子最陡的一侧
（加上管子的容差）下降，每分钟比真实飞机多丢 72 m（最平一档）、45 m（第二档）（中位数）。等真实飞机沿下滑道下降、标注换成第三档，执行器从自己
已经偏低的高度起按这一档飞，一直在下滑道下方。

词没有错：这一档从 −0.5° 到 1.52°，"平飞等下滑道"和"现在按 1.5° 下降"都在里面，词没说在档里的哪一处下降；执行器不知道
下滑道（只用词表和 TCH），没法"等下滑道"。把第 2 步截获后的取法改成这一档的名义角度（其余不变）时，被判低于下沿只少
三分之一，却有约 10 % 过入口时高于落地条件——"朝越过点飞"正是标注的词能落地的原因，不能简单拿掉。怎么改待用户决定
（执行器读跑道公布的下滑角，或词表分开"保持高度等下滑道"与"现在下降"；改完先看照标注的词开着下沿检查能否回到约 99.9 %）。

### 5.4 截获目标高度：什么时候开始改平

以 γ_k 下降、航迹角以 γ̇_max 回到 0，这段过程掉的高度是 `V γ_k² / (2 γ̇_max)`。飞机离 T 还有这么多时转入高度保持，正好在
T 改平、不越过。100 m/s、3.06° 时约 8 m。爬升同理。

### 5.5 高度保持

```text
γ_ref = −(h − T) / (V τ_h)，限在 [−4.41°, +1.32°]（最陡一档与爬升类的名义角度）
τ_h   = 4 τ_γ = 8 s
```

把 γ 内环看作一阶，代入得 `τ_γ ḧ + ḣ + (h − T)/τ_h = 0`，临界阻尼（不越过 T）要求 `τ_h = 4 τ_γ`。

## 6 速度

```text
V_ref = V_g* / cos γ                              速度词说的是地速，换成空速（无风）
V_ref = max(V_ref, 1.10 · V_stall(n))             失速下限，在本周期反解定下的载荷因子下（speed_floor 的同一个定义）
V̇*    = max( min((V_ref − V) / τ, a), −a_dec )    τ = δv / (加速时 a，减速时 a_dec)，δv = 5 m/s
```

- **a = 0.25 m/s²**（词表）：一个速度级差 ÷ 速度词最短保持时间 = 5 m/s ÷ 20 s（用户 2026-09-24 定）。加速、减速都用它；
  离目标还剩一个带的半宽 δv 时从匀变速转成指数逼近，进带时速度单调、不越过目标（词表的速度过渡包络）。
- **"未指定"**是飞行员自己落地用的速度：本机**识别出的机型**公布的进近速度（`aircraft/reference_speeds`，FAA 飞机特性
  数据库，每个数有出处），按质量换算 `V_app(m) = V_pub · √(m / MALW)`，再由指示空速换成真空速 `· √(ρ0/ρ(h))`。
  执行器的质量就是 MALW（§2.4），所以取的就是公布值。减到它的减速度 a_dec 取 a，和"按离入口的直线距离在入口前减到它
  所需的减速度"中较大的一个，最多到词表的加速度上限 1.4 m/s²；只用 a 时，说得晚、五边长、速度高的航班越过入口时比机型的
  速度窗口快 20 m/s。
- 用替代机型动力学的航班（§11.3），质量是替代机型的，"未指定"取本机型公布值、不换算。
- 复飞时保持当前空速（§4.6）。推力由 §3 的反解给出。

## 7 同时顶到限制时怎么办

每个周期按这个顺序施加限制，每一条被触发都记下来（§8.1）：

1. **失速下限**先定（在速度律里）：速度参考不低于 1.10·V_stall(n)。
2. **纵向优先于横向**：先按 γ̇* 定 `B = n cos φ`；坡度被上限或变化速度截住时，由 `n = B / cos φ` 保住 γ̇，损失的是转弯率。
   高度比横向位置更要紧：管子只有 ±25 m，横向的漏斗随距离张开。
3. **载荷因子**截在可飞包线 `[0.5, 2.0]` 里。正常飞行达不到这个界；达到了说明词要求的机动太猛。
4. **推力**截在 `[−0.2, 1.0]·T_max` 里，损失的是速度变化率：顶到上限，飞机加速或爬升不了那么快；顶到下限，飞机以这个
   角度下降时减不了速。执行器按下降角保高度、让速度让步，因为下降角是词明说的，速度过渡本身有包络可查。

## 8 判定：这句话飞出来了没有

执行器的轨迹由动力学积分而来、控制量在界内，所以在动力学意义上总是可飞的。要判的是**这句话**能不能被飞出来，分三层
（`judge.py`）。

### 8.1 第一层：每个周期，要的与给的

每个周期记下想要的三个变化率、实际得到的变化率，以及哪条限制被触发（坡度上限、坡度变化速度、γ̇ 上限、载荷因子、失速
下限、推力上限、推力下限、动力学的失速截断）。每架报出每条限制占多少周期，以及触发时要的与给的差多少（按这条限制损失
的那个变化率）。"想要的"是各律在自己的上限（γ̇ 上限、失速下限）之前要的量。

### 8.2 第二层：每个词，是否飞在它自己的包络里

飞出的航迹按句子的 2 s 行读出，过标注器的同一道闸门（`read.admit`，平滑与落地截断都一样），再用标注器的同一套检查，
从执行器听到这个词的那一行起判：

| 词 | 检查 | 函数 |
|---|---|---|
| 航向 | 在第 r 行听到的词，从 r + 提前行数到下一条词的行 + 提前行数，每行航迹与词相差 ≤ 4.5°；判到下一次许可或第一次截获为止，提前量越过它、一行都没有的词记为"不判" | `envelope.heading_words_inside`（标注器的同一函数） |
| 许可 | 截获转弯（从开始截获到航迹在跑道航向 2° 以内）单调、转弯率与坡度在词表范围内；进了走廊之后一直在走廊里（到入口前） | `labeller.lateral.turn_check`、`envelope.corridor` |
| 自行切入 | 许可时航向碰不到航线、执行器按 30° 切入且离这条航向词超过容差：这条航向词不合格 | 模式 `intercepting_off_word` |
| 高度与下降角 | 高度逐行在管子里 | `labeller.vertical.tube_checks` |
| 速度 | 过渡单调、加速度不超过词表上限、到达后在 V ± 5 m/s 内 | `labeller.speed.span_checks` |

- **只读入口前的行**：航迹在越过入口的那一行之前结束，与标注器的句子一样结束在落地之前。
- **没到的词**：航班结束之后的词执行器根本没收到，记为"没到"，不判。落地的航班飞了它收到的全部词；没落地的在第三层已经失败。
- **被取代的词**：按航迹说词时时钟可能一步跨过一行，同一列两条高度、角度或速度词落在同一行，前一条没飞就被取代，
  记数不判（航向词各自判）。

### 8.3 第三层：每架航班的结局

**落在所指跑道上了没有**，直接用 harvest 判观测航班着陆的同一个条件：航迹越过所指跑道的入口平面（沿航道距离由正变负），
在前后两点之间插值出越过点（`final_approach.crossing.bracket_fraction`），越过点离中线不超过 1000 m、且不超过到相邻平行
跑道距离的一半，离入口高不超过 100 m（`final_approach.assign.LandingScreen`，标注器用同一个条件）。

| 结局 | 判定（同一行几件事同时发生时按表中顺序取） |
|---|---|
| 动力学失效 | 状态非有限、空速 ≤ 0，或动力学的失速截断起了作用（失速下限在，不应发生） |
| 入口前触地 | 还在入口前，高度已低于入口高程 |
| 落地 | 已截获，越过点满足上面的条件 |
| 没截获就越过入口 | 越过点满足条件，但没有"已截获" |
| 越过了但不在这条跑道上 | 已截获，越过点不满足条件（多是入口处太高） |
| 超时 | 时限内以上都没发生。时限 = 这架航班自己的剩余时长 × 1.5：给执行器留出速度落后的余地，又不让绕圈的航班无限飞下去 |

**按原话飞出来** = 落地，且收到的所有词都合格（"没到"的不算），没有动力学失效（`Verdict.flew_the_sentence`）。

**落得好不好**交给 evaluation：执行器的记录写成 evaluation 的记录格式（与 ts 控制路径的预测记录同一套），判横向、垂直、
速度三道门，不在执行器里重写。执行器不读程序；程序数据只在评判里出现。

## 9 参数怎么定

比 15 s 快的参数（§1）都由词表推出（办法 A，`derive.py`），不用数据：

- **τ_ψ = L = 4 s**：执行器自己的转弯按一条词给的时间收尾；满足 τ_ψ ≥ 2Δt（每个周期最多消掉一半误差，单调逼近）。
- **p = 32° ÷ 4 s = 8°/s**：一个提前量之内压到词表允许的最大坡度（用户 2026-09-24 定）。
- **γ̇_max** 取 §5.1 下限的 2 倍。
- **截获按 √(r_min r_max) 规划**（§4.4），**速度快慢 a = 5 m/s ÷ 20 s**（§6）。

再在 train 的固定抽样上查敏感度（`experiments/executor_sensitivity.py`，每机场 400 架、自己的动力学；参数与现行规格相同，
2026-09-24 的代码）：τ_ψ 2–6 s、
γ̇ 系数 1–3、p 6–10°/s 时词的合格率都在 97.9–98.0 %；p = 4°/s 时 96.8 %。结论：这些值不影响结论，不需要用数据标定。
val 只用来判门，不用来定参数。

## 11 回放门（阶段 4）

**问题**：把标注的句子交给执行器，它能不能把飞机按原话飞到所指跑道上。

### 11.1 输入

句子产物里已标注的航班，从第 0 行起飞，初态为第 0 行。句子最后一行之后，词保持不变，直到落地或失败。每架都先用标注器
重读，必须与存下的句子逐格相同（执行器飞的是这架航班的读法，不是一张看起来一样的表）。

### 11.2 词在哪里说

一条词只给目标、不给快慢（速度词不说减速多快），所以执行器按自己的节奏飞时，会沿航迹比观测飞机早到或晚到。若按观测的
时刻说词，后面的词就落在不该落的地方（基线转弯早了 2 km，五边短了 3.5 km、高 160 m）。管制是在飞机到了某处时说词，
闭环里先验也是看执行器自己的状态说词；回放标注的句子时，就在执行器到了观测飞机听到这条词的位置时说
（`ExecutorParams.word_clock`，`sentence.py`）：

- **`track`**（回放门用这一种）：执行器到了观测航迹上离它最近的那一点（往前最多看 60 s，只进不退，每个周期最多前进一行，
  所以绕圈的航迹不会被跨过）时，说那一点的词；
- `distance`：执行器飞过的路程等于观测飞机飞过的路程时说（转得比观测急时路程对不上位置，比 `track` 差）；
- `time`：按观测的时刻说，留作对照。

时钟一步跨过一行时，两条航向词会同时到：前一条没飞，与它同时到的那一条单独计数（`replay.told_with_skipped`），门仍按
全部词算。

### 11.3 谁进门

| 组 | 条件 | 处理 |
|---|---|---|
| 自己的动力学 | 识别出的机型就是动力学机型，且公布了进近速度 | **进门** |
| 替代机型 | 性能索引表给这个机型换了另一个机型的动力学（例如 GLF4 按 CRJ9 飞） | 只报不判：误差是替代机型的气动，不是执行器 |
| 不飞 | 没有识别出机型；没有动力学（索引表排除、或没有模型）；机型没公布进近速度 | 只计数 |

### 11.4 门

每个机场分开、直线进近与被引导分开，每格都要过（`experiments/executor_replay.GATE_SHARE = 0.95`）：

1. 落在所指跑道上的比例 ≥ 95 %（§8.3）；
2. 词的合格率 ≥ 95 %（§8.2，按词计）；
3. **evaluation 与观测配对**：观测航迹自己通过 evaluation 的航班里，执行器回放也通过的比例 ≥ 95 %。观测本身没通过的只报
   不判（观测基线本来就不是 100 %）。两份报告的 schema 与 methodology 必须相同，否则拒绝；观测的一份由同一份代码判。

与观测的差别（落地时刻之差、时间对齐的 ADE / FDE、路径对齐的 chamfer / Fréchet、每条词发令时的横向 / 垂直 / 速度误差、
限制的触发率）报出，不设门。门没过时，先看 §8 三层里失败落在哪一层、哪条限制，再决定改执行器还是回头看词表；不在 val
上调参数。

## 12 执行器规格与源码指纹

- **规格**（`spec.py`，runner `experiments/executor_spec.py`）：`spec.json` 记参数（`ExecutorParams`）与它们的 sha、所用词表
  规格的 sha、标注器源码的 sha、执行器源码的 sha 和 git 状态；`measurements.json` 记每个值从哪来。写一次，从不覆盖；只在
  干净的工作树上写。格式 `ts-executor-spec-v5`。
- **源码指纹**（`spec.executor_source_files`）覆盖 `autopilot/*.py`（`spec.py` 除外），加上它们**直接** import 的、仓库自己的
  模块（动力学、包线、进近速度表、`data/dataset.py`、geokit……），按模块名计，与检出位置无关；不计的是 `UNHASHED_IMPORTS`
  （词表包由标注器指纹管、路径与文件工具、evaluation 的命令行）。`README.md` 等非 `.py` 文件不计。
- **打开时核对**（`replay.open_executor`）：执行器源码指纹与现行代码的相同、词表规格 sha 与句子产物的相同、句子产物的
  标注器是现行代码、规格记的标注器指纹也是现行代码的——任何一项不同都拒绝。
- **后果**：改 `autopilot/` 里任何 `.py`（连说明文字在内），或它直接 import 的仓库模块，现行代码就拒绝已有的规格；要按新代码
  重写一份规格（`executor_spec`），再重跑训练集回放门（`executor_replay`）。v7 → v9 就是这样来的。

## 13 与后面阶段的接口

- **逐步执行**：`executor.Executor` 一次飞一个周期；`fly()` 是它整句飞完的循环，闭环里说话的一方与它交替（先验说一步的词，
  执行器飞这一步，`sentence.Spoken` 记下说过的每一步）。执行器每 2 s 给出与信号同一套量（机场坐标系里的位置、MSL 高度、
  航迹、地速、垂直速率，以及到每条候选跑道的相对量）。
- **先验的自由生成与后训练**（`experiments/prior_free_generation.py`）：`fly_reference` 照标注的词从第一个预测步飞，
  `speak_and_fly` / `ClosedLoop` 让先验说、执行器飞；时限 = 观测飞机从第一个预测步到落地的时间 × 1.5（`limits_s`）；
  下滑道下沿的检查读执行器飞出的每一步（`glidepath_stops`，后训练设计 §3）。
- **前端 Training 视图**：后端（`aeroviz_backend/autopilot_segment/backend.py` `executor_for`）在执行器根目录下取现行代码唯一
  接受的那份规格，点词即飞它的一段。
- 执行器不学习；闭环再训只训先验，执行器是环境。

## 15 用户的设计决定

1. 动力学用点质量模型；坡度变化速度由执行器自己限制。控制周期 1 s。
2. **只用词表**（2026-09-24）：不从数据挖参数，词说出即执行（没有延迟）；p = 32° ÷ 4 s；截获按词表转弯率的几何平均规划；
   速度快慢取 5 m/s ÷ 20 s；落地用被指跑道公布的 TCH，候选跑道没有 TCH 时标注器第一步就拒绝。
3. "未指定"的速度用机型公布的进近速度，不从训练数据拟合。
4. 所有有动力学的机型按公布的最大着陆重量飞，B737 取 Boeing 737-700 的数（2026-09-26）。
5. 没有 A320 替身：没有动力学的航班只计数；性能索引表给的替代机型只报不判。
6. 门：落在所指跑道上、词的合格率、evaluation 与观测配对；落地判定与 harvest / evaluation 一致，标注器用同一个条件。
7. 平行跑道的横向上限暂不挪进 `final_approach`：标注器与执行器用 `instructions/airport.landing_cross_limit_m`（harvest
   `_runway_bracket_cross_limit` 的镜像，测试逐跑道核对二者相等）。
8. 执行器只用词表：要靠数据挖出的参数才能做好，说明不能泛化；执行器保持简单。

## 16 已知问题与遗留

1. **平缓档下"下降至落地"截获后偏陡**（§5.3.4，先验读数 §12）：怎么改待用户决定。
2. **复飞期间说的航向词不飞**：复飞时横向一直飞跑道航向，直到复飞结束（2026-09-24 审查记下）。
3. **判定只给第一次截获定航向词的截止**：复飞后再次截获，不另起一段（2026-09-24 审查记下）。
4. **回放别人的句子时转弯半径不同**：词只说转到哪个航向、不说多急，执行器与观测飞机的转弯半径不同，大转弯能在五边前
   差出几公里（例：KSMF 17R 的被引导航班落到中线西边 3–4 km，入口前几百米才截获）。这不是执行器能不看答案补上的；
   闭环里先验按执行器自己的状态说词。
5. **多襟翼机型的进近速度**：E75L、B737、A319、E170、E190（占先验训练航班的 25 %）用单一的 FAA 进近速度，没有公开的
   原始出处给减襟翼的 V_REF（`docs/code-health-followups.md` #21，卡在出处上）。
6. **`autopilot/__init__.py` 的说明里还是本文的旧文件名**（`2026-09-23_executor_design.zh.md`）：改它会动源码指纹、让现行代码
   拒绝 v9（§12），随下一次执行器规格一起改；`autopilot/README.md` 指向本文。
