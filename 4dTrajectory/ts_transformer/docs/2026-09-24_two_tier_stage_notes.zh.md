## 2 执行器（结论；设计与推导在执行器设计文档）

- **只用词表**（用户的原则：要靠大量从数据挖的参数才能做成，就说明不能泛化）。所有转弯在词表的转弯率 0.5–4.7°/s 与坡度上限
  32° 内；词说出即执行，每 2 s 一行只在行首听一次；τ_ψ = 提前量 4 s；p = 32° ÷ 4 s = 8°/s；截获按 √(0.5 × 4.7) ≈ 1.53°/s 规划；
  速度变化快慢 = 速度级差 ÷ 速度词最短保持时间 = 0.25 m/s²；落地越过被指跑道公布的 TCH（`autopilot/runway_data.py`，FAA CIFP；
  候选跑道没有 TCH 时标注器第一步就拒绝）；落地时留在生效那条词的管子里下降，直到从管子出发、在平飞与最陡一档下沿 3.73° 之间
  飞也够不到 TCH ± 12.5 m 才离开。固定的设计选择：周期 1 s、τ_γ 2 s、γ̇ 系数 2、超时系数 1.5。
- **落地质量**（2026-09-26 合并，用户"按你的建议改"）：每种有动力学的机型都按**公布的最大着陆重量**飞（FAA 飞机特性数据库；
  那里的进近速度就是在这个重量下定义的）。B737 的 FAA 那一格（66,043 kg）其实是 737-7 的，改用 Boeing 737-700 的 58,604 kg；
  OpenAP 的最大着陆重量对 C550、B38M、B37M、A20N、B752 不对，不用。性能索引按分析的规则重判：E545 / E550 → C550，B733 → 排除；
  原生失速余量范围按新质量重判。影响：选择集 711 / 1,000 架换了质量或进近速度，B737 的进近目标速度 63.0 → 66.9 m/s；
  对先验的落地率影响在 0.5 个百分点以内（§5）。
- **执行器规格的源码指纹**覆盖 `autopilot/` 包和它直接 import 的仓库模块（含 `data/dataset.py`）：这些文件一改，就要重写执行器规格、
  重跑训练集回放门（v7 → v9 就是这样来的）。
- **敏感度**（v5）：τ_ψ 2–6 s、γ̇ 系数 1–3、p 6–10°/s 都不敏感，p 4°/s 时词 96.8 %。
- **已知问题：平缓档下"下降至落地"截获后偏陡**（先验读数 §12，执行器设计 §5.3.4）：配最平一档或第二档时，截获中线后执行器朝越过点、
  贴着管子最陡的一侧下降，真实飞机在下滑道下方基本平飞等下滑道；照标注的词重飞训练集 2.45 % 被判低于下沿，其中 41 / 49 架真实飞机
  在同一位置就在下滑道上。只把截获后的取法换成档的名义角度，被判少三分之一、却有约 10 % 过入口太高。怎么改待用户决定。
- **留下没做的**：审查记下的两点（2026-09-24）——复飞期间说的词执行器不理；只有第一次截获结束词的判定窗口。多翻襟型别
  （E75L、B737、A319、E170、E190，占先验训练航班的 25 %）用的是单一的 FAA 进近速度，没有公开的原始出处给减襟翼的 V_REF
  （2026-09-25 查过，`docs/code-health-followups.md` #21，**卡在出处上**）。

## 3 先验

### 3.1 设计（第三版，用户 2026-09-24 确认；全文在先验设计文档）

- **原则**：输入只给说这一步之前管制员能知道的东西；标注器读出的词只当预测目标；以场景（同一机场、同一时刻的一组飞机）为单位；
  按运行日划分，测试集按整天另封。
- **没有未来信息**（用户 2026-09-26 要求再确认过）：第 t 行只读第 t 行及以前；地速、运动方向（sin / cos）、垂直速度是第 t−1 行
  与第 t 行的**位置差 ÷ 2 s**（`prior/data.py` 的 `rows_inputs` / `_motion`），不用拟合的、以窗口为中心的速度（那会带约 7.5 s 的
  未来）；另有相对跑道的位置、第 t 步之前生效的词、第 t 步之前的落地情况。
- **数据**：句子前 `N_look` = 8 行（16 s）只观察；第一个预测步六列都要说；每条候选跑道的向量含几何、相对位置、此前 30 分钟内
  这条跑道上的落地架数和距上次落地的时间（排除测试集运行日、排除本机自己的落地）；已说的词 = 每列当前生效的词 + 距上次换词的
  步数；每架飞机的静态属性留接口、本版为空（不加机型）；不给钟点和风。
- **模型**：每层 = 沿时间的因果注意力 → 同一步各架飞机之间的注意力（边特征作每头的偏置、也加到值上）→ 前馈；d 192、4 层、6 头。
  同一步内各列按 跑道 → 进近 → 航向 → 高度 → 下降角 → 速度 的顺序输出，后列看前列刚选的值；各架飞机同时说。
- **分步**：0 准备 → 1 单机 → 2 M1（25 km 范围里看不看得到交互）→ 3 前机一条边 → 4 完整场景 → 5 多机闭环与后训练；每步的门在设计 §9。

### 3.2 结果

- **第一、二版**（按航班划分，不作本设计的对照）：第二版选中 V2d（给过去的运动和方向差），决定了第三版的这两块输入（读数文档 §1、§2）。
- **第 0 步**（划分、重测规格、句子产物、普查）：读数文档 §3。
- **第 1 步（单机）**：选中 full（候选跑道带落地情况、各列按顺序）；验证集每个预测步负对数似然 0.2643；门过了——每列都赢两个
  基线；还没建立在五边上的航班第一步跑道 81.5 %（基线 69.6 % / 72.1 %）（读数文档 §4）。
- **单机自由生成**（先验说、执行器飞；`prior_free_generation`，R17）：base 模型落地 89.3 %（内部选择集）、90.2 %（验证集，直线
  94.0 % / 被引导 83.3 %）；照标注的词飞 100 % / 99.9 %；失败的多是一直给航向、迟迟不许可直到超时。门先只记录（用户 2026-09-25）
  （读数文档 §5）。

## 4 后训练（设计全文：后训练设计文档）

**共同**：闭环就是单机自由生成；训练只用训练集运行日、选轮用内部选择集、验证集每个阶段定稿后只读一次、**测试集运行日一架都不读**。
**base 模型** = 第 1 步只用数据训出的 `full_s1337`，每个阶段的拉回项都拉回它（用户 2026-09-25 定名）。

### 4.1 闭环监督微调（CAT-K）——不采用（用户 2026-09-25，读数文档 §6）

验证集 90.2 → 93.1 %，但全部来自直线进近（94.0 → 99.7 %），被引导的 83.3 → 81.0 %，航向词只剩标注的一半，teacher forcing 负对数
似然 0.284 → 0.452。原因：链离观测越飞越远（100 s 偏 460 m），按时间对齐的标注在链上不成立。代码已归档（`archive/closed_loop_sft_2026_09/`）。

### 4.2 第一阶段：按落地强化——采用（读数文档 §7）

- **做法**（`prior_landing_reward`，R19）：从 base 起；每轮每机场 400 架训练集航班、每架自由说 8 句；落地且在机场此刻的落地方向上
  得 1；同一架航班的几句互相比（优势 = 奖励 − 这架 8 句的平均）；损失 = 优势加权的负对数似然 + 0.04 × 拉回 base（按采到的词估计的
  KL）+ 1 × teacher forcing 数据项；AdamW 学习率 1e-5；8 轮，在内部选择集上按护栏选轮。
- **结果**：选中第 1 轮（选择集 90.0 → 96.5 %）；验证集 90.2 → **97.2 %**（直线 94.0 → 99.0 %，被引导 83.3 → 93.9 %），teacher forcing
  负对数似然不变，被引导航班的航向词 37.4 → 31.5（标注 31.4）。

### 4.3 第二阶段：下滑道下沿屏蔽 + 扩充起点——不采用（用户 2026-09-26）

- **屏蔽**（后训练设计 §3，`prior/procedure.py`，R20）：只留 FAF 以内、LPV 扇形里的下滑道下沿（公布下滑道 − 60 m，照优化器）；
  RNAV 在 FAF 以外的高度限制在标注数据上量过后不做（与 10–14 % 的记录航迹矛盾）。只屏蔽高度列；屏蔽照顾不到的由飞出来的
  航迹再查（低于下沿 100 m 以上 → 结局"低于下滑道下沿"，奖励 0）。第 0 步过了（读数文档 §8.2）：训练集标注的高度词被屏蔽 0.09 %、
  重飞被结束 2.50 %（通过线 1 % / 3 %）；开着屏蔽，第一阶段模型在选择集上落地 95.7 → 92.1 %，差的全是低于下沿（执行器飞
  "下降至落地"时下沉）。
- **扩充起点**（§4，`prior/augment.py`）：只变换前 8 行和执行器的初始状态——绕机场转 ±15°、高度 ±150 m、速度 ±5 %，均匀取；之后由
  执行器照先验的词飞。时限 = 源航班从第一个预测步到落地的观测时间 × 1.5（用户 2026-09-26 确认保持）。每轮 100 % 扩充起点。
- **训练**（§5，`prior_augmented_reward`，R21）：从第一阶段模型起、拉回 base；损失与第一阶段同一配方（奖励 + 0.04 × 拉回 + 1 × 数据项），
  奖励和拉回按每句说时的屏蔽算。**数据项** = 训练集运行日真实航班、带标注词的 teacher forcing 负对数似然（标注器从 ADS-B 航迹读出的
  词，不是无线电录音）；每次更新一半本轮句子、一半数据批；**扩充起点从不进数据项**，两者只共享参数。选轮看扩充起点的落地率；护栏：
  真实起点落地 ≥ 第 0 轮 − 1 个百分点、落在观测跑道上 ≥ 第 0 轮 − 2 个百分点、五列每架词数与标注之比的 |ln| ≤ 第 0 轮的 + ln 1.2；
  teacher forcing 负对数似然只记录。
- **五次运行**（读数文档 §9、§10）：

  | 运行 | 做法 | 结局 |
  |---|---|---|
  | `v3_augmented_20260926` | 固定拉回强度，无数据项 | 第 1 轮扩充起点 82.7 → 93.5 %，但离 base 0.29、许可 / 复飞词 2.6 倍；停 |
  | `v3_augbudget_20260926` | 距离预算第一版 | 调节把拉回强度降到 0.003，模型冲出去；停 |
  | `v3_augbudget2_20260926` | 第二版（快升慢降、下限 0.04、硬停） | 第 1 轮过全部护栏（真实 96.0 %、扩充 90.4 %），第 2 轮被单批距离误停 |
  | `v3_augbudget3_20260926` | 第三版（距离平滑） | 来回摆：第 2 轮被拉回到比起点更靠近 base（87.4 %），第 3 轮又冲（84.1 %）；没有一轮在护栏内 |
  | `v3_augdata_20260926` | 加回数据项（用户 2026-09-26） | 第 1 轮过护栏（选择集真实 91.8 %、扩充 84.5 %）；第 2、3 轮不过、离 base 到 0.38；第 4 轮中用户叫停 |

- **验证集，第 1 轮 vs 第一阶段模型**（都开着屏蔽，执行器 v7）：扩充起点 83.4 → 85.5 %，真实起点 94.2 → 93.5 %，扩充起点上每架
  航向词 15.2 → 21.6——没有明确的提升，不采用。
- **学到的**：没有数据项时，拉回 base 要么拴不住、要么抹掉第一阶段的提升（距离预算的代码已删）；有数据项时 teacher forcing 负对数
  似然拴得住，但模型在自己的闭环里照样漂走，扩充起点的收益最多两个百分点，还多说航向词。现行代码里数据项是必需的（runner 拒绝
  `--data-weight` ≤ 0）。
