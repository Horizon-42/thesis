# 先验设计（阶段 5，2026-09-24）

**一句话**：先验是一个自回归模型，读航班的背景（机场与候选跑道）和到此刻为止的状态与生效的词，写出下一步
六列词（每列"不变"或一个新词）。它从句子产物里学（教师强制）；以后与执行器接起来，一步说词、一步飞。

词的定义见[指令词表](2026-09-23_instruction_vocabulary_design.zh.md)，执行器见[执行器设计](2026-09-23_executor_design.zh.md)，
框架见[两层模型框架](2026-09-23_two_tier_framework.zh.md) §1、§4。

## 1 数据

- **来源**：句子产物 `4dTrajectory/outputs/POOLED/instruction_language/v2_20260924/`（规格 `103a6eae6b90`）。train 50,214 架、
  970 万步；val 10,540 架。只读这一份产物，核对规格 sha 与标注器源码 sha（框架 §1："句子产物是唯一的真值来源"）。
- **划分**：train 训练；val 只用于早停和读数；test 不打开。
- **一步** = 句子的一行（2 s）。一架航班的句子是信号的前 `len(words)` 行（在落地前结束）。

## 2 每一步的输入与输出

第一版在第 t 步看到的如下（**第二版的改动见 §8**：这里的航迹、地速、垂直速率含有之后 7.5 s 的信息）：

- **状态**（信号的第 t 行，机场坐标系，米制，按固定尺度缩放）：E、N、MSL 高度、航迹（sin、cos）、地速、垂直速率、
  从第 0 行起的时间；
- **相对生效跑道的量**：离入口沿航道的距离、偏离中线、入口上方的高度、航迹与跑道航向之差（sin、cos）。第 0 步
  跑道指针还没说，这几个量为 0，另给一个标志位——否则第 0 步就从特征里知道了要说哪条跑道；
- **生效的词**（第 t−1 步为止）：六列各一个嵌入；第 0 步用"还没有词"的嵌入；另给每列"上次换词之后过了几步"
  （对数缩放）；
- **背景**（每架一份，加在每一步上）：机场的嵌入；候选跑道的几何（最多 8 条：入口 E、N、高程，跑道航向 sin、cos，
  有效位）。

输出第 t 步的六列词。每列一个分类头，类别 = "不变" + 这一列的全部取值：

| 列 | 取值数 | 类别数 |
|---|---|---|
| 跑道指针 | 候选数（≤ 8，按机场屏蔽无效的） | 9 |
| 进近 | 3（未许可、许可加入、复飞） | 4 |
| 航向 | 72（5° 一档） | 73 |
| 高度 | 181 档 + 下降至落地 | 183 |
| 下降角 | 平飞、4 个下降档、爬升 | 7 |
| 速度 | 47 档 + 未指定 | 49 |

第 0 步六列都写（初始的词），之后每列在约 1–2 % 的步上换词。

## 3 模型

因果 Transformer（只看自己和之前的步），每步的输入是上面各项投影后相加，六个分类头。第一次的尺寸（§6）：
d = 192、4 层、6 头、前馈 768、dropout 0.1，约 200 万参数。按长度把航班分桶成批，不截断（最长 1,133 步）。

## 4 训练

- 损失：六列交叉熵之和（跑道头只在有效候选上做 softmax）。
- 优化：AdamW，学习率 3e-4，权重衰减 0.01，梯度裁剪 1.0。
- 早停：看 val 的平均每步负对数似然，3 个 epoch 不降就停，最多 30 个 epoch，保留 val 最好的一次。
- 产物：`4dTrajectory/outputs/POOLED/prior/<名字>/` 写一次、不覆盖：`checkpoint.pt`、`config.json`（含产物目录、规格 sha、
  标注器 sha、git 状态）、`history.json`（每个 epoch 的 train / val 损失）、`readout.json`。只在干净的工作树上跑。

## 5 读数（这次只读，不设门）

框架 §4 的先验门有四项：困惑度、前 K 覆盖、自由生成能否以落地结束、赢过"重复上一条"和"只看上一个词"。第一次
训练读前两项和两个基线；自由生成要和执行器接起来，放在下一步。

- **每步负对数似然与困惑度**，分列报；
- **换词的步**（真值换了词）：模型给"换词"的概率；取值的前 1 / 前 5 命中率；
- **不换的步**：模型说要换词（取最大概率的类不是"不变"）的比例；
- **两个基线**（都从 train 数出来，在 val 上算同样的负对数似然）：
  - 重复上一条：每列按 train 的换词频率给"换词"的概率，换成什么按 train 各取值的频率；
  - 只看上一个词：换成什么按"这一列上一个词 → 下一个词"的 train 频率（加一平滑）。

## 8 第二版：输入与结构的改动（计划，2026-09-24）

### 8.1 为什么改

1. **速度类的输入含有未来的信息。** 信号里的航迹、地速、垂直速率来自 `flight_scenarios.state_samples_from_track`：对每个
   ADS-B 点，在它前后各 7.5 s 的窗口里做最小二乘拟合（`DEFAULT_WINDOW_S = 15`，repo `docs/open-items.md`）。所以第 t 步的
   这些量已经含有 t 之后 7.5 s 的信息。合成例子：100 m/s、第 0 s 起每秒右转 2°，这样拟合出的航迹在 −2 s 已偏 0.89°、
   0 s 偏 2.30°；只用过去 15 s 拟合的在 0 s 仍为 0。
   - 航向词正好标在转弯开始的那一行，先验可能学成"看到航迹开始弯了才说转"。闭环时执行器要先听到词才会转，这样学到的
     先验会说晚或不说。影响有多大还没量（§8.3 的变体 0 就是量它的）。
   - 位置（E、N、高度）直接取自报告点，没有拟合，不受影响。标注器照旧用拟合：它读完整条航迹产出标签，看到未来是允许的。
2. **没有相对每条候选跑道的量。** 第一版只算"相对生效跑道"的量，第 0 步跑道还没说时为 0。所以第 0 步选跑道时，模型只能
   用绝对位置和拼成一个向量的候选几何，在网络里自己算出相对关系。词表设计 §4.2 本来规定每一步对每条候选都算相对量，
   §4.1 规定候选跑道编码成与排列顺序无关的 token、§4.3 用"本步隐状态对每条候选打分"选跑道；第一版把这些简化了，
   当时没有写明。
3. **第 0 步的航向、速度词是从拟合的速度里读出来的。** 去掉速度类输入后，只有一个位置点，看不出往哪飞、飞多快。

### 8.2 改动（四项）

1. **不输入拟合的速度类量**：去掉航迹（sin、cos）、地速、垂直速率，以及"航迹 − 跑道航向"（它也用拟合的航迹）。
   保留 E、N、MSL 高度、从第 0 行起的时间。飞多快、往哪飞，模型从之前各步的位置里自己看（每 2 s 一个位置）；要不要
   另外给"只看过去"的速度，由 §8.3 在 train 上比。
2. **第 0 步：交接时已知的列当条件，不预测。** 每步输入里"生效的词"从第 0 步起就含这些列；损失和读数里第 0 步只算要
   预测的列。逐列（用户 2026-09-24 确认，跑道预测）：

   | 列 | 第 0 步 | 理由 |
   |---|---|---|
   | 航向 | 已知条件 | 描述交接时的状态（当前航迹取最近一格）；一个位置点看不出方向 |
   | 速度 | 已知条件 | 同上（当前速度的档） |
   | 高度、下降角 | 已知条件 | 交接时正在执行的高度指令（平飞在当前高度，或正下降到某个目标）；它是交接之前定下的，一个位置点也看不出下降的目标 |
   | 进近 | 已知条件 | 进入切片时已在五边上就是"许可加入"，否则"未许可"，由状态决定 |
   | 跑道 | **预测** | 先验要做的决定；靠 8.2 第 3、4 项的相对量和候选 token |

   闭环时这些条件来自交接的场景（观测航班第 0 步的词），和给执行器的初始状态是同一份交接。另一种做法是跑道也当条件
   （真实运行里跑道在进入终端区之前多半已经定了）；这里选预测，保留"选跑道"这一项读数。
3. **每一步对每条候选跑道算相对量**（词表设计 §4.2）：离入口多远（沿航道，入口之前为正）、偏离航道多远（右为正）、
   高出入口多少，都只由位置算；方向那一项（运动方向 − 跑道航向）不用拟合的航迹，改用"上一步位置指向这一步位置"的方向，
   第 0 步没有上一步，记 0 并给标志位；这一项留还是去由 §8.3 比。对所有候选都算，不只算真值跑道，所以不泄露答案。
   第一版"相对生效跑道的量"去掉：跑道说出之后，"生效的跑道"就是那条候选的向量（词表设计 §4.3 "说出之后"）。
4. **候选跑道 token**（词表设计 §4.1、§4.3）：每条候选的几何（入口 E、N、高程、航向 sin、cos、长度）和 8.2 第 3 项的相对量
   经同一个小网络变成这一步的候选向量，与排列顺序无关；汇总进这一步的输入（对候选求和或注意力汇总，实现时二选一，
   写进 §6）。跑道列的输出改成对每条候选打分：分数 = 本步隐状态 · W · 候选向量，另加一个"不变"的分数，在本机场的
   候选上做 softmax（补齐的位置为负无穷）。

**不在这次四项里、另外记下的差别**：词表设计 §4.4 规定同一步里各列依次给出、后一列能看到前面刚选的值，并按规则屏蔽；
第一版六个头互相独立。教师强制下影响不大，但自己采样时同一步可能出现不配的组合（例如给了"许可加入"却没给切入航向）。
和执行器接起来自由生成时一起定。

### 8.3 在 train 上比什么

- **选择用的数据**：从 train 按航班留出一份（例如 10 %，按机场分层）做内部选择集；val 只用于早停和最后的读数，不用来挑变体。
- **变体**（其余都按 8.2）：
  - 变体 0：照第一版给拟合的航迹、地速、垂直速率——**只用来量未来信息的影响，不会用于闭环**；
  - 变体 1：只给位置；
  - 变体 2：位置 + 只看过去的速度（上一步到这一步的位移除以 2 s：地速、运动方向、垂直速率）；
  - 8.2 第 3 项的方向那一项：在变体 1、2 上各试留 / 去。
- **读什么**：内部选择集上第 1 步起的每步负对数似然（分列）；换词的步上给"换"的概率和取值前 1；第 0 步跑道的前 1。
  变体 0 与变体 1、2 在"换词的步上给'换'的概率"上的差，就是先验靠未来信息的程度。
- **怎么选**：在变体 1、2（及方向项留 / 去）里取内部选择集上每步负对数似然最低的；差别小于随机种子之间的差时取输入少的。
  选定后在 val 上读一次（与两个基线比），变体 0 不参与选择。
- 读数口径与第一版不同（第 0 步只算跑道），两版的数不直接比；各自与按同一口径重算的两个基线比。

### 8.4 不变的

词表不变；标注器照旧用拟合的量读句子；模型尺寸、训练设置沿用 §6（交叉验证另做）。

### 8.5 什么时候做

## 9 第三版：输入只给那一刻看得到的东西，按场景做（计划，2026-09-24）

用户 2026-09-24 看了第二版第 0 步"已许可"的问题后问：这种做法有没有考虑泛化和多机交互？初始状态离跑道 20 km 左右，
怎么会已经批准进近？之后又问：多机交互最好的训练方式是什么，要不要接图网络？这一节是回答和改法。用户同意写入，

### 9.1 查到的事实

**句子从哪里开始、"第 0 步已许可"是什么**（train 50,223 架，句子产物 `v3_20260924`，2026-09-24 量，脚本只读）：

- 第 0 步离落地跑道入口的直线距离 p10 / p50 / p90 = 23.1 / 24.1 / 26.4 km（harvest 到达清单的 `entry_radius_km` = 25）。
- 第 0 步进近词是"许可加入"的有 13,039 架（26.0 %）。其中 **11,941 架第 0 步就已在五边的走廊里**：离中线中位数 37 m、
  航迹偏差中位数 0.4°、高出入口中位数 1,267 m（24 km 处 3° 下滑道是 1,258 m）——已经建立在航道和下滑道上；另外 1,098 架
  第 0 步正在转向航道。各机场：KSJC 57 %、KMSY 28 %、KRDU 20 %、KSMF 11 %、KSTL 9 %。
- 所以许可是我们的窗口开始之前、前一个管制员给的（ILS 截获常在 20 km 以外）。标注器把"已在走廊里"与"正转向、且在用的
  航向能切上航道"读成第 0 步的"许可加入"（`instructions/labeller/lateral.py` `read_lateral`）：前者只看状态就能认出，后者要先
  知道飞机后来切上了哪条线，是事后读出的。

**第二版哪些输入不是那一刻看得到的**（§8.2 第 2 项的第 0 步条件）：

| 第 0 步的条件 | 那一刻看得到吗 |
|---|---|
| 航向、速度（当前航迹、地速取最近一档） | 看得到，但信号里的航迹、地速是居中 15 s 拟合，含之后 7.5 s（§8.1） |
| 高度、下降角（交接时正在执行的高度指令） | **看不到**：下降到哪个高度，是看到后面在哪里改平才读出来的 |
| 进近"许可加入" | 已在走廊里的看得到；**正转向的看不到**（要知道后来切上哪条线） |
| （结果）跑道 | 给了"许可加入"又让模型猜跑道：已建立在五边上的航班，位置就说出了跑道。第二版 V1 在内部选择集上：还没许可的 3,747 架前 1 命中 75.7 %（机场最常用跑道 50.5 %），已许可的 1,275 架 98.0 %（81.4 %），合计 81.4 % 被后者抬高 |

**泛化**：

- 划分按航班随机（`data.splits`：每架按 `airport:flight_id` 的哈希）。同一天、同一时段的航班共用机场的跑道构型，分在 train 和
  val 两边。跑道意图研究（`docs/2026-09-13_runway_intent_plan.zh.md`，下同）的 R1 在按运行日划分下才看到：KSJC 30L 关闭的两天
  整天落 30R，按航班划分训练的跑道头当天只判对 55–57 %，而"入场前 30 min 各跑道落地数取最多"（B1）是 97–98 %；原因是逐小时
  的风和钟点在训练日里成了"今天是哪种构型"的指纹（traps T4）。第二版的输入里没有钟点和风，但同样没有按运行日量过。
- 第 0 步的条件里有事后读出的量（上表），部署时拿不到。

**多机**（五个机场的到达清单，2026-09-24 量）：

| 机场 | 到达 | 窗口时长中位数 | 进圈时圈里的其他到达 p50 / p90 / 最多 | 与本机窗口重叠的其他到达 p50 / p90 |
|---|---|---|---|---|
| KMSY | 7,696 | 321 s | 1 / 2 / 5 | 1 / 3 |
| KRDU | 24,202 | 328 s | 2 / 4 / 8 | 3 / 7 |

- 场景很小：同一时刻 25 km 圈里的到达飞机一般 1–3 架，最多 8 架。航迹库（`tracks/manifest.json`）里还有 3–9 倍于到达的
  "不落地"航迹（离场、飞越等：KRDU 77,033、KSJC 144,965），现在都没用。
- **窗口只看到最后约 5 分钟**：航迹在进圈之前平均只多约 45 s（repo `CLAUDE.md`）。谁先谁后的排序、为拉开间隔的引导大多在
  25 km 以外完成；窗口里看得到的交互主要是五边上的尾随间隔、速度词、加长的下风边与基线转弯时机。跑道意图 R3（独立 ETA +
  联合调度，五个机场）没有在落地时刻上量出交互的增益，R4（联合意图模型）因此没有启动——与此一致；那是落地时刻，不是
  逐步的指令词，词上有没有交互没有量过。
- 选跑道首先是机场层面的事（当时往哪个方向落、开了哪几条跑道），所有飞机共享：跑道意图 R0 在入场时刻（按航班划分的 val，
  harvest v5）只用"入场前 30 min 同机场的落地"就把**方向**判对 96.3–99.4 %，难的是平行跑道**左右**（KRDU 73–75 %、KSMF
  61–65 %，少数跑道 33–49 %）。这是证据，不是本版的结论：对象不同，要在第三版上重量。

### 9.2 原则

1. **输入只给"说这一步的词之前，管制员能知道的东西"**，每一项写明来源和时刻（≤ 这一步）：本机过去的位置、机场此前的
   落地、其他飞机此刻及之前的位置和已说的词。
2. **标注器读出的词只当预测目标**；到上一步为止已说的词是自回归的前文（训练时是标注的词，闭环时是模型自己说的）。
   第一个预测步六列全部预测，不再当条件给。
3. **一开始就按场景做**：数据、模型、划分都以"同一机场、同一时刻的一组飞机"为单位；单机是只有一架的场景，同一套代码。
4. **按运行日划分**，test 按天另封（§9.5）；跑道另按"方向层 / 左右层"和"第一个预测步已建立在五边上 / 没有"分开报。

### 9.3 输入（每架飞机、每一步）

1. **本机的位置历史**：每步的 E、N、MSL 高度、从第一行起的时间；运动只从过去的位置算（上一行到这一行的位移 ÷ 2 s），不用
   拟合的航迹、地速、垂直速率。
2. **看够过去再开口**：句子的前 `N_look` 行只当观察，不预测；先验从第 `N_look` 行起说话，第一个预测步给出这时生效的六列词
   （由句子里到这一行为止说过的词得出）。这样第一个预测步已有 `N_look` 行的过去位置，能看出方向、快慢和升降，不用改
   数据平面。另一种做法是在信号里加进圈之前的位置（平均约 45 s），要改 ts 的数据平面和信号格式，这里不选（§9.8）。
3. **每条候选跑道一个向量**（第二版 §8.2 第 3、4 项）：几何、只由位置算的相对量，再加**机场层面的一项**——第一个预测步之前
   `T_cfg` 分钟内同机场在这条跑道上的落地架数、离上一次在它上面落地过了多久（没有就记"无"并给标志位）。不给每条跑道固定
   的量（跑道意图 R1.1 的教训：每条跑道的常数会让模型认出"这是 30L"，构型变了就错）。落地从 harvest 的到达清单数
   （跑道与落地时刻），只取落地早于第一个预测步的，**不含 test 运行日的航班**（§9.5）。
4. **场景里的其他飞机**（§9.6）：第一步为空（掩码），之后填同一场景里其他飞机的状态、已说的词和相对本机的边特征。

### 9.4 输出

- 第一个预测步：六列都预测（跑道、是否已建立在五边上、航向、高度目标、下降角、速度）；之后每步照旧（每列"不变"或新词）。
- **同一步里各列按顺序给出**（词表设计 §4.4，第二版记下没做）：跑道 → 进近 → 航向 → 高度 → 下降角 → 速度，后一列看得到前面
  这一步选的值（训练时用真值）。这样"已许可"和跑道不会各说各的，自由生成时组合是配得上的。
- **同一步里各架飞机同时说**：每架只看到上一步为止所有飞机的状态和词（MotionLM 的做法，`docs/literature/manoeuvre_tokens/`）；
  2 s 一步，同一步里互不等待的近似很小，读数时报"同一步里两架都换词"的比例。
- 损失和读数只算预测的步（前 `N_look` 行不算）。

### 9.5 划分：按运行日，test 按天另封（用户 2026-09-24 定 c）

场景要整段时间里的全部飞机；现在的外层 test 按航班抽，每天都有 test 航班，场景里会缺掉约 15 % 的飞机（前机凭空消失），或
者要打开 test 的航迹。用户选 c：**两层模型这条线另封一批 test 运行日**。

- **运行日**：`data/runway_context.operational_day`（UTC − 9 h 的日期：夜间最少的时段切）。harvest 现有 90 个运行日
  （2026-04-30 到 09-21）。
- **按天分**（所有机场同一批日期，种子 1337，按日期字符串的哈希）：test 15 % 的天、val 15 % 的天、train 70 % 的天；train
  的天里再按天留 1/7 作内部选择集（比变体用，§8.7 的做法）。val 与 test 同比例。
- **test 运行日封存**：这些天的全部航班（不论原来的划分）在两层模型这条线上都不打开——不读信号、不标注、不进落地上下文和
  场景。其他天的航班全部可用，包括原来按航班划到 test 的（它们的航迹要第一次被这条线打开）。
- **原来按航班的 test 照旧留给 ts 的其他模型**。跨模型比较（例如先验 + 执行器 对 控制路径）只用两边都没见过的航班：新的 test
  运行日里、原来也在 test 的那些航班。
- **后果**：句子产物要按新划分重建（新目录；标注器与规则不变）。词表规格原来在旧 train 上量，旧 train 里有新 test 天的航班；
  建议在新 train 天上重量规格（最干净，下游都便宜：标注约半小时、执行器规格几秒、train 回放几分钟），列在 §9.8。

### 9.6 场景与多机（用户 2026-09-24 同意的做法）

- **场景**：同一机场、同一时刻（2 s 一步，按绝对时间对齐）的一组飞机。每架的行时间加上它的进圈时刻（到达清单
  `entry_time_utc`）得到绝对时间；按时间建"场景索引"：每一步场上有哪些飞机。**说话的**是有句子的到达航班；没有句子的
  到达（标注器拒绝的）先只作"只有位置、不说话"的背景飞机；离场与飞越（航迹库里的"不落地"）第一版不放，读数里写明。
- **模型**：时间 × 飞机的分解注意力（Scene Transformer 的做法）——每架飞机自己沿时间的因果注意力，加上每一步所有飞机之间
  的注意力。飞机之间的注意力带相对几何的边特征作偏置：是否同一条 / 平行跑道、沿航道离入口的距离差（谁在前、隔多远）、
  跑道坐标系里的相对位置、由过去位置算的接近速度。这就是全连接图上的图注意力；场景只有几架，不另接图网络框架。
- **预训练**：场景上的联合教师强制，下一步的词（§9.4）。
- **后训练**（交互主要在这里学）：执行器同时飞场景里所有飞机，闭环。筛选或奖励：不失去间隔（FAA JO 7110.65 的雷达间隔
  与尾流间隔，原文在 `docs/literature/arrival_separation/`）、落地、不离数据太远；解码时加间隔的硬屏蔽。方法（闭环监督微调
  或强化学习）在第一步读完后定，文献在 `docs/literature/multi_agent_interaction/`（2026-09-24 起由 agent 整理）。
- **窗口的限制**：25 km 圈里排序大多已定（§9.1）。要学排序本身，得把 harvest 的收集半径扩到 50–60 km（重新下载）——这是
  另一个数据决定，先不做；读数里写明模型学到的交互只限窗口里这一段。

### 9.7 实现之前先量（train 天，只读）

1. `N_look` 行之后已建立在五边上的航班占多少、各机场多少。
2. 第一个预测步之前 `T_cfg` 分钟内同机场有落地的航班占多少（夜间可能没有）；B1、B3 的前 1。
3. 新划分下 train / 选择 / val / test 的天数与航班数、每个机场的份额；原来在 test 的航班落在新 test 天里的有多少（跨模型比较的
   样本量）。
4. 场景规模：每步同一场景里有句子的飞机、背景飞机的架数分布；同一条跑道前方 10 km 内有前机的步占多少（§9.9 的 M1 要用）。

### 9.9 分步与门

1. **单机（场景里只放本机）**：§9.3–§9.5。门：每列都赢两个基线；跑道在"没有建立"的航班上赢 B1 和 B3（左右层单独看）；
   按运行日划分下成立。
2. **M1：窗口里看得到交互吗**（不训练新模型）：用第 1 步的模型，在 train 天上比速度词、航向词的换词时刻与取值，在"同一条
   跑道前方 10 km 内有前机"和"没有"的步上是不是明显更差。不差：交互在窗口里看不出来，停在这里，先做闭环与后训练的单机
   部分；差：继续。
3. **前机这一条边**：只加同一跑道前方最近那架的边特征（距离、接近速度）。门：有前机的步上速度词、航向词的负对数似然比
   第 1 步低。
4. **完整的场景模型**：所有飞机之间的注意力（§9.6）。门：比第 3 步再好，且在繁忙时段（同时 ≥ 3 架）更明显。
5. **多机闭环与后训练**：执行器同时飞场景里所有飞机；读间隔违规、落地率、入口处相邻到达的间隔分布（与观测比）；再做后训练。
