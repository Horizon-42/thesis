## §1 意图

v3 回答的问题只有一个：**在跑道已知的 TMA 里，一个可飞的 L1 执行器分段再问能把进近飞到什么程度；它的表现由哪些自身参数决定；
什么样的第二层信息能在此之上再加分。**

09-18 计划的前提是"L1 需要意图码才能短、单峰"。这个前提没有被验证也没有被推翻：那份 campaign 的执行器基线自身没有定——回看被固定在 60 s，
段长只在 60 s 回看下读了 30 / 60 / 90 s 三点，而 90 s 在一条 300–400 s 的进近里不算短。今天的读数只能当作**一个配置下的迹象**：
在 (L = 60 s, Δ = 60 s) 上，无 token 的分段执行器闭环建立约 0.70，真值码换来跟踪不换来穿越，先验给的码没有加分，学习码本只装了航向，
语义词表的码执行器不看，雷达引导段的穿越是 0.3–0.4。这些迹象决定了 v3 的顺序，不决定 v3 的结论。

所以 v3 先把**执行器自身**的轴做成真正的消融（段长 Δ 与回看 L 都作轴，Δ 要包含真正短的段），定出基线，再弄清雷达引导段为什么穿不过；
"第二层"不预设为意图码，定义为"任何在同一闭环协议下好过无 token 基线的东西"，候选放在单机历史里真正没有的信息上（落地跑道、其他飞机）；
意图码是其中一个有界候选，在定牢的基线上重新问一次，过相对门才继续。

## §2 大纲（开发计划的结构；后面各节按此编号展开）

1. **目标与范围**：要交付什么（一个可飞的分段执行器 + 定量的第二层结论）；不做什么（风、ATC 文本、天气不作输入；机场当时的 runway configuration——哪几条跑道在用于进场——也不作输入，模型只知道本机的落地跑道，configuration 的信息只能经它间接带入）。
2. **对象与契约**：执行器的输入（lookback L、跑道系、机型）、输出（Δ 段控制经动力学滚出）、执行协议（每 Δ 在飞出行上再问）；哪些是固定的
   （cohort、锚点、动力学契约、种子），哪些是轴。
3. **问题与假设**：Q1 执行器的 (L, Δ) 怎么选；Q2 雷达引导段为什么穿不过；Q3 什么样的第二层信息在基线上加分；Q4 跑道未知时执行器损失多少、
   什么形式的跑道信息补得回来；Q5 有前机时执行器缺什么、什么形式的多机信息补得回来。每个问题写清"用什么读数回答、答案长什么样"。
   **第二层（L2）在 v3 里的地位**：它的形式是待回答的问题，不是继承的设计。它的任务由新执行器的失败方式（A2）和"信息缺失时损失多少"的测量来定义；
   09-13 计划里做过的跑道头 `r11_lift` 与 R3 的多机联合分配是在旧的整段执行器上测的，在 v3 里是**候选与证据**（左右跑道可预测、交互对落地时刻无增益），
   不是 v3 的第二层。
4. **指标与读数协议**：§3 的表；两种子、种子线、预算规则、固定锚点。
5. **实验阶段与门**：阶段 A（执行器轴）、B（第二层相对门）、C（跑道、多机）、D（发布、跨机场）；每阶段的臂、门、go / no-go，
   以及"不过门时做什么"。
6. **每阶段需要的开发**（每项：现在有什么、缺什么、为什么要做）：
   - 阶段 A：现在的 campaign 臂文件只把 segment（`control_horizon_s`）当轴，lookback（`seq_len`）是写死的；要让臂文件能声明 (L, Δ) 网格，
     现有的训练 runner 就能跑。A2 需要一个逐架诊断脚本：读 lockstep 的每架记录，对没穿越的雷达引导航班说清它停在哪
     （final approach course 的正横、之前、之后、另一侧）、转弯比真值早还是晚——先把失败方式叫出名字，再谈改法。
   - 阶段 B：现在的 gate 都是和固定数字比；要一个"相对 gate"的 runner：读同一 (L, Δ) 下两份 lockstep 产物（第二层的 protocol 和 `none`），
     判"established 与雷达 ADE 两种子都不差、至少一项好过 seed 线"。
   - 阶段 C：先做测量，后做开发。C0 量新执行器在跑道未知（错跑道的坐标系）和有前机时损失多少；开发内容由 C0 与 A2 的结果决定，
     现在只能列可能项：让坐标系由预测的跑道来建（若跑道是主要损失）；给执行器加前机 context 输入，先真值后模型（若前机是主要损失）。
     具体形式在 C0 之后再定，写进决定项。
   - 阶段 D：发布用现有的 publisher 加 `--category-variant`，只需登记 intents，没有新开发。
7. **决定项**：计划里每一个被定死的参数或规则都在这一节有一个编号条目，写明是什么、为什么这样定、它没有解决什么。
   今天的教训是 lookback 被写在设计文字里而没有条目，于是没人审它。从 09-18 计划继承、需要在这里重新列出的有四条：
   - 用哪些航班（cohort）：KRDU 的进场，要求锚点之后至少还剩 120 s，这样五个 segment 长度比的是同一批航班；train 6798 架、val 1392 架。
   - 首问时刻（锚点 59）：进入 25 km 切片后第 59 行，即 118 s；与 v2 相同，数才能对比。
   - 执行器的控制律（pa 契约）：specific-force + path-angle，带一阶滞后；v2 三种契约里唯一关掉平滑项后仍可飞的。
   - 两个 seed：每臂用 1337、2024 各训一次；差别小于 seed 线的不算差别。
8. **里程碑与交付**：每阶段完成的标志（表、发布的类目、写进哪份文档）。
9. **队列与成本**：GPU 小时、磁盘、顺序、通知。
10. **风险与后备**：每条风险的信号与后备动作。

## §3 指标与读数协议

### 3.1 一次"读数"是什么

- **对象**：一个训练好的执行器（一个臂），在 KRDU 的 val 航班上（1392 架，与 train 的 6798 架不重叠）逐架飞一遍。
- **闭环协议 `none`**：从固定锚点（进入 25 km 切片后第 59 行，118 s）开始，执行器看最近 L 秒的飞出历史，飞出 Δ 秒，接到历史后面，再看、再飞；
  没有任何码或外部信息。直到轨迹在 final approach course 上穿过跑道入口（记 crossed），或用完预算（记 horizon）。
  预算 = 真值剩余时长 T₀ + max(30 s, 0.1·T₀)，只是上限。第二层的读数用同一套轮次与预算，只是多了它提供的信息。
- **开环读数**（固定锚点飞一段、算段内误差）只在训练时作诊断，不进任何 gate：历史已决定段的大部分，它看不到闭环里的差别（09-18 的 gate T 就是这样失效的）。
- **两个 seed**：每个臂用 seed 1337、2024 各训一次，读数成对出现。**seed 线**：established 差 3 个百分点、ADE 差 125 m 以内的算同一水平
  （控制路径的历史测量，`ts_transformer/CLAUDE.md`"How to read results"）。只读大小，不读 p 值。
- **分层**：每个数分三层报——池化（全部 1392 架）、直线（straight-in，锚点时已在 final 附近、路线曲折度 < 1.05，892 架）、雷达引导（vectored，497 架）。
  雷达引导层是难点所在，也是 v3 主要看的一层。

### 3.2 指标定义

| 指标 | 一句话定义 | 单位 | 出处 |
|---|---|---|---|
| established | 在预算内于 final approach course 上穿过入口的航班份额 | 份额 | `manoeuvre_lockstep` 每架的 `reference.established` |
| fully flyable | 整条飞出轨迹每一点都在飞机的坡度 / 载荷 / 速度包线内的份额 | 份额 | `geometry.flyability` |
| ADE | 飞出轨迹对真值逐时刻位置误差的平均，一架一个数；报层均值与 p50 | m | `observed_series_metrics` |
| FDE | 飞出轨迹终点对真值终点的误差；报 p50 | m | 同上 |
| 位移 @120 / 180 s | 锚点后 120 / 180 s 那一刻飞出位置对真值的误差 p50 | m | 每架 `at` |
| e_track 逐轮 | 第 r 次询问飞出的那一段末端对真值的误差 p50，按 r 列出 | m | 每架 `asks_e` |
| 结束方式 | crossed / horizon 各多少架 | 架 | 每架 `ended` |
| 到达时刻误差 | 飞出时长减真值时长 | s | `final_time_error_s` |
| 失败方式（A2 用） | 没穿越的航班停在 final 的哪一侧、离入口多远、转弯比真值早或晚多少 | 类别 + m + s | A2 的诊断脚本（待写） |

### 3.3 每个阶段用哪些指标、怎么判

| 阶段 | 用哪些指标 | 判定规则 | 不过时做什么 |
|---|---|---|---|
| A1 选 (L, Δ) | 主：池化 established 与雷达引导 established；约束：fully flyable ≥ 0.95；辅：雷达 ADE、FDE p50 | 两 seed 都最好的 (L, Δ) 胜出；主指标与辅指标不一致时以 established 为准；差在 seed 线内算平手，平手取 Δ 短、L 短的（信息少、承诺短的更保守） | 若整张网格 established 都在 seed 线内，段长与 lookback 不是关键变量，记为结论，A2 决定下一步 |
| A2 诊断 | 失败方式的分布（雷达引导层没穿越的那 ~300 架）；e_track 逐轮 | 不是 gate，是分类：哪种失败占多数，写成 A3 的假设 | — |
| A3 改执行器 | 与 A1 相同 | 在同一 (L, Δ) 上，两 seed 的 established 都好过 A1 胜者且至少一个超过 seed 线，fully flyable 不掉 | 假设不成立，回 A2 换下一种失败方式 |
| B 第二层相对 gate | 第二层的闭环对 `none`，同一 (L, Δ)：established（池化与雷达）、雷达 ADE | 两 seed 都不差（seed 线内），且至少一项好过 seed 线 | 该第二层不加分，不进 C / D |
| C0 量损失 | 跑道错建坐标系时、有前机时的 established / ADE 相对已知跑道、无前机的差 | 不是 gate，是测量；差大于 seed 线才值得建第二层去补 | 差在 seed 线内 → 该信息不值得建层，记为结论 |
| D 跨机场 | 选出的 (L, Δ) 在 KSJC / KSTL / KSMF / KMSY 上的同一套指标 | 每个机场分层报，不比池化数（路线混合不同，`data/approach_difficulty.py`） | — |

第二层若是多假设形式（Q6，待归档论文后加），再加它自己的读数（K 条候选里最好的一条对真值、模式概率的校准、跑道模式命中率），写在 Q6 下。

## §4 实验框架

### 阶段 A：执行器自身的轴（无 token）

- **A1 网格**：Δ ∈ {30, 60, 90, 120} × L ∈ {30, 60, 90, 120}（L ≤ 120 s，锚点 59 处都可行），两种子。已有 L = 60 的 30 / 60 / 90 三格，
  新增 13 格 × 2 = 26 臂，约 6 h；每臂协议 `none` 各 2 min。用门 S 选 (L, Δ)。
- **A2 诊断**：在最好的格子上逐架看雷达引导段为什么穿不过（停在哪、是转晚还是转不到位、与规则制导的 0.88 差在哪）。
  这是后续改执行器的依据，不预设修法。
- **A3**（若 A2 指向具体缺陷）：对应的执行器改动，一个臂族，同网格读。

### 阶段 B：第二层的相对门

- 任何第二层（码、上下文、别的条件）只有在同一 (L, Δ) 下，闭环建立与雷达 ADE 两种子都不差于 `none`、且至少一项好过种子线，才算加分。
- 意图码作为一个有界候选：目标里加垂直 / 速度分量，一个 K、一个段长、两种子；过相对门才有后文。

### 阶段 C：单机历史里没有的信息（形式待定，先测后建）

- **C0 测损失**：在阶段 A 选出的执行器上，(i) 跑道未知：用错的平行跑道建坐标系时 established / ADE 掉多少，与 09-13 R2a 在旧执行器上的 +55 m 对照；
  (ii) 有前机：按前机存在与否、间隔大小分层读 `none` 的失败率，看多机是不是失败的来源之一。
- **C1 / C2 的设计**：由 C0 与 A2 决定，之后再写臂与 gate。候选：跑道——09-13 的跑道头（`r11_lift`，左右层可预测）或别的形式；多机——前机 context 进执行器，
  先 oracle 量上限（gate G 的第一步），R3 / R3.1 的"交互对落地时刻无增益"作为已知证据。第二层若走离散码，必须过阶段 B 的相对 gate；连续向量是默认。

### 阶段 D：发布与跨机场

- 发布到 picker（每个读数臂）；跨机场（KSJC / KSTL / KSMF / KMSY）验证选出的 (L, Δ)。
