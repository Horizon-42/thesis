## §1 意图

v3 回答的问题只有一个：**在跑道已知的 TMA 里，一个可飞的 L1 执行器一段一段地预测能把进近飞到什么程度；它的表现由哪些自身参数决定；
什么样的第二层信息能在此之上再加分。**

09-18 计划的前提是"L1 需要意图码才能短、单峰"。这个前提没有被验证也没有被推翻：那份 campaign 的执行器基线自身没有定——回看被固定在 60 s，
段长只在 60 s 回看下读了 30 / 60 / 90 s 三点，而 90 s 在一条 300–400 s 的进近里不算短。今天的读数只能当作**一个配置下的迹象**：
在 (L = 60 s, Δ = 60 s) 上，无 token 的分段执行器闭环建立约 0.70，真值码换来跟踪不换来穿越，先验给的码没有加分，学习码本只装了航向，
语义词表的码执行器不看，雷达引导段的穿越是 0.3–0.4。这些迹象决定了 v3 的顺序，不决定 v3 的结论。

所以 v3 先把**执行器自身**的轴做成真正的消融（段长 Δ 与回看 L 都作轴，Δ 要包含真正短的段），定出基线，再弄清雷达引导段为什么穿不过；
"第二层"不预设为意图码，定义为"任何在同一闭环协议下好过无 token 基线的东西"，候选放在单机历史里真正没有的信息上（落地跑道、其他飞机）；
意图码是其中一个有界候选，在定牢的基线上重新测一次，过相对门才继续。

## §2 大纲（开发计划的结构；后面各节按此编号展开）

1. **目标与范围**：要交付什么（一个可飞的分段执行器 + 定量的第二层结论）；不做什么（风、ATC 文本、天气不作输入；机场当时的 runway configuration——哪几条跑道在用于进场——也不作输入，模型只知道本机的落地跑道，configuration 的信息只能经它间接带入）。
2. **对象与契约**：执行器的输入（lookback L、跑道系、机型）、输出（Δ 段控制，经动力学积分成一条轨迹）、执行协议（每 Δ 秒在飞出的轨迹上再预测一次）；哪些是固定的
   （cohort、锚点、动力学契约、种子），哪些是轴。
3. **问题与假设**：Q1 执行器的 (L, Δ) 怎么选；Q2 雷达引导段为什么穿不过；Q3 什么样的第二层信息在基线上加分；Q4 跑道未知时执行器损失多少、
   什么形式的跑道信息补得回来；Q5 有前机时执行器缺什么、什么形式的多机信息补得回来。每个问题写清"用什么读数回答、答案长什么样"。
   **第二层（L2）在 v3 里的地位**：它的形式是待回答的问题，不是继承的设计。它的任务由新执行器的失败方式（A2）和"信息缺失时损失多少"的测量来定义；
   09-13 计划里做过的跑道头 `r11_lift` 与 R3 的多机联合分配是在旧的整段执行器上测的，在 v3 里是**候选与证据**（左右跑道可预测、交互对落地时刻无增益），
   不是 v3 的第二层。
   **Q6 多假设的第二层**：飞机在一段里可能有几个方向可飞（继续下风、现在转 base、延长再转），临近时有平行跑道可选。
   第二层能否每段输出 K 个意图节点（segment frame 里的段末目标状态或连续向量，各带概率），L1 对每个节点飞一段，训练时只让最接近真值的那条
   拿到梯度（winner-takes-all / min-over-K），推理时按概率或按对 K 条 rollout 的评分选；段与段串成一棵意图树，跑道是树顶的分支。
   文献（`docs/literature/multimodal_intent/README.md`，13 篇已核实）：MultiPath / TNT / DenseTNT / MTR 是一次性输出 K 条的做法；plain WTA 会塌缩且有测量
   （MultiPath 的 min-of-K 基线只剩 1–2 个活模式），要从 evolving / annealed WTA 起步；DESIRE 不是 WTA，它靠评分器选；航空里显式 K 假设只有 ASCENT
   （ICRA 2026，一次性 120 s），**没有任何航空论文把多步预测做成意图分支的树**。用什么读数回答：它的闭环（top-1 即概率最大的那条，或评分选出的那条）对基线协议的相对 gate（阶段 B），
   加多假设自己的读数（K 条候选里最好的一条对真值的 ADE、模式概率的校准、跑道模式命中率）。答案长什么样：过相对 gate 且多假设读数好于单假设，
   才说明多模态被显式化了。

## §3 指标与读数协议

### 3.1 训练怎么取样、读数怎么做

**数据**：每架航班的记录从它进入机场周围 25 km 圆圈那一刻开始，每 2 s 一行，直到落地。KRDU 的航班按航班随机分成训练集和验证集，
所有读数都在验证集上做，训练时没见过。（集合的大小随 §6 的 cohort 决定项定，每个 (L, Δ) 报 n。）

**训练（锚点是随机的）**：一个训练样本 = 记录里的某一行往前 L 秒的历史 → 这一行之后 Δ 秒的真值。这一行按剩余路程均匀随机抽
（`random_train_anchor_sampling = remaining-path-uniform`），要求它之后至少还剩 Δ 秒。所以执行器学的是整条进近的每一个阶段，
从下风边到 final；L 只是窗口长度，Δ 只是目标长度，训练里没有"固定锚点"。

**评估（闭环，基线协议）**：
- **开始预测的时刻**：进入圆圈后 L 秒——有了 L 秒历史就让模型开始预测，不再等到 118 s（09-18 的读数固定在第 59 行，60 % 的验证航班那时已在 final 上，
  短航班被整个排除；这是从 v2 继承的可比性约定，v3 不再用）。不同 L 的臂开始预测的时刻不同，但每个臂都是"有 L 秒历史就开始"，与部署一致。
- **验证集的条件**：开始预测时剩余时长 ≥ Δ（能飞满一段）。短航班回到集合里；每个 (L, Δ) 的集合略不同，报 n。
- **闭环**：从开始预测起，执行器看最近 L 秒的飞出历史，预测并飞出 Δ 秒，接到历史后面，再看、再预测、再飞；直到轨迹在 final approach course 上穿过跑道入口
  （记 crossed），或用完预算（记 horizon）。预算 = 该航班真值剩余时长 T₀ + max(30 s, 0.1·T₀)，只是上限。基线协议（代码里叫 protocol `none`）
  不给执行器任何第二层信息；第二层的读数用同样的轮次与预算，只多它提供的信息，两者可直接比。
- **开环读数**（从真实历史预测一次、算段内误差）只在训练时作诊断，不进任何判定：历史已决定段的大部分，它看不到闭环里的差别
  （09-18 的 gate T 是开环的，三个段长六个词表全分不出差别）。
- **两个 seed**：seed 指训练的随机数种子（权重初始化、数据顺序），数据和划分完全相同；每个臂训两次（1337、2024），读数成对出现。
  **seed 线**：两个 seed 之间 established 通常差 3 个百分点、ADE 差 125 m 以内，差在这以内的算同一水平（控制路径上的历史测量，
  `ts_transformer/CLAUDE.md`"How to read results"）。只读大小，不读 p 值。
- **三个分组**：每个数报三次——全部；直线进近（straight-in，开始预测时航线曲折度 < 1.05、基本已对准跑道）；雷达引导（vectored，还在被引导、要转弯）。
  雷达引导组是难点所在，也是 v3 主要看的一组。

**评估的第二种读法：从离跑道入口固定距离处开始预测（已采用；与训练无关）**：按上面的规则，各航班开始预测时离落地远近不同，"从进圈后 L 秒起的 established"会被航班进圈时的
阶段左右。所以每个臂再读一组：每架航班在离跑道入口固定距离处（剩 12 / 8 / 6 km，距离点在 §6 定）各开始一次闭环预测、从那一刻飞到底，每个距离点报一套 §3.2 的指标。
这样"从远处起飞"和"从近处起飞"分开看，长短航班在同一尺度上比（包里已有 anchor grid / anytime curve 的机制）。它只是评估的第二种读法，不改训练、不改验证集。

**评估的第三种读法：所有格从同一行开始预测（2026-09-19 M-A1 之后补，D28）**：读法 (a) 把"历史长度"和"起点"混在一起——L = 120 的执行器进圈后 120 s 才接手，比 L = 60 少飞 60 s、起点更靠近五边，
赢的是少飞一段而不是多看一段（M-A1 的证据：每轮误差只差约 10%，同一起点的 12 km 读数上 L60_D20 反而更好）。所以每个臂再读一组：每架航班都从第 59 行（进圈后 120 s，L = 120 自己的起点）开始预测、飞到底，
20 格飞的是同一段进近、同一批真值，只有历史窗长短不同，这才是纯粹的信息优势对比（`manoeuvre_lockstep --first-prediction-row 59`，`lockstep.from_row`，与 (b) 同一种切法；那一行后面要有 Δ 秒真值，没有的航班计数不飞）。
论文里"历史多长够用"用这一读法答。

### 3.2 指标定义

| 指标 | 一句话定义 | 单位 | 出处 |
|---|---|---|---|
| established | 在预算内于 final approach course 上穿过跑道入口的航班份额 | 份额 | `manoeuvre_lockstep` 每架的 `reference.established` |
| fully flyable | 整条飞出轨迹每一点都在飞机的坡度 / 载荷 / 速度包线内的份额 | 份额 | `geometry.flyability` |
| ADE | 飞出轨迹对真值逐时刻位置误差的平均，一架一个数；报组内均值与 p50 | m | `observed_series_metrics` |
| FDE | 飞出轨迹终点对真值终点的误差；报 p50 | m | 同上 |
| 位移 @120 / 180 s | 锚点后 120 / 180 s 那一刻飞出位置对真值的误差 p50 | m | 每架 `at` |
| 逐段预测的误差（e_track） | 闭环里执行器预测了好几次（第 0、1、2…次）。每预测一次飞一段，段飞完的那一刻，量它所在位置与真实飞机同一时刻所在位置的距离；把所有航班第 r 次的这个距离取中位数，就得到第 r 次的一个数。按 r 排成一列，看误差随着一次次预测怎么长（09-18 的例子：175 → 434 → 812 → 1497 m，每预测一次翻一倍） | m | 每架 `asks_e` |
| 结束方式 | crossed / horizon 各多少架 | 架 | 每架 `ended` |
| 到达时刻误差 | 飞出时长减真值时长 | s | `final_time_error_s` |
| 失败方式（A2 用） | 没穿越的航班停在 final 的哪一侧、离跑道入口多远、转弯比真值早或晚多少 | 类别 + m + s | A2 的诊断脚本（待写） |

第二层若是多假设形式（Q6），除相对 gate 外再报它自己的读数：K 条候选里最好的一条对真值的 ADE（minADE_K）与未命中率、模式概率的校准（预测概率对实际被选中的频率）、
跑道模式命中率（树顶分支选对跑道的份额）。这些是多模态被显式化的证据，不替代相对 gate。

## §10 审计（2026-09-20，用户叫停阶段 B 队列后；每条写"计划里写了什么 / 代码实际做什么 / 缺什么决定"）

**1. 执行器的训练不是闭环的，计划没把这当决定写。**
- 计划写的（§3.1）：一个训练样本 = 某一行往前 L 秒的历史 → 之后 Δ 秒的真值；评估是闭环（每 Δ 秒在飞出的轨迹上再预测）。
- 代码实际做的（`outputs/control/strategy.py` 的一行样本；`data/dataset.py` 随机锚点窗口）：历史永远是**真值**的观测行，目标是真值的下一段；损失只算这一段。执行器在训练里从没见过自己飞出的历史；闭环只在评估（`manoeuvre/lockstep.py`）里出现——每轮输入 = 锚点那行真值 + 已飞出的行（`rolled_series`），飞 Δ 秒接上再预测，直到穿越或预算用完。
- 09-18 计划 §2.7"第四步：闭环训练"明确有第 (2) 项"执行器在自己飞出的历史上再训"，§1.2 第 1 条更把 plan 路径的测量列为教训："rolled windows 不是可选项"（只在观测窗口上训的头每 30 s 再问时雷达 ADE 5391 m，rolled 后 3641 m）。v3 取代 09-18 的 §2–§4 时只保留了先验那一半（B3 / D40，且是条件步骤），执行器这一半**漏掉了**，也没有作为决定项写明"不做"。09-18 §1.1 给 v2 失败下的结论是"两层各自在真值上训练，闭环耦合没有任何一层见过"——v3 的执行器重犯了同一条。
- 后果：阶段 A 的 40 臂与阶段 B 的 12 臂全是开环训练的执行器；逐轮误差每轮累积约 110 m（§1、§10 结果文档），token 只补意图、补不了纠偏；阶段 B 的负结论（真值 / 先验 token 都不换来穿越）是在这个缺陷之上读的，不能作为"意图码无用"的定论。阶段 A 关于 L、Δ 的结论也是在开环训练的执行器上读的，闭环训练后要重读。
- 缺的决定：D49 执行器闭环训练——用哪种协议在 train 上飞（无 token 执行器：none；带 token：C）、飞出的历史切成窗口的标签（同一绝对时间的真值下一段，09-18 v2 §8 的决定）、混合份额（plan 路径量到的 0.75，作起点）、做一轮还是两轮、"该停"怎么进标签（09-18 §1.2 第 2 条）、两 seed。先在 L60_D20（无 token）上做并重读 §3.1 的闭环指标，再回头问 token 的问题。归档的 `archive/plan_head_2026_09/rolled.py` 是 plan 路径的 rolled 窗口实现，作参考，不照搬。

**2. 闭环 ADE / FDE 怎么算，计划只给了一句定义。**
- 代码：`lockstep.whole_forecast` 把各轮飞出的段拼成一条从首次预测起的轨迹；`observed_series_metrics` 在真值锚点之后每一行的时刻上取飞出位置与真值位置的距离，ADE = 均值、FDE = 终点；`e_track` = 每轮段末对同一时刻真值的距离；预算 = T₀ + max(30 s, 0.1·T₀)；established = 在最后进近航道上穿过跑道入口。
- 缺的：§3.2 要写明"飞出轨迹"就是评估时自回归飞出的整条（训练里没有这条轨迹），以及 ADE 的时间基准是真值的时钟（飞出轨迹比真值晚到时，末段按位置差计）。

**3. 真值 token 读法的 token 按真值的时间索引，不按执行器的位置。**
- 代码：协议 C 第 k 轮的码 = 真值从首次预测起第 k // hold 段的码（`flight_sequences`），与执行器此刻在哪无关；过了真值最后一个整段就一直用最后一个码。
- 计划 §5.2.0 写了"每段的 token 直接用真值段算出的码"，没写"按时间取、不按位置取"及其含义：执行器飞偏后，真值码说的是真值在别处的意图。§11 结果文档里先验 token 的穿越高于真值 token，就是这条。缺的决定：真值 token 读法是否应按执行器位置（最近的真值行）取段——那是另一种上限读法，要列出来选。

**4. 训练时 token 用真值（teacher forcing），计划写了但没写它与闭环的错配。**
- §5.2.0 写了执行器"输入 60 s 历史加 z"、联合训练；没写训练里 z 永远来自真值段且历史永远是真值历史，闭环里 z 来自先验、历史来自自己。这是第 1 条的 token 版。
