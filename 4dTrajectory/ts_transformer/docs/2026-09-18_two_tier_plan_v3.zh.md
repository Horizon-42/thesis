## §1 意图

v3 回答的问题只有一个：**在跑道已知的 TMA 里，一个可飞的 L1 执行器分段再问能把进近飞到什么程度；它的表现由哪些自身参数决定；
什么样的第二层信息能在此之上再加分。**

09-18 计划的前提是"L1 需要意图码才能短、单峰"。这个前提没有被验证也没有被推翻：那份 campaign 的执行器基线自身没有定——回看被固定在 60 s，
段长只在 60 s 回看下读了 30 / 60 / 90 s 三点，而 90 s 在一条 300–400 s 的进近里不算短。今天的读数只能当作**一个配置下的迹象**：
在 (L = 60 s, Δ = 60 s) 上，无 token 的分段执行器闭环建立约 0.70，真值码换来跟踪不换来穿越，先验给的码没有加分，学习码本只装了航向，
语义词表的码执行器不看，雷达引导段的穿越是 0.3–0.4。这些迹象决定了 v3 的顺序，不决定 v3 的结论。

所以 v3 先把**执行器自身**的轴做成真正的消融（段长 Δ 与回看 L 都作轴，Δ 要包含真正短的段），定出基线，再弄清雷达引导段为什么穿不过；
"第二层"不预设为意图码，定义为"任何在同一闭环协议下好过无 token 基线的东西"，候选放在单机历史里真正没有的信息上（落地跑道、其他飞机）；
意图码是其中一个有界候选，在定牢的基线上重新问一次，过相对门才继续。

## §2 大纲（开发计划的结构；后面各节按此编号展开）

1. **目标与范围**：要交付什么（一个可飞的分段执行器 + 定量的第二层结论）；不做什么（风、ATC 文本、天气不作输入；机场当时的 runway configuration——哪几条跑道在用于进场——也不作输入，模型只知道本机的落地跑道，configuration 的信息只能经它间接带入）。
2. **对象与契约**：执行器的输入（lookback L、跑道系、机型）、输出（Δ 段控制经动力学滚出）、执行协议（每 Δ 在飞出行上再问）；哪些是固定的
   （cohort、锚点、动力学契约、种子），哪些是轴。
3. **问题与假设**：Q1 执行器的 (L, Δ) 怎么选；Q2 雷达引导段为什么穿不过；Q3 什么样的第二层信息在基线上加分；Q4 跑道未知时怎么办；Q5 多机怎么进。
   每个问题写清"用什么读数回答、答案长什么样"。
4. **指标与读数协议**：§3 的表；两种子、种子线、预算规则、固定锚点。
5. **实验阶段与门**：阶段 A（执行器轴）、B（第二层相对门）、C（跑道、多机）、D（发布、跨机场）；每阶段的臂、门、go / no-go，
   以及"不过门时做什么"。
6. **每阶段需要的开发**：A 的臂文件加 lookback 轴、A2 的逐架诊断工具；B 的相对门 runner；C1 的跑道条件坐标系、C2 的前机上下文进执行器；D 的发布。
7. **决定项**：编号、理由、不解决什么（含继承的：120 s cohort 契约、锚点 59、pa 契约、两种子）。
8. **里程碑与交付**：每阶段完成的标志（表、发布的类目、写进哪份文档）。
9. **队列与成本**：GPU 小时、磁盘、顺序、通知。
10. **风险与后备**：每条风险的信号与后备动作。

## §3 指标

全部在协议 `none`（或第二层的对应协议）下读，KRDU val 1392 架，固定锚点 59，两种子；开环的段内 ADE 只作训练诊断，不作门。

| 指标 | 定义 | 用途 |
|---|---|---|
| 建立份额 | 在预算内于最后进近航道上穿过入口的份额，分池化 / 直线 / 雷达引导 | 主指标 |
| 完全可飞 | 整条飞出轨迹通过可飞性检查的份额 | 硬约束，≥ 0.95 |
| 雷达 ADE 均值、池化 ADE p50 | 整条飞出段对真值 | 几何 |
| FDE p50 | 终点误差 | 到达精度 |
| 雷达 120 / 180 s 位移 p50 | 锚点后固定时刻的误差 | 与 B61、v2 可比 |
| 逐轮 e_track | 每一问末端对真值 | 误差怎么叠加 |
| 结束方式 | 穿越 / 预算 各多少 | 失败在哪 |
| 到达时刻误差 | 飞出时长对真值 | 时间维 |
| 种子线 | 建立 3 点、ADE 125 m | 任何差小于它不算差别 |

预算规则沿用：T₀ + max(30 s, 0.1·T₀)，T₀ = 真值在首问时的剩余时长。

## §4 实验框架

### 阶段 A：执行器自身的轴（无 token）

- **A1 网格**：Δ ∈ {30, 60, 90, 120} × L ∈ {30, 60, 90, 120}（L ≤ 120 s，锚点 59 处都可行），两种子。已有 L = 60 的 30 / 60 / 90 三格，
  新增 13 格 × 2 = 26 臂，约 6 h；每臂协议 `none` 各 2 min。用门 S 选 (L, Δ)。
- **A2 诊断**：在最好的格子上逐架看雷达引导段为什么穿不过（停在哪、是转晚还是转不到位、与规则制导的 0.88 差在哪）。
  这是后续改执行器的依据，不预设修法。
- **A3**（若 A2 指向具体缺陷）：对应的执行器改动，一个臂族，同网格读。

### 阶段 B：第二层的相对门

- 任何第二层（码、上下文、别的条件）只有在同一 (L, Δ) 下，闭环建立与雷达 ADE 两种子都不差于 `none`、且至少一项好过种子线，才算加分。
- 意图码作为一个有界候选：目标里加垂直 / 速度分量，一个 K、一个段长、两种子；过相对门才有后文。

### 阶段 C：单机历史里没有的信息

- **C1 跑道意图**：按 `2026-09-13_runway_intent_plan.zh.md` 的分类器，输出决定执行器坐标系；读数是门 R 加"预测跑道对已知跑道"的闭环差。
- **C2 多机**：先 oracle（前机真值作上下文）量上限，够大再学；读后机的雷达位移与建立、间隔违反率对观测数据。
  条件进执行器用连续向量，不经过码。

### 阶段 D：发布与跨机场

- 发布到 picker（每个读数臂）；跨机场（KSJC / KSTL / KSMF / KMSY）验证选出的 (L, Δ)。
