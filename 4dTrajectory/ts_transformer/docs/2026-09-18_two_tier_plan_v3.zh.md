## §1 意图

v3 回答的问题只有一个：**在跑道已知的 TMA 里，一个可飞的 L1 执行器一段一段地预测能把进近飞到什么程度；它的表现由哪些自身参数决定；
什么样的第二层信息能在此之上再加分。**

09-18 计划的前提是"L1 需要意图码才能短、单峰"。这个前提没有被验证也没有被推翻：那份 campaign 的执行器基线自身没有定——回看被固定在 60 s，
段长只在 60 s 回看下读了 30 / 60 / 90 s 三点，而 90 s 在一条 300–400 s 的进近里不算短。今天的读数只能当作**一个配置下的迹象**：
在 (L = 60 s, Δ = 60 s) 上，无 token 的分段执行器闭环建立约 0.70，真值码换来跟踪不换来穿越，先验给的码没有加分，学习码本只装了航向，
语义词表的码执行器不看，雷达引导段的穿越是 0.3–0.4。这些迹象决定了 v3 的顺序，不决定 v3 的结论。

所以 v3 先把**执行器自身**的轴做成真正的消融（段长 Δ 与回看 L 都作轴，Δ 要包含真正短的段），定出基线，再弄清雷达引导段为什么穿不过；
"第二层"不预设为意图码，定义为"任何在同一闭环协议下好过无 token 基线的东西"，候选放在单机历史里真正没有的信息上（落地跑道、其他飞机）；
意图码是其中一个有界候选，在定牢的基线上重新测一次，过相对门才继续。

## §2 大纲（开发计划的结构；后面各节按此编号展开）

1. **目标与范围**：要交付什么（一个可飞的分段执行器 + 定量的第二层结论）；不做什么（风、ATC 文本、天气不作输入；机场当时的 runway configuration——哪几条跑道在用于进场——也不作输入，模型只知道本机的落地跑道，configuration 的信息只能经它间接带入）。
2. **对象与契约**：执行器的输入（lookback L、跑道系、机型）、输出（Δ 段控制，经动力学积分成一条轨迹）、执行协议（每 Δ 秒在飞出的轨迹上再预测一次）；哪些是固定的
   （cohort、锚点、动力学契约、种子），哪些是轴。
3. **问题与假设**：Q1 执行器的 (L, Δ) 怎么选；Q2 雷达引导段为什么穿不过；Q3 什么样的第二层信息在基线上加分；Q4 跑道未知时执行器损失多少、
   什么形式的跑道信息补得回来；Q5 有前机时执行器缺什么、什么形式的多机信息补得回来。每个问题写清"用什么读数回答、答案长什么样"。
   **第二层（L2）在 v3 里的地位**：它的形式是待回答的问题，不是继承的设计。它的任务由新执行器的失败方式（A2）和"信息缺失时损失多少"的测量来定义；
   09-13 计划里做过的跑道头 `r11_lift` 与 R3 的多机联合分配是在旧的整段执行器上测的，在 v3 里是**候选与证据**（左右跑道可预测、交互对落地时刻无增益），
   不是 v3 的第二层。
   **Q6 多假设的第二层**：飞机在一段里可能有几个方向可飞（继续下风、现在转 base、延长再转），临近时有平行跑道可选。
   第二层能否每段输出 K 个意图节点（segment frame 里的段末目标状态或连续向量，各带概率），L1 对每个节点飞一段，训练时只让最接近真值的那条
   拿到梯度（winner-takes-all / min-over-K），推理时按概率或按对 K 条 rollout 的评分选；段与段串成一棵意图树，跑道是树顶的分支。
   文献（`docs/literature/multimodal_intent/README.md`，13 篇已核实）：MultiPath / TNT / DenseTNT / MTR 是一次性输出 K 条的做法；plain WTA 会塌缩且有测量
   （MultiPath 的 min-of-K 基线只剩 1–2 个活模式），要从 evolving / annealed WTA 起步；DESIRE 不是 WTA，它靠评分器选；航空里显式 K 假设只有 ASCENT
   （ICRA 2026，一次性 120 s），**没有任何航空论文把多步预测做成意图分支的树**。用什么读数回答：它的闭环（top-1 即概率最大的那条，或评分选出的那条）对基线协议的相对 gate（阶段 B），
   加多假设自己的读数（K 条候选里最好的一条对真值的 ADE、模式概率的校准、跑道模式命中率）。答案长什么样：过相对 gate 且多假设读数好于单假设，
   才说明多模态被显式化了。

## §3 指标与读数协议

### 3.1 训练怎么取样、读数怎么做

**数据**：每架航班的记录从它进入机场周围 25 km 圆圈那一刻开始，每 2 s 一行，直到落地。KRDU 的航班按航班随机分成训练集和验证集，
所有读数都在验证集上做，训练时没见过。（集合的大小随 §6 的 cohort 决定项定，每个 (L, Δ) 报 n。）

**训练（锚点是随机的）**：一个训练样本 = 记录里的某一行往前 L 秒的历史 → 这一行之后 Δ 秒的真值。这一行按剩余路程均匀随机抽
（`random_train_anchor_sampling = remaining-path-uniform`），要求它之后至少还剩 Δ 秒。所以执行器学的是整条进近的每一个阶段，
从下风边到 final；L 只是窗口长度，Δ 只是目标长度，训练里没有"固定锚点"。

**评估（闭环，基线协议）**：
- **开始预测的时刻**：进入圆圈后 L 秒——有了 L 秒历史就让模型开始预测，不再等到 118 s（09-18 的读数固定在第 59 行，60 % 的验证航班那时已在 final 上，
  短航班被整个排除；这是从 v2 继承的可比性约定，v3 不再用）。不同 L 的臂开始预测的时刻不同，但每个臂都是"有 L 秒历史就开始"，与部署一致。
- **验证集的条件**：开始预测时剩余时长 ≥ Δ（能飞满一段）。短航班回到集合里；每个 (L, Δ) 的集合略不同，报 n。
- **闭环**：从开始预测起，执行器看最近 L 秒的飞出历史，预测并飞出 Δ 秒，接到历史后面，再看、再预测、再飞；直到轨迹在 final approach course 上穿过跑道入口
  （记 crossed），或用完预算（记 horizon）。预算 = 该航班真值剩余时长 T₀ + max(30 s, 0.1·T₀)，只是上限。基线协议（代码里叫 protocol `none`）
  不给执行器任何第二层信息；第二层的读数用同样的轮次与预算，只多它提供的信息，两者可直接比。
- **开环读数**（从真实历史预测一次、算段内误差）只在训练时作诊断，不进任何判定：历史已决定段的大部分，它看不到闭环里的差别
  （09-18 的 gate T 是开环的，三个段长六个词表全分不出差别）。
- **两个 seed**：seed 指训练的随机数种子（权重初始化、数据顺序），数据和划分完全相同；每个臂训两次（1337、2024），读数成对出现。
  **seed 线**：两个 seed 之间 established 通常差 3 个百分点、ADE 差 125 m 以内，差在这以内的算同一水平（控制路径上的历史测量，
  `ts_transformer/CLAUDE.md`"How to read results"）。只读大小，不读 p 值。
- **三个分组**：每个数报三次——全部；直线进近（straight-in，开始预测时航线曲折度 < 1.05、基本已对准跑道）；雷达引导（vectored，还在被引导、要转弯）。
  雷达引导组是难点所在，也是 v3 主要看的一组。

**评估的第二种读法：从离跑道入口固定距离处开始预测（已采用；与训练无关）**：按上面的规则，各航班开始预测时离落地远近不同，"从进圈后 L 秒起的 established"会被航班进圈时的
阶段左右。所以每个臂再读一组：每架航班在离跑道入口固定距离处（剩 12 / 8 / 6 km，距离点在 §6 定）各开始一次闭环预测、从那一刻飞到底，每个距离点报一套 §3.2 的指标。
这样"从远处起飞"和"从近处起飞"分开看，长短航班在同一尺度上比（包里已有 anchor grid / anytime curve 的机制）。它只是评估的第二种读法，不改训练、不改验证集。

**评估的第三种读法：所有格从同一行开始预测（2026-09-19 M-A1 之后补，D28）**：读法 (a) 把"历史长度"和"起点"混在一起——L = 120 的执行器进圈后 120 s 才接手，比 L = 60 少飞 60 s、起点更靠近五边，
赢的是少飞一段而不是多看一段（M-A1 的证据：每轮误差只差约 10%，同一起点的 12 km 读数上 L60_D20 反而更好）。所以每个臂再读一组：每架航班都从第 59 行（进圈后 120 s，L = 120 自己的起点）开始预测、飞到底，
20 格飞的是同一段进近、同一批真值，只有历史窗长短不同，这才是纯粹的信息优势对比（`manoeuvre_lockstep --first-prediction-row 59`，`lockstep.from_row`，与 (b) 同一种切法；那一行后面要有 Δ 秒真值，没有的航班计数不飞）。
论文里"历史多长够用"用这一读法答。

### 3.2 指标定义

| 指标 | 一句话定义 | 单位 | 出处 |
|---|---|---|---|
| established | 在预算内于 final approach course 上穿过跑道入口的航班份额 | 份额 | `manoeuvre_lockstep` 每架的 `reference.established` |
| fully flyable | 整条飞出轨迹每一点都在飞机的坡度 / 载荷 / 速度包线内的份额 | 份额 | `geometry.flyability` |
| ADE | 飞出轨迹对真值逐时刻位置误差的平均，一架一个数；报组内均值与 p50 | m | `observed_series_metrics` |
| FDE | 飞出轨迹终点对真值终点的误差；报 p50 | m | 同上 |
| 位移 @120 / 180 s | 锚点后 120 / 180 s 那一刻飞出位置对真值的误差 p50 | m | 每架 `at` |
| 逐段预测的误差（e_track） | 闭环里执行器预测了好几次（第 0、1、2…次）。每预测一次飞一段，段飞完的那一刻，量它所在位置与真实飞机同一时刻所在位置的距离；把所有航班第 r 次的这个距离取中位数，就得到第 r 次的一个数。按 r 排成一列，看误差随着一次次预测怎么长（09-18 的例子：175 → 434 → 812 → 1497 m，每预测一次翻一倍） | m | 每架 `asks_e` |
| 结束方式 | crossed / horizon 各多少架 | 架 | 每架 `ended` |
| 到达时刻误差 | 飞出时长减真值时长 | s | `final_time_error_s` |
| 失败方式（A2 用） | 没穿越的航班停在 final 的哪一侧、离跑道入口多远、转弯比真值早或晚多少 | 类别 + m + s | A2 的诊断脚本（待写） |

| 阶段 | 用哪些指标 | 判定规则 | 不过时做什么 |

| A2 诊断 | 失败方式的分布（雷达引导层没穿越的那 ~300 架）；e_track 逐轮 | 不是 gate，是分类：哪种失败占多数，写成 A3 的假设 | — |
| A3 改执行器 | 与 A1 相同 | 在同一 (L, Δ) 上，两 seed 的 established 都好过 A1 胜者且至少一个超过 seed 线，fully flyable 不掉 | 假设不成立，回 A2 换下一种失败方式 |

**设计**（D29）：只动 `dt_s`，其余全同 A1 胜出格 L120_D20：dt ∈ {2, 5, 10} s × seed {1337, 2024}。dt = 2 的两臂就是网格里的 L120_D20，不重训；新训 4 臂（约 1 h GPU）。
每个 dt 一份臂声明、各自的 cohort（cohort 规划器要求同一声明里各臂只在 GRID_AXES 上不同，`dt_s` 不在其中；规则仍是"记录 ≥ L + Δ"，按秒，航班集应相同，跑完用键集合核对）。
读数：(a) 从各自的 L−1 起；(c) 从同一时刻 t* = 120 s 起（行号 60 / 24 / 12，`--first-prediction-row`；dt = 2 的两臂在第 60 行补读一次，与网格里的第 59 行读数不混）。
比什么：established 全部 / 雷达、fully flyable、FDE p50、60 / 120 / 180 / 300 s 处的误差、选中的 epoch；噪声线用网格读数 (c) 上量到的 seed 线（established 全部 0.080，同一执行器家族、同一读法，引用时带此配置）。
不用 `executor_grid_gate`（格名按 (L, Δ) 取，三个 dt 会重名），结果表由脚本从三份 payload 直接读（`gates.cell_reading` 逐份）。

**已核的可行性**：TSConfig 在 simple-v3 下接受 dt_s 5 / 10 配 seq_len 24 / 12（视界 20 s、N₁ = 2、min_future 20 s 不变）；控制路径积分步长 `control_rollout_integrator_dt_s` = 0.5 s 与 dt 无关；闭环每轮行数 = round(Δ / dt)，所以 dt 必须整除 Δ = 20（6 s 不行）；评估的 common grid、各 lead、established 规则、预算都按秒，跨 dt 可比。

**要写明的混杂**：监督点数随 dt 变（20 s 视界内 10 / 4 / 2 个点），损失的分辨率跟着变；历史行数变是本消融的目的；dt = 10 时只有 12 行，可能触发 L = 30 那种"选模落在第 1 epoch"的情况（记录选中的 epoch，出现就标注）。

**成本与顺序**：4 臂 × 约 13 min + 12 份读数 ≈ 1.2 h GPU，磁盘 < 1 GB；排在阶段 B 的执行器选定之后或之前都可以，由用户定；结果写进结果文档新一节，论文里作为"采样间隔"一句消融。

### 5.2 阶段 B：指令词表的第二层（2026-09-20 重写，用户尚未看过；意图码版本作废，读数留作证据）

**问题**：A2 说雷达引导航班穿不过跑道入口的主要原因是没转基边、转晚了、末段形状错——都是"什么时候转、转到哪"的决策，历史里没有。阶段 B 问：把进近写成一串**管制指令**（每 τ 秒一个词：航向目标、高度目标、速度目标、切入航道），一个学出来的第二层能不能**说出**一串让执行器安全到达跑道入口的指令——不是复述真飞机说过的话，而是在自己飞偏之后仍能说对下一句。执行器仍从 L60_D20 起（D30），词表自建（5.2.1），两层都做后训练（5.2.2），程序与多机怎么进来见 5.2.3 / 5.2.4。

**证据（只作起点，全带配置）**

#### 5.2.0 三个改变（对 2026-09-19 版本）

1. **词表**：不再用编码器把 20–60 s 的真值段压成一个码，改为从航迹里读出来的**管制指令**——绝对目标，不含变化率，每 τ = 5–10 s 一个位置（D50–D54）。为什么：指令就是真实的生成过程；绝对目标与飞机偏在哪无关，执行器只要跟踪；"切入航道"这个词带位置锚，能把偏掉的飞机拉回航道；平台段读目标比斜率读变化率稳一个量级。
2. **两层都做后训练**：执行器在自己飞出的历史上再训（D49）；先验先在真值句子上预训练，再在执行器飞出的历史上再训（D55）。为什么：两层现在都是"在真值上训、在自己的输出上评"（§10 第 1 条），这是 v2 失败的诊断（09-18 §1.1），v3 没治。
3. **解码带目标**：部署时先验每个位置给 K 个候选指令，各交给执行器飞一段，按部署时拿得到的目标打分（到跑道入口的推进、对航道的对准、可飞性、先验概率），选一条（D56；Q6 落地）。为什么：现在的 top-1 是"最像真飞机会说的"，不是"最能到跑道入口的"；连真值码都换不来穿越，说明缺的是选择，不是信息。

#### 5.2.1 词表怎么建（D50–D54、D62–D65）

**词是什么**：一条指令只改一项，目标是绝对值（档位见 D51）。**六类**——2026-09-20 用户加了跑道与复飞两类（D62、D63），
原因见下面两段：

| 类 | 目标 | 档位 | 词数 | 定于 |
|---|---|---|---|---|
| **跑道** | 这一段话是**对哪条跑道**说的；其余各类词的参考系就是当前生效的这个词 | 该机场的跑道表，按机场绑定（同 `context.TypeVocabulary`） | KRDU 6 / KSJC 4 / KSTL 8 / KSMF 4 / KMSY 4 | D62 |
| 航向 | 相对**最后进近航道**的角度（下风边 = +180°，基边 = ±90°） | 10° 一档 | 36 | D51 |
| 高度 | **跑道入口以上**高度 | 1000 ft 一档，0 … 10 000 ft（按读出的分布定，结果文档 §12.1） | 11 | D51 |
| 速度 | 地速（ADS-B 无空速，风在里面，不当空速用） | 10 kt 一档，100 … 320 kt（同上） | 23 | D51 |
| 切入 | 以某角度切入最后进近航道 | ≤ 30° / 30–45° / > 45°（> 45° 占真值一半以上，结果文档 §12.5） | 3 | D51 |
| **复飞** | 这一次不落地：转去复飞等待定位点 MAHF 等待。它不是一个目标格，而是**撤销这一句的句号** | 无档位 | 1（**待 B0′′-b**：数据里为零则不进词表） | D63 |
| 保持 | 当前目标不变 | — | 1 | D52 |

有档位的四类共 73 个词，**与机场无关**；加上跑道词之后总数按机场走（KRDU 73 + 6 + 复飞 1 = **80**，另加"保持"）。
跑道词让词表的**类别集合**依赖机场，但 spec 的**结构**仍然与机场无关，做法和机型词表一样。

不含变化率（D50）：率由机型和动力学决定，是执行器的事；从斜率反推出来的率不可靠；09-18 的 63 类"变化档"词表没有锚点，
执行器不看它。

**跑道为什么是一个词，而不是坐标系（D62）**

前四类词都是相对跑道说的：航向是相对最后进近航道的夹角，高度是跑道入口以上，切入也是相对那条航道。这等于一句话从头到尾
都假设跑道已经定了，句子本身说不出"去哪条跑道"。但在真实管制里，跑道就是管制员说出口的一句话（"预期 23L 号跑道 ILS
进近"）。按 D50 的标准它就是一个词，藏在坐标系里不对。

- **词的形式**：一个分类槽，类别集合按机场绑定，做法和机型词表一样（`manoeuvre/context.TypeVocabulary`：排序过的类别、
  没见过的归第 0 类）。这样词表 spec 的结构仍然与机场无关，只有类别集合来自该机场的跑道表。五个机场的跑道数：
  KRDU 6（05L / 05R / 14 / 23L / 23R / 32）、KSJC 4、KSTL 8、KSMF 4、KMSY 4。
- **其余四类词的参考系 = 当前生效的那个跑道词。**
- **位置**：第一个位置就说，管制员先给跑道。
- **代价**：词表变了，sha 变，B0′ 的产物要重做一遍。前四类的读法一个字没动，所以 B0′ 那五轮人工核仍然作数，只有新词要它
  自己的核。

**跑道词可以中途改（D64，依据 FAA 原文）**

用户问的是真实塔台/进近里到底怎么做：指定了跑道就一路引导过去、出问题只能复飞，还是中途可以换。查了本地原文，结论是
**换跑道是常规做法，写在三个地方**，复飞不是唯一出路（逐条引到段：`docs/literature/runway_assignment/README.md`）：

| 什么时候 | 段 | 说了什么 |
|---|---|---|
| 指定跑道，以及此后任何一次变更 | 7110.65BB **4-7-1 b** | 跑道号在初次联系时或尽早给出；跑道指定"或此后任何一次跑道变更"若到距跑道过渡航路点 10 NM 以内才发出，就**必须改为雷达引导至最后进近** |
| 落地许可里改跑道 | 7110.65BB **3-10-5 c** | 有专门用语："CHANGE TO RUNWAY (number), RUNWAY (number) CLEARED TO LAND"，注释说明目的就是强调跑道换了 |
| 改到相邻平行跑道 | 7110.65BB **4-8-7** / AIM **5-4-19** | 侧移机动（side-step）：按一条跑道进近、落在相邻平行跑道；适用于间距 ≤ 1200 ft 的平行跑道，落地标准按非精密 |

所以跑道词必须**可改**：改的那一刻之后，其余四类词换参考系，标注器和先验都要知道这件事。4-7-1 b 还给了这件事一个几何
含义——10 NM 之外的晚改必须雷达引导，而雷达引导正是其余四类词本来就在描述的东西，所以换参考系之后句子接着往下说是自洽的。

**B0′′-a 仍然要量，但问题变了**：不再是"发不发生"，而是**多频繁、发生在哪里**，尤其是平行跑道的晚改（side-step）。
这一项在现有产物里看不见：harvest 给每条航迹指派**一条**跑道（arg-min），KRDU 的 16 056 条里 `ambiguous` 只有 1 条。
要找的是：有没有航班先在 A 跑道的航道上建立过、最后落在 B。仓库自己的跑道意图工作已经指过同一个方向——方向层 96–99 %
已解决，难的是左右层（KRDU 73–75 %），而 side-step 正好就是一次晚发生的左右改变；KRDU 05L/05R 与 23L/23R、KSJC 30L/30R、
KSMF 17L/17R 都是这样的平行对。

**复飞词的形式，和要先量的那件事（D63）**

术语：这件事叫**复飞**（missed approach / go-around）。程序里有指定的点：**复飞点 MAPT**（Missed Approach Point），过了它
还不能落地就必须复飞；之后按公布的复飞程序飞到**复飞等待定位点 MAHF**（Missed Approach Holding Fix）进入等待航线盘旋。
这两个在我们的 CIFP 处理里都已经有了（`aeroviz-4d/python/preprocess_procedures.py`：`missed_approach_point`、
`missed_hold_fix`、`expectedMissedHoldFix`，程序腿分出 `missed` 段），所以复飞的目标不用另造，就是 MAHF。

- **词的形式**：和别的词不一样。它不是一个目标格，而是**撤销这一句的句号**——说了它，这句话就不在跑道入口结束，而是转去
  MAHF 等待。
- **先量（B0′′-b）**：我们的数据里到底有没有复飞。harvest 的 outcome 只有 assigned / not_landing / unassignable /
  ambiguous 四类，没有复飞；一次复飞之后又落地的航班会被记成 assigned，而它中断的那次进近在 25 km 到达切片之外，可能整个
  被切掉。所以要在**完整航迹**上量，不是在到达切片上：找"降到入口以上某个高度之后又爬回去、然后再来一次"的航班。
- **仓库自己的规矩**（根 CLAUDE.md）：一个永远不可能触发的词，比没有这个词更糟。所以如果量出来五个机场的数据里复飞是零，
  这个词就不进词表，只把这件事写进结论。


**句子是什么**（D52）：每 τ 秒一个位置，每个位置写"此刻生效的各项"——跑道、航向目标、高度目标、速度目标、切入标志，以及复飞标志（若 D63 成立）；某个目标在某个位置换了值，那就是在那一刻发出了一条指令；没换就是"保持"。为什么用固定位置而不是变长的指令流：执行器的段和先验的位置能对齐，"什么时候发指令"由位置表达，不用另造"保持 10 s"这样的时长词。没解决：变长指令流（每条指令一个词、时长另记）作为替代形式，先不做。

**怎么从航迹里读出这些词（标注器，B′-dev1；规则是 D53，定稿 `plateau-v9`）**：

1. **一段稳住不动的航迹就是一条指令的目标**（下面叫 level）。航向（6 s 平滑）、入口以上高度和地速（各 10 s 平滑）三路
   分开看：一个量在容差里（航向 ±4°、高度 ±30 m、地速 ±2.5 m/s，都不到半档）保持 ≥ 20 s，且这 20 s 拟合斜率把它带走的
   量不超过半个容差，就算一个 level。缓慢下降、缓慢减速、下降途中的小停顿都不算。
2. **两个 level 之间是机动，不管快慢**：目标 = 到达的那个 level 的中位数，按档取词；**发出时刻** = 信号离开紧挨着它前面
   那个 level 的那一行；settled = 新 level 开始。
3. **什么不成词**（都记在 `absorbed` 里、统计里计数）：到达的还是原来那个词；变化不到最小量（5° / 500 ft / 10 kt）**且**
   没守住 40 s、或与当前指令的目标差不到一个容差；末尾读不出来的短尾。
4. **切入**：最后一条换了词的航向指令，之前不在航道上、之后在航道上（`approach_difficulty` 的 established 规则：离中心线
   500 m 内、在入口前、夹角 30° 内）。
5. **跑道词**（D62）：预训练阶段直接取该航迹被指派的跑道；能不能中途改见 D64，改点怎么定由 B0′′-a 量完再写。
6. **复飞词**（D63）：**读法未定，等 B0′′-b**。候选读法是"降到入口以上某个高度之后又爬回去、随后再来一次进近"，要在
   完整航迹上读，不在 25 km 到达切片上。
7. 每 τ 秒采一次"当前生效的各项"，得到句子；最后一个位置之后是落地——**除非说了复飞**，那时这一句不在入口结束。
8. **人工核（B0′）**：随机 300 架（直线 / 雷达引导各半，从 train 里抽），把读出来的指令画在航迹上逐架核。前四类词已核过
   五轮，定稿 v9（一致率 136/150 = 0.907，结果文档 §12.2）；**跑道词与复飞词要各自核一轮**（B0′′）。
9. 词表是带哈希的产物：版本、档位、阈值、读法的版本号、读的时候用的 cohort 身份、每类份额都在文件里；执行器与先验的
   checkpoint 记住这个 sha，对不上按名字拒绝。

**执行器怎么吃**（B′-dev2）：`plan_conditioning` 新值 `instruction`——条件向量加上执行器这一段（Δ 秒）内各位置生效的指令（Δ/τ 个位置，每个位置四个字段：航向目标的 cos / sin、高度目标、速度目标、切入标志，按档位中心值）；训练与真值指令读法用真值句子，先验读法用先验说的。其余同 D30 的执行器（lookback 60 s、段 20 s、pa 契约、随机锚点）。τ 与 Δ 的搭配是 D54（起点 τ = 10 s、Δ = 20 s，一段两个位置；τ = 5 s 作消融）。

**这件事把顺序顶回去了。** 第二层先训（§5.2.5 的顺序）的前提是词表已经定稿；加第五、第六个词就是换词表，而"一个实验要读
的结构在它开跑之前就定死"是仓库的硬规矩。所以 B0′′ 排在第二层训练之前：先量这两件事 → 定跑道词能不能改、复飞词进不进 →
重做词表产物 → 新词各自人工核 → 然后才训第二层。v9 那份四词产物不删，它是四词设计下完整的一份，留作对照。


#### 5.2.2 两层怎么训、怎么"会说话"（D49、D55–D58）

**预训练（两层都在真值上）**
- 执行器：D30 配方 + 指令条件，真值指令，随机锚点，180 epoch，两 seed。
- 先验：因果 Transformer（D46 起点：宽 128、4 层），每个位置输入 = 状态 token + 当前生效的各项词，上下文 = 机型。**跑道从上下文挪到了输出**——这正是 D62 的实质：原来跑道是喂进去的已知条件，现在它是要说出来的词。输出是下一位置**每类各一个 softmax**（因式头：跑道、航向、高度、速度、切入，复飞若 D63 成立）+ 落地。跑道那一项在基座预训练里**不屏蔽**（D65）。teacher forcing，val 上选模。读数：每字段的困惑度与 top-1、指令翻转率（相邻位置目标无故变化的份额）、top-k 覆盖率。

**后训练 1：执行器闭环再训（D49，B2′）**
- 为什么：执行器从没见过自己飞偏的历史；逐轮误差线性涨（每轮约 110 m）。
- 做什么（CAT-K 式，文献核实后定）：在 train 上用预训练执行器闭环飞，**每一段开 K 个分支**——真值指令和它相邻档位的指令（航向 ±10°、高度 / 速度各 ±1 档；先验训好后可换成先验的 top-K），各飞一段，只保留段末状态离真值最近的分支继续飞；这样飞出来的历史既是执行器自己飞的、又贴着真值走。把这些历史切成训练窗口，标签 = 同一绝对时间真值的下一段（09-18 v2 §8 的决定），指令 = 真值；在预训练之后再训 N 个 epoch（起点 = 预算的 10 %，CAT-K 是 32 个 BC epoch 后 10 个）；两 seed。**不做不加引导的直接混合**：CAT-K Tab. 2 里不加引导的放任它每步取最可能那一个往下飞、再拿这些历史微调（0.6361）比不微调（0.7581）还差，plan 路径 09-18 §1.2 第 2 条"DAgger 第一轮没帮上"也是同一现象。
- 怎么判：无 token 读法的 established / 雷达 ADE 对预训练执行器（相对门 A3 行）；逐轮误差是否不再线性涨。
- 不过怎么办：份额、轮数各消融一次；仍不过则结论"闭环再训在本数据量下无效"，记录，后续步骤仍在预训练执行器上做。

- 机制（B′-dev4，2026-09-20 写清，未建）：(1) 飞——用 `lockstep.fly` 的骨架在 train 上闭环飞，每轮每架开 K 个分支：真值指令与其相邻档（航向 ±1 档、高度 ±1 档、地速 ±1 档，切入不变；K = 7 起点），K 份 forecast 一批算，保留段末（Δ 秒后）离同一绝对时间真值最近的那支继续；每轮记下被选分支的指令与偏离；(2) 切窗口——每轮的锚点上取飞出历史的最后 L 秒作输入窗口、同一绝对时间真值的后 Δ 秒作目标（`dataset.target_horizon_s` 那份契约）、真值指令作条件，写成一张表（像归档的 `plan_head_2026_09/rolled.py` 的 `RolledWindowTable`：flight、锚点时刻、历史、目标、指令）；(3) 混合——训练时 `WindowContext.override(i, epoch_seed)` 按份额把一个真值窗口换成同一航班的一个飞出来的窗口，**替换窗口带真值目标**（现在的 override 只换历史、目标为零，是 plan 路径的用法，要扩）；份额起点 0.5，消融 0.25 / 0.75；(4) 再训——从预训练 checkpoint 起（`train` 要加"从 checkpoint 起训 N 个 epoch"的入口），N = 18（预算 180 的 10 %），lr 同预训练的末值；两 seed。读数：无 token 读法与真值指令读法各一份，相对门 A3 行；逐轮误差曲线对预训练执行器。
- 没解决：K 与相邻档范围；飞的时候执行器是否每轮都用预训练权重（CAT-K 是固定的预训练模型只飞一遍，再训的时候不再飞）——起点按 CAT-K：只飞一遍，不反复迭代。

**后训练 2：先验闭环再训（D55，B3′ 内）**
- 做什么（同样 CAT-K 式）：在 train 上用执行器闭环飞，每个位置在先验 top-K 的候选指令里挑一个交给执行器飞一段，留落点离真值下一个状态最近的那个继续，飞出来的状态序列配同一绝对时间的真值下一指令为标签，再训若干 epoch。K 要对词表大小扫一遍：CAT-K 在 2048 词上 K = 16–64 都平、K = 5 变差；我们每个字段只有 8–36 档，K 取 {2, 4, 8} 各读一次（D55）。
- 怎么判：先验读法的门 B；先验读飞出历史与读真值历史两种读法的差是否缩小。

**目标导向解码（D56，B3′）**
- 做什么：每个位置从先验分布取 K 个候选指令（起点 K = 4），各交给执行器飞 Δ 秒（束深 1；束深 2 作消融），打分只用部署可得项：先按程序与可飞性**屏蔽**（D59；SaFeR 的做法——掩码换来的是可解率不是精度），剩下的候选按先验概率与向跑道入口的推进（沿最后进近航道的 to-go 减少）、对航道的对准（横向距离、航向差）打分；文献里没有可抄的权重（DTPP 的代价是学出来的，SaFeR 只做掩码），起点 = 各项归一化后等权，权重作消融（D56）；选最高分的候选飞。上限读法：同一套候选用真值打分（minADE_K）——它说明"候选里有没有对的"。
- 怎么判：门 B（相对无 token 基线）；上限读法对 top-1 的差说明选择环节值多少。

- 机制（B′-dev5，2026-09-20 写清，未建）：lockstep 新协议 `prior-decode`：(1) 每轮先验读到此刻的句子（已说过的词 + 飞出历史在各位置的状态 token；第一轮的词 = 真值读出在锚点时刻生效的四个词，也就是"管制员刚说过的"）→ 四个头的分布 → 联合 top-K 候选（`_joint_ranks` 的同一种排序：每头 top-8 的乘积里取前 K，K = 4 起点）；(2) K 个候选各作执行器的指令条件飞 Δ 秒（K × 航班一批算）；(3) 掩码——可飞性（`geometry.flyability.required_controls` + `flyability_summary` 对飞出来的状态，不全可飞的候选去掉）与程序（D59：切入角门槛待用户；低于 OCS 的高度目标；航道外侧走向——`outputs/guidance/route` 的规则一处定义）；全被屏掉时退回先验 top-1 并记一次"无可行候选"；(4) 打分——先验联合对数概率、向跑道入口的推进（段末 to-go 的减少）、对航道的对准（段末横向距离与航向差）；各项在候选间归一化后等权（起点），权重作消融；(5) 选最高分的候选飞出，它的词写进句子作下一轮的输入。上限读法：同一套候选用真值下一状态的距离打分（minADE_K）。读数：门 B；每轮记候选数、被屏掉的数、选中候选与真值指令的一致率。
- 没解决：K；束深 2（两轮联合打分）作消融；先验在执行器每轮的锚点上读词——先验的位置是 τ 网格、执行器的锚点不在网格上（`Reading.words_at` 的规则：取之前最近的位置）。

**RL 微调（D58）：本阶段不做。** 驾驶领域在 CAT-K 之后再做 RL（R1Sim）只多 +0.0001；只有奖励里有"离真值远近"表达不了的东西时才值得——间隔（阶段 C）、指定到达时刻（CTA）。到那时再列。

**读数与门**：闭环协议不变（§3.1：从第 29 行起、B cohort 1404 架、两 seed、三分组、预算规则）；相对门用 §3.3 B 行；**门 B1（真值指令上限）改为"两项 established 不差 + 任一项超线"**（§10 第 5 条；旧规则放行了主指标掉一半的配置，D57）。真值指令读法里指令按**执行器位置**取（与飞机现在最接近的真值行所在位置的生效指令），不按时间（§10 第 3 条）。

#### 5.2.3 与 procedure 的结合

- **坐标系就是程序的**：航向相对最后进近航道、高度相对跑道入口，切入词直接是程序的动作；同一词表在任何跑道上读出同样的句子。
- **程序作为语法与掩码**（解码时，不进损失）：违反程序的候选指令在打分前屏蔽——切入角 > 45°、低于该处 OCS 的高度目标、航道外侧的走向；规则只有一处定义（`outputs/guidance/route` 的六条路线规则与 OCS 几何，D5 的结论是程序不进训练损失）。规则制导（`outputs/guidance/`）只作基线与诊断，不作模型的修法（用户规则）。
- **程序的固定点**（IAF / IF / FAF）可作句子里的锚 token 或打分里的路标：先不做，B3′ 读完再定（D59）。

#### 5.2.4 与多机交互的结合（阶段 C 之后；框架承接 09-18 §2.8）

- 指令词表让多机层与管制员的实际操作同形：前机的指令序列就是管制员对前机说的话，后机的先验读它作上下文；间隔规则（`inference/runway_schedule.py` 一处定义，`docs/literature/arrival_separation/`）作用在**候选指令**上——后机某条指令交给执行器飞出来的那一段，若对前机已提交的段违反间隔，该候选在打分前屏蔽；掩码约束的是指令，飞出的实际间隔由门读。
- 场景 = 同一机场、切片时间重叠的到达（KRDU：p50 3 架邻机，六成航班的同跑道前机在切片里，09-18 §2.8 的量）；同跑道按预计到达顺序串行提交；边特征（相对位置、同跑道 / 平行、到达时钟差、尾流类别、间隔余量）作机间注意力的偏置；切分按运行日（T4）。
- 先量上限（C0，最便宜）：不建图，把前机的**真值**指令序列作为上下文喂给单机先验，读雷达引导层的变化；差大于 seed 线才值得建层。

#### 5.2.5 步骤（每步：为什么 → 做什么 → 怎么判 → 不过怎么办）

**顺序（用户 2026-09-20 定）：第二层先训、先读，再回到 B1′ / B2′。** 理由是用户的：执行器这一层原则上可以用一个
常规的自动驾驶或制导程序直接解出来（仓库里已经有一个规则跟踪器 `outputs/guidance/PlanGuidance`，自己飞自己的航路；

每类的 perplexity、top-1、该换词时没换的比例、不该换时乱换的比例，都是拿它自己和两个基准比（`hold_baseline`：
一个永远保持、从不说话的模型，外加一个 bigram），不依赖 B1′ 给出的执行器上限。

解码、门 B）→ B4′。** 步骤的编号不改，因为全文都在引用它们。B0′′ 排在最前面不是我加的一层手续：加第五、第六个词就是换
词表，而一个实验要读的结构必须在它开跑之前定死，所以第二层不能在旧词表上先训（§5.2.1 末）。

### 6.1 阶段 A（D1–D11、D28、D29）

- **D1 验证集与训练集**：KRDU 全部进场航班（openap 能提供机型参数的），按航班随机一次划分（split seed 1337，与 09-18 相同），所有格共用同一划分；

**新增**
- **D49 让执行器在自己飞出来的历史上再训一遍**（审计 §10 第 1 条；文献 `trajectory_as_language/` §1.2 B1）
  - **要修的毛病**：执行器至今只在真实航迹上训过——每个训练样本都是"真飞机的一段历史 → 真飞机接下来 Δ 秒"。
    但闭环里它要从**自己上一段飞到的位置**接着往下预测，而那个位置不是真飞机当时所在的位置。这种局面它一次也没见过，
    所以没人教过它怎么飞回来。
  - **做什么**：预训练结束之后，让它在 train 的航班上闭环飞一遍，把它**自己飞到的位置**当作新的训练输入，
    标签仍然是同一绝对时刻真飞机的下一段。它学的是"你现在偏在这儿、真飞机在那儿，该怎么回去"。
  - **为什么要引导着飞，而不是让它随便飞偏**：CAT-K 量过，放任它每步都按最可能的那一个往下飞、再拿这些历史微调，
    结果比不微调还差（0.6361 对 0.7581）；引导着飞才有用（0.7616），而且赢过把模型放大 14 倍（测试集 0.7702，
    102M 的模型 0.7614）。
  - **CAT-K 是什么**：名字就是方法本身，Closest Among Top-K，"在最可能的 K 个里挑离真值最近的那个"。每一步不取模型
    最看好的那一个，而是取它最看好的 K 个，各飞一步，谁的落点离真飞机当时的位置最近就留谁接着飞。于是飞出来的这条
    轨迹既贴着真值走，每个点又都是模型自己产生的。
  - **在我们这里怎么落地**：每段开 K 个分支，候选 = 真值指令和它相邻的格（航向 ±1 格、高度 ±1 格、地速 ±1 格；
    先验训好之后可以换成先验的 top-K），各飞一段，留段末离真值最近的那一支。预训练之后再训 N 个 epoch
    （起点 = 预算的 10 %，CAT-K 是 32 个 BC epoch 之后再 10 个），两个 seed。详细机制见 5.2.2。
  - **没解决**：K 取多少、"相邻的格"放多宽、N 取多少。CAT-K 在 2048 个词上扫过 K：5 → 0.7423、16 → 0.7604、
    32 → 0.7616、40 → 0.7617、64 → 0.7602，从 16 往上就平了；我们每个字段只有 8 到 36 格，不能照搬。还有一处真的
    不一样：CAT-K 的模型每步输出的是一个词的概率分布，"最可能的 K 个"是现成的；我们的执行器每步输出的是连续的
    控制量，它自己没有 K 个候选，所以分支只能从指令层来。

## §10 审计（2026-09-20，用户叫停阶段 B 队列后；每条写"计划里写了什么 / 代码实际做什么 / 缺什么决定"）

**1. 执行器的训练不是闭环的，计划没把这当决定写。**
- 计划写的（§3.1）：一个训练样本 = 某一行往前 L 秒的历史 → 之后 Δ 秒的真值；评估是闭环（每 Δ 秒在飞出的轨迹上再预测）。
- 代码实际做的（`outputs/control/strategy.py` 的一行样本；`data/dataset.py` 随机锚点窗口）：历史永远是**真值**的观测行，目标是真值的下一段；损失只算这一段。执行器在训练里从没见过自己飞出的历史；闭环只在评估（`manoeuvre/lockstep.py`）里出现——每轮输入 = 锚点那行真值 + 已飞出的行（`rolled_series`），飞 Δ 秒接上再预测，直到穿越或预算用完。
- 09-18 计划 §2.7"第四步：闭环训练"明确有第 (2) 项"执行器在自己飞出的历史上再训"，§1.2 第 1 条更把 plan 路径的测量列为教训："rolled windows 不是可选项"（只在观测窗口上训的头每 30 s 再问时雷达 ADE 5391 m，rolled 后 3641 m）。v3 取代 09-18 的 §2–§4 时只保留了先验那一半（B3 / D40，且是条件步骤），执行器这一半**漏掉了**，也没有作为决定项写明"不做"。09-18 §1.1 给 v2 失败下的结论是"两层各自在真值上训练，闭环耦合没有任何一层见过"——v3 的执行器重犯了同一条。
- 后果：阶段 A 的 40 臂与阶段 B 的 12 臂全是开环训练的执行器；逐轮误差每轮累积约 110 m（§1、§10 结果文档），token 只补意图、补不了纠偏；阶段 B 的负结论（真值 / 先验 token 都不换来穿越）是在这个缺陷之上读的，不能作为"意图码无用"的定论。阶段 A 关于 L、Δ 的结论也是在开环训练的执行器上读的，闭环训练后要重读。
- 缺的决定：D49 执行器闭环训练——用哪种协议在 train 上飞（无 token 执行器：none；带 token：C）、飞出的历史切成窗口的标签（同一绝对时间的真值下一段，09-18 v2 §8 的决定）、混合份额（plan 路径量到的 0.75，作起点）、做一轮还是两轮、"该停"怎么进标签（09-18 §1.2 第 2 条）、两 seed。先在 L60_D20（无 token）上做并重读 §3.1 的闭环指标，再回头问 token 的问题。归档的 `archive/plan_head_2026_09/rolled.py` 是 plan 路径的 rolled 窗口实现，作参考，不照搬。

**2. 闭环 ADE / FDE 怎么算，计划只给了一句定义。**
- 代码：`lockstep.whole_forecast` 把各轮飞出的段拼成一条从首次预测起的轨迹；`observed_series_metrics` 在真值锚点之后每一行的时刻上取飞出位置与真值位置的距离，ADE = 均值、FDE = 终点；`e_track` = 每轮段末对同一时刻真值的距离；预算 = T₀ + max(30 s, 0.1·T₀)；established = 在最后进近航道上穿过跑道入口。
- 缺的：§3.2 要写明"飞出轨迹"就是评估时自回归飞出的整条（训练里没有这条轨迹），以及 ADE 的时间基准是真值的时钟（飞出轨迹比真值晚到时，末段按位置差计）。

**3. 真值 token 读法的 token 按真值的时间索引，不按执行器的位置。**
- 代码：协议 C 第 k 轮的码 = 真值从首次预测起第 k // hold 段的码（`flight_sequences`），与执行器此刻在哪无关；过了真值最后一个整段就一直用最后一个码。
- 计划 §5.2.0 写了"每段的 token 直接用真值段算出的码"，没写"按时间取、不按位置取"及其含义：执行器飞偏后，真值码说的是真值在别处的意图。§11 结果文档里先验 token 的穿越高于真值 token，就是这条。缺的决定：真值 token 读法是否应按执行器位置（最近的真值行）取段——那是另一种上限读法，要列出来选。

**4. 训练时 token 用真值（teacher forcing），计划写了但没写它与闭环的错配。**
- §5.2.0 写了执行器"输入 60 s 历史加 z"、联合训练；没写训练里 z 永远来自真值段且历史永远是真值历史，闭环里 z 来自先验、历史来自自己。这是第 1 条的 token 版。
