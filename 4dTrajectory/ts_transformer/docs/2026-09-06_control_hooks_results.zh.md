# control 输出上的命令 hook：屏障过滤器与名义律 + 有界残差（实验报告，2026-09-06）

承接 `2026-09-05_control_constraint_design.zh.md`（方案，第六版）和 `2026-09-05_control_penalty_results.zh.md`（罚项）。两轮实验：`control_hooks_20260906`（v1 代码 cd981f4，KRDU）和 `control_hooks_v2_20260906`（屏障 v2 dff1cf0 + 名义律 v2 bc2a4f2，KRDU + KSJC），都是 simple-v3、openap-direct 队列、一个种子（1337），基线是 `control_procedure_20260905/A_control_v3`（同一清单、名册、划分种子，不重跑）。读数：`docs/compare_constraint_arms.py`（走廊、终点、分层配对、回收率；各实验目录下 `readout.json/.txt`）、`docs/score_control_arms.py`（坡度统计；`score.txt`），hook 诊断读 `history.json` 的 `command_hook`；终点能量、门开距离分箱和配对差分布用本次的临时脚本（数字见文中）。

## 一句话结论

**屏障过滤器作为推理时的安全层（不重训，软饱和 + 软门控，v2）在两个机场都是净收益**——KRDU 全体 FDE 均值 1650 → 1449 m、ADE 1333 → 1278 m，配对 FDE 在 84 % 的航班上更好且没有一架变差超过 1 km；KSJC 996 → 930 m，90 % 更好；直线进近的终点 |xt| p95 从 1821 / 407 m 压到 70 / 46 m。做到这一步花了两个版本：v1 的速率型航向规则在“命令按段保持 + 执行器滞后”下 bang-bang，且只改坡度不改载荷偷走垂直升力（最差航班飞过阈值 16 km）；v2 加滞后补偿、前瞻位置和载荷协调后消失。**让网络在训练回路里穿过 hook，两个 hook、两个机场共六个臂，没有一个好过它的推理套对照，且全部付出全体 ADE**：网络学会把工作交给 hook（屏障臂被夹步 15–24 %，六臂坡度技能都低于基线），雷达引导层的路径中段变差。**名义律 + 有界残差的横向最像真实航迹、垂直最好，但 v1 的推力透传让它减速 30 m/s、落在阈值前 600 m**；v2 用并行积分的无 hook 参考 rollout 做速度保持后能量问题消失（终点相对入口高度中位 −164 → −7 m，垂直违反行 46.6 → 29.1 %），作为推理 hook 是小幅净收益，训练穿过仍不是。两条路线互补：屏障管横向、名义律管垂直，组合 hook 是下一个候选。

读法：

1. **直线进近上，过滤器做到了罚项做不到的事**：不重训，横向违反行 35.5 % → 1.6 %（软），终点 |xt| p95 1821 → 56 m，FDE 中位 703 → 492 m，且 ADE 不退（469 → 455）。罚项 1e-3 在同一层只到 28.1 % / 1432 m / 668 m。
2. **雷达引导航班是双峰**：中位 Δ = 0（大多数航班门根本不开或开得很晚，hook 不动），但硬过滤有 49 个航班 FDE 变差 > 1 km（最差 +14 km），软过滤 40 个；它们抵消了直线进近的均值收益，全体 FDE 均值只从 1650 到 1668（硬）/ 1634（软）。最差的 12 架都是门在 d = 10–20 km 处打开、真值剩余路径 27–58 km、弯曲度 1.7–5.6 的航班：飞机正沿着延长中线穿过成员锥（与跑道航向差在 30° 内），门开，过滤器把要离开走廊去飞三边/四边的坡度夹掉，rollout 之后沿走廊飞向跑道，而真值还有几十公里要绕。**这是"门控是预测自身状态的函数"的代价，不是过滤器算错**：推理时没有信息区分"建立五边"和"穿过延长中线"。按基线预测自身门打开的距离分箱（雷达引导航班）：门在 d < 8 km 打开的 114 架，硬过滤 FDE 均值 +398 m、20 架变差 > 1 km；8–12 km 的 61 架 +581 m；12–16 km 的 102 架反而 −146 m；≥ 16 km 的 46 架 +978 m。伤到的是早开门和晚开门两端。
3. **软过滤处处好于硬过滤**（违反行、终点尾部、雷达引导退化都更小）。软门控在成员锥边缘是一条 ~5 % 宽的斜坡，软饱和在区间边上有 2° 的过渡，命令改动更温和、连续。硬版是"部署形态"，软版是训练形态；这里软版更好，说明硬版的额外损失来自跳变，不是来自约束更紧。
4. **横向过滤器让垂直变差**：垂直违反行 46.6 → 47.6 %，但垂直 hinge 15.6 → 48–54（越出量变大）。它不碰载荷，改坡度会改变沿程距离 d 与时间的对应，下降剖面没跟着改，高度误差就放大。第一版只做横向是设计取舍，代价在这里可见。
5. **坡度统计**（`score_control_arms.py`）：共享分量 3.8 → 2.4–2.5 %（飞行航迹 1.8 %），直线参考坡度 RMS 0.39 → 0.90 / 0.86°（飞行航迹 0.41°）——过滤器在直线参考上加了坡度；每航班坡度技能 0.728 → 0.549（硬）/ 0.578（软），底线 0.170、同跑道孪生 0.699（基线数字取自 `control_procedure_20260905/score.txt` 的 A 臂，与 CLAUDE.md 里另一次 simple-v3 运行的 0.735 不同）。过滤器覆盖了网络在门控段学到的坡度，技能掉了 0.15–0.18。

## 屏障 v2：滞后补偿 + 载荷协调（推理时套在同一个基线上）

上面的退化机制在最差航班（ASA434，FDE 2.7 → 17 km）上逐段看清了：预测自身的门在 d = 17.5 km 打开时（真值门 20.2 km）飞机正以 30° 航向差切入五边，v1 在第 37 段要求 +28° 坡度、第 38 段又 +26°（滞后 2 s 让第一段没转够），航向随即摆过区间另一边，第 41–43 段要求 −11°/−29°/−23°——7 s 保持 + 2 s 滞后下的 bang-bang；而且 v1 只改坡度，网络配好的垂直升力分量 n·cos μ 在 28° 坡度下丢了 12 %，航迹角从 −1° 变到 −10°，速度 93 → 200 m/s，469 s 的 rollout 飞过阈值 16 km。两处都是设计缺陷，不是门控歧义（真值确实在那里建立了五边）。（逐段数字来自本次的临时脚本，未存档；同一组数字记在 `control/constraints/barrier_filter.py` 的模块 docstring 里。）

v2（提交见 CHANGELOG 2026-09-06 第二条）：航向层改成"这一段内应当改变的航向量"，并把执行器当前的实际坡度已经承诺的那部分转弯抵掉（Δψ ≈ (g·L/V_h)·[tan μ_c·(Δt − τ_eff) + tan μ_0·τ_eff]，τ_eff = τ·(1 − exp(−Δt/τ))，L = n·cos μ 取执行器状态）；走廊余量在命令生效时刻的预测位置上评估；载荷因子按 n' = n·cos μ/cos μ' 协调；航向增益默认 0.3 → 0.1。同一个基线检查点、同一批航班，推理时套 v2：

读法：

4. **坡度技能 0.644**，仍低于基线 0.728，但已回到同跑道孪生上限（0.699）附近：过滤器在门控段覆盖网络坡度的代价从 −0.15 降到 −0.08。

hook 诊断（`history.json` 的 `command_hook`，按步）：门控步份额 60 % → 66 %（第 1 → 140 轮），被夹步份额 19.5 % → 16.8 %，每步平均坡度改动 0.008 → 0.011 rad。被夹步份额在 140 轮里有 35 轮 ≥ 20 %（最高 46.1 %），收敛到 16.8 %，每航班坡度技能 0.472（基线 0.728，推理套 0.578，底线 0.170），直线参考坡度 RMS 0.94°（飞行航迹 0.41°）：预注册规则的两个条件里技能一项成立（0.472 远低于 0.728 − 0.02）、被夹步一项（> 20 %）只在训练前段成立——按末轮读否决不成立，按训练期间读成立；读作“靠 hook”没有疑问。

## 结论与下一步

**结论。**

1. **推理时的安全层是 control 输出上约束的正确用法。** v2 软屏障不重训地把两个机场的 FDE 均值压低 12 % / 7 %、ADE 4 % / 3 %，直线进近终点 |xt| p95 压到 46–70 m，没有一架航班的 FDE 变差超过 1 km（KRDU 1404、KSJC 1083 架）。这是罚项（`2026-09-05_control_penalty_results.zh.md`）做不到的：罚项改的是目标，把雷达引导的路径中段推坏了 +581 m；过滤器改的是可行集，只在门开时动坡度，且垂直 hinge 回到基线。
2. **过滤器必须尊重“命令按段保持 + 执行器滞后 + 网络配好的能量”三件事。** v1 只有屏障条件本身，三件都没管，结果是 bang-bang（+28° → −29°）和垂直升力丢失（γ −1° → −10°、93 → 200 m/s）。v2 的三处修正——航向层按“这一段内应当改变的航向量”并抵掉执行器已承诺的转弯、走廊余量在命令生效时刻的预测位置上评估、载荷按 n' = n·cos μ/cos μ' 协调——都可以从离散时间 CBF 和点质量方程直接推出；航向增益 0.3 → 0.1 是配合滞后补偿的重新标定。
3. **软处处好于硬。** 硬饱和 + 硬门控在成员锥边缘的跳变让一段之内的命令突变：KRDU 硬版 10 架 FDE 变差 > 1 km（软 0），KSJC 硬版有违反的航班 66 %（软 23 %）。部署形态若要硬饱和，门控仍应软。
4. **让网络在训练回路里穿过 hook 不是净收益（六个臂，没有一个好过它的推理套对照）。** 屏障 v1 / v2、名义律 v1 / v2 在 KRDU，屏障 v2 / 名义律 v2 在 KSJC：全体 ADE 都高于基线（+2 % 到 +21 %），坡度技能都低于基线，雷达引导层的路径中段都变差；最接近的一臂是 KSJC 的屏障训练臂（FDE 934 好于基线 996，但仍输给推理套的 930，且 ADE 退 2 %、雷达引导 ADE 中位 +112 m）。预注册的“懒网络”否决在 KRDU 的 v2 屏障臂成立（训练期间被夹步 > 20 % 且技能低于基线减种子噪声），KSJC 被夹步 15 % 但技能掉到孪生水平。机制上的假设（未测）：hook 兜底后，位置损失对门控段坡度的梯度变弱；模仿项仍直接监督坡度，所以这只能解释门控段的行为。
5. **名义律 + 有界残差的价值在垂直。** 它的横向最像真实航迹（KRDU 技能 0.659、直线参考 RMS 0.54° vs 飞行 0.41°），垂直是所有臂里最好的（KRDU 终点相对入口高度中位 −164 → −7 m、垂直违反行 46.6 → 29.1 %；KSJC 有垂直违反的航班 83 → 61 %），但改航迹角必须配推力：v1 的推力透传让它减速 30 m/s、落在阈值前 600 m，这是设计文档里的错误。v2 的答案——网络的意图只在它自己的 rollout 里，让引擎并行积分一条无 hook 的参考状态、推力做参考速度的比例保持——解决了能量问题，但速度保持增益受 1/Δt 上限约束，KSJC 仍留 5 m/s 的差。
6. **基线的垂直通道本身有系统偏差**：两个机场的 control 基线终点相对下滑道 −157 / −162 m（中位），而横向过滤器不碰它。这是名义律能在垂直上大幅改善的原因，也是一个独立于 hook 的发现——control 输出的下滑道跟踪值得单独看。

**采用。** `control_command_hook="barrier"`、`control_hook_saturation="soft"` 作为**推理时**的默认安全层（`predict --command-hook barrier --hook-saturation soft`），不进训练配方。名义律 hook 保留为选项。

**下一步（按价值排序）。**

1. **组合 hook：横向屏障 + 垂直名义律（+ 速度保持）**，推理时套。两者作用在不同的控制通道（坡度 vs 载荷/推力），门控、几何、诊断共用；预期同时拿到屏障的终点尾部和名义律的垂直。
2. **基线的垂直偏差**（阈值处低 150–170 m）：先看它是数据（观测航迹在阈值前的高度分布）还是模型（位置损失对高度不敏感），再决定是训练侧修还是 hook 侧修。
3. **门控**：v1 / 硬版伤到的雷达引导航班集中在门在 d < 8 km 或 ≥ 16 km 打开的两端（v2 软下每个箱都已转正）；一个“承诺进入五边”的门（例如要求下降剖面也在窗口内，或连续 N 段在锥内）可能去掉剩下的退化，代价是覆盖率。
4. **PatchTST、第二个种子、其他三个机场**：本报告是单种子、两机场；屏障 v2 在 KRDU 的效应量（FDE −201 m、ADE −55 m，零架 > 1 km 变差）远大于已测的种子噪声（状态路径 pooled ADE 5–22 m，`2026-09-05_final_constraint_results.zh.md`；模仿剂量实验 ADE 1.7 m），KSJC 的 ADE −17 m 落在那个带内——第二个种子在 KSJC 更必要。
5. **不做**：把 hook 写进训练回路（六臂无一好过推理套）；硬门控（跳变）；把过滤器写成损失（罚项报告）。
