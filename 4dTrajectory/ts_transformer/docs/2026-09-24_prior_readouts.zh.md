# 先验的读数

先验的设计在[先验设计](2026-09-24_prior_design.zh.md)；这里只放每一次训练的读数，以及跑之前写定的比较规则。每次训练一节，
写明它当时的配置（与现行设计不同的地方），数字只和同一节里、按同一口径算的基线比。

---

## 1 第一版（2026-09-24，`4dTrajectory/outputs/POOLED/prior/v1_20260924/`）

**配置**：句子产物 `instruction_language/v2_20260924`（规格 `103a6eae6b90`），按航班划分（`data.splits`）；每步输入是信号的状态
（含居中 15 s 拟合的航迹、地速、垂直速率——含之后 7.5 s 的信息）、相对生效跑道的量（第 0 步为 0 并给标志位）、到上一步为止
生效的词、机场与候选跑道几何；六个互相独立的头；d 192、4 层、6 头。代码 `11888357`（分支 `dev-executor`，干净的工作树）。
读数在 val 上。

230 万参数，28 个 epoch（第 25 个最好，每个约 58 s，共 27 分钟），train 970 万步、val 205 万步。

| 列 | 模型 | 重复上一条 | 只看上一个词 | 换词的步数 | 换词的步上 P(换) | 取值前 1 | 取值前 5 | 不换的步上误说要换 |
|---|---|---|---|---|---|---|---|---|
| 跑道指针 | 0.0023 | 0.0082 | 0.0082 | 10,540（都是第 0 步） | 1.000 | 0.808 | 1.000 | 0.0000 |
| 进近 | 0.0120 | 0.0222 | 0.0222 | 16,092 | 0.693 | 0.923 | 1.000 | 0.0001 |
| 航向 | 0.0460 | 0.0925 | 0.0832 | 25,827 | 0.507 | 0.557 | 0.843 | 0.0005 |
| 高度 | 0.0184 | 0.0433 | 0.0429 | 18,374 | 0.815 | 0.645 | 0.886 | 0.0007 |
| 下降角 | 0.0452 | 0.1003 | 0.0959 | 39,536 | 0.549 | 0.772 | 1.000 | 0.0020 |
| 速度 | 0.0539 | 0.0778 | 0.0736 | 26,752 | 0.444 | 0.483 | 0.830 | 0.0001 |
| **合计（每步）** | **0.1778** | 0.3444 | 0.3260 | | | | | |

读法：

- 每一列都比两个基线低，合计约低 45 %，每步困惑度 1.19。流程（产物 → 数据 → 训练 → 早停 → 读数）跑通了。
- "什么时候换词"比"换成什么"难：换词的步上模型给"换"的平均概率只有 0.44–0.82（速度、航向最低）；换成什么，前 5
  覆盖 83–100 %。换词的时刻本身有几秒的读法误差（执行器设计 §9 办法 B：高度、角度词读晚 4–6 s，速度词 8–9 s），
  模型学到的时刻也就带着这个误差。
- 跑道指针在第 0 步说，前 1 命中 80.8 %：只靠机场、候选跑道和第 0 步的状态，平行跑道之间还分不清。

## 2 第二版（2026-09-24 起，`4dTrajectory/outputs/POOLED/prior/v2_20260924/`）

**配置**：句子产物 `instruction_language/v3_20260924`（规格 `0b4ea75be36d`），按航班划分；不用拟合的速度类输入（变体 0 除外）；
第 0 步的进近、航向、高度、下降角、速度五列是已知条件（交接时的词），跑道预测；对每条候选跑道算相对量，候选跑道 token
（共用的小网络，求和进每步输入）与跑道打分头；其余同第一版。代码 `e7f0cf66` + 审查修正 `8f5af0a3`（分支 `dev-prior-v2`）。
队列：`v2_20260924/queue.sh`（日志 `queue.log`）。

**比较的规则（2026-09-24，跑之前写定）**：

| 变体 | 状态里的速度 | 候选的方向项 | 比输入少的顺序（加了几个量） | 参加选择 |
|---|---|---|---|---|
| V0 | 拟合（航迹、地速、垂直速率） | 拟合航迹 − 跑道航向 | — | 否，只量未来信息 |
| V1 | 无 | 无 | 0 | 是 |
| V1d | 无 | 过去运动方向 − 跑道航向 | 1 | 是 |
| V2 | 过去的地速、方向、垂直速率 | 无 | 3 | 是 |
| V2d | 过去的地速、方向、垂直速率 | 过去运动方向 − 跑道航向 | 4 | 是 |

- **内部选择集**：train 50,223 架里每个机场抽 10 %（种子 1337，按航班），每个变体用同一份（sha 写进每次的 `config.json`）。
  其余约 45,200 架训练；val 只做早停（每个 epoch 的 val 负对数似然）和最后一次读数。
- **种子**：`--seed` 同时定初始权重、批次顺序和 dropout（审查后改：原来模型在设种子之前就建好了，初始权重每次随机）。GPU 上的
  运算本身仍不完全确定，同一种子重跑只能近似复现。
- **位置插值**（审查提出，未量）：信号每 2 s 一行是报告点之间的线性插值；报告中断时，中断里各行的位置在"到中断后第一个报告点"
  的直线上，"只看过去"的位移就指向了中断之后飞机的位置。有多少行落在超过 2 s、超过 7.5 s 的中断里还没量（需要读原始航迹）。
- **跑的顺序**（一个接一个，同一台显卡）：V1、V1d、V2、V2d（种子 1337）→ 领先者再用种子 2024 跑一次 → V0（种子 1337）→
  选择与 val 读数。
- **规则**：
  1. 领先者：V1、V1d、V2、V2d（种子 1337）里，内部选择集上每步负对数似然（第 0 步只算跑道）最低的；
  2. 种子线：领先者两个种子的这个数之差的绝对值；
  3. 选：与领先者相差不超过种子线的变体里，加的量最少的（上表的顺序）；一样少时取负对数似然低的。
- **读什么**（写进 `choice.json`）：每个变体在内部选择集上的每步负对数似然（总的；第 1 步起分列，按第 1 步起的步数平均）、换词的
  步上 P(换) 与取值前 1、不换的步上误说要换、第 0 步跑道前 1 / 前 2（另按交接时的进近词分开）；变体 0 减去每个参选变体的 P(换) 与前 1（分列），就是先验靠未来信息的程度。
- **val 读一次**：只读选中的那一次（它在 train 去掉选择集后训练的那个模型，不重训），与按同一口径、从它自己的训练航班数出的
  两个基线比。

**审查发现的一处（交用户定，后来由第三版设计改掉）**：第 0 步的"进近"条件里带着跑道的答案。标注器判"交接时已许可加入"，看的是
第 0 行是否已在**落地那条跑道**的走廊里（或正转上它）；"速度未指定"也从许可那一行起算。审查在 v3 val 上粗数：10,542 架里 2,793 架
交接时已许可、1,828 架速度未指定。所以第 0 步跑道的读数按交接时的进近词分开报（`by_handover_approach`）。

**报告间隔**（审查提出，第二版量）：信号每 2 s 一行是 ADS-B 报告点之间的线性插值，一行的位置会用到它之后最近的报告点。
用到 2 s 以后报告点的行占 0.86 %，7.5 s 以后的占 0.044 %。

**读数**：

- V1（种子 1337），内部选择集 5,022 架（train 里按机场抽的 10 %；val 只用于早停）：每步负对数似然 0.2752（第 1 步起 0.2744），
  两个基线（同口径：第 0 步只算跑道）"重复上一条" 0.8432、"只看上一个词" 0.5598。第 0 步跑道前 1 为 81.4 %、前 2 为 98.3 %；
  "每个机场按 train 里各跑道的落地频率猜"为 58.3 %。按交接时的进近词分开：

  | 交接时 | 架数 | 前 1（模型） | 前 1（机场最常用跑道） |
  |---|---|---|---|
  | 未许可 | 3,747 | 75.7 % | 50.5 % |
  | 已许可 | 1,275 | 98.0 % | 81.4 % |

- 其余变体、领先者的第二个种子、V0（先验靠未来信息的程度）、选择与 val 读数：队列跑完后写在这里。
