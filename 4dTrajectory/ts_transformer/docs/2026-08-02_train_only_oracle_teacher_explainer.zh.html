Train-only Oracle Teacher

先在训练航迹上用“看得到完整未来”的离线优化器，为每条样本求出一份高质量控制方案； 再让只看历史的模型模仿并通过真实 rollout 损失微调。Teacher 只负责训练时搭桥，部署时完全退出。

Train-only 32 条 teacher 航迹全部来自 outer-train；与 validation 航班交集为 0，本文不展示或使用 test 结果。
不是标签泄漏 训练标签的未来本来就可用于监督；关键约束是不能用 validation/test 的未来构造 teacher 或调参。
部署无额外成本 最终模型仍只接收历史序列，一次前向输出控制与时长；不需要优化器，也看不到真实未来。

01 · Definition

它不是一个新 backbone，而是一种训练路径

设 x 是部署时可见的历史，y 是训练集中已知的未来，z 是控制参数，R 是可微动力学 rollout。 Teacher 对每条训练样本直接优化 z；Student 学习从 x 预测这份 z，最后再回到任务本身的轨迹损失。

核心定义：“Oracle”指 teacher 在离线求解时拥有训练样本的完整未来和逐样本优化权限； 它不是理论最优真值，也不是线上可调用的神谕。“Train-only”则规定这种特权严格止于训练分区。 Teacher: z* ≈ argmin_z L_task(R(anchor, z), y_future) Student warm-up: min_θ D(f_θ(x_history), z*) Rollout fine-tune: min_θ L_task(R(anchor, f_θ(x_history)), y_future) Deploy: z_hat = f_θ(x_history) // 无 y_future，无 teacher optimizer
T

Teacher 是求解过程

每条训练航迹单独优化，直接把控制张量和时长当变量。它回答“什么输出能解释这条已知未来”。

S

Student 是部署模型

iTransformer 或 PatchTST 仍只看历史。Teacher 产物改变初始化路径，不改变部署接口。

R

Rollout 负责纠偏

模仿控制不等于轨迹正确；最终用真实动力学和任务损失微调，修复 teacher 误差与参数多解性。

03 · Data firewall

为什么它仍然遵守“不偷看 test”原则

判断泄漏的关键不是“是否看未来”，而是“看了哪个分区的未来，以及看完后用它做了什么”。 监督学习本来就使用训练标签；oracle teacher 只是用优化器把训练标签变成更适合学习的中间监督。

OUTER-TRAIN · 可构造

Teacher 的唯一数据来源

  • 允许读取训练航迹完整未来
  • 允许逐航迹优化控制和时长参数
  • 允许模仿学习与 rollout 训练
  • 本实验 teacher cohort：32 条，均属 outer-train
VALIDATION · 只评价

用于开发选择，不生成 teacher

  • 模型只接收 validation 历史
  • 未来只用于计算 validation 指标
  • 不可按单条 validation 航迹反推控制
  • 与 teacher cohort 航班交集：0
OUTER-TEST · 封存
⌁

本轮不运行、不查看

  • 不产生 teacher artifact
  • 不参与 loss、超参或 epoch 决策
  • 仅在实验冻结并明确 release 后一次性使用
一条实用审计规则： 如果删除 validation/test 的所有未来文件，teacher 构造与模型训练仍应能完整执行； 如果删除 teacher 优化器，部署推理仍应能完整执行。两者同时成立，数据边界和部署边界才算清楚。

04 · How the idea emerged

它不是凭空套用“知识蒸馏”，而是沿诊断链推出来的

最初问题是：控制 rollout 表现差，究竟是表示能力不够，还是网络难以在长时域动力学中找到好解？ 于是逐层移除不确定因素，最终发现“可行解存在，但从随机网络输出走到那里很难”。

① 模型为何落不准？

训练 loss 能下降，但 ADE/FDE 仍大。仅看端到端结果无法区分 backbone、控制表示、动力学和优化条件谁是瓶颈。

② 暂时拿掉模型

直接把一条已知训练航迹的控制参数当作待优化变量，用梯度法拟合完整未来。这是诊断“表示 + 动力学是否有能力”的 direct-control oracle。

③ 中性初值仍失败

最初 direct shooting 的 ADE 约 17.4 km。这没有证明表示无能，反而暴露了长 rollout、强耦合 Jacobian 和坏初值造成的优化困难。

④ 逆动力学给出方向

由已知状态变化反推近似控制作为 warm start，再用分阶段 horizon 优化，单航迹可达到数百米量级。说明好控制解是存在的。

⑤ 把“解”变成“老师”

既然逐航迹优化能找到网络难以自行发现的区域，就把这些 outer-train 解缓存成 schedule，让网络先学会站到正确的优化盆地附近。

⑥ 模仿后回到任务

控制参数可能多解，teacher 也不完美，因此模仿只是初始化；最终必须用可微动力学下的真实几何、速度、终端和时间损失继续训练。

06 · Optimization view

为什么先模仿，再 rollout 微调

长时域控制训练的困难不只是“预测错一点”，而是早期控制会改变后续全部状态，使梯度经过长链传播。 Teacher 的主要价值是缩短搜索距离，而不是替代任务目标。

1

结构化 warm start

把网络输出从“几乎任意控制”拉到能产生合理进近形状的区域，降低长时域搜索难度。

2

把稀疏梯度变稠密

轨迹终端误差要穿过完整 rollout；teacher schedule 则为每个控制段提供直接监督。

3

避免只复制 teacher

不同控制可能生成相似轨迹。纯参数 MSE 会惩罚等价解，因此需要任务损失解除这种约束。

4

恢复部署时钟

teacher 构造可冻结真实总时长以稳定优化；rollout 微调让 student 重新学习可部署的时长预测。

07 · Generalization pattern

可泛化的不是“飞机控制”，而是特权求解器蒸馏

抽象后，这个思路适用于：训练时能获得更完整信息或调用昂贵求解器，部署时却只能快速、部分观测地决策的问题。 点击领域，观察四个角色如何替换，而训练逻辑保持不变。

通用模板： 在训练样本上让昂贵 teacher 使用特权信息求出中间决策 z*；训练 student 从部署输入 x 预测 z*； 再用最终任务损失校正 teacher 偏差。泛化对象是“求解过程的结果与搜索偏置”，而非 teacher 的运行时依赖。

08 · Applicability & failure modes

什么时候值得用，什么时候会失败

这不是保证提升的技巧。它最擅长解决“好解可离线求得，但端到端训练很难自行到达”的问题。

适合使用的信号

  • 直接优化或规划器在训练样本上明显优于当前模型
  • 昂贵求解只需离线执行，产物可缓存、可版本化
  • Student 的部署输入包含足以推断 teacher 决策的信号
  • 中间量有稳定语义，或可用任务损失处理多解
  • 存在可微仿真、评价器或其他闭环微调手段

主要失败模式

  • 用 validation/test 未来生成 teacher，形成数据泄漏
  • 未来具有不可由历史判断的多种意图，单一 MSE 把模式平均
  • Teacher 优化的是代理目标，Student 忠实复制了错误偏好
  • Teacher cohort 太小或选择偏置，初始化只覆盖狭窄区域
  • 把“oracle”误当理论上界，忽略局部最优与求解失败

与相邻概念的区别

方法 Teacher 从哪里来 部署时是否需要 teacher 本方法的关键区别
普通监督学习 数据集原始标签 否 Oracle teacher 先用物理/优化把原始未来转为结构化控制监督。
经典知识蒸馏 更大的已训练网络 否 这里的 teacher 可以没有网络，而是逐样本运行的求解器。
在线 MPC / 规划 运行时反复求解 是 这里把昂贵计算前移到训练期，线上只有 Student 前向计算。
理论 oracle / 真值控制 假设完美信息或解析最优解 通常用于上界分析 当前 teacher 只是数值局部解；“oracle”描述信息权限，不保证全局最优。
最终判断： Train-only oracle teacher 的本质是“用训练期可用但部署期不可用的计算与信息，塑造一个更容易学习的起点； 再让模型回到真实任务目标”。它解决的是优化路径和监督结构，不会自动补上历史中根本不存在的意图信息。
