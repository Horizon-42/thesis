# 对照实验：连续片段代替指令词（设计）

**一句话**：把先验说的"指令词"换成每 6 s 一段、从航迹上直接量出来的连续量（航向、高度、速度；跑道和进近许可仍是离散的），不再需要
标注器；其余一切——航班、划分、网络主干、执行器、落地判定、落地强化——都不变。两臂比一件事：**在"自己说、执行器飞、飞到结局"上，
离散的指令词是不是比连续的运动片段好**。这是论文里回答"为什么要离散词、为什么要标注"的对照。

思路来自用户（2026-09-29）："能不能把 embedding 这一层换成连续输入，每段固定 6 s，把 6 s 内的各种信息（与现在词表的种类一致，跑道
这种保持不变）作为连续向量，这样可以跳过词表标注这一步"。分析与建议做成对照而不是替换的理由：§2；新颖性评估里的位置：
[新颖性评估](../../../docs/two_tier/readouts/2026-09-28_novelty_assessment.zh.md) §6 第 2 条。

路径都相对 `4dTrajectory/`（`outputs/…`）或 `4dTrajectory/ts_transformer/`（`docs/…` 和包名）。

## 1 要回答的问题

1. **只换"说什么"的表示，自由生成的落地率怎么变？** 先比 base 对 base（只用数据训练），再比 landing 对 landing（按落地强化之后）。
2. **差在哪类航班上？** 直线进近和被引导的进近分开读，每个机场分开读。
3. **离航迹有多近？** 与观测航迹的几何距离、落地时间差：连续片段可能更像记录，离散词可能更会落地，两件事都要读。
4. **离散臂失败的闭环监督微调（CAT-K），在连续臂上能不能成？** 可选的一步（§9 第 4 步）：连续片段下，"让飞机回到记录的那个值"可以直接
   从状态算出来，而这正是离散臂失败的原因（后训练设计 §6）。

**不回答的**：连续臂不追求好过离散臂。它输了，说明指令词这层表示有价值；它赢了，同样是必须知道的事。事先不预设方向，比较规则写在
§8，实验开始前定下。

## 2 为什么做对照、不做替换

### 2.1 "换成连续"必须换在输出上

先验的输入已经大部分是连续的：本机过去的位置、地速、运动方向、垂直速率，以及与各候选跑道的相对量（先验设计 §4.1、§4.2）。输入里
唯一离散的是"已经说过的词"。只把输入换成连续，训练目标仍是词，标注器照样要跑。要跳过标注，**输出**必须换成连续：模型每 6 s 说一组
连续的值，执行器照着飞。

### 2.2 6 s 里量出来的是"现在的样子"，不是"要去哪"

指令词是一个**目标**："航向 270"是转完之后的航向，"下降到 900 m"是改平的高度。要知道这个目标，得看后面十几秒到几十秒——这正是
标注器做的事。6 s 装不下一个意图：按 3°/s 转 90° 要 30 s。直接从 6 s 窗口量出来的是一段**运动**（与 SMART、BehaviorGPT 的词同类），
执行器就从"飞向目标"变成"跟着一段段短目标走"。

### 2.3 预期（证据，带配置；不作设计依据）

| 方面 | 预期 | 依据 |
|---|---|---|
| 可重建（回放门） | 连续臂接近 100 % | 跟着记录的状态走本来就飞得回去；§9 第 0 步要实测 |
| teacher forcing 拟合 | 不能与离散臂比 | 一个是分类的对数概率，一个是连续密度 |
| 自由生成落地 | 连续臂可能更差，尤其被引导的进近 | 2026-09-18 的"无 token 执行器"（连续控制、每段再问一次、不用标注）：KRDU 验证集，在五边上穿越入口 0.70–0.75，被雷达引导的 0.33–0.44（`archive/manoeuvre_codes_2026_09/docs/2026-09-18_manoeuvre_token_results.zh.md` 首节）。**配置与本实验差很多**：只有 KRDU、执行器开环训练、判定不同、起点不同、没有后训练；每再问一轮误差累积约 110 m（`docs/history/2026-09_two_tier_v3/2026-09-18_two_tier_plan_v3.zh.md` §10 第 1 条）。只说明方向，要在本实验的对象上重新量 |
| 纠偏 | 离散臂占优 | 目标词本身把飞机往回拉：偏了之后执行器仍飞向同一个航向、高度。连续片段只是一小段轨迹，偏了要模型自己学会纠正 |
| 多种可能（左转 / 右转） | 需要混合分布才不被平均 | 连续回归会取两种可能的平均；§5 用混合分布的输出头 |
| 闭环监督微调 | 连续臂可能能成 | §1 第 4 条 |
| 论文的新颖性 | 连续臂没有新意 | 它就是"航空版的运动片段模型"；它的价值只在当对照 |

## 3 两臂只差在哪

| | 离散臂（现有） | 连续臂（本实验） |
|---|---|---|
| 航班 | 句子产物 `v5_20260926` 里有句子、执行器飞得了的航班 | **同一批**（标注器拒绝的约 1 % 两臂都不用，保证配对） |
| 划分 | 运行日划分 `data/day_split_20260924.json`，测试日封存 | 相同 |
| 行 | 2 s 一行，信号相同（`instructions/signals.py`） | 相同：模型仍按 2 s 一行读输入 |
| 说话的时刻 | 从第 `N_LOOK` = 8 行起，每行（2 s） | 从第 8 行起，**每 3 行（6 s）**说一次，中间两行只读不说 |
| 说什么 | 六列：每列"不变"或一个新词（分类） | 跑道指针、进近许可（分类）；航向、高度、速度（连续，§4）；下降角、"下降至落地"由规则得出（§4） |
| 目标从哪来 | 标注器反推 | 直接从航迹量（§4），不用标注器 |
| 网络主干 | 宽 192、4 层、6 头；时间因果注意力 + 飞机之间注意力 | 相同尺寸、相同层；输入端"生效的词"换成"上一段的值"（§5） |
| 输出头 | 按列顺序的分类头 | 同一顺序；连续列用混合高斯（§5） |
| 执行器 | v11 `outputs/POOLED/executor/v11_20260927` | **同一个执行器、同一份规格**，不改一行（§6） |
| 结局判定 | `autopilot.judge` | 相同 |
| 预训练 | teacher forcing，AdamW 3e-4，每批约 16,000 步，验证集负对数似然决定停 | 相同设置（`prior/train.py:32` `TrainConfig`） |
| 落地强化 | 截断的比 ε 0.2 + KL 拉回 β 0.04 + 数据项 λ 1；每轮每机场 400 架 × `K` 8 句，8 轮 | 相同取值；比和 KL 用连续值的密度（§7） |
| 程序高度屏蔽 | landing 不开（空），augmented 开 | 只比到 landing，不做第二阶段（§12） |

## 4 连续句子怎么量

一架航班的第 r 行起一段（r = 8, 11, 14, …），这一段的值取**段末**第 r + 3 行（6 s 之后）的观测：

| 列 | 连续臂里是什么 | 从哪来 |
|---|---|---|
| 跑道指针 | 这架的落地跑道，从第一段起一直不变 | 到达清单里 harvest 分配的跑道（`FlightSignals.runway`，`instructions/signals.py:38`）；不用标注器 |
| 进近许可 | "未许可"，从截获所在的那一段起"许可加入"，之后不再变；没有复飞 | 截获行 = 航迹从这一行起一直留在截获走廊里直到入口（`instructions/labeller/lateral.py:48` `capture_row`，与执行器判截获用同一个走廊 `envelope.corridor`）。这是几何量测，不读意图 |
| 航向 | 段末的航迹方向（度，罗盘） | 观测航迹 |
| 高度 | 段末的 MSL 高度（米） | 观测航迹 |
| 下降角 | 由高度差和这一段的水平距离算出：atan(−Δh / 水平距离) | 规则得出，不单独预测（§10 D5） |
| 下降角的档（执行器的"管子"要用） | 下降角落在词表的哪一档 | 词表规格的档界（`Words.angle_deg` 同一份规格） |
| 下降至落地 | 从进近许可那一段起为"是"，档限在下降档 | 规则得出（执行器要求"下降至落地"配下降档，`autopilot/vertical.py:115`） |
| 速度 | 段末的地速（米/秒），总是"指定" | 观测航迹 |

- **量法一处定义**：新模块读信号、写一份连续句子产物（§11），带自己的格式名 `ts-continuous-segments-v1` 和它读的信号产物的摘要；
  读的一方核对，不符就拒绝。
- **每一段三列连续值都"新说"一次**：执行器的"这是不是新词"（`WordsNow.issued_step`）每段都更新。
- **第一段**：与离散臂"第一个预测步六列都说"相同。

## 5 模型

- **主干不变**：直接用先验的层（`prior/model.py:167` `SceneLayer`）和候选跑道向量的做法（`prior/model.py:312` `_rows`），尺寸同 base。
- **输入**：每行的状态特征与离散臂相同（`prior/data.py:175` `rows_inputs`）；离散臂的"生效的词"嵌入换成"上一段说的值"：连续三列相对
  此刻状态的差值经一个线性层；跑道仍是被指跑道的候选向量；进近许可、"下降至落地"各一个小嵌入。离散臂的"每列距上次换词几步"不给
  （每段都换）。
- **说话的行**：只在段首的行（第 8、11、14 … 行）算损失、采样；中间两行只作输入。
- **输出头**，同一步里按顺序：跑道 → 进近许可 → 航向 → 高度 → 速度；后面的头读前面刚选的值（训练时用真值），与离散臂的"各列按顺序输出"
  相同（先验设计 §5）。
  - 跑道、进近许可：分类头，与离散臂相同（跑道头仍是候选跑道打分）。进近许可说出之后不能撤回（屏蔽）。
  - 航向、高度、速度：各一个**混合高斯**，预测段末相对此刻的变化量（航向差、高度差、速度差），`M` 个分量（§10 D6）。预测变化量而不是
    绝对值，是因为 6 s 内变化小、分布更稳定。
- **损失**：说话的行上，分类列的交叉熵 + 连续列的负对数密度，按段数平均。两臂的损失数值不能互相比，只各自用来选停止的时刻。

## 6 执行器怎么接：一行不改

- 执行器每个周期读的 `WordsNow`（`autopilot/sentence.py:65`）本来就是连续的物理量：航向（度）、高度（米）、下降角（度）、速度（米/秒），
  外加跑道、进近许可、"下降至落地"、下降角档和每列的"说出时刻"。连续臂只需要**直接造出 `WordsNow`**，不经过词表的查表
  （`WordTables.now`，`autopilot/sentence.py:110`）。
- 这个转接放在执行器包**之外**（runner 一侧的模块，§11）：`autopilot/` 一个字不改，执行器源码指纹（`autopilot/spec.py:121`）不变，
  v11 规格照样能用，两臂由同一个执行器、同一份规格飞。
- 闭环与离散臂的 `ClosedLoop`（`experiments/prior_free_generation.py:188`）同样的节奏：先验每 2 s 读一次执行器飞到哪（保持 2 s 的输入行），
  每 6 s 说一次，执行器每周期 1 s 照当前的值飞。
- **回放门**（§9 第 0 步）先确认执行器能照"量出来的连续句子"飞回落地。执行器的参数只从词表推出（用户 2026-09-24 的规矩），**门不过
  也不为连续臂调执行器**，带着数字回来问用户。

## 7 训练与后训练

- **预训练**：teacher forcing，设置同 base（`prior/train.py:32`）；训练日训练，验证集负对数密度决定停，连续 3 个 epoch 不降就停。
- **自由生成**：温度 1，按列顺序采样；词表相容规则里用得上的只剩"换跑道时进近许可跟着改""进近许可不撤回""被锁的跑道不换"
  （离散臂的 `prior/generate.py:237` 同一套规则的子集）。结局、时限（观测剩余时间 × 1.5）与离散臂相同。
- **落地强化**：与离散臂第一阶段同一个配方（后训练设计 §2、§8）：
  - 奖励相同（落在机场此刻的落地方向上 = 1），同一架航班 `K` = 8 句互相比；
  - 比 r = 现在的模型给这一段的值的密度 ÷ 采样那一遍开始时的密度（分类列仍是概率），截断 ε = 0.2（离散臂 `prior/train.py:117`
    `flight_surrogate` 的连续版）；
  - KL 拉回连续臂自己的 base，用离散臂同一个按样本的估计 exp(r − p) − (r − p) − 1（`prior/train.py:101` `flight_kl`），r、p 换成两模型在
    采到的值上的对数密度；
  - 数据项 = 训练日真实航班的 teacher forcing 损失，λ = 1；优化器同离散臂（学习率 1e-5 等）。
- **护栏**：跑道——落在观测跑道上的比例降 ≤ 2 个百分点（同离散臂）；说话方式——离散臂数"每架航向词数"，连续臂没有词可数，换成
  "每架累计转过的角度与观测之比"不超过 1.2 倍（§10 D10）。
- **选轮**：同离散臂，在内部选择集上按落地率、在护栏之内选。

## 8 读数与比较规则（实验前定下）

- **主读数**：验证集自由生成的落地率，总的、直线、被引导分开，每机场分开；每阶段比 base 对 base、landing 对 landing。两臂同一批航班、
  同一种子，逐架配对（每架 4 句的落地数）。
- **辅助读数**：结局分布；第一段所指跑道与观测一致的比例（第一个预测步的跑道前 1）；落地时间与观测之差；飞出航迹与观测的几何距离
  （evaluation 的判定与几何指标，与离散臂读数同一套）；执行器限位触发的比例（两臂都由同一执行器飞，报限位是看谁更"难为"执行器）。
- **怎么判**：
  - 差距以百分点报。**离散臂的 base、landing 都只有一个种子，种子之间差多少还没量过**；已知的只有同一模型在执行器 v9、v10、v11 上
    重读时落地率变 0.5 个百分点以内（读数文档 §11、[v11 读数](../../../docs/two_tier/readouts/2026-09-27_executor_v11_readout.zh.md) §3）——那是换执行器的变化，不是
    种子差，不能当噪声线。所以：两臂之差 **< 2 个百分点**时，两臂各补一个种子再判；**≥ 2 个百分点**时先按单种子报，注明只有一个种子
    （2 个百分点是我定的，§10 D9）。
  - 离散臂的参照数用 v11 上的重读：base 89.46 %（直线 93.63 / 被引导 82.43），landing 97.11 %（99.06 / 93.82）（v11 读数 §3）。
  - 不按 p 值判（n 大时纯噪声也显著，`CLAUDE.md` "How to read results"）。
- **报法**：结果写进新的读数文档 `readouts/<日期>_continuous_segment_ablation.zh.md`；本设计文档只改状态表。

| D3 | 跑道指针 | **harvest 分配的落地跑道，整句不变** | 让它可以变（离散臂的句子里跑道会变），但没有标注器就说不出"何时变" |
| D4 | 进近许可 | **截获所在的那一段起**（几何量测） | 截获转弯开始时（`capture_turn_onset`）——那就是标注器的读法，不再"跳过标注" |
| D5 | 下降角 | **由高度差算出，不单独预测**（6 s 内二者是同一件事） | 单独一个连续头（与词表列数一致，但两个头可能说得互相矛盾） |
| D6 | 混合分量数 `M` | **5** | 3 或 8；只按验证集负对数密度选 |
| D7 | 预测什么 | **段末相对此刻的变化量** | 段末的绝对值 |
| D8 | 回放门的线 | **训练日落地 ≥ 99 %**，evaluation 不低于离散臂 1 个百分点以上 | 与离散臂回放门逐格相同 |
| D9 | 种子 | **先一个（1337）**；两臂之差 < 2 个百分点时两臂各补一个（§8） | 一开始就两个；或换一条线 |
| D10 | 连续臂的说话方式护栏 | **每架累计转过的角度 ÷ 观测 ≤ 1.2** | 不设，只记录 |
| D11 | 比到哪个阶段 | **base 与 landing**；不做程序高度那一阶段（§12） | 也做 augmented（要给连续值定义程序高度的屏蔽） |
| D12 | 闭环监督微调 | **第 3 步之后再定** | 直接排进来 |
| D13 | 用哪批航班读数 | **与离散臂 v11 读数同一批**（验证集每机场 400 架，种子 1337） | 另抽 |

## 12 不做的，和风险

- **不做程序高度那一阶段**（augmented）：要为连续值另定"低于下滑道下沿的值不许说"，工作量大，也不影响"表示方式"这一比较。
- **不做多机**：多机的交互问题与表示方式无关。
- **风险 1：执行器是为目标词设计的**，连续臂拿短目标去喂它，可能天生吃亏，比较就混进了"执行器合不合适"。第 0 步的回放门就是量这件事：
  照记录量出的连续句子能飞回落地，说明执行器能执行这种说法；之后的差距才归到"先验说得好不好"。
- **风险 2：说话间隔不同**（6 s 对 2 s）。D1 的另一种做法可以把它分开。
- **风险 3：只有一个种子**。按 §8 的线判，不够就补。
