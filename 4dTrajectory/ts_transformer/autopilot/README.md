# autopilot — 执行器

两层模型的执行器：一个自动驾驶，每秒读一次飞机状态和此刻生效的词，把词翻译成想要的变化率，由点质量动力学方程精确反解出
推力、坡度、载荷因子，再用 ts 控制路径的动力学积分一秒。它不读程序数据，不学习，参数全部从词表推出。

**设计文档**：[`../docs/executor_design.zh.md`](../docs/executor_design.zh.md)——原理、每条律的推导、参数总表、判定、回放门，
§14 是本包关键代码的索引（文件与行号）。

| 模块 | 做什么 | 设计文档 |
|---|---|---|
| `executor.py` | 一个控制周期（`Executor.cycle`）与整句飞完的循环（`fly`） | §3 |
| `lateral.py` | 横向律：航向词、许可、截获、沿线跟踪、复飞 | §4 |
| `vertical.py` | 纵向律：四种模式、下降至落地 | §5 |
| `speed.py` | 速度律、"未指定"的速度、失速下限 | §6 |
| `inverse.py` | 想要的变化率 → 坡度、载荷因子、推力，限制按顺序施加 | §3、§7 |
| `plant.py` | 积分一个周期（控制路径的动力学） | §2.3 |
| `frame.py` | 动力学的状态读成词的坐标（罗盘航迹、机场坐标系） | §2.1 |
| `sentence.py` | 每个周期生效的词；说词的时钟 | §11.2 |
| `flights.py` | 重建航班的输入，与句子产物逐行核对 | §2.4 |
| `runway_data.py` | 候选跑道公布的 TCH | §5.3 |
| `judge.py` | 三层判定：限制、每个词、结局 | §8 |
| `replay.py` | 回放：抽样、谁进门、飞、判；打开规格时的核对 | §11、§12 |
| `params.py` / `derive.py` | 执行器的参数与约束；从词表推出 | §9、§10 |
| `spec.py` | 执行器规格与源码指纹 | §12 |

**改代码之前**：执行器规格的源码指纹覆盖本包所有 `.py`（`spec.py` 除外）和它们直接 import 的仓库模块。改其中任何一个
（连说明文字在内），现行代码就拒绝已有的规格，要重写规格（`run_ts.py executor_spec`）并重跑训练集回放门
（`run_ts.py executor_replay`），见设计文档 §12。本文件不在指纹里。`__init__.py` 的说明里设计文档还是旧文件名
（`2026-09-23_executor_design.zh.md`），随下一次规格一起改。

测试：`tests/test_autopilot.py`。
