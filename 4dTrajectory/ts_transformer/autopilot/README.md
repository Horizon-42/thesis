# autopilot — 执行器

两层模型的执行器：一个自动驾驶，每秒读一次飞机状态和此刻生效的词，把词翻译成想要的变化率，由点质量动力学方程精确反解出
推力、坡度、载荷因子，再用 ts 控制路径的动力学积分一秒。它不读程序数据，不学习，不从数据取参数。

**设计文档**：[`../docs/two_tier/design/vocabulary.md`](../docs/two_tier/design/vocabulary.md) §5（两层模型 v4：执行器只飞词，
没有截获、沿线跟踪、着陆瞄准与下滑道下限；高度词是机场标高 E 以上的高度，在 T + E MSL 上飞；判定见 §5.8，关键代码索引见 §11）。
旧的 [`executor_design.zh.md`](../archive/two_tier_v3_2026_10/docs/executor_design.zh.md) 描述 instruction-v3 的执行器（v11），
推导与参数来源仍可参考；下表"设计文档"一列不带"词表"的节号是它的。

| 模块 | 做什么 | 设计文档 |
|---|---|---|
| `executor.py` | 一个控制周期（`Executor.cycle`）与整句飞完的循环（`fly`） | §3 |
| `lateral.py` | 横向律：航向词（听到时按生效跑道的航道换算成航迹）；"复飞"不改航向目标 | 词表 §5.4 |
| `vertical.py` | 纵向律：保持、下降/爬升到目标高度（T + E MSL）、"不改平"按类角度下降；复飞时的爬升词按推力允许的稳定爬升角，限在 1.885°–3° | 词表 §5.5 |
| `speed.py` | 速度律、"未指定"的速度（复飞时保持听到复飞时的空速）、失速下限 | §6、词表 §5.6 |
| `inverse.py` | 想要的变化率 → 坡度、载荷因子、推力，限制按顺序施加 | §3、§7 |
| `plant.py` | 积分一个周期（控制路径的动力学） | §2.3 |
| `frame.py` | 动力学的状态读成词的坐标（罗盘航迹、机场坐标系） | §2.1 |
| `sentence.py` | 每个周期生效的词；句子按自己的行说出（D57） | §11.2 |
| `flights.py` | 重建航班的输入，与句子产物逐行核对 | §2.4 |
| `judge.py` | 三层判定：限制、每个词、结局（含决断高检查，用 `candidates.json` 里每条跑道公布的 TCH、下滑角、决断高，D61；按每个周期的 R 与 G） | 词表 §5.8 |
| `replay.py` | 回放：抽样、谁进门、飞、判；打开规格时的核对 | §11、§12 |
| `params.py` | 执行器的参数与约束（p 是规格 runner 里引用标准的固定值） | §10 |
| `spec.py` | 执行器规格；规格只给飞得出它参照航迹的代码打开（通过记录） | §12 |
| `conformance.py` | 按航迹核对：参照航迹的写出、三种方式各飞一遍、按容差比、写通过记录 | §12.3 |
| `single.py` | 单机单条：一架航班、纯 Python 标量（后端现飞用） | §12.4、§13 |

**改代码之前**：执行器按航迹核对，不按源码指纹（用户 2026-10-01，设计文档 §12.2–§12.5）。改了本包或它直接 import 的仓库模块的代码之后，
在干净的检出上跑一次 `python run_ts.py executor_conformance --executor <规格目录> --instructions <句子产物>`（约 30 s）：参照航迹按三种方式
（单机批量、多机批量、单机单条）各飞一遍，全在容差内（状态 1e-6 m）就写通过记录，规格、训练、读数都不用重跑；超出容差说明行为变了，
要按新代码写新规格（`run_ts.py executor_spec`，它会连参照一起写）。只改说明文字和注释不用核对。

测试：`tests/test_autopilot.py`、`tests/test_executor_conformance.py`；单条执行器 `aeroviz_backend/tests/test_single_executor.py`。
