## 0. 结论

1. **训练集里有 13,164 条航班（26.0 %）用 A320 的参数飞**：12,552 条机型已知、但模型没有这个机型（183 个机型），
   612 条连机型都识别不出来。另有 1,091 条（11 个机型）用 OpenAP 自带的同义替代机型。按机场差别很大：KRDU 36.2 %、
   KSJC 32.7 %、KSTL 18.5 %、KMSY 15.0 %、KSMF 8.3 %。
2. **"A320 是大飞机"本身不是问题所在。** 这个模型的动力学除以重量以后只剩两个机型量：翼载除以最大升力系数（它决定失速速度，
   也就决定进近速度），和推重比；阻力系数全机队是同一个常数。所以替代得好不好，要看这两个比值像不像，而不是看飞机大小。
   按这个标准，A320 对进近类别 C 的中型公务机其实不算差；**它真正出错的是慢速飞机**：12,552 条里有 4,599 条（36.6 %）
   的机型，FAA 公布的进近速度落在 A320 模型的失速分支里（升力需求超过最大升力的 90 %）或更低，
   其中 3,910 条低于 A320 模型的失速速度 —— 这些航班实际飞出的进近，在 A320 参数下根本产生不了足够的升力。活塞机全部如此。
3. **公开数据源**：没有一个既公开、又允许在论文里发表数值、又覆盖公务机 / 涡桨 / 活塞机完整气动模型的来源。
   - OpenAP 最新版 2.6.2 的机型数据与我们在用的 2.4 逐字节相同，没有新增。
   - Poll–Schumann 参数表（pycontrails，Apache-2.0）有 17 个缺失机型的本机数据，但只有客机，而且只给干净构型。
   - EUROCONTROL BADA 覆盖最全，但许可证禁止发表系数和"计算结果"，也不许在发表物里写机型名，论文不能用。
   - ICAO/ECAC ANP 的许可证状态不明，要先问 EASA。
4. **但这个模型每个机型只读三个数：着陆质量、翼面积、最大推力**（其余都是全机队通用的规则，§3）。这三个数在
   **型号合格证数据单（TCDS）、厂家文件和 FAA 飞机特性数据库**里是公开的一手数据。收集了一手文件的 47 个机型里，
   有 21 个喷气机型三个数都齐全（7,460 条 train 航班，占 13,643 条的 55 %；C56X 是 2026-09-24 补的）。它们用自己的参数以后，失速余量
   （见 §3.3 的定义）全部落在模型对原生机型的范围里。
5. **在已有机型里找替代**：按 §6 的方法（同一动力类型、同一 FAA 进近类别、相似距离最小）：
   - 39 个喷气机型（1,640 条）换到更相似的已有机型。按航班加权的相似距离从 0.24（用 A320）降到 0.07。
   - 8 个 OpenAP 同义机型（688 条）检查后保留原样。
   - 10 个客机型（34 条）用 Poll–Schumann 的本机参数。
6. **排除 121 个机型、3,821 条训练航班**：螺旋桨飞机（活塞、涡桨，含支线涡桨）83 个机型 3,452 条 —— 用户 2026-09-23
   决定排除，它们原来几乎全部（3,388 条）低于 A320 模型的失速分支；FAA 表里没有进近速度的 264 条；旋翼机和军机 36 条；
   找不到同类替代的喷气机 SF50 69 条。另外 612 条识别不出机型的航班也只能排除。
7. 现在的 two-tier ts 数据集（`aircraft_filter = openap-direct`）**本来就把这些航班整条丢掉**，并没有用 A320
   （KRDU 的 train+val 里丢了 8,003 / 20,298 条，39 %）。A320 替代发生在优化器场景和 `aircraft_filter = all` 的 ts 数据里。
   本报告的映射如果落地，会改变这两处的机型参数，也会让 `openap-direct` 以外多出一种"可用机型"的口径 —— 要你决定（§9）。

## 1. A320 替代是在哪里发生的

- `flight_scenarios/build.py` `_resolve_aircraft`：先把航班识别成 ICAO Doc 8643 机型代码（FAA 注册库 / OpenSky），
  再向 `aircraft_for_code` 要这个机型的动力学参数（手工预设 A320 / B77W / C172 优先，其次 OpenAP 缓存）。
  要不到（机型不在 OpenAP 里，或者机型识别失败）就用调用方给的 `fallback_type`，并在 `source` 里记下
  `aircraft_fallback_used = True` 和原因。真实机型代码仍然保存在 `resolved_typecode` 里，不会被覆盖。
- `fallback_type` 的默认值是 A320：`flight_scenarios/__main__.py`（`--aircraft-type`，`prepare_scenario_inputs.py` 走这里，
  所以优化器场景用它），`4dTrajectory/ts_transformer/config.py` 的 `DEFAULT_AIRCRAFT_TYPE`（ts 的 `aircraft_filter = all`）。
- ts 的 `aircraft_filter = openap-direct`（现在 two-tier cohort 用的，例如
  `4dTrajectory/outputs/KRDU/experiments/cohorts_v7_20260923/two_tier_v3_grid/data_selection.json`）不做替代，
  只保留 OpenAP 有原生模型的机型，其余整条丢掉。
- OpenAP 本身也会替代：它对 21 个机型用"同义"机型的性能数据（例如 LJ45 → GLF6），我们的数据里有 11 个这样的机型。

## 3. 模型实际用到哪些机型参数，以及"替代得好"怎么衡量

### 3.1 每个机型真正读的只有三个数

| 量 | 现在从哪来 | 用在哪里 |
|---|---|---|
| 着陆质量 m | OpenAP 的最大着陆重量；没有就取 0.85 × 最大起飞重量 | 初始 / 目标状态的质量；ts 控制标签的逆动力学；优化器 |
| 翼面积 S | OpenAP | 升力、阻力、失速 |
| 最大推力 T_max（全部发动机之和）| OpenAP | 推力上限；ts 的推力输出是 T / T_max |
| 着陆构型最大升力系数 C_L,max | **按最大起飞重量分档**：A320 系列 3.0；> 100 t 为 2.4；30–100 t 为 2.7；< 30 t 为 2.2（`aircraft/aero_params.py`）| 失速模型 |
| 阻力系数 C_D0、k | **全机队常数 0.02、0.04**（`AeroParams` 默认值；OpenAP 的阻力极曲线读进来了，但没有用）| 阻力 |
| 进近参考速度 | 分析时：**按最大起飞重量分三档的默认值**（5.7–150 t 一律 145 kt）。**2026-09-23 起改为各机型的公布值**（`aircraft/reference_speeds.json`，§9 第 5 项）| 目标状态的速度；优化器 `runway` 模式的终端速度和速度下限的上界 |
| 跑道入口高度、末段长度等程序参数、推力初值 | 按最大起飞重量分三档的默认值（三个手工预设除外）| 没有 CIFP 目标时的合成场景；优化器初值 |

所以，给一个机型换参数，改变的只有 m、S、T_max，以及 C_L,max 落在哪一档。

### 3.2 为什么看比值而不是看大小（我们对点质量方程的解读）

点质量方程沿航迹和垂直航迹两个方向写出来，除以重量 W = m g：

```
(1/g) dV/dt      = T/W − (½ρV² S C_D)/W − sin γ
(V/g) dγ/dt       = (½ρV² S C_L)/W · cos φ − cos γ
C_D = C_D0 + k C_L²（常数），C_L ≤ C_L,max
```

右边只通过 **W/S（翼载）、T/W（推重比）、C_L,max** 依赖机型。两个机型只要这三样相同，飞出来的轨迹就完全一样，
和它们各自多重无关；推力输出 T/T_max 也一样。失速速度 V_s = √(2 (W/S) / (ρ C_L,max))，进近速度大约是它的 1.2–1.3 倍，
所以 **FAA 公布的进近速度的平方，正比于 (W/S)/C_L,max**。两个机型进近速度接近，就等于"翼载除以最大升力系数"接近。

### 3.3 两个衡量量

- **失速余量** = FAA 公布的进近速度 ÷ 模型用某组参数算出的 1 g 失速速度（`aero_params.stall_speed_ms`，着陆质量，海平面密度）。
  它说的是：这个机型实际的进近速度，在模型里离失速有多远。模型对自己原生的 37 个机型（OpenAP 原生 + 预设，有 FAA 进近速度的）
  算出来是 **1.13（B77W）到 1.62（GLF6），中位数 1.28** —— 下文称"原生范围"。低于 1/√0.9 = **1.054** 时，
  升力需求超过 C_L,max 的 90 %，模型进入失速分支（加失速阻力）；低于 1 时，模型产生不了所需升力。这些界限是模型自己的，不是规章。
- **相似距离**（替代机型 c 相对目标机型 t）：

  ```
  d = 2 |ln(V_app,t / V_app,c)| + |ln((T/W)_t / (T/W)_c)|
  ```

  第一项是 (W/S)/C_L,max 之比的对数（速度平方），第二项是推重比之比的对数；两项都是"单位重量上的力"之比，
  所以等权相加。两边的进近速度都取自同一张 FAA 表。推重比 = 额定起飞推力之和 ÷ (最大起飞重量 × g)；目标机型的推力来自
  发动机 TCDS / 飞机 TCDS（§5.2），候选机型的来自 OpenAP。没有一手推力的喷气机只算第一项（表中标 *）。
  这个距离是我们从方程出发的定义，不是现成标准。

## 4. A320 替代的偏差有多大

A320（手工预设：着陆质量 66.3 t，S = 122.6 m²，C_L,max = 3.0）在模型里的失速速度是 **53.7 m/s**（104.4 kt），
进入失速分支的速度是 **56.6 m/s**。把用 A320 的 12,552 条航班按机型的 FAA 进近速度分：

| FAA 进近速度相对 A320 模型 | train 航班 | 占比 |
|---|---:|---:|
| 低于失速速度（失速余量 < 1，模型给不出所需升力）| 3,910 | 31.2 % |
| 在失速分支里（1 ≤ 失速余量 < 1.054）| 689 | 5.5 % |
| 1.054–1.15 | 1,270 | 10.1 % |
| ≥ 1.15 | 6,395 | 50.9 % |
| FAA 表无进近速度 | 288 | 2.3 % |

- 活塞机 2,439 条全部在第一行（例如 P28A：FAA 进近速度 36.0 m/s，A320 失速余量 0.67）。
- 涡桨和轻型公务机大多在前两行（PC12 0.81，C68A 0.96，C25M 0.96）。
- 进近类别 C / D 的中大型公务机，A320 的失速余量是 1.16–1.38，落在原生范围里（CL60 1.31、GLF4 1.38）。
  对它们，A320 的主要偏差是推重比（公务机约 0.33–0.42，A320 0.31），而不是"太大"。

对 ts 的影响：推力标签是用逆动力学从观测轨迹反算的（`ts_transformer/outputs/dynamics/inverse.py`）。当观测速度低于
模型失速速度时，升力被截在 C_L,max，同时加上失速阻力，反算出的推力和载荷因数不再对应任何真实飞行。
这 4,599 条航班如果进了 `aircraft_filter = all` 的训练集，它们的推力标签就是这样来的。

### 5.2 模型真正需要的三个数：一手文件

§3.1 说明模型每个机型只读 m、S、T_max。这三个数不需要"性能模型"，一手文件里都有：

- **着陆质量**：FAA 飞机特性数据库（2024-10）的最大允许着陆重量（MALW），已在仓库里使用（`aircraft/reference_speeds.json` 的来源）。
- **翼面积**：飞机 TCDS 的"Dimensions"一节，或厂家的机场规划手册（A220 ACP、CRJ700 APM）。
- **推力 / 功率**：发动机 TCDS 的额定起飞推力（涡扇）或起飞功率（涡桨、活塞）；飞机 TCDS 规定了更低的装机限制时取飞机的。

收集结果（[`airframe_facts.csv`](../literature/aircraft_performance/airframe_facts.csv)，出处与取舍规则见
[`airframe_facts_sources.md`](../literature/aircraft_performance/airframe_facts_sources.md)）：最常见的 37 型里，
翼面积找到 28 型（TCDS 或厂家文件），推力 / 功率 37 型全部来自 TCDS；另补了 9 型。找不到翼面积的：
CL60、GLF4、GLEX、G280、H25B、GA6C、GL7T、BE40、C408（TCDS 不印翼面积，厂家页面只给翼展，其余只有转载站，按规则不用）。
来源之间的矛盾（例如 E545 推力：飞机 TCDS 29.53 kN、发动机 TCDS 33.91 kN、厂家手册 29.09 kN）逐条记在该文件里，
取值规则是"与 FAA 表的型号和 MTOW 对应的那个构型；正常起飞推力，不取自动推力储备"。

**21 个喷气机型三个数齐全**（含 09-24 补的 C56X），用自己的参数时失速余量在 1.15–1.51 之间，全部在原生范围里（§7）。
这是比任何替代都好的做法，而且数据可以发表；但它是给模型加一种新的参数来源，属于代码改动（§9 第 1 项）。

## 6. 在已有机型里找替代：方法

对每个缺参数的机型，按下面的顺序决定（脚本 `docs/aircraft_performance/scripts/final_mapping.py`）：

1. 旋翼机、军机：排除（不是固定翼民航进近）。螺旋桨飞机（FAA 表的动力类别为活塞或涡桨）：排除（用户 2026-09-23 决定；
   分析时曾把活塞机换到 C172，那一列在表里保留为"仅参考"）。
2. 喷气机，着陆质量（FAA）、翼面积和推力（一手文件）三个数齐全，且用自己参数的失速余量在原生范围里：**用本机参数**。
3. 现在用 OpenAP 同义机型的：如果同义机型的失速余量在原生范围里、并且 FAA 进近类别相同，**保留**。
   （第 2、3 步的先后按来源的可靠程度排：一手文件先于 OpenAP 的同义机型，再先于 Poll–Schumann。2026-09-24 补到 C56X
   的一手推力后调成这个顺序，只改变了 C56X 一个机型。）
4. Poll–Schumann 有本机数据的客机：**用 PS 参数**。
5. 以上都不适用：在模型已有的 37 个机型里找替代。候选必须与目标 **动力类型相同**（FAA 表的 `Physical_Class_Engine`：
   喷气 / 涡桨 / 活塞）并且 **进近类别相同**（FAA 表的 `AAC`，按进近速度把飞机分成 A–E 类）。在合格候选里取相似距离 d 最小的；
   d 相同（FAA 速度是整节）时取最大起飞重量最接近的。
6. 合格候选的失速余量 ≥ 1.054 才接受；高于原生范围上限 1.62 的接受但注明。
7. 没有合格候选：排除（表里仍列出全机队最近的机型，标"不同类，仅参考"）。FAA 表没有进近速度的也排除。

两条说明：
- FAA 表里有两行的进近类别和它自己的进近速度矛盾（GL7T 写 B、速度 125 kt；B190 写 B、速度 121 kt）。表的数据字典说类别
  "由最高的进近速度决定"，表中其余 386 行都符合 A < 91、B 91–120、C 121–140、D 141–165 kt 的分界，所以这两行按速度归为 C。
- 第 5 步不要求"长得像"。例如 GLEX（Global Express）的替代是 A19N：两者进近速度 67.4 / 66.9 m/s，推重比 0.30 / 0.29，
  按 §3.2 在这个模型里飞法几乎一样；而尺寸相近的 GLF6 进近速度差 4.6 %、推重比差 15 %。

### 7.3 几处需要单独说明的

- **活塞机已按用户决定排除。** 分析时的结论保留在这里，供以后需要时参考：**活塞机 → C172 的失速余量偏大（1.71–2.15）**，原因有两个。一是 C172 预设的翼载很低（着陆质量 983 kg / 16.2 m² ≈ 61 kg/m²），
  而 SR22 约 115 kg/m²。二是模型给所有 30 t 以下的飞机同一个 C_L,max = 2.2。用这些机型自己的着陆质量和翼面积算，失速余量是：
  S22T 1.33、SR22 1.39、BE36 1.48、DA40 1.62、P28A 1.71，也就是说 P28A 用 C172 与用自己的几何是一样的，但 Cirrus / Bonanza
  用自己的几何会好得多。活塞机不能直接"用本机参数"，是因为模型的推力是一个不随速度变的力，而活塞 / 涡桨发动机给的是功率。
  这要一个螺旋桨推力的近似（例如 T ≈ η·P / V）；用户决定不做（§9 第 3 项）。
- **CRJ7**：Poll–Schumann 自己的同义表把它映到 CRJ9；我们有一手的 S = 70.61 m² 和 2 × 56.36 kN，直接用本机参数。
- **C56X**：原来是 OpenAP 同义机型 C550，并在代码里手工改回了自己的质量和翼面积。2026-09-24 从 EASA 型号合格证数据单补到
  翼面积 34.4 m²（369.7 ft²）和发动机推力 2 × 18.32 kN（PW545B / PW545C），改用本机参数，失速余量 1.41 不变。FAA 飞机特性
  数据库给它的最大起飞重量是 20,200 lb（XLS / XLS+），不是代码原来写的 20,000 lb（最初的 Excel）。
- **LJ45 → GLF6（OpenAP 的同义）** 看起来大小差很多（9.8 t 对 45 t），但按 §3.2 这个模型只看比值：失速余量 1.46、推重比相近，所以保留。
  E145 更近（d 0.02），不改是因为现有替代已经合格；要统一按最近替代，改 E145 也可以。
- **CRJ2**：OpenAP 的同义机型 E145 属于进近类别 C，CRJ2 是 D，按规则改为同类的 CRJ9（进近速度相同，d = 0）。
- **B735**：OpenAP 的同义 B734 失速余量只有 1.09（低于原生范围），改用 Poll–Schumann 的本机参数（1.23）；只有 1 条航班。
- **LJ31、ASTR**（19 条 + 1 条）：同类替代 C550 的相似距离不比 A320 小，CSV 的 `notes` 列已注明。
- 带 * 的公务机没有一手推力数据，推重比没有核对；最常见的是 C56X、LJ45、GL5T、PC24、C25A、C525、HDJT、GA5C。

## 8. 局限

- **FAA 进近速度是每个机型一个数**（最大允许着陆重量下，FSB 或厂家文件的最高进近速度）。实际航班更轻、更慢，
  所以失速余量是按机型比较的尺度，不是逐条航班的真实裕度。
- **换参数只改 m、S、T_max 和 C_L,max 落在哪一档。** 阻力系数（全机队常数）和 C_L,max 分档都不变，这些对原生机型
  同样成立。进近参考速度原来也是分档默认值（5.7–150 t 一律 145 kt），2026-09-23 已改为各机型的公布值（§9 第 5 项）；
  本报告的失速余量和相似距离都不读它，所以数字不受影响。
- 推重比用额定起飞推力和最大起飞重量；A220 / B717 / E175 有多个发动机选项时取了最大额定的那个。
- 进近类别 A–E 的分界（91 / 121 / 141 / 166 kt）是从 FAA 表自身核对出来的（386 / 388 行一致），
  没有引用 FAA AC 150/5300-13B 原文；类别本身取的是 FAA 表的列。
- 原生范围 1.13–1.62 和失速分支阈值 1.054 都来自模型本身，是我们判断"合格"的尺度，不是规章要求。
- 相似距离 d 的形式和两项等权是我们从点质量方程得出的定义（§3.2），论文里应当作方法陈述，不能当成文献结论。
- Poll–Schumann 只有干净构型；它的 S 与 TCDS 有出入（E75S 差 14 %），所以一手文件优先。
- test 集没有统计（封存）。val 的比例与 train 一致（用 A320 的 26.5 %）。
- 612 条识别不出机型的航班没有办法按机型处理。

### 9.1 第 5 项做了什么

- `aircraft/aircraft_sets.py`：`Approach.speeds` 是该机体在 `aircraft/reference_speeds.json` 里的一行（FAA 飞机特性数据库
  `Approach_Speed_knot` 及双襟翼档的值，和它们对应的 MALW）；`reference_speed_ms(m)` = 公布速度 × √(m / MALW)，
  与阈值速度门同一条换算、同一个上沿参考（`ReferenceSpeed.vref_kt(m, edge="high")`）。所以优化器精确飞到目标时，
  穿越速度就在速度门的窗口里；只公布一个值的机型正好落在下沿（门是闭区间，算通过）。依据：FAA AC 91-79B §5.2.2
  "Vref 加风和阵风修正，保持到跑道入口上方 50 ft"，模型没有风，修正为 0。三个手工预设同样取表。
- 第一版（09-23）没有按质量换算，代码审查发现：A320 预设的着陆质量（66.3 t）比 FAA 的 MALW（66.0 t）重，
  按构造就落到门的下沿以下，这样的机型有 13 个。按用户选的方案 A 改成按质量换算后，这个问题消失。
- `aircraft/query_aircraft_parameters.py`：OpenAP 机型取"质量所属机体"那一行 —— 原生机型取自己的；OpenAP 同义机型
  取替代机型的（LJ45 的质量是 GLF6 的，所以速度也用 GLF6 的，不然换算出 257 kt）；C56X 的质量已被改回它自己的，所以用自己的。
  没有公布值的机型（只有 B3XM）既不能建模，也不再算 OpenAP 原生机型。
- `aircraft/reference_speeds.json`：补 18 个 OpenAP 机型的 FAA 行，规则与原有 FAA 行相同（`docs/reference_speeds/README.md`）。
- 已准备好的场景文件（`flight_scenarios/outputs/*_threshold_scenarios.json`，存的是 145 kt）在加载时被拒绝，
  重新求解前要重跑 `prepare_scenario_inputs.py`（覆盖数据，到时再征得同意）。
- 后端机型目录与 Pilot 面板：Pilot 的状态一律按最大起飞质量求解，目录的目标速度 = 这个质量下的公布速度，可调范围 =
  速度门在同一质量下的窗口 [V_ref,lo, V_ref,hi + 20 kt]，范围下端就是交互优化器的默认速度下限（第二轮审查发现：
  原来目录按着陆质量给、求解按最大起飞质量，默认目标解不出来）；前端去掉了 145 / 135 / 155 kt 的缺省值，目录没加载时不显示目标编辑框。
- 优化器：速度下限原来的 V_ref 上界永远不起作用（1.10 × 失速速度最多是公布下沿的 0.93 倍），已删；`--resume` 遇到目标
  不同的旧记录会重新求解，不再把 145 kt 目标下的记录当成完成。
- 评估报告的方法说明记录参考速度表的 sha256 和行数（190 行）。
- 影响：优化器 `runway` 模式的终端速度、速度下限的上界、交互优化器的默认速度下限；评估报告的速度偏差字段；
  后端目录与 Pilot 面板。**ts 数据集不读目标速度，cohort 和 checkpoint 都不动。** 磁盘上的 70,267 条优化器记录保持原来的
  目标，重新求解才会变。
- 一个明确的近似（写在 `Approach` 的说明里）：公布速度是指示空速，模型当真空速用（这些机场高度下差 < 1 %）。
- 文档：`flight_scenarios/docs/population_reference.md` FS5、`4dTrajectory/docs/optimizer_reference.md` K10、
  `evaluation/docs/THRESHOLD_SPEED_GATE.md` §7、`docs/reference_speeds/README.md`、`docs/code-health-followups.md`
  #18（已解决）/ #23（解决一半）、`docs/CHANGELOG.md`。

## 11. 复现

脚本在 `docs/aircraft_performance/scripts/`，只读仓库数据，中间结果写到 `AERO_SUB_WORK`（默认 `/tmp/aero_substitution`），

脚本所在的仓库，在没有数据的 worktree 里运行时把它设成主目录。2026-09-23 按这个顺序重跑，CSV 与本文的表逐字节相同：

conda activate aeroviz
python docs/aircraft_performance/scripts/read_acd.py        # FAA 表 → acd.json（只用标准库读 xlsx）
